# Planetory 명세안 시제품

2026-09-07 제작한 시제품을 2026-09-08 저장소에 정리했다. 비교 기준과 축소 범위를 아래에 기록한다.

## 실행

실행 및 단일 HTML 생성 방법은 [공통 README](../README.md)를 따른다. 소스는 `spec/`, 공통 자산은 `shared/`에 있다.

## 시연 순서

1. 처음에는 TIC 259377017만 표시된다.
2. 별을 선택하고 분석 시작을 누른다.
3. 실제 광도곡선의 읽기 전용 미리보기와 분석 프론트 연결 자리를 확인한다.
4. ‘안내 완료 상황 보기’는 명시적인 시연 버튼이다. 채점·성과·등급을 발생시키지 않는다.
5. 튜토리얼 안내가 완료되고 TIC 307210830, TIC 199574208이 부모 별 바깥에 열린다.
6. 두 별 중 하나를 선택해 해당 별의 분석 연결 화면으로 이동한다.
7. 지도 복귀·새로고침 후 진행 유지·목록 선택·도움말·시연 초기화를 확인한다.
8. 충분히 축소하면 가까운 별이 묶인다. 묶음에 마우스를 올리면 구성 요약, 누르면 확대된다.

## 명세에서 반영한 것

- 순수 검정 배경, 흰색 경계, 각진 패널, NASA 파랑 #1c67e3, Pretendard.
- 회원별 탐사 지도, 초기 튜토리얼 1개만 표시, 해금된 별만 지도·목록에 표시.
- 실제 천구 좌표 대신 미리 정해진 개인 지도 좌표, 부모 별 바깥 방향으로 해금.
- 캔버스 이동·휠 확대·전체 보기·별 선택·상세 정보·분석 시작 및 이어하기.
- 파란 튜토리얼 번호. 별 색의 행성 수 범례. 이번 시연의 발견 행성 수는 항상 0이며 별 색은 #d9dcff이다.
- WebGL 별 렌더링, 미지원·컨텍스트 손실 시 목록 대체, 키보드 이동 및 축소·확대.
- 멀리서 가까운 별을 묶는 축소 표현. 3개 대상의 시연용 계산이다.

## 대화에서 합의한 시제품 축소 범위

- 명세의 튜토리얼 5개를 TOI-270 1개로 축소.
- 안내 완료 후 나머지 2개를 고정 해금. 실제 명세의 등급별 무작위 해금이 아니다.
- `guideDone`과 별의 분석 상태를 분리. 안내 완료 후 TOI-270은 분석 중이다.
- 분석 화면은 다른 프론트와 연결할 자리다. 그래프 조작·BLS 판정·제출 API·잔차 계산은 구현하지 않았다.
- 서버·계정 연결 대신 이 시제품 전용 localStorage를 사용한다. 제품 명세에서는 서버에 저장해야 한다.
- 지도 좌표는 시제품 fixture다. 제품 명세에서는 서버가 계산한 사용자별 StarUnlock 좌표를 제공한다.
- 5단계 사전 집계 LOD, 대규모 타일 조회, 10만 개 성능 검증은 하지 않았다. 3개 별의 작동 결과를 명세의 성능 목표 달성으로 해석하면 안 된다.
- 섹터는 상세 패널에 관측 회차로 표시한다. 실제 하늘 위에 경계선을 올리는 기능은 제안안에 해당하므로 여기에 넣지 않았다.
- 별/행성의 정답 이름과 개수를 초기 지도에서 미리 공개하지 않는다. 실제 천체 이름은 데이터 파일과 이 문서의 출처 식별용으로만 포함된다.

## 데이터

팀 실험 폴더의 공식 TESS SPOC FITS 7개를 읽어 정적인 `data.js`로 추출했다.

| 천체 | TIC | 섹터 |
|---|---|---|
| TOI-270 | 259377017 | 3, 4, 5 |
| L 98-59 | 307210830 | 2, 5, 8 |
| CM Draconis | 199574208 | 16 |

FITS의 TICID, SECTOR, CAMERA, CCD, TESSMAG, TEFF, RADIUS, RA_OBJ, DEC_OBJ와 TIME, PDCSAP_FLUX, QUALITY를 읽었다. 광도곡선 미리보기는 QUALITY=0 및 유한한 값만 사용하고, 섹터별 중앙값으로 정규화한 뒤 시간순으로 일정한 인덱스 간격의 표본을 골라 축약했다. 일부 짧은 신호가 표본 사이에서 빠질 수 있으므로 실제 분석에는 원본 정제곡선을 사용해야 한다. 과학 분석용 detrending, BLS 계산 및 후보 검증을 수행한 결과가 아니다. 관측 공백을 선으로 잇지 않는다. RA/Dec는 보존하지만 명세안 지도 배치에는 쓰지 않는다.

## 분석 프론트 연결 지점

`app.js`의 `startAnalysis()`, `returnMap()`, `completeGuide()`가 현재 연결 지점이다. 실제 통합 시에는 두 프론트와 백엔드가 합의한 인터페이스로 교체한다.

- 진입: TIC, 분석 데이터 묶음/버전, 안내 단계, 지도 복귀 위치.
- 복귀: 분석 시도·판정 결과·별 완료·새 해금 목록을 별도 상태로 받기.
- 안내 완료만으로 과학적 성과나 별 전체 완료를 만들지 않기.
- 중복 완료 이벤트가 해금을 반복 생성하지 않기.
