# Planetory 제안안 시제품

2026-09-07. 서진 파트의 탐사 지도 제안안. 명세안과 같은 실제 별 3개, 같은 분석 연결 범위로 비교한다. 2026-09-08 비교 소스와 재생성 도구를 저장소에 정리했다.

## 실행과 공유

실행 및 단일 HTML 생성 방법은 [공통 README](../README.md)를 따른다. 소스는 `proposal/`, 공통 자산은 `shared/`에 있다.

진행은 이 브라우저의 `planetory-sky-prototype-v1` 저장 공간에만 남는다. 명세안 저장 공간과 별개다. 파일을 다른 사람에게 전달해도 내 진행은 포함되지 않는다. `file:`에서 브라우저가 저장을 제한하면 현재 화면에서만 유지하며, 하단에 그 상태를 표시한다.

## 추천 시연 순서

1. 첫 화면은 첫 튜토리얼 별 1개만 선택할 수 있다. 작은 배경 점들은 장식이다.
2. 번호가 붙은 별 또는 왼쪽 목록을 선택한다. 실제 좌표와 관측 회차를 확인한다.
3. **관측 레이어 → TESS 관측 영역**을 켜면 Sector 3의 카메라·CCD 영역이 보인다. **이 관측 영역으로 이동**으로 범위 전체를 살펴본다. 격자, 섹터 2·3·4·5·8·16, 선명도를 바꿀 수 있다.
4. 드래그로 시선을 돌리고 휠로 시야각을 바꾼다. 아래 숫자는 세로 시야각이다. 범위는 12°–120°다. 방향키 및 ＋/−도 지원한다. Home/선택 방향은 선택한 별(선택하지 않았으면 첫 별)로 돌아간다.
5. **분석 시작**에서 실제 밝기 기록을 본다. 그래프는 읽기 전용 미리보기다.
6. **안내 완료 상황 보기**로 튜토리얼 뒤에 두 별이 열리는 상황을 재현한다. 실제 채점은 하지 않는다. 첫 별은 여전히 ‘분석 중’이다.
7. **전체 하늘에서 위치 보기**에서 열린 별 3개의 위치를 비교한다. 첫 별에서 나머지 별까지의 각거리는 약 31°, 175°다.
8. 새 별 카드를 고르면 그 별의 실제 방향으로 시선이 이동한다. 북쪽 별 TIC 199574208을 고르면 이전의 남쪽 하늘이 화면 밖으로 사라지는 점을 확인한다. 이후 Sector 16을 켜면 해당 관측 영역을 볼 수 있다.
9. 각 별의 분석 연결 화면, 지도 복귀, 새로고침을 확인한다. 시연 설정에서 처음 방문으로 초기화할 수 있다.

## 명세안과의 차이

| 항목 | 먼저 만든 명세안 | 이번 제안안 |
|---|---|---|
| 별 위치 | 사용자별 개인 x/y 지도 좌표 | 관측 자료의 RA/Dec 방향 |
| 조작 | 평면 이동·배율 확대 | 천구 안에서 시선 회전·시야각 조절 |
| 새 별 | 부모 주변에 배치 | 실제 좌표 유지, 카드·목록에서 방향 이동 |
| 전체 보기 | 개인 지도에 별을 모아 보기 | 전체 하늘을 펼친 보조 지도, 위치 선택 |
| 섹터 | 상세 정보의 관측 회차 | 같은 하늘 좌표 위에 관측 영역을 겹침 |
| 색과 진행 | 내가 찾은 행성 수에 따른 색 | 온도에 따른 대략적인 색, 진행은 별도 배지 |
| 분위기 | 검정·각진 패널·파랑 | 남색·둥근 패널·옅은 청록 |
| 대규모 처리 | 소수 대상의 축소 묶음 시연 | 소수 대상의 시야 밖 제외, 방향 이동 시연 |

두 버전 모두 3개 별로 대규모 성능을 입증하지 않는다. 이번 제안안에는 대규모 데이터용 LOD·타일 조회·클러스터링이 구현되어 있지 않다.

## 좌표와 섹터의 의미

별의 RA/Dec를 단위 구의 방향 벡터로 변환하고, 그 구 안의 관찰자가 바라보는 방향으로 원근 투영한다. 실제 거리나 항성의 공간 크기를 표현하는 3차원 우주 모형이 아니다. 북쪽은 위, 적경 증가 방향은 왼쪽이다. 시선 이동은 두 방향 사이의 짧은 대원 경로를 따른다. 북극·남극을 넘는 회전은 제한하고 북쪽이 위인 상태를 유지한다.

큰 화면도 결국 평면 모니터에 투영된다. 주변으로 갈수록 왜곡되며, 한 화면에 하늘 전체를 담지 않는다. ‘하늘 전체’는 적경·적위의 등간격 평면 보조 지도다. 양쪽 끝이 이어지고 극지방은 늘어나 보인다. 초록 점선은 현재 화면의 투영 범위, 흰 원은 시선 중심이다.

섹터는 한 회차에 TESS의 4개 카메라가 관측한 영역이다. 한 카메라당 4개의 CCD가 있어 16개 영역과 틈을 표시한다. 세로로 연결된 관측 영역을 천구에 올리는 방식이며, 구의 중심에서 뻗어나가는 피자 조각이 아니다. 배경의 별 장식과 섹터의 실제 좌표는 구분한다.

`sectors.js`에는 tesswcs 1.9.0 wheel에 포함된 archival WCS를 바탕으로 만든 6개 섹터, 96개 CCD 경계가 들어 있다. CCD 과학 영상 영역(FITS 1-based 열 45–2092, 행 1–2048)의 바깥 픽셀 경계를 각 변당 32개 점으로 샘플링했다. CRVAL/CRPIX/CD 및 기록된 SIP 계수를 사용했다. 반올림은 소수점 7자리다. 이것은 해당 관측의 대표 WCS이며 실시간 자세 변화나 광학 경계의 정밀 판정 도구가 아니다. 공개 데이터 패키지를 빌드 시 읽었고, 시제품 실행 중 네트워크를 호출하지 않는다.

7개 실제 관측의 별 좌표가 각각 FITS에 기록된 sector/camera/CCD의 과학 영상 영역 안에 들어가는지 역변환으로 검증했다. 계산 결과와 wheel SHA-256은 `sector-validation.json`에 보존했다.

## 실제 자료와 시연 자료

| 사용 대상 | 실제 자료 |
|---|---|
| TOI-270 / TIC 259377017 | RA 68.41550094°, Dec −51.95623229°, S3·4·5 |
| L 98-59 / TIC 307210830 | RA 124.53175629°, Dec −68.31299987°, S2·5·8 |
| CM Draconis / TIC 199574208 | RA 248.58470796°, Dec +57.16232376°, S16 |

명세안에서 추출한 `data.js`를 그대로 사용한다. 이 파일의 개인 x/y·generation 값은 제안안 렌더링에 사용하지 않는다. 실제 천체 이름은 출처를 확인하기 위한 데이터·문서에만 보존하고 제품 화면에는 TIC 식별자만 보여 준다.

광도곡선은 공식 TESS SPOC FITS 7건의 TIME, PDCSAP_FLUX, QUALITY에서 추출했다. QUALITY=0 및 유한한 값만 고르고 섹터별 중앙값으로 정규화한 후, 각 섹터에서 시간순 인덱스 간격으로 1,400개를 골랐다. 총 9,800점이다. 관측 공백을 선으로 연결하지 않는다. 축약 때문에 짧은 신호가 빠질 수 있으며 detrending·BLS·후보 판정을 수행한 결과가 아니다.

배경의 작은 점 6,000개는 고정 난수로 구 위에 균일하게 배치한 장식이다. 실제 카탈로그를 흉내 내는 탐사 대상이 아니며 선택할 수 없다. 대상 별의 색은 TEFF에 따른 대략적인 따뜻한 색 표현이고, 크기·밝기·글로우는 읽기 쉽도록 조정했다. 과학적인 항성 색온도 재현은 아니다.

시연에서만 사용하는 사항:

- 튜토리얼 5개를 1개로 줄이고 안내 완료 후 지정한 2개 별을 고정 해금한다.
- 채점·등급 변화·행성 발견 성과를 만들지 않는다. 내가 찾은 행성은 0개로 유지한다.
- 계정·서버 동기화 없이 브라우저에만 진행을 저장한다. 지도 방향과 레이어 설정은 세션 내에서 유지하며 새로고침 시 기본값으로 돌아간다. 선택된 별과 분석 진행은 복원한다.
- 분석 그래프 조작·제출·판정·별 전체 완료는 분석 프론트와 연결할 부분으로 남겨 놓았다.
- 로컬 데이터는 공개 관측 자료다. 초기 표시를 숨기는 것이 접근 제어를 제공하는 것은 아니다.

## 팀에서 검토할 연결 지점

`app.js`의 `startAnalysis()`, `returnMap()`, `completeGuide()`를 실제 분석 프론트와 서버 계약으로 교체한다. 진입에는 TIC, 데이터 버전, 안내 단계, 복귀할 시선 방향을 전달한다. 복귀에는 안내 완료, 분석 시도/판정, 별 전체 완료, 신규 해금 목록을 별도로 받는다. 서버에서 실제 이용 가능한 좌표와 해금 권한을 관리해야 한다. 명세의 등급별 무작위 해금 규칙을 바꾸려면 팀 합의가 필요하다.

성능 목표는 측정 전이다. 명세의 10만 개, 첫 표시 2초, 프레임 P95 16.7ms·최악 33ms, 힙 300MB 등을 달성했다는 의미가 아니다. 제안안을 제품에 적용한다면 구면 공간 인덱스와 타일, 시야에 따른 요청 취소, 투영 뒤 겹침 처리, 별/라벨/클러스터 상한, 대표 기기의 실측이 필요하다. WebGL 미지원·컨텍스트 손실 시 DOM 별과 목록으로 이어갈 수 있도록 처리했으나 컨텍스트 손실의 실기기 검증은 수행하지 않았다.
