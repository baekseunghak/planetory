# 별 지도 명세안·제안안 비교 PoC

대표 Jira: S15P21C206-38 · 참고 Jira: `S15P21C206-33`, `S15P21C206-26`

이미 만든 두 시제품을 팀이 실행하고 비교할 수 있도록 정리한 실험이다. 첫 별 선택 → 분석 화면 미리보기 → 안내 완료 시연 → 두 별 자유 선택까지 같은 흐름을 제공한다. **실제 분석·채점·서버 연동을 구현한 제품은 아니다.** 기존 요구사항 문서를 변경하지 않는다.

## 바로 실행

저장소 루트에서 Python 3.11 이상으로 실행한다. 데이터 처리 패키지는 필요 없다.

```sh
python -m http.server 58219 --bind 127.0.0.1 --directory experiments/star-map-prototype
```

- 명세안: <http://127.0.0.1:58219/spec/>
- 제안안: <http://127.0.0.1:58219/proposal/>
- 서버 종료: 실행한 터미널에서 Ctrl+C

Chrome/Edge의 데스크톱 화면을 기준으로 한다. `spec/index.html`, `proposal/index.html`을 직접 열 수도 있지만 브라우저 저장 정책 차이가 있어 HTTP 실행을 권장한다. 처음 1개, 안내 완료 시연 후 3개가 선택된다. 별 6,000개처럼 보이는 제안안 배경 점은 선택할 수 없는 장식이다.

## 팀에 단일 HTML 파일로 공유

```sh
cd experiments/star-map-prototype
python scripts/build_exports.py
```

생성되는 `dist/planetory-spec.html`, `dist/planetory-proposal.html`을 각각 전달하면 된다. 글꼴·코드·데이터·라이선스를 포함해 네트워크 없이 실행된다. ZIP·원본 FITS·단일 HTML 중복 산출물은 Git에 넣지 않는다. AI가 만든 초기 콘셉트 이미지는 구현 화면과 다를 수 있으므로 이 PoC의 검증 증거로 사용하지 않는다.

## 비교할 차이

| 항목 | 명세안 | 제안안 |
|---|---|---|
| 별 배치 | 개인 지도 x/y 고정 좌표 | FITS의 실제 RA/Dec 방향 |
| 조작 | 평면 이동, 배율 확대 | 천구 내부에서 시선 회전, 시야각 조절 |
| 신규 별 | 첫 별 주변에 표시 | 실제 방향 유지, 목록·카드로 이동 |
| 전체 보기 | 개인 지도에 세 별을 모음 | 하늘 전체를 펼친 보조 지도 |
| 섹터 표시 | 상세 정보의 관측 회차 | 실제 좌표 위 16개 CCD 경계와 틈 |
| 별 색 | 발견 행성 수 범례, 시연에서는 모두 0개 | 온도 기반 대략적인 색, 진행 배지 별도 |
| 분위기 | 검정, 각진 패널, NASA 파랑 | 남색, 둥근 패널, 청록 |
| 대규모 처리 | 소수 대상 축소 묶음 | 시야 밖 제외, 실제 방향 이동 |

**두 안 모두 10만 개 성능을 검증하지 않았다.** 명세안도 전체 명세의 완성본이 아니다. 튜토리얼 5개를 1개로 줄였고, 등급별 무작위 해금 대신 지정된 2개 별을 연다.

## 5분 시연 순서

1. 하단 `시연 설정`에서 처음 방문으로 초기화한다.
2. 첫 별 TIC 259377017 선택 → 관측 회차 확인 → `분석 시작`.
3. 실제 광도곡선 미리보기와 분석 프론트 연결 범위를 확인한다.
4. `안내 완료 상황 보기` → 두 별 중 하나 선택 → 해당 별 분석 → 지도 복귀.
5. 나머지 별도 선택하고 새로고침 후 진행 복원을 확인한다. 안내 완료는 첫 별의 분석 완료나 행성 발견을 뜻하지 않는다.
6. 명세안은 축소·전체 보기, 제안안은 `관측 레이어`의 TESS 영역·섹터 변경·영역 이동을 비교한다.
7. 제안안의 `전체 하늘에서 위치 보기`로 남쪽 별과 북쪽 TIC 199574208의 방향 차이를 확인한다.

## 구성과 연결 지점

```text
spec/                 명세안 HTML/CSS/JS
proposal/             제안안 HTML/CSS/JS 및 구면 투영 계산
shared/               세 별의 최소 표본, 섹터 경계, 데이터 출처, 글꼴·라이선스
scripts/              관측 표본·경계 재생성과 단일 HTML 내보내기
tests/verify-math.cjs  구면 투영·방향·보간·섹터 표본 검증
docs/                 두 안 설명, 데이터 스키마, 검증 기록
```

각 `app.js`의 `startAnalysis()`, `returnMap()`, `completeGuide()`가 분석 프론트와 합의할 연결 지점이다. TIC, 분석 데이터 버전, 안내 단계, 지도 복귀 위치를 전달하고, 안내 완료·분석 판정·별 전체 완료·새 해금 목록을 구분해 돌려받아야 한다. 현재 실제 API 계약은 구현하지 않았다.

진행은 `planetory-spec-prototype-v1`, `planetory-sky-prototype-v1`이라는 서로 다른 localStorage 키에 저장된다. 사용자 프로필 ‘서진의 우주’는 고정 시연 문구이며 로그인이 아니다. 해금 전 데이터를 숨기는 동작은 접근 제어가 아니다.

## 팀 리뷰에서 결정할 것

- 개인 탐사 지도와 실제 하늘 지도 중 기본 화면 및 두 화면을 함께 둘지 여부
- 분석 프론트로 이어지는 안내의 담당 범위와 복귀 상태 계약
- 해금 규칙, 관측 영역 기본 표시 여부, 모바일 범위
- 최종 성능 측정 대상 기기·데이터 개수·목표 및 실제 API 공급 범위

팀 리뷰, MR 병합, 인수 조건 확인이 끝나기 전까지 Jira는 `진행 중`으로 유지한다.
