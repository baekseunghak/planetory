# 데이터와 구현 안내

## 데이터 출처·재현

- `server/fixtures.ts`가 알려진 예시 TIC와 합성 식별자를 포함한 카탈로그·곡선·신호를 생성합니다. 곡선은 수식으로 만든 150개 표본이며 TESS 원본 광도곡선이 아닙니다.
- `server/galaxy-demo.ts`의 `prepareGalaxyDemo`가 `catalogue(50000 - 6)`으로 50,000개 고유 별을 준비합니다. `seojin` 시연 계정에 별을 열고 예시 신호 2개를 기록합니다.
- `galaxyPosition(index)`는 인덱스별 초기값 `Math.imul(index + 71, 2654435761) >>> 0`, 증가값 `0x6d2b79f5`의 의사 난수를 사용합니다. 같은 코드·인덱스는 같은 좌표·크기·색을 만듭니다. 첫 여섯 개는 시연 위치를 명시적으로 지정합니다.
- 분포는 중앙 20%, 나선 팔·원반 80%에 두께를 더한 시각화 수식입니다. 은하의 실제 규모·물리 단위·거리 자료가 아닙니다.
- `npm ci` 후 `npm run api`가 없는 상태 파일을 자동 생성합니다. 실제 원시 자료나 대용량 생성 JSON을 Git에 넣지 않습니다. 좌표·신호는 재현되지만 진행 시각·세션 토큰은 매 실행 시각과 로그인에 따라 달라집니다.
- 글꼴 외 별도 외부 시각 자산은 사용하지 않습니다. NASA Eyes/Sketchfab은 시각 참고였으며 모델·텍스처·관측 API를 가져오지 않았습니다.

## 코드 흐름

1. `server/http.ts`가 로컬 인증과 HTTP 요청을 처리합니다. `/api/map/galaxy`는 `galaxyData()`의 전체 최소 필드 응답을 반환합니다.
2. `src/pages/SkyPage.tsx`가 데이터·카메라 상태와 드래그·휠·선택 입력을 관리합니다.
3. `shared/galaxy.ts`의 공통 좌표 계산을 캔버스와 DOM 선택 표시가 공유합니다.
4. `src/map/galaxy-renderer.ts`는 WebGL 1 GPU 버퍼, 별·빛 번짐 두 패스, 화면 격자 기반 선택 판정을 구현합니다.
5. `src/galaxy.css`와 기존 상세·분석·커뮤니티 화면이 시연 흐름을 연결합니다. 5만 개 DOM 버튼을 생성하지 않습니다.

## 실행 설정

| 변수 | 기본값 / 용도 |
| --- | --- |
| `API_PROXY_TARGET` | Vite가 연결할 API, 기본 `http://127.0.0.1:58242`; 프로세스 환경 → `.env` → 기본값 순 |
| `PORT` | API 포트, 기본 58242 |
| `CLIENT_PORT` | 허용할 로컬 프론트 포트, 기본 58241 |
| `FIXTURE_STATE_PATH` | 상태 파일, 기본 `.local/galaxy-state.json`; 부모 폴더 자동 생성 |
| `FIXTURE_RESET` | `1`이면 시작 시 기존 상태를 읽지 않고 새로 생성. 지정 파일을 덮어쓰므로 테스트 전용 경로에 사용 |
| `TEST_BROWSER` | 브라우저 테스트 채널. 미지정 시 Playwright Chromium |

기본 API는 `127.0.0.1`에만 바인딩합니다. 한 상태 파일에 여러 API 프로세스를 연결하지 마세요. 자동 테스트는 별도 포트와 별도 상태 경로를 사용합니다. `.env`는 Vite 설정용이며 API 환경 변수는 실행 셸에서 지정합니다.

## 공유하면서 정리한 부분

- 화면·투영·입자·카메라·합성 배치 구현은 원본 은하형 시제품과 동일하게 복사했습니다.
- 예제 프록시 주소를 58242로 맞추고, 테스트가 환경 변수로 독립 프록시를 지정할 수 있게 했습니다.
- 상태 파일 부모 폴더를 지정 경로에 생성하게 하여 새 테스트 경로에서도 시작할 수 있게 했습니다.
- `check`/`test:browser`가 이 은하형의 테스트를 실행하도록 맞췄습니다. 원본 평면 지도 전용 브라우저 테스트·과거 명세 합격 자료·개인 경로가 담긴 복제 스크립트는 공유하지 않습니다.
- 원본 개인 작업 폴더와 기존 저장소의 별지도 비교 PoC는 수정하지 않았습니다.

운영 배포·Docker·CI는 기존 팀 구성을 변경하지 않았습니다. 이 폴더를 검사하는 자동 GitLab CI 작업은 현재 없으므로 [로컬 검증 결과](validation.md)를 별도로 제공합니다.
