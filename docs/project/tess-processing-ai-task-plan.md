# 천문 데이터 처리·AI 후속 Task 계획

작성일: 2026-09-10, 팀 결정 반영: 2026-09-14 / 담당: 윤성용 / Jira: `S15P21C206-46` / 기준: 요구사항 명세서 v1.1, ERD v1.1, [역할 명세](tess-processing-ai-role-spec.md), [갭 분석](../data/tess-pipeline/candidate-detection.md) 5.7절·[검증과 재처리](../data/tess-pipeline/validation-and-reprocessing.md) 9절, [Jira Task·Bug](../workflows/jira-task.md) / 상태: Epic·티켓 생성 완료, 대응표(9절) 반영, MR 리뷰 대기

이 문서는 `S15P21C206-29` 기획에서 나온 천문 데이터 처리·AI 역할의 후속 Task 를 실험·구현 두 층으로 나누고, 착수 순서·선행 관계를 정리한다. 2026-09-10 에는 Epic 묶음과 티켓 범위를 팀 결정 입력으로 제안했고, 2026-09-14 에 팀이 Epic `S15P21C206-56` 아래 티켓 25개와 발표 Epic `S15P21C206-224` 아래 3개를 생성했다. 3·4·8절에 결정 결과를, 9절에 원본 17행과 생성된 티켓의 대응표를 기록한다. 역할 명세서 8절과 갭 분석 9절의 후속 Task 요약과 다르면 이 문서를 따르고, 이 문서와 Jira 티켓 설명이 다르면 Jira 티켓을 따른다.

## 1. 두 종류의 Task

명세서 v1.0 은 구조와 규칙은 확정했고 수치는 DEC 항목으로 비워 두었다. 그래서 Task 를 두 종류로 나눈다.

| 종류 | 하는 일 | 산출물 | 리뷰에서 보는 것 | 넘겨받는 사람 |
|---|---|---|---|---|
| 실험 | 고정 fixture 에 합성 신호를 심고 설정을 바꿔 비교해 수치와 근거를 낸다 | 비교표·제안값·문서 | 비교가 공정했는가, 제안값에 근거가 있는가 | 팀 (DEC 항목 결정) |
| 구현 | 결정된 값을 기본 설정으로 갖는 커널 코드와 fixture 회귀 테스트를 만든다 | 함수·테스트·계약 예시 데이터 | 테스트가 있는가, 계약대로 출력하는가 | 김동혁 (Spark 실행), 강재민·백지웅 (스키마 계약) |

실험 하나가 끝나면 대응하는 구현을 이어서 진행한다. 커널은 기존 PoC 처럼 Spark 의존성 없는 순수 함수로 유지한다.

## 2. 착수 순서와 명세 필수 여부는 다른 축이다

**착수 순서(P1~P3)** 는 "무엇을 먼저 시작하나"다. 다른 역할의 계약을 막는 것을 앞에 둔다. **명세 필수 여부**는 "v1 서비스에 없어도 되는가"다. 구현 Task 8개는 모두 요구사항 명세서 v1.0 의 필수 기능을 구현하므로 일정이 부족해도 생략 대상이 아니다. 일정이 부족할 때 줄이는 것은 실험의 범위와 고도화 항목이다.

| 축 | 값 | 뜻 |
|---|---|---|
| 착수 순서 | P1 | 늦으면 다른 역할의 계약(Candidate·transit_model API, Gold 적재)이 밀린다. 먼저 시작 |
| 착수 순서 | P2 | 병행 가능. P1 이 상대 담당자 대기 상태일 때 진행 |
| 착수 순서 | P3 | 선행 결과가 나온 뒤 착수. 늦게 시작하지만 필수 |
| 명세 필수 | 필수 | v1.0 요구사항(DAT·AI·POL)에 직접 대응. 생략 불가 |
| 명세 필수 | 축소 가능 | 실험 표본 수·비교 경로·고도화 항목. 최소 범위로 줄일 수 있음 |

**축소 가능한 범위(일정 부족 시 먼저 줄이는 것)**

| 항목 | 최소 범위 | 축소되는 것 |
|---|---|---|
| 42 전처리 벤치마크 | 별 4개·설정 11개(완료) | 다른 별의 잡음 바탕곡선, 통과 마스킹 재적합 비교 |
| A BLS 벤치마크 | 격자 밀도·품질 게이트 비교 | 사전 선별 경로(B·C 경로) 비교, 시간 측정의 정밀도 |
| B 반복 제거 벤치마크 | 종료 조건·제거 QA·P/2·2P | 셋 이상 신호 겹침, 격자 v2 세트(스트레스·식쌍성) |
| D 비닝·discoverable | 최단 통과 대비 bin 수, 봉우리 판정 기준 | fixture 밖 표본의 무신호 별 비율(DEC-01 Task 로 이관) |

| 43a·43b AstroNet | 단일 checkpoint 평가 | 10개 ensemble 비교, Vetting 모델 비교 |
| 구현 7 AI 어댑터 | 채택 모델 1개의 입력 변환·배치 추론 | 모델 교체 대비 추상화 |

**필수 최소 구현(생략 불가, 순서 아님)**. 착수 순서는 6절 표의 P 열을 따르고, 여기서는 필수 항목만 나열한다.

- 구현 1 전처리 커널 (DAT-02~04)
- 구현 2 탐색 BLS·품질 게이트 커널 (DAT-05, DEC-03)
- 구현 3 반복 제거·후보·transit_model 생성 (DAT-05~06·10)
- 구현 4 세그먼트·비닝·discoverable 판정 (DAT-07·11)
- 구현 5 외부 카탈로그 스냅샷·조인 (DAT-08·09)
- 구현 6 Gold 직렬화·QA·manifest (DAT-10~12)
- 구현 7 AI 입력·추론과 AI 결과의 Gold 연결 (AI-01~05)
- 구현 8 Spark Worker 초기 연결 (NFR-09~11)

4·5·7 은 착수 순서가 늦을 뿐 명세 필수다. 위 축소 표의 "축소되는 것"(격자 v2 세트, ensemble·Vetting 비교 등)은 확장 범위이며, 이 문서 전체에서 "확장(제안)"으로 표시한다.

**Task 별 목적 (티켓 설명 첫 줄용)**

- 42: 품질 마스크·구간 분리·detrending 방법과 창 길이를 fixture 에서 비교해 서비스 전처리 기본값을 제안한다.
- A: 탐색용 BLS 의 격자·주기 범위·품질 게이트 기준을 회수율·오검출·시간으로 비교해 DEC-03 채택 임계값 후보를 제안한다.
- B: Silver 내부 반복 제거의 종료 조건·제거 QA 수치·고조파 병합·판 사이 후보 동일성 허용 오차를 실측한다.
- C: 후보표의 transit_model JSONB 필드·shape·모델 버전과 "고정 모델 제거" 잔차 규칙을 강재민과 확정한다.

## 7. Task 명세 작성 규칙

[Jira Task·Bug](../workflows/jira-task.md)의 `Task 작성` 템플릿을 그대로 쓰고, 이 역할의 Task 에는 두 항목을 더한다.

```markdown
## 목적
이 작업이 필요한 이유.

## 작업 내용
- 구현하거나 조사할 내용.

## 제외 범위                      ← 추가
- 이 Task 에서 하지 않는 것 (실험이면 "수치 확정", 구현이면 "Spark 연결" 등).

## 완료 조건
- [ ] 확인 가능한 조건. "무엇이 어디에 있으면 끝".
- [ ] 결과물 또는 문서 위치.

## 검증 방법
실행 명령, 테스트 방법(pytest 등), 리뷰 방법. 실험이면 비교 지표와 읽는 법.

## 관련 정보
- 선행 작업: 착수 조건과 완료 검증 조건을 구분해서 적는다.
- 관련 문서: 갭 분석 절, 이 계획 문서, fixture 문서.
- 데이터 또는 환경: fixture 대상(별·Sector), 격자·설정 버전, Python·uv 환경, 실행 위치(로컬/WSL/Worker).
- 결정 ID: DAT·DEC·AI·ERD 미결 번호.   ← 추가
```

- 제목은 `[영역] 작업 목적`. 영역은 컨벤션 후보 중 데이터·분석·Spark·문서를 쓴다. **AI 영역 접두는 `[ML]` 로 결정됐다**(2026-09-14). 43 의 제목이 `[ML]` 로 바뀌었고 신규 118·126·130 도 `[ML]` 이다. 완료된 40 의 `[AI]` 는 그대로 둔다. 이 문서 본문에서 "43a·43b", "구현 7" 처럼 `[AI]` 로 부른 곳은 이력이며 현재 접두는 `[ML]` 이다.
- Task 하나 = 브랜치 하나 = MR 하나. 두 사람이 걸치면 "공동" 표기하고 담당은 한 명.
- 실험 스크립트는 실행하면 터미널에 진행 상황과 핵심 수치를 출력하고, 실행마다 manifest(`S15P21C206-41` 스키마)를 남긴다.
