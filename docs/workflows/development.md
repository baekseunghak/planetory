# 기능·수정 작업 가이드

## 이 문서를 읽는 경우

`기능 만들어줘`, `구현해줘`, `버그 고쳐줘`, `리팩터링해줘`, `설정 바꿔줘`, `실험해줘`

## 탐색 순서

[AGENTS.md](../../AGENTS.md)의 `작업 전 필수 순서` 10단계를 그대로 따른다. 같은 단계를 이 문서에 복제하지 않는다. 아래는 개발 작업에만 해당하는 확인 사항이다.

## 구현 전 확인

- **요청한 것이 이미 있는지 먼저 본다.** 테이블·엔티티·API·설정이 ERD, API 명세, 코드에 이미 있으면 새로 만들지 않고 무엇이 부족한지 사용자에게 확인한다.
- **요구사항 우선순위를 본다.** 기능 ID의 P0·P1과 `TBD`·`DEC` 상태를 확인한다. P1 테이블이 있어도 P1 API 구현이 승인된 것은 아니며, 미결 정책은 추측해 구현하지 않는다.
- **실험 코드는 운영 코드가 아니다.** `experiments/` 아래 구현은 참조만 하고 그대로 옮기지 않는다.

## 변경 유형별 정본

| 바꾸는 것 | 먼저 볼 정본 | 함께 갱신 |
| --- | --- | --- |
| DB 테이블·열·제약 | [서비스 DB ERD](../architecture/database-erd.md), [백엔드 개발 환경](../../apps/backend/docs/development-setup.md)의 Flyway 규칙 | ERD 본문·SVG, 마이그레이션 목록 |
| 서비스·탐사 API | [API 문서 안내](../api/README.md), `apps/backend/docs/` 명세 | 해당 API 명세, 프론트 명세의 요청 형식 |
| 기능 정책·화면 동작 | [요구사항 안내](../requirements/README.md) | 상태표·인수 조건 |
| 분석 화면·프론트 | [분석 프론트엔드 상세 명세](../development/analysis-frontend-spec.md) | API 계약이 바뀌면 API 명세 |
| TESS 처리·배치 | [데이터 문서 안내](../data/README.md) | 데이터 계약, 파이프라인 문서 |
| 시스템 경계·인프라 | [아키텍처 안내](../architecture/README.md) | 시스템 아키텍처, 운영 문서 |

정본이 `초안`·`검토안`이면 그 상태로 구현 확정을 주장하지 않는다.

문서와 코드가 충돌하면 임의로 선택하지 않고 Jira 요구사항, 정본, 실제 구현과 검증 결과를 비교해 보고한다. 공통 안전 규칙은 [AGENTS.md](../../AGENTS.md)를 따른다.
