# 기능·수정 작업 가이드

## 이 문서를 읽는 경우

`기능 만들어줘`, `구현해줘`, `버그 고쳐줘`, `리팩터링해줘`, `설정 바꿔줘`, `실험해줘`

## 탐색 순서

1. Jira 키, 목적, 범위와 완료 조건을 확인한다.
2. [문서 인덱스](../README.md)에서 작업 유형에 맞는 정본만 선택해 읽는다.
3. 과거 판단이나 오류가 관련되면 `docs/changes/`를 Jira 키·문서 경로·키워드로 검색하고 일치한 기록만 읽는다.
4. 변경 대상과 가장 가까운 `README.md`, 현재 구현, 호출 경로, 설정과 테스트를 확인한다.
5. 기존 구현과 재사용 가능한 구성요소를 먼저 찾는다.
6. 요청 범위의 최소 변경을 구현한다.
7. 관련 테스트나 정적 검증을 실행한다.
8. 영향을 받은 아키텍처·API·데이터·운영 문서를 갱신한다.
9. 중요한 결정이나 반복 오류 방지 내용이 생기면 [변경 이력](../changes/README.md)의 해당 날짜 파일을 간략히 갱신한다.
10. 변경 파일, 상대 링크, 미확정 사항을 확인한다.

문서와 코드가 충돌하면 임의로 선택하지 않고 Jira 요구사항, 정본, 실제 구현과 검증 결과를 비교해 보고한다. 공통 안전 규칙은 [AGENTS.md](../../AGENTS.md)를 따른다.

브랜치는 [브랜치 가이드](branch.md), 완료 후 커밋은 [커밋 가이드](commit.md), MR은 [MR 가이드](merge-request.md)를 필요한 시점에만 읽는다.
