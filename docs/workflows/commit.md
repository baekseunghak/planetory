# 커밋 가이드

## 이 문서를 읽는 경우

`커밋해줘`, `커밋 메시지 작성해줘`, `변경사항 저장해줘`

## 실행 경계

- “커밋 메시지 작성” 요청이면 메시지만 제공하고 `git commit`을 실행하지 않는다.
- “커밋해줘”처럼 실행을 명시한 경우에만 검증 후 커밋한다.
- 요청 범위의 파일만 경로를 명시해 stage하고 사용자의 다른 변경을 섞지 않는다.
- 한 커밋에는 하나의 논리적 변경만 포함한다.

## 형식

```text
<type>(<area>): <summary> [JIRA-KEY]
```

`type`은 `feat`, `fix`, `docs`, `test`, `refactor`, `perf`, `build`, `chore` 중에서 선택한다.

```text
docs(docs): AI 협업 지침과 문서 탐색 체계 정리 [S15P21C206-34]
fix(schema): 누락 식별자 처리 [S15P21C206-27]
```

Jira 키 예외 문서는 `docs: <summary>`를 사용한다. 특정 Jira Task의 문서 산출물은 예외가 아니며 일반 형식을 사용한다.

## 커밋 전 확인

1. `git status`와 diff에서 변경 범위를 확인한다.
2. 관련 테스트·정적 검사와 문서 링크 검사를 실행한다.
3. 비밀정보, 개인정보, 원본 데이터와 대용량 파일이 없는지 확인한다.
4. stage된 파일과 diff를 다시 확인한 뒤 커밋한다.
