# Hadoop 운영 작업 가이드

## 이 문서를 읽는 경우

`Hadoop 설치·설정해줘`, `HDFS·YARN·Spark 작업해줘`, `클러스터 기동·중지해줘`, `장애 복구·데이터 이동·검증해줘`, `실행 중 오류를 고쳐줘`

## 먼저 볼 문서

- 역할·데이터 경계·배치 규칙: [Hadoop·Spark 개발 규칙](../data/spark-hadoop-guidelines.md)
- 현재 설치·운영 명령과 검증 상태: [분산 시스템 운영 절차](../../infra/distributed-system/README.md)
- 노드 접속·상태 확인·복구 경계: [GCP 노드 운영 런북](../operations/gcp-node-runbook.md)
- 과거 오류와 결정: [변경 이력](../changes/README.md)에서 Jira 키·스크립트명·오류 메시지로 검색

관련 없는 문서는 미리 읽지 않고, 현재 작업에 해당하는 정본과 가장 가까운 스크립트·README만 확인합니다.

## 기본 원칙

- 설치, 설정 변경, 기동·중지, 장애 복구, 데이터 이동과 검증은 가능한 한 저장소에서 버전 관리하는 스크립트로 수행합니다.
- 수동 명령은 읽기 전용 진단이나 긴급 대응에 한정합니다. 재사용할 성공 경로가 확인되면 같은 작업에서 스크립트와 가장 가까운 운영 README 또는 런북에 반영합니다.
- 실서버에서만 임시로 수정하고 끝내지 않습니다. 스크립트와 문서에 반영되지 않은 긴급 조치는 완료로 간주하지 않습니다.
- 비밀번호·토큰·개인 키, 실제 비밀 값과 불필요한 원본 데이터는 스크립트·로그·문서에 남기지 않습니다.

## 실행 순서

1. Jira 범위, 대상 노드·역할, 변경 대상, 완료 조건과 중단 조건을 확인합니다.
2. 현재 상태를 읽기 전용으로 점검하고 기존 스크립트와 재사용 가능한 단계를 찾습니다.
3. 실행 전 검사, 본 작업, 검증과 필요한 정리를 하나의 재실행 가능한 흐름으로 작성합니다.
4. 정적 검사와 오프라인 모의 실행을 먼저 통과시킵니다.
5. 실제 클러스터에서는 가장 작은 안전 단위부터 실행하고 단계별 결과를 확인합니다.
6. 오류가 나면 아래 실패 기록을 남기고 원인을 스크립트에서 수정한 뒤 실패한 단계부터 안전하게 재실행합니다.
7. 최종 검증 결과와 실제 실행 범위를 담당 운영 문서에 반영합니다.
8. 중요한 운영 방식이나 재발 방지 규칙이 바뀌면 [변경 이력](../changes/README.md)을 갱신합니다.

## 스크립트 필수 조건

- 실행 전에 대상 노드·역할·현재 상태, 필요한 용량과 선행 조건을 검사합니다.
- 정확한 대상만 변경하며, 중간 실패 시 즉시 중단하고 신규·부분 완료 상태에서 안전하게 재실행할 수 있어야 합니다.
- 삭제·포맷·강제 전환처럼 되돌리기 어려운 단계는 별도 승인, 정확한 대상과 명시적인 가드를 둡니다.
- 성공 여부를 종료 코드와 명확한 검증 결과로 남기고, 정적 검사·모의 실행·실제 클러스터 검증을 구분합니다.
- 실행 중 만든 임시 파일과 리소스는 현재 실행 범위만 정리합니다. 다른 실행, 영속 데이터와 HDFS 원본을 넓은 패턴으로 삭제하지 않습니다.

## 실패 기록

오류가 발생하면 긴 원시 로그를 그대로 복사하지 않고 다음 항목을 담당 운영 README 또는 런북에 짧게 남깁니다.

- 실행 단계와 대상
- 관찰한 증상과 식별 가능한 오류 메시지
- 확인한 원인과 영향 범위
- 스크립트·설정 수정 내용
- 안전한 재실행 시작점과 남은 임시 상태
- 수정 후 실행한 검증과 결과
- 아직 확인하지 못한 항목과 후속 Jira

같은 실수를 막는 데 필요한 조건과 오류 메시지는 보존하되 비밀정보, 개인정보, 대용량 출력과 일회성 디버그 로그는 기록하지 않습니다.

## 완료 조건

- 최종 스크립트가 신규 또는 부분 완료 상태에서 재실행 가능합니다.
- 운영 문서에 전제 조건, 실행 명령, 예상 결과, 실패 시 복구 방법과 실환경 검증 범위가 있습니다.
- 실패로 확인한 경로가 스크립트 검사 또는 회귀 검증에 반영되어 같은 오류를 다시 탐지합니다.
- 임시 수동 조치가 남아 있으면 위험과 후속 Jira가 기록되어 있으며, 이를 구현 완료나 검증 완료로 보고하지 않습니다.
