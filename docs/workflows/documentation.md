# 문서 작성·수정 가이드

## 이 문서를 읽는 경우

`문서 만들어줘`, `README 수정해줘`, `명세 정리해줘`, `중복 문서 정리해줘`, `링크 고쳐줘`

## 탐색과 수정

1. [문서 인덱스](../README.md)에서 해당 주제의 정본과 상태를 확인한다.
2. 정본·아키텍처를 바꾸거나 과거 오류가 관련되면 `rg -n "<Jira 키|문서 경로|키워드>" docs/changes`로 검색하고 일치한 기록만 읽는다.
3. `rg --files -g "*.md"`와 `rg -n "검색어"`로 중복 설명과 참조 링크를 찾는다.
4. 상세 규칙은 담당 정본 한 곳만 수정하고 상위·연관 문서는 요약과 상대 링크로 연결한다.
5. `확정`, `목표 설계`, `가정`, `후보`, `미정`, `초안`, `실험`, `구현·검증 완료`를 구분한다.
6. 기존 문서의 책임에 넣을 수 없을 때만 새 문서를 만들고 목적·범위·상태·Jira·상위 정본을 적어 가장 가까운 디렉터리 `README.md`에 등록한다. 새 유형일 때만 문서 인덱스도 수정한다.
7. 중요한 정본·아키텍처 변경은 [변경 이력 규칙](../changes/README.md)에 따라 해당 날짜의 간략한 기록과 주차 인덱스를 갱신한다.
8. 코드와 설정이 바뀌지 않았다면 문서 작업의 영향 범위에 이를 명시한다.

## 검증

- 변경한 상대 링크가 실제 파일 또는 디렉터리를 가리키는지 확인한다.
- `git diff --check`를 실행한다.
- 문서 변경만 요청받았다면 애플리케이션 코드와 운영 설정을 변경하지 않는다.
- 실제 Codex·Claude 로딩을 실행하지 않았다면 정적 라우팅 검증과 구분해 보고한다.

오탈자·링크만 고친 작업, KPT, 자동 생성 결과, 변경 이력 문서 자체의 수정은 별도 변경 이력을 만들지 않는다.

브랜치·커밋·MR이 필요할 때만 각각 [브랜치](branch.md), [커밋](commit.md), [MR](merge-request.md) 가이드를 추가로 읽는다.
