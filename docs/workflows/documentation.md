# 문서 생명주기 가이드

## 이 문서를 읽는 경우

`문서 찾아줘`, `문서 만들어줘`, `README 수정해줘`, `명세 정리해줘`, `문서 옮겨줘`, `중복 문서 삭제해줘`, `링크 고쳐줘`

## 탐색과 수정

1. [문서 인덱스](../README.md)에서 해당 주제의 정본과 상태를 확인한다.
2. 정본·아키텍처를 바꾸거나 과거 오류가 관련되면 `rg -n "<Jira 키|문서 경로|키워드>" docs/changes`로 검색하고 일치한 기록만 읽는다.
3. `rg --files -g "*.md"`와 `rg -n "검색어"`로 중복 설명과 참조 링크를 찾는다.
4. 상세 규칙은 담당 정본 한 곳만 수정하고 상위·연관 문서는 요약과 상대 링크로 연결한다.
5. 문서 상태는 [AGENTS.md](../../AGENTS.md)의 상태 어휘를 그대로 사용하고 목록을 여기에 복제하지 않는다.
6. 기존 문서의 책임에 넣을 수 없을 때만 새 문서를 만들고 목적·범위·상태·Jira·상위 정본을 적는다.
7. 중요한 정본·아키텍처 변경은 [변경 이력 규칙](../changes/README.md)에 따라 해당 날짜의 간략한 기록과 주차 인덱스를 갱신한다.
8. 코드와 설정이 바뀌지 않았다면 문서 작업의 영향 범위에 이를 명시한다.
9. 본문은 `~한다`체로 쓰고 셸 예시는 `powershell` 코드펜스를 사용한다.

## 작업 중 확인한 정보 기록

- 작업 중 새로 확인한 비민감 접속 방법·식별자·테이블 구조·운영 절차·실험 결과가 반복 작업, 장애 대응, 계약 또는 중요한 결정에 영향을 주면 별도의 문서 요청이 없어도 같은 작업에서 담당 정본이나 운영 문서에 기록한다.
- 재사용 가능성, 중요도 또는 정본 위치가 불명확한 정보는 임의로 영구 기록하지 않고 사용자에게 기록 여부와 위치를 확인한다. 일회성 명령 출력과 중간 시행착오는 결론의 근거로 필요할 때만 요약한다.
- 비밀번호, API 키, 토큰, 자격 증명, 개인 키와 개인정보는 기록하지 않는다. 필요한 경우 값 대신 비밀의 용도와 안전한 주입 위치 또는 placeholder만 적는다.
- 실험 결과는 실행 조건, 관찰 결과와 검증 범위를 함께 적고 가정·부분 검증·검증 완료를 구분한다. 운영에 채택한 결론만 담당 정본에도 반영한다.

## 배치·분할·탐색 링크

- 특정 코드·설정 디렉터리의 사용법처럼 그 위치에 직접 속하는 내용은 가장 가까운 `README.md`에 둔다. 그 밖의 정책·설계·운영·실험 문서는 문서 지도에서 책임 디렉터리를 골라 `docs/` 아래에 둔다.
- 문서 길이만으로 분할하지 않는다. 서로 다른 책임이 섞이거나 반복 작업에 필요한 내용을 찾기 어려워지면 책임별 문서로 분할하고, 기존 문서에는 요약과 새 문서 링크만 남긴다.
- 새 문서는 가장 가까운 디렉터리 `README.md`에 설명과 링크를 등록한다. 새 문서 유형일 때만 [문서 인덱스](../README.md)에 디렉터리를 추가한다.
- 기존 문서를 수정·분할·이동해 다른 작업 맥락의 진입 경로가 달라지면 관련 디렉터리 `README.md`에도 짧은 설명과 링크를 추가하거나 고친다. 기존 경로로 충분히 찾을 수 있는 일반 본문 수정은 목록을 중복 갱신하지 않는다.

## 검색·이동·삭제

- 검색: 문서 지도에서 범위를 고른 뒤 파일명·제목·Jira 키·관련 용어로 검색하고, 필요한 문서와 역참조만 읽는다.
- 이동: `git mv`로 이력을 보존하고 가까운 디렉터리 `README.md`, 모든 역참조와 필요한 변경 이력을 함께 갱신한다.
- 삭제: 정본 여부와 대체 문서를 먼저 확인하고 역참조를 검색한다. 삭제 대상과 영향이 불명확하거나 복구가 어려우면 실행 전에 확인받는다.
- 의도적으로 없앤 문서는 [프로젝트 운영 문서](../project/README.md)의 삭제·대체 상태에 경로·이유·대체 문서·재도입 조건을 남긴다. 관련 README와 링크를 갱신한 뒤 깨진 상대 링크가 없는지 검증한다.

## 검증

- 변경한 상대 링크가 실제 파일 또는 디렉터리를 가리키는지 아래 명령으로 확인한다. 출력이 없으면 0건이다.

```powershell
git -c core.quotepath=false ls-files '*.md' | ForEach-Object {
  $d = Split-Path $_ -Parent; if (-not $d) { $d = '.' }
  Select-String -Path $_ -Pattern '\]\((?!https?:|mailto:)([^)#]+\.(?:md|svg))' -AllMatches |
    ForEach-Object { $_.Matches } | ForEach-Object {
      $t = $_.Groups[1].Value
      if (-not (Test-Path (Join-Path $d $t))) { "BROKEN $($_.Path): $t" }
    }
}
```

- `git diff --check`를 실행한다.
- 문서 변경만 요청받았다면 애플리케이션 코드와 운영 설정을 변경하지 않는다.
- 실제 Codex·Claude 로딩을 실행하지 않았다면 정적 라우팅 검증과 구분해 보고한다.

오탈자·링크만 고친 작업, KPT, 자동 생성 결과, 변경 이력 문서 자체의 수정은 별도 변경 이력을 만들지 않는다.

브랜치·커밋·MR이 필요할 때만 각각 [브랜치](branch.md), [커밋](commit.md), [MR](merge-request.md) 가이드를 추가로 읽는다.
