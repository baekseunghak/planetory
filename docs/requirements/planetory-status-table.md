## 0. 원칙

1. **매칭·판단·성과·완료를 나눈다.** 수치 매칭은 신호를 찾았는지, 판단은 행성 여부의 해석, 성과는 인정 조건 충족 여부, 탐색 완료는 탐색 가능한 신호를 모두 매칭했는지다.
2. **전역과 개인을 나눈다.** 라벨·AI·후보표는 전역 값이다. 개인의 오판이 후보 라벨을 바꾸지 않으며, 별별 성과·등급·발견·진행은 서버에 저장한다.
3. **성과 조건을 유형별로 적용한다.** 확정 행성·FP는 수치 매칭과 올바른 판단을 모두 요구한다. 미확정은 매칭 후 본인 분석을 공식 공개했을 때 인정한다. 근거 체크·일반 토론·반응은 점수가 아니다.
4. **공개는 선택이다.** 미게시도 다음 곡선 탐색과 완료가 가능하다. 공개 분석 목록과 일반 토론을 분리하고 사용자의 명시적 공개 요청 없이 게시·댓글·반응을 만들지 않는다.
5. **고유 후보 단위 성과를 보존한다.** 재도전은 새 기록을 남기되 중복 성과는 없다. 공개 취소·숨김·일반 삭제는 기존 성과를 자동 회수하지 않는다. 등급 상한과 기존 정정 정책은 유지한다.
6. **무신호 별은 제공하지 않는다.** 자체 BLS 채택 신호가 0개인 별은 분석 대상에서 제외한다. FP 신호만 있는 별은 일반 분석 대상이고 진입만으로 완료·FP 성과를 주지 않는다.

## 표 A. 후보 저장 필드

SRS 엔티티 기준. Candidate(자체 BLS 대표값) + ExternalSignalReference(TCE·TOI) + CandidateDisposition(통합 상태) + AIEvaluation.

| 필드 | 값 | 출처 | 비고 |
|---|---|---|---|
| period, epoch, duration, depth, tolerances | 수치 | DAT 04·08 자체 BLS | 신호 매칭의 정답. 모든 후보에 있음 |
| removal_step, transit_model_ref | 정수, 경로 | DAT 05 | 배치 내부 순차 탐색에서의 제거 순서와 통과 모델. 사용자용 잔차 곡선·주기도 파일 경로는 저장하지 않음 |
| tce_ref | TCE ID / 없음 | DAT 09 | 외부 비교값. 자체 값을 덮어쓰지 않음 |
| toi_disposition | `KP` / `CP` / `PC` / `APC` / `FP` / `FA` / 없음 | DAT 09, TOI 카탈로그 | 원본 그대로, 스냅샷 날짜 포함 |
| ai_score | 0.0 ~ 1.0 / 없음 | AI 03 자체 모델 | 모델·체크포인트·입력 버전 포함 |
| ai_status | `approved` / `hold` / `rejected` / `not_evaluated` | AI 04 | 실행 불가는 별도 상태(RES 04) |
| is_confirmed | true / false | DAT 09 (표 B) | ai_status와 독립 |
| answer_class | `graded` 채점형 / `analysis` 분석형 | DAT 09 (표 B) | 판단을 채점할지 |
| planet_truth | `planet` / `not_planet` / 없음 | DAT 09 (표 B) | 채점형만 |
| discoverable | true / false | DAT 07 원본 재검증 | 현재 공개 묶음의 순차 탐색 기준에서 사용자가 찾을 수 있는가. false면 사용자용 주기도에 봉우리를 만들지 않고 자동 완료 판단에서 제외(결정 23) |
| 버전 | 전처리·BLS·모델·규칙·카탈로그 스냅샷 | NFR 03 | 변경 시 CandidateStatusHistory |

사용자용 잔차 곡선·잔차 주기도는 Gold의 후보 저장 필드가 아니다. EC2가 원본 전체 포인트와 공개된 통과 모델로 계산하고, `(tic_id, publication_bundle_id, 정렬한 removed_candidate_ids, residual_model_version, periodogram_config_version)` 키로 캐시한다. 활성 분석 세션은 진입 시 선택한 공개 묶음에 고정하며 새 공개 묶음은 새 세션부터 사용한다. 구버전 공개 묶음과 그 키의 캐시는 보존기간 종료 시 함께 만료한다.

## 표 B. 후보 판정 규칙 (DAT 09 · AI 04 · DEC 20)

외부 라벨은 answer_class·planet_truth·is_confirmed를 결정한다. AI 상태는 모든 행에서 자체 점수·실행 상태로 별도 산정하며 라벨로 덮어쓰지 않는다.

| 순서 | toi_disposition | ai_score | → ai_status | → is_confirmed | → answer_class | → planet_truth |
|---|---|---|---|---|---|---|
| 1 | KP, CP | 무관 | 점수 규칙대로 기록 | **true** | 채점형 | 행성 |
| 2 | FP, FA | 무관 | 점수·실행 상태 규칙대로 기록 | false | 채점형 | 아님 |
| 3 | APC | 무관 | 점수·실행 상태 규칙대로 기록 | false | 분석형 | 없음 |
| 4 | PC | 무관 | 점수·실행 상태 규칙대로 기록 | false | 분석형 | 없음 |
| 5 | 없음 | ≥ 승인 임계값 | approved | false | 분석형 | 없음 |
| 6 | 없음 | 보류 이상 승인 미만 | hold | false | 분석형 | 없음 |
| 7 | 없음 | < 보류 임계값 | rejected | false | 분석형 | 없음 |
| 8 | 없음 | 없음 / 실행 불가 | not_evaluated | false | 분석형 | 없음 |

- 임계값은 자체 모델의 점수 분포를 라벨 있는 별로 검증해 정한다(DEC 04). 공개 표의 0.5 / 0.2는 참고값일 뿐이다.
- AI 보류(hold)는 자체 AI 점수 구간이며 외부 APC 라벨과 독립이다. TOI 정보가 없거나 AI가 기각했다고 채택 신호가 0개이거나 확정 FP라는 뜻은 아니다.
- 정답 주기: 채점형 후보는 외부(TOI) 주기·epoch를 대표값으로 정렬한다 `확인 필요`. 검토 문서 2-8에서 TCE 주기가 틀린 별 3개를 확인함. 분석형은 자체 BLS 값.

## 표 C. 표시 상태와 공개 시점

| 표시 상태 | 조건 | 문구·표시 | 공개 시점 |
|---|---|---|---|
| 확정 행성 보유 (별) | 후보표에 is_confirmed 후보가 있음 | 확인된 행성 있음 여부만 | 분석 진입 시. 홈에서는 숨김(EXP 02) |
| 확정·FP 해설 (후보) | 외부 라벨이 있는 후보 | 확인된 행성 또는 행성 아님, 근거·출처·조회일 | 해당 후보 매칭 후 또는 해당 결과의 상세 보기(RES 02·09) |
| AI 점수·실행 상태 | 후보에 연결된 AI 결과 | 승인/보류/기각 구간·미평가를 구분하고 인정에는 쓰이지 않음을 표시 | 후보가 연결된 제출 결과. 오류를 0점으로 표시하지 않음 |

| 탐색 완료 + 판단 불일치 | 마지막 탐색 가능 신호를 매칭했지만 확정 행성에 UNLIKELY 또는 FP에 LIKELY로 판단 | 탐색 완료, 판단이 달라요, 이번 제출 성과 미인정을 각각 표시 | 같은 결과 화면. 완료 별의 다시 풀기 유지 |

미확정 공개 통계는 공개 유효 집합에서 Submission 서버 접수 시각 내림차순, 동률이면 서버의 단조 제출 순번 내림차순으로 사용자별 하나를 고른다. 공개 시각이나 첨부 시각으로 판단을 덮어쓰지 않는다. 세 판단을 모두 분모에 넣어 n = a + b + c로 계산하며 n=0은 공개 분석 없음으로 표시한다. 미게시 재제출·토론 댓글·동의/비동의·일반 글 첨부는 이 집계를 바꾸지 않는다. 공개 취소·운영 숨김·공식 스레드 숨김으로 제외된 기록 대신 남아 있는 유효 공개 분석 중 최신을 사용한다. 사용자별로 남는 기록이 없으면 그 사용자를 분모에서 제외한다.

채점형의 성과 자격 분포와 미확정의 공개 분석 분포는 모수를 합치지 않는다. 최신 판단이 달라졌다고 기존 성과를 회수하지 않는다. 신호 링크·판단 필터 링크·일반 토론에서 표시하는 미확정 통계는 공식 스레드와 같은 집계·신호 식별자를 참조한다. 일일 StatsSnapshot은 집계 시점을 별도 표시한다.

인증된 회원은 공개된 커뮤니티 자료를 열람할 수 있지만 개인 히스토리 원본은 본인·권한 있는 운영자만 조회한다. 별이 잠겨 있으면 공개 자료를 읽을 수 있어도 분석 진입은 기존 열림 검사를 통과해야 한다. 화면에는 정답·오답을 쓰지 않고 기록과 일치 / 판단이 달라요 / 판단 보류 / 일치하는 신호 없음으로 표현한다. 미확정 신호를 확정 행성으로 표현하지 않는다.

## 표 D. 제출 항목과 결과

한 번의 후보 제출은 신호 하나를 겨냥한다. 수치 매칭·판단 결과·성과·탐색 완료는 별도 상태이며, 오판이나 미게시로 수치 매칭을 취소하지 않는다. 후보를 매칭한 뒤 다음 곡선 단계로 이동하면 EC2가 원본 전체 포인트에서 공개된 통과 모델을 빼 잔차 곡선을 먼저 만들고, 그 결과로 잔차 주기도를 계산한다. 같은 캐시 키는 결과를 재사용하며 원본으로 언제든 복귀할 수 있다(결정 9·37). 온라인 요청은 `대기 → 잔차 계산 중 → 잔차 준비 → 주기도 계산 중 → 준비`를 구분하고 실패 원인과 재시도를 제공한다. 잔차 계산 실패는 이미 저장한 매칭·판단·히스토리·완료·기성과를 취소하지 않으며 마지막 준비 완료된 곡선을 유지한 채 같은 Bundle·제거 조합으로 재시도한다.

**주기 변경 규칙 (EXP 05·08·10·12·13)**

| 사용자 동작 | 주기 상태 | 접힌 곡선 | 이후 입력 | x축 확대 |
|---|---|---|---|---|
| 주기도의 다른 봉우리 선택 | 주기 재선택 | 새 주기로 다시 계산 | `phase_start`·`phase_end`, epoch·지속시간, 판단·근거·메모 초기화 | 1배로 초기화 |
| 현재 주기 허용 범위 내 이동 | 주기 미세 조정 | 조정된 주기로 다시 계산 | `phase_start`·`phase_end`, epoch·지속시간, 판단·근거·메모 초기화 | 기존 x축 확대 배율만 유지 |

두 동작 모두 현재 `curve_step`, `publication_bundle_id`, 제거 후보 조합과 주기도의 확대·이동 범위를 유지한다. 브라우저는 현재 곡선의 유효 관측점 전체와 Bundle의 `fold_reference_time_btjd`로 새 주기에 다시 접으며 주기 변경만으로 BLS·잔차 계산 API를 호출하지 않는다. 미세 조정에서 추가로 유지하는 접힌 곡선 표시값은 **x축 확대 배율(1~8배)**뿐이다. 접힌 곡선의 이동 위치·y축 표시 범위·transit 선택값은 유지하지 않고 새 접힌 곡선의 기준 위치로 다시 맞춘다. 휠은 포인터 기준 x축만 확대하고 더블클릭은 1배로 복귀한다. 차트 포커스 상태의 `+`·`-`는 차트 중앙 기준으로 1·2·4·8배 단계를 이동하고 `0`은 1배로 복귀하며 y축 범위는 바꾸지 않는다. 두 주기 변경 동작 모두 이후 단계에서 수행하면 주기 맞추기 단계로 돌아간다. 미세 조정 허용 범위는 버전된 서버 설정으로 제공한다. 브라우저 재접기 중에는 구간 선택·판단·제출을 비활성화한다. 범위 이탈이나 재접기 실패 시 그래프·확대 배율·작성 중 입력은 마지막 성공 상태로 복구하되 마지막 입력값과 오류를 보여준다. Web Worker 등 비동기 클라이언트 계산 결과의 순서가 뒤집히면 revision이 가장 최신인 성공 결과만 적용한다.

**제출 종류 1 · 후보 제출 (SUB 01)**

| 항목 | 값 | 필수 | 비고 |
|---|---|---|---|
| 주기 P | 일 | 필수 | 주기도 봉우리 재선택 또는 현재 주기의 서버 허용 범위 내 미세 조정(EXP 05) |
| `phase_start`, `phase_end` | 위상 | 필수 | **접힌 곡선에서만** 선택. 시간 영역의 원본·잔차 곡선에는 읽기 전용 예측 transit 띠만 표시 |
| epoch | BTJD | 브라우저 미리보기 / 서버 최종 파생 | 선택 중에는 위상 중심과 Bundle의 `fold_reference_time_btjd`로 즉시 미리보기. 제출 시 서버가 같은 저장값으로 다시 계산·검증하며 사용자가 입력·수정하지 않음(EXP 06) |
| 지속시간 | 시간 | 브라우저 미리보기 / 서버 최종 파생 | 선택 중에는 위상 구간 폭과 주기로 즉시 미리보기. 제출 시 서버가 다시 계산·검증하며 사용자가 입력·수정하지 않음(DEC 19) |
| 판단 | LIKELY_PLANET / UNLIKELY_PLANET / UNSURE | 필수 | POL 13 |
| 근거 체크 | 홀짝 깊이 / 2차 식 / V·U형 / 품질 구간 | 선택 | 체크박스. UNLIKELY일 때 이유를 남기는 용도. 중심 위치는 P0 근거가 아님 |
| 메모 | 자유 한 줄 | 선택 | |
| 현재 곡선 | 원본 / 잔차 단계 n | 자동 | 어느 곡선에서 제출했는지 기록 |

`selection_space` 필드는 두지 않는다. 선택 공간은 접힌 곡선으로 고정한다. 저장 좌표는 `0 ≤ phase_start < 1`, `phase_start < phase_end < phase_start + 1`인 연속 두 주기 표현을 쓰고, 위상 경계를 넘으면 `phase_end`가 1을 넘을 수 있다. 선택 핸들이 바뀔 때마다 브라우저가 epoch·지속시간 미리보기와 시간 영역의 읽기 전용 transit 띠를 즉시 갱신하며, 제출 시 서버가 위상 원본값에서 최종 epoch·지속시간을 다시 계산·검증한다. 관측 공백은 데이터가 있는 것처럼 그리지 않고 시간 영역에서는 핸들로 수정할 수 없다. P0의 중심 위치 항목은 `중심 위치: 데이터 없음`으로 비활성 표시한다. 이는 `중심 이동 없음`이라는 관측 근거가 아니며 제출·매칭·성과·등급·통계에 포함하지 않는다. 조작된 요청으로 중심 위치 근거를 보내도 서버는 유효한 `evidence_checks` 값으로 접수하지 않는다.

**제출 종류 2 · 후보 없음 의견**

"이 별에서 더 찾을 신호가 없다"는 사용자 의견. `submission_kind=no_candidate`로 주기·`phase_start`·`phase_end`·epoch·지속시간 없이 선언한다. 채택 신호가 0개인 별은 제공하지 않으며, 찾을 수 있는 후보를 모두 매칭한 별에서는 이 의견을 직접 제출하지 않는다. 회원이 제출할 수 있는 때는 찾을 수 있는 미매칭 후보가 남아 있을 때뿐이며 `none_wrong`으로 안내하고 후보·Post·성과를 만들지 않는다(SUB-11).

**튜토리얼 건너뛰기**

SUB 12의 건너뛰기는 서버 설정 횟수와 튜토리얼 조건을 검사하고 skipped 기록·다음 순번 열림만 남긴다. 후보 판단·공식 공개·성과를 자동 생성하지 않는다. no_candidate·skipped는 주기·위상·판단이 필수인 후보 제출과 구분한다.

**결과 1 · 신호 (SUB 03~08, 5장 규칙)**

| 신호 결과 | 의미 | 성과·진행 |
|---|---|---|
| matched | 대표 주기와 일치 | 매칭을 기록하고 성과는 결과 2를 적용. 판단·게시와 무관하게 잔차 탐색 가능 |
| matched_harmonic | 허용 배수를 대표 주기로 자동 정정 | 수치 매칭 성공이며 원본·정정값 보존. 성과 조건은 matched와 같음 |
| not_matched | 일치 후보 없음 | Submission·히스토리 보존, 성과·제거 조합·완료 변화 없음. 상세 보기(대상 0개면 비활성)·다시 풀기와 선택형 일반 토론 제공 |
| ambiguous_match | 우세 후보 없음 | 임의 후보·성과를 만들지 않으며 구분 정보나 재제출을 안내 |
| duplicate | 이미 성과를 인정받은 고유 후보에 다시 매칭 | 추가 성과 없음. 채점형 최신 판단은 갱신하며 미확정 공개 통계는 새 분석을 공개할 때만 갱신 |

**결과 2 · 판단과 성과 (수치 매칭 시)**

| 후보 구분 | 판단 | 결과 | 이번 제출의 최초 성과 조건 |
|---|---|---|---|
| 채점형 · 확정 행성 | LIKELY_PLANET | 기록과 일치 | 확정 행성 성과 1건 |
| 채점형 · 확정 행성 | UNLIKELY_PLANET | 판단이 달라요 | 미인정, 다시 풀기 가능 |
| 채점형 · FP | UNLIKELY_PLANET | 기록과 일치 | FP 후보 성과 1건. 별의 FP 등급은 A까지만 |
| 채점형 · FP | LIKELY_PLANET | 판단이 달라요 | 미인정, 다시 풀기 가능 |
| 채점형 · 확정 행성 / FP | UNSURE | 판단 보류 | 이번 성과 미인정, 다시 풀기 가능 |
| 분석형 | LIKELY_PLANET / UNLIKELY_PLANET / UNSURE | 수치 매칭됨, 아직 확인 안 된 신호 | 본인 분석을 공식 공개한 최초 1회에 미확정 성과 1건 |

근거 체크나 AI 점수는 성과 조건이 아니다. 성과 없이 끝난 확정 행성·FP의 판단 불일치·판단 보류와 미확정 미게시 기록은 duplicate가 아니며 이후 조건을 충족하면 처음 인정한다. 이미 인정된 후보의 재제출은 이번 추가 성과가 없을 뿐 과거 성과를 잃지 않는다. 마지막 탐색 가능 신호의 매칭이면 위 판단·성과와 독립적으로 탐색 완료를 함께 표시한다.

**판단 불일치·판단 보류와 재도전 (SUB 10, RES 09)**

```
확정 행성·FP 판단 불일치 또는 판단 보류
 ├─ [상세 보기] → 방금 매칭한 신호의 해설·외부 근거 공개, answer_viewed 기록
 └─ [다시 풀기] → 해당 제출 상태를 새 초안으로 복원

not_matched
 ├─ [상세 보기] → 해당 제출 곡선 단계에서 아직 제거되지 않은 탐색 가능한 후보 중 BLS 품질 최고 후보 하나
 │                 대상이 0개이면 버튼 비활성·해설 없음 안내
 ├─ [다시 풀기] → 해당 제출 상태를 새 초안으로 복원
 └─ [토론하기] → 같은 TIC 일반 DISCUSSION 작성
none_wrong → SUB 11·RES 09의 상세 보기·다시 풀기 경계 유지
```

다시 풀기는 완료 별에서도 제공한다. 후보 제출의 publication_bundle_id, 매칭 직전 curve_step·제거 후보 조합, 원본 period·phase_start·phase_end, 판단·유효 근거·메모와 표시 상태를 복원한다. 자동 정정값을 사용자 원본값에 덮어쓰지 않는다. 단순 복원은 제출을 만들지 않으며 실제 재제출은 새 요청 ID의 Submission·AnalysisHistory를 만든다. 동일 요청의 통신 재전송만 기존 결과를 반환한다. 현재 잔차에서 이미 제거한 후보를 재도전 대상으로 삼지 않도록 제출 당시 단계를 복원하며, 원본으로 돌아가거나 재도전해도 기존 탐색 완료·성과·히스토리를 되돌리지 않는다.

not_matched의 상세 힌트 후보 집합은 회원의 누적 미매칭 목록이 아니라 해당 Submission의 Bundle·곡선 단계·제거 조합으로 정한다. 완료 별에서 다시 풀어도 당시 단계에 남아 있는 탐색 가능한 후보를 비교하며, 대상이 없으면 상세 보기를 비활성화하고 해설 없음 안내를 제공한다. 수치 매칭 후 판단 불일치·보류의 상세는 방금 매칭한 신호를 유지한다.

**공개 분석과 일반 토론 흐름 (COM 10·17~20)**

```
수치 매칭
 ├─ 채점형 → 판단 확인 → 올바르면 최초 성과. 일반 글 작성은 선택
 └─ 미확정 → 다음 곡선 탐색 또는 탐색 완료
              ├─ 나중에 공개 → 완료·입력·히스토리 유지
              └─ [게시 검토] → 고유 신호별 대표 기록 확인·선택
                                └─ [모두 게시] → 항목별 공식 공개 등록
                                                   첫 공개 신호: SYSTEM 공식 스레드 생성
                                                   성공한 신호: 최초 미확정 성과 인정
                                                   실패한 항목: 미게시 유지·실패분 재시도

not_matched → [토론하기] 선택 → 같은 TIC 일반 DISCUSSION 글
              본인 히스토리 첨부 가능. 공식 신호·공개 분석·성과 자동 생성 없음
no_candidate → none_wrong 안내. 공식 공개 분석·성과 없음
skipped → 튜토리얼 건너뛰기 기록. 공식 공개 분석·성과 없음
```

미확정의 공개 분석은 일반 Post나 댓글이 아니라 독립된 목록 항목이다. 같은 고유 신호에 여러 제출이 있으면 대표 기록을 선택하며 이미 공개한 항목은 구분한다. 성과 인정 후 다시 매칭한 duplicate 기록도 해당 본인 신호의 새 공개 분석으로 선택할 수 있지만 성과는 다시 지급하지 않는다. 미게시 기록은 히스토리에서 나중에 공개할 수 있다. 공개 검토 화면을 열거나 일반 글에 자료를 첨부하는 것만으로 공개 등록·성과·공식 스레드를 만들지 않는다.

**공식 스레드·공개 분석의 저장과 권한 (물리 테이블명은 별도 설계)**

| 대상 | 식별·보존 | 생성·변경 권한 |
|---|---|---|
| 공식 신호 스레드 | 미확정 고유 후보당 하나. 같은 후보의 고조파·Bundle 변경으로 중복 생성하지 않음 | 첫 유효 공개 등록 때 SYSTEM 생성. 관리자 로그인 불필요. 운영 권한 계정은 숨김·복원하며 작성자가 될 필요 없음 |
| 공개 분석 | 작성자·고유 후보·본인 AnalysisHistory 참조·공개 요청 상태·본인 공개 여부·운영 숨김을 구분 | 본인의 유효한 매칭 기록만 명시적 공개. 동일 기록 재전송은 중복 없음. 개인 원본 대신 공개 투영을 제공 |
| 일반 토론 글·댓글 | 기존 Post·Comment. 공식 스레드에서는 공개 분석 목록과 토론 댓글을 분리 | 사용자 직접 작성. 본인 수정·삭제와 기존 운영 숨김 규칙. 분석 등록으로 댓글 자동 생성 없음 |
| 일반 동의·비동의 | 기존 사용자·게시글 반응 관계 | 일반 토론 의견 지표. 자동 반응 없음. 공식 공개 여부·판단 통계·성과와 무관 |
| 개인 AnalysisHistory | 원본 제출·버전·그래프 재현값 불변 | 본인·권한 있는 운영자만 원본 조회. 공개 취소·숨김이 원본을 삭제하지 않음 |

| 공개 동작·상태 | 화면·서버 처리 | 성과·통계 |
|---|---|---|
| 미게시 / 게시중 / 공개 / 게시실패 | 공개 요청 처리 상태. 공개 항목별 성공·실패를 표시 | 공개 성공한 본인 신호만 최초 성과 인정 |

| 숨김 스레드에 재공개 요청 | 기존 스레드 식별자를 유지하고 자동 재생성하지 않음 | 실패 안내·재시도 가능 상태 보존. 기존 성과·개인 히스토리는 유지 |

공개 성공은 부모 스레드와 분석의 유효 공개 상태 검사를 통과해야 한다. 동시 첫 공개·중복 요청·부분 실패에서도 공식 스레드·공개 기록·성과를 중복 생성하지 않는다. 첫 공개 실패만으로 비어 있는 공개 공식 스레드를 남기지 않는다. 새로운 공개를 허용할 수 없는 상태이면 공개 성공이나 최초 성과를 먼저 기록하지 않는다.

**일반 글의 TIC·첨부·출처 경계 (COM 07·20)**

| 작성·첨부 상황 | 허용 범위 | 공식 공개·성과 영향 |
|---|---|---|
| 별 게시판에서 일반 글 작성 | 해당 TIC 자동 선택 | 없음 |
| 자유 양식 글에서 별 선택 | 선택한 TIC 연결, 같은 별의 본인 히스토리 첨부 | 없음. 공식 공개 분석 등록과 별도 |
| 별 미선택 자유글·그 댓글 | TIC 없는 일반 글. 별 자료 히스토리·링크 카드 첨부 불가 | 없음 |
| 같은 TIC 본인 히스토리 | 기존 원글 카드·댓글 요약 첨부. 다른 TIC·타인의 개인 히스토리 원본은 불가 | 없음 |
| 공식 신호·공개 분석 링크 카드 | 같은 TIC의 유효 공개 출처. 타인의 공개 분석도 원 작성자·원문·신호·판단 필터 출처를 유지하여 링크 | 없음. 사본 작성·내 분석 등록으로 취급하지 않음 |

작성·첨부·조회 때 TIC와 공개 상태를 재검사한다. 출처가 취소·숨김되면 캐시된 카드로 원문이나 그래프를 계속 노출하지 않고 열람 불가를 안내한다. 내 별 목록 공개 설정이나 자료를 읽을 수 있는 권한이 타인 히스토리 원본 접근·잠긴 별 분석 권한으로 확장되지 않는다.

기존 not_matched DISCUSSION의 P1 전문가 제보는 유지한다. 운영자가 공개 글을 선택하고 보고서·근거·수신자를 확인한 뒤 발송하며 후보·BLS·AI·성과·곡선 단계를 바꾸지 않는다. 외부 회신을 Candidate에 반영하는 새 절차는 추가하지 않는다.

## 표 E. 성과와 별 등급 (GRD 01~08)

성과 단위는 사용자 × 고유 후보다. 같은 후보의 반복 제출·고조파·배치 버전 변경·공개 재시도는 추가 성과를 만들지 않는다.

| 유형 | 최초 인정 조건 | 등급 (TIC별 인정 고유 후보 수) | 등급 상승 시 열림 수 |
|---|---|---|---|
| 확정 행성 | 확정 후보 매칭 + LIKELY_PLANET | 1 / 2 / 3 / 4개 이상 → A / S / SS / SSS | 1 / 2 / 3 / 4 |
| FP 판단 | FP 후보 매칭 + UNLIKELY_PLANET | A만 (개수 무관) | A 획득 시 1 |
| 미확정 후보 | 해당 후보 매칭 + 본인 분석 공식 공개 | 1 / 2 / 3 / 4개 이상 → A / S / SS / SSS | 1 / 2 / 3 / 4 |

- FP 신호가 여러 개면 각 고유 후보의 올바른 판단을 기록하되 FP 등급 상한은 A다. 신호가 없는 별의 별 단위 보상 예외는 없다.
- 같은 별의 유형별 인정 수·등급과 HOME 05의 궤도·행성 표시 수는 별도로 관리한다. 별 색은 표 G의 표시 규칙을 따른다.
- 미확정의 개인 히스토리·미게시·일반 글·댓글·출처 링크·동의/비동의에는 최초 성과가 없다. 공개 요청 처리 상태를 별도의 성과 인정 대기 상태로 만들지 않는다.
- 공개 취소·운영 숨김·일반 삭제·재판단만으로 이미 인정된 성과를 회수하지 않는다. 후보 병합·분리·부정 사용 등 기존 운영 정정은 이력을 남기며 GRD 06을 따른다.
- 외부 라벨 갱신으로 미확정이 확정/FP가 되어도 기존 공식 스레드·공개 분석·성과 유형·등급·발견한 별·통계 스냅샷을 보존하고 기록이 갱신됨을 표시한다. 재분류 이후 신규 공개와 구버전 Bundle 세션의 상세 정책은 DEC 26 후속 범위로 두며, 이 표에서는 기존 기록 보존만 명시한다.
- 사용자 단위 등급은 두지 않는다. 공개 성공으로 완료된 별의 미확정 성과를 뒤늦게 인정해도 탐색 완료는 유지하고 GRD 08의 등급 상승 사건만 처리한다.
