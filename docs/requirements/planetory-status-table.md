## 0. 원칙

1. **상태는 후보 단위다.** 별은 상태를 갖지 않고, 후보들과 내 제출에서 파생값을 계산해 그린다.
2. **전역과 개인을 나눈다.** 라벨·AI·확정·후보표는 모두에게 같다. 성과·등급·열림·진행은 내 제출에서만 계산한다.
3. **신호와 행성은 다른 질문이다.** 주기를 맞히면 고유 후보 성과, 행성 여부는 판단(user_judgment)으로 따로 기록한다. 정답 있는 후보만 판단을 채점하고, 없는 후보는 분석글 공유를 성과로 친다.
4. **정답이 없는 것은 데이터 사정이다.** 분석형 후보에서 사용자에게 불리한 처리를 두지 않는다.
5. **등급은 희귀도다.** 후보가 많은 별을 풀수록 높고, 그만큼 밤하늘이 넓게 열린다.

## 표 A. 후보 저장 필드

SRS 엔티티 기준. Candidate(자체 BLS 대표값) + ExternalSignalReference(TCE·TOI) + CandidateDisposition(통합 상태) + AIEvaluation.

| 필드 | 값 | 출처 | 비고 |
|---|---|---|---|
| period, epoch, duration, depth, tolerances | 수치 | DAT 04·08 자체 BLS | 신호 매칭의 정답. 모든 후보에 있음 |
| removal_step, residual_ref | 정수, 경로 | DAT 05 | 이 후보를 제거한 배치 단계와 그 단계의 잔차 곡선·주기도 |
| tce_ref | TCE ID / 없음 | DAT 09 | 외부 비교값. 자체 값을 덮어쓰지 않음 |
| toi_disposition | `KP` / `CP` / `PC` / `APC` / `FP` / `FA` / 없음 | DAT 09, TOI 카탈로그 | 원본 그대로, 스냅샷 날짜 포함 |
| ai_score | 0.0 ~ 1.0 / 없음 | AI 03 자체 모델 | 모델·체크포인트·입력 버전 포함 |
| ai_status | `approved` / `hold` / `rejected` / `not_evaluated` | AI 04 | 실행 불가는 별도 상태(RES 04) |
| is_confirmed | true / false | DAT 09 (표 B) | ai_status와 독립 |
| answer_class | `graded` 채점형 / `analysis` 분석형 | DAT 09 (표 B) | 판단을 채점할지 |
| planet_truth | `planet` / `not_planet` / 없음 | DAT 09 (표 B) | 채점형만 |
| discoverable | true / false | DAT 07 원본 재검증 | 원본 또는 잔차 주기도에서 사용자가 찾을 수 있는가. false면 주기도에 봉우리를 만들지 않고 자동 완료 판단에서 제외(결정 23) |
| 버전 | 전처리·BLS·모델·규칙·카탈로그 스냅샷 | NFR 03 | 변경 시 CandidateStatusHistory |

## 표 B. 후보 판정 규칙 (DAT 09 · AI 04 · DEC 20)

위에서부터 먼저 맞는 행 하나. 라벨 우선, 없으면 AI 점수.

| 순서 | toi_disposition | ai_score | → ai_status | → is_confirmed | → answer_class | → planet_truth |
|---|---|---|---|---|---|---|
| 1 | KP, CP | 무관 | 점수 규칙대로 기록 | **true** | 채점형 | 행성 |
| 2 | FP, FA | 무관 | rejected | false | 채점형 | 아님 |
| 3 | APC | 무관 | hold | false | 분석형 | 없음 |
| 4 | PC | 무관 | approved `확인 필요` | false | 분석형 | 없음 |
| 5 | 없음 | ≥ 승인 임계값 | approved | false | 분석형 | 없음 |
| 6 | 없음 | 보류 이상 승인 미만 | hold | false | 분석형 | 없음 |
| 7 | 없음 | < 보류 임계값 | rejected | false | 분석형 | 없음 |
| 8 | 없음 | 없음 / 실행 불가 | not_evaluated | false | 분석형 | 없음 |

- 임계값은 자체 모델의 점수 분포를 라벨 있는 별로 검증해 정한다(DEC 04). 공개 표의 0.5 / 0.2는 참고값일 뿐이다.
- 검토 중(hold) = 사람이 모호(APC)하다고 했거나, 사람 판정 없이 AI 점수가 보류 구간.
- 정답 주기: 채점형 후보는 외부(TOI) 주기·epoch를 대표값으로 정렬한다 `확인 필요`. 검토 문서 2-8에서 TCE 주기가 틀린 별 3개를 확인함. 분석형은 자체 BLS 값.

## 표 C. 표시 상태와 공개 시점

| 표시 상태 | 조건 | 문구 (RES 02·03) | 공개 시점 |
|---|---|---|---|
| 확정 행성 보유 (별) | is_confirmed 후보가 있음 | "확인된 행성 있음" 여부만 | 분석 화면 진입 시 (EXP 02). 홈에서는 숨김 (HOME 02) |
| 확정 (후보) | is_confirmed = true | "확인된 행성" · 행성명·반복 주기·가려진 시간·기준 시각·출처·조회일 | 그 후보 매칭 후, 또는 오답에서 [상세 보기] 선택 후 |
| 승인 / 보류 / 기각 / 평가 불가 | ai_status | "AI 점수 0.NN · 승인/보류/기각 구간 · 인정에는 쓰이지 않음" + 모델 버전 | 그 후보를 제출한 뒤 (결과 카드와 결과 페이지, 결정 18) |
| 위양성 확인 (후보) | planet_truth = 아님 | "행성 아님" 상태·근거·출처 | 그 후보 매칭 후, 또는 [상세 보기] 후 |
| 판단 분포 (모든 후보) | 성과가 인정된 제출의 user_judgment 집계 (결정 25) | "다른 사람들의 판단 · 행성 같음 8 · 아님 3 · 모르겠음 2 (인정된 제출 13건)" | 그 후보를 제출한 뒤 |

금지 표현(RES 03, SRS 1.4): 화면에는 정답·오답을 쓰지 않는다. 채점 결과는 "기록과 일치 / 판단이 달라요 / 일치하는 신호 없음"으로, 확정 표현은 채점형에만. 분석형은 자체 BLS 값·AI 점수·외부 비교값을 구분해 보여준다.

## 표 D. 제출 항목과 결과

한 번의 제출은 후보 하나를 겨냥한다. 후보를 매칭하면 그 후보를 뺀 잔차 곡선으로 넘어가 다음 후보를 찾는다(결정 9). 원본으로 언제든 복귀할 수 있다.

**제출 종류 1 · 후보 제출 (SUB 01)**

| 항목 | 값 | 필수 | 비고 |
|---|---|---|---|
| 주기 P | 일 | 필수 | 주기도 피크 클릭 또는 허용 범위 내 조정 (EXP 05) |
| transit 시작·끝 | BTJD | 필수 | 원본 곡선 또는 접힌 곡선에서 선택. 접힌 곡선이면 위상을 epoch로 환산. 피크 클릭 시 BLS 통과 시각을 기본값으로 제안 |
| epoch | 자동 | 자동 | (시작 + 끝) / 2 (EXP 06) |
| 지속시간 | 시간 | 필수 | 선택 폭을 기본값으로 채우고 수정 가능 `확인 필요` (DEC 19) |
| 판단 | LIKELY_PLANET / UNLIKELY_PLANET / UNSURE | 필수 | POL 13 |
| 근거 체크 | 홀짝 깊이 / 2차 식 / V·U형 / 중심 이동 / 품질 구간 | 선택 | 체크박스. UNLIKELY일 때 이유를 남기는 용도 |
| 메모 | 자유 한 줄 | 선택 | |
| 현재 곡선 | 원본 / 잔차 단계 n | 자동 | 어느 곡선에서 제출했는지 기록 |

**제출 종류 2 · 후보 없음 의견 (신규)**

"이 별에서 더 찾을 행성 후보가 없다"는 사용자 의견. 주기 없이 선언만 한다. 채점형 후보(CP·KP)가 남아 있으면 오답, 아니면 분석형과 같은 분석글 흐름으로 간다.

**결과 1 · 신호 (SUB 03~08, 5장 규칙)**

| 신호 결과 | 의미 | 고유 후보 성과 |
|---|---|---|
| matched | 대표 주기와 일치 | 후보 유형에 따라 (결과 2) |
| matched_harmonic | 1/2·2배를 대표 주기로 자동 정정 | 동일 |
| not_matched | 일치 후보 없음 | 없음. 오답 분기 |
| ambiguous_match | 우세 후보 없음 | 없음. 구분 정보 또는 재제출 |
| duplicate | 이미 매칭한 후보 | 없음. 판단은 첫 제출 유지 `확인 필요` |

**결과 2 · 판단과 성과 (신호 매칭 시)**

| 후보 구분 | 판단 | 결과 | 성과 |
|---|---|---|---|
| 채점형 · 확정 행성 | 무관 | 확정 행성 매칭. 판단과 외부 상태 일치 여부를 함께 표시 (RES 02) | 확정 행성 유형 +1 |
| 채점형 · FP | UNLIKELY | FP 판단 성공 | FP 유형 +1 (A) |
| 채점형 · FP | LIKELY / UNSURE | FP 판단 실패. 오답 분기 | 없음 |
| 분석형 | 무관 | `post_pending` 분석글 게시 대기 → 게시하면 `unconfirmed_credited` | 게시 시 미확정 유형 +1 |

**오답 분기 (not_matched, FP 판단 실패, 채점형 별에서 후보 없음)**

```
오답 결과 화면
 ├─ [상세 보기]  → 확정 상세·해설 공개. answer_viewed = true 기록
 └─ [다시 풀기]  → 공개 없이 분석 화면 복귀
이후 재제출로 맞히면 어느 쪽이든 정답 처리, 성과·등급 동일 (결정 6)
```

**분석글 흐름 (분석형 후보, 후보 없음 의견)**

```
제출하기
 ├─ not_matched / duplicate / ambiguous → 결과만. 글 없음
 ├─ 채점형 후보                        → 채점 → 성과 즉시 → [글쓰기]는 선택 (COM 10)
 ├─ 분석형 후보 매칭                    → 분석글 화면이 채워진 채로 열림
 │                                       [게시] 1회 → 게시 + 미확정 성과 +1
 │                                       게시 안 함 → 제출·히스토리만. 히스토리의 [이 분석 게시하기]로 나중에 게시 가능
 └─ 후보 없음 의견 (채점형 후보 없음)     → 같은 분석글 흐름. 게시하면 별 완료 + 미확정 성과 +1 `확인 필요`
```

자동으로 채우는 것: 제목, 매칭 후보·제출 수치·정정 배율, 판단, 근거 체크, 접힌 곡선·확대 구간 스냅샷(AnalysisHistory 첨부, HIS 05), 태그 ANALYSIS. 사용자가 고칠 수 있는 것은 제목과 메모. 성과 인정 시점 = 게시 시점이므로 SRS의 "인정 대기" 상태는 없다.

## 표 E. 성과와 별 등급 (GRD 01~07)

성과 단위는 사용자 × 고유 후보(UserCandidateAchievement). 같은 후보의 반복 제출·배수 정정·배치 버전 변경은 한 건.

| 유형 | 조건 | 등급 (TIC별 고유 후보 수) | 열림 수 |
|---|---|---|---|
| 확정 행성 | 확정 후보 매칭 | 1 / 2 / 3 / 4개 이상 → A / S / SS / SSS | 1 / 2 / 3 / 4 `확인 필요` |
| FP 판단 | FP 후보 매칭 + UNLIKELY | A만 (개수 무관) | 1 |
| 미확정 후보 | 분석형 후보 매칭 + 분석글 게시 | 1 / 2 / 3 / 4개 이상 → A / S / SS / SSS | 1 / 2 / 3 / 4 |

- 한 별에 여러 유형이 있으면 유형별로 따로 기록·표시한다 (GRD 07, POL 23). 밤하늘의 색상 계열 = 유형, 강도 = 등급.
- 등급은 내려가지 않는다. 예외는 후보 병합·분리, 외부 disposition 정정, 부정 사용 조치이며 이력을 남기고 재계산한다 (GRD 06).
- 라벨 갱신으로 분석형 후보가 채점형이 되면 그 후보의 미확정 성과는 확정 행성 또는 FP 유형으로 재분류한다. 사용자의 과거 판단이 새 라벨과 맞으면 그대로 인정, 틀려도 미확정 성과는 회수하지 않는다 `확인 필요`.
- 사용자 단위 등급은 두지 않는다. 프로필은 TIC별 등급·개수 목록(ACC 05).
