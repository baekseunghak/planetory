## 1. 문서 목적과 적용 범위

이 문서는 Planetory 서비스 정책서 v0.6과 이후 확정된 팀 결정을 구현 가능한 기능·데이터·운영·검수 요구사항으로 구체화한다. 사용자 화면과 운영 문서의 공식 서비스명은 Planetory를 사용한다.

요구사항 충돌 시 적용 우선순위는 다음과 같다.

1. 팀이 이후 확정한 명시적 결정
2. Planetory 서비스 정책서 v0.6
3. 이 요구사항 명세서
4. 이전 정책서와 기능명세 초안 (기능명세서 v0.4, 상태표 v0.1~v0.5 포함)

Planetory는 회원 전용 서비스다. 로그인 화면과 OAuth 콜백을 제외한 모든 화면·조회·분석·커뮤니티 기능은 인증 후 이용한다. 회원은 공개 상태이며 삭제·숨김 처리되지 않은 게시글·댓글·첨부 자료를 모두 열람할 수 있다.

탐사 기능은 별도 모드로 나누지 않고 하나의 분석 흐름으로 제공한다. 다만 처음 열리는 튜토리얼 별 다섯 개는 정답이 있는 별로 고정한다 `(v0.3)`. 제출 후에는 외부에서 확정된 대상과 아직 확정되지 않은 대상의 해설 근거와 표현을 구분한다.

분석의 기본 단위는 다음 반복이다 `(v0.3.1)`. 별의 신호 주기를 찾아 후보표와 맞춘다 → 그 신호가 행성 후보인지 판단한다 → 남은 신호가 있으면 잔차에서 다시 주기를 찾아 판단한다 → 찾을 수 있는 신호가 더 없으면 시스템이 별을 완료로 표시한다(SUB-11). 회원은 신호가 남아 있다고 시스템이 아는 별에서만 더 없음 의견을 낼 수 있고, 주기를 찾지 않은 판단은 성과로 인정하지 않는다. 자체 BLS 기준을 넘는 신호가 없어 후보표가 비어 있는 별도 공개 대상에 포함하며, 이런 별은 진입 즉시 자동 완료된다. `(v0.5)`

이 문서는 랭킹·최초 발견 순위·선착순 혜택, 별도 분석 클립보드, PostAnalysisReference·PostReanalysis·ReviewCase 기반 후보 승격, 사용자 단위 누적 등급을 범위에 포함하지 않는다. 이의 제기 기능은 정책 확정 전까지 TBD로 두며 4장 기능 범위에서는 제외한다.

### 1.3 핵심 가치

- 외계행성 탐색의 진입 장벽을 낮춰 누구나 TESS 실측 데이터를 쉽게 분석하고 탐색에 참여할 수 있게 한다.
- 더 많은 사용자가 더 많은 관측 데이터를 탐색하고 신호를 토론·재분석함으로써 새로운 외계행성 후보의 발견 가능성을 높인다.
- 제출마다 분석 근거를 재현 가능한 히스토리로 보존하고, 사용자가 선택한 분석을 커뮤니티에서 자유롭게 공유한다.
- 운영자가 가치 있다고 판단한 게시글을 재현 가능한 보고서로 정리해 전문가에게 제보할 수 있게 한다.

## 2. 핵심 정책 요구사항

| ID | 요구사항 |
|---|---|
| POL-01 | 로그인 화면과 OAuth 콜백 외 모든 서비스 화면과 요청은 인증된 회원만 접근한다. |
| POL-02 | 회원은 공개 상태이며 삭제·운영 숨김 처리되지 않은 모든 게시글·댓글·히스토리 첨부를 열람할 수 있다. |
| POL-03 | 후보표 매칭과 AI 판정은 항상 배치 산출물을 쓴다. 회원이 보는 잔차 곡선과 잔차 주기도는 EC2 서비스가 Gold의 원본 정제 곡선과 후보별 통과(transit) 모델로 요청 시 계산하는 온라인 파생 계산이다(DAT-14). 배치는 어떤 제거 조합의 잔차·주기도도 사용자 제공용으로 미리 저장하지 않으며, 원본 곡선의 주기도만 저장한다. 같은 조합의 결과는 캐시 키(DAT-14)로 재사용한다. 계산 주체·캐시 저장소·동시 실행 상한·검증 기준은 DEC-35(아키텍처 Task). `(v0.9)` |
| POL-04 | 확정 행성 보유 여부는 홈이 아니라 분석 화면에서 제출 전에 표시한다. 보유 여부는 후보표에 실제로 있는 확정 후보를 기준으로 하며, 개수와 상세값은 공개하지 않는다. `(v0.3)` |
| POL-05 | 행성명·주기·지속시간·기준 통과 시각 등 확정 상세 정보는 해당 후보를 매칭한 뒤, 또는 오답 결과에서 사용자가 [상세 보기]를 선택한 뒤 공개한다. 확정 행성 개수는 공개하지 않는다. `(v0.3)` |
| POL-06 | 학습·검증·일반 탐사 모드를 따로 만들지 않는다. 동일 분석 흐름에서 미확정 대상은 정답으로 표현하지 않고 자체 BLS 대표값·AI 후보 적합성 점수·외부 비교값을 구분해 보여준다. |
| POL-07 | 사용자는 원본 정제곡선을 탐색하며 선택한 주기로 같은 곡선을 위상 접기한다. 후보를 매칭하면 배치가 저장한 그 후보 제거 후 잔차 곡선·주기도를 제공하고, 원본이나 이전 단계로 복귀할 수 있다. 잔차 곡선은 즉시 계산하고 잔차 주기도는 POL-03 규칙을 따른다. `(v0.3.1)` |

## 3. 전체 흐름

### 3.1 배치 흐름

대상 선정 → 원천 등록 → TESS LC 수집 → Sector별 전처리 → 원본 정제곡선·주기도 생성 → BLS 후보 탐색 → 후보 모델 적합·내부 신호 제거 → 잔차 BLS 반복(단계별 잔차 곡선·주기도 저장) → 후보 병합 → 외부 TCE·TOI 연결 → AI 입력 생성 → 자체 모델 추론·판정 → 원본 탐색 가능성 검증 → 공개 묶음 검증 → 원자적 공개 `(v0.3)`

### 3.2 사용자 흐름 `(v0.3)`

로그인 → 튜토리얼 별과 열린 별, 내 TIC별 진행이 통합된 홈 → 별 선택 → 분석 화면에서 확정 행성 보유 여부 확인 → 원본 정제곡선·주기도 탐색 → 주기 선택 → 원본 또는 접힌 곡선에서 transit 시작·끝 선택 → 중앙 epoch 자동 산정 → 지속시간 조정 → 사용자 판단(+근거 체크) 선택 → 제출 → 후보표 매칭 → AnalysisHistory 자동 저장 →

- 정답 있는 후보: 결과·성과·등급·해설 → 잔차 곡선으로 다음 후보 탐색 또는 메인
- 정답 없는 후보: 채워진 분석글 화면 → [게시] → 성과·등급 → 잔차 곡선으로 다음 후보 탐색 또는 메인
- 오답: [상세 보기] / [다시 풀기] 선택 → 재제출 또는 메인
- 찾을 수 있는 신호가 더 없음: 시스템이 자동 완료 안내 → 빈 별이면 FP 유형 A / 모두 매칭했거나 찾을 수 없는 후보만 남았으면 성과 없이 완료(후자는 재개 대기). 회원이 더 없음 의견을 냈는데 찾을 수 있는 후보가 남아 있으면 판단이 다르다는 안내와 오답 분기 `(v0.5)`

별을 풀어 등급이 정해지면 주변 별이 열린다.

### 3.3 커뮤니티 흐름

회원이 공개 별 게시글·자유 게시글·댓글·첨부 열람 → 결과 화면 또는 별 게시판에서 게시글 작성 선택 → 대표 목적 태그와 본문 작성 → 같은 TIC의 본인 AnalysisHistory를 글이나 댓글에 선택 첨부 → 게시글에서 이 별 분석하기 → 같은 TIC의 원본 정제곡선 분석 화면 → return_post_id로 원 글 복귀

전문가 제보는 운영자가 공개 게시글 선택 → 시스템 보고서 생성 → 운영자 내용·수신자 확인 → 시스템 이메일 발송 → 발송 상태·수신자·시각·오류 기록 순서로 진행한다. 커뮤니티 제보 경로는 후보표·AI 판정·후보 ID를 변경하지 않는다.

| SUB-11 | 후보 없음 의견 | P0 | 회원이 현재 별에 대해 후보 없음 의견을 제출한다. 서버는 후보표를 기준으로 세 경우로 처리한다. (1) 후보표가 비어 있는 별: 정답. FP 유형 성과(A)를 인정하고 별을 완료한다. (2) 매칭하지 않은 후보가 남아 있는 별: 오답. "아직 확인하지 못한 신호가 있습니다"로 안내하고 오답 분기(RES-09)를 제공한다. (3) 후보를 모두 매칭한 별: 정답. 성과 없이 별을 완료한다. 이 FP 성과는 후보가 없으므로 UserCandidateAchievement가 아니라 UserStarProgress의 fp_success에 별당 한 번 기록한다. 별도 Post는 만들지 않는다. `(v0.3.1)` **자동 완료 `(v0.4)`:** 남은 후보가 없으면(후보표가 빈 별에 진입했을 때, 또는 마지막 후보를 매칭했을 때) 시스템이 "더 찾을 신호가 없습니다"로 안내하고 별을 완료로 표시한다. 후보표가 빈 별은 (1)의 FP 유형 A를 자동 인정하고, 모두 매칭한 별은 (3)처럼 성과 없이 완료한다. (4) 남은 후보가 있어도 모두 현재 공개 데이터의 주기도에서 찾을 수 없는 후보(discoverable=false, 예: 주기가 관측 기간의 1/2보다 길어 통과가 한 번뿐인 후보)뿐이면 시스템이 "현재 관측 데이터로 찾을 수 있는 신호는 모두 찾았습니다"로 안내하고 성과 없이 별을 완료하며 reopen 대기로 표시한다. 새 관측 회차로 그 후보가 찾을 수 있게 되면 DEC-27에 따라 진행 중으로 되돌리고 알린다. 주기도에는 discoverable=false 후보의 봉우리를 그리지 않는다(EXP-04). 회원이 직접 더 없음 의견을 내는 경우는 찾을 수 있는 후보가 남아 있는 별뿐이며 그때는 (2)로 처리한다. |

## 5. 매칭 업무 규칙

### 5.1 초기 허용 기준

| 항목 | 초기 기준 |
|---|---|
| 주기 | 허용 고조파를 대표 주기로 환산한 뒤, 관측된 통과 전체에서 누적되는 통과 중심 오차가 후보 지속시간의 1/2 이내여야 한다. 후보 주기 P, 후보 지속시간 D, 실제 관측된 통과 수 N(상한은 DEC-03)에 대해 abs(P_user_corrected − P) × N ≤ D/2. 다중 Sector 별에서 기준선 전체의 주기 횟수를 쓰면 허용 오차가 비현실적으로 작아지므로 N은 관측된 통과 수로 계산한다. `(v0.3)` |
| epoch | 사용자가 선택한 transit 구간의 시작·끝 시각 중앙(접힌 곡선이면 환산값)을 제출 epoch로 사용한다. 후보 주기로 환산한 순환 위상 차이 min_k abs(epoch_user − epoch_candidate − kP)가 후보 지속시간의 1/2 이내여야 한다. |
| 지속시간 | 사용자값이 후보값의 0.5배 이상 2배 이하여야 한다. |
| 통과 구간 중첩 | 사용자 예상 통과 창은 자동 산정 epoch를 중심으로 제출한 지속시간을 적용해 만든다. 실제 관측점이 존재하는 구간에서 이 창과 후보 예상 통과 창이 겹쳐야 하며, 데이터 공백은 중첩 통과로 계산하지 않는다. 최소 중첩 통과 수·비율은 실측 벤치마크로 확정한다. |
| 최소 허용 창 | epoch·통과 중첩 허용 창은 데이터 케이던스의 2배보다 좁게 설정하지 않는다. |
| 고조파 | 초기에는 1/2배와 2배만 허용한다. |
| 매칭 대상 | 현재 곡선 단계에서 아직 제거되지 않은 후보로 한정한다. `(v0.3)` |

주기·epoch·지속시간·통과 구간 중첩 조건은 모두 만족해야 한다. user_judgment는 사용자의 해석을 나타내는 별도 값이며 수치 매칭 결과를 변경하지 않는다.

### 5.2 후보 선택

1. 공개 중인 동일 PublicationBundle의 자체 BLS 후보 중 현재 곡선 단계에서 제거되지 않은 후보만 비교한다. `(v0.3)`
2. 각 후보와 허용 고조파에 대해 주기·epoch·지속시간·통과 중첩 조건을 계산한다.
3. 조건을 만족하는 후보가 없으면 not_matched.
4. 배율 1로 일치하는 후보가 있으면 고조파 일치보다 항상 우선한다. `(v0.3)`
5. 후보가 하나이면 matched 또는 matched_harmonic.
6. 후보가 여러 개이면 정규화한 거리와 통과 구간 중첩을 비교하고, 우세 후보를 안전하게 고르기 어려우면 ambiguous_match.
7. 같은 사용자가 이미 성과를 인정받은 고유 후보에 다시 일치하면 duplicate. 성과 없이 끝난 매칭은 재제출로 판단을 갱신할 수 있다. `(v0.3.1)`
8. not_matched 제출도 Submission과 AnalysisHistory에 남기고 오답 분기로 안내한다.

### 5.3 사용자 판단과 별별 성과·등급 `(v0.3)`

- 사용자 판단은 LIKELY_PLANET, UNLIKELY_PLANET, UNSURE 중 하나로 저장한다. 근거 체크는 선택이며 성과에 영향을 주지 않는다.
- 확정 행성 신호에 matched 또는 matched_harmonic이면 확정 행성 성과로 즉시 인정한다.
- 확정 FP 신호에 매칭되고 판단이 UNLIKELY_PLANET이면 FP 판단 성공으로 즉시 인정한다. LIKELY_PLANET·UNSURE면 오답 분기이고, 이후 UNLIKELY_PLANET으로 재제출하면 인정한다.
- 미확정 후보에 매칭되면 분석글 화면이 열리고, 사용자가 게시하는 시점에 미확정 성과로 인정한다. 게시하지 않으면 인정하지 않되 히스토리에서 나중에 게시할 수 있다. 인정 대기 상태는 없다.
- 별의 완료는 SUB-11에 따라 시스템이 판정한다. 후보표가 빈 별의 자동 완료에만 FP 유형 성과(A, 별당 1회)를 인정하고, 그 외 자동 완료와 회원의 더 없음 의견은 성과가 없다. `(v0.5)`
- 오답 결과에서 [상세 보기]를 선택하고 재제출해 맞힌 경우도 위와 동일하게 인정한다. answer_viewed는 기록만 한다.
- 등급은 사용자·TIC별로 산정한다. 확정 행성 또는 미확정 후보의 인정된 고유 후보 수가 1/2/3/4개 이상이면 A/S/SS/SSS, FP 판단 성공은 A다.
- 등급이 오르면 GRD-08에 따라 주변 별을 연다.
