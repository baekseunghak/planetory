# 통계 지표 사전과 인수 기준

상태: **초안·정책 승인 대기**. Jira: [S15P21C206-176](https://ssafy.atlassian.net/browse/S15P21C206-176). 상위 정본은 [SRS STA-01~04·DAT-13](planetory-requirements-spec.md), 결정 상태는 [DEC-31·DEC-11](planetory-decision-register.md)이다. 이 문서는 지표별 검산·시간 경계의 상세를 담당한다. API·잡 구현, DDL·운영 DB 적용은 포함하지 않는다.

## 1. 확정 계약과 현재 구현

- **확정:** 채점형은 회원×신호 첫 매칭 제출, 공개 판단은 회원×신호 최신 유효 공개 제출이다. 전체는 10분 MV, 비교 기준선은 일별 Snapshot의 최근 90일 제출 회원 중앙값이다. 회원 순위·백분위는 제공하지 않는다.
- **확정:** 공개 취소·숨김은 공개 판단 대표를 다시 선택하지만 성과를 자동 회수하지 않는다. 외부 라벨 갱신으로 과거 Snapshot을 다시 계산하지 않는다. 첫 매칭과 성과 인정은 같은 사건이 아니다.
- **현재 구현(ed7d72d):** `SubmissionRepository.statistics`는 채점형에 `match_result IN ('matched','matched_harmonic')`, `(created_at,id)` 오름차순을 사용한다. 공개형은 `PublicAnalysisVisibility.VISIBLE`과 내림차순을 사용한다. 두 쿼리 모두 회원 active 필터가 없다. `QuestRepository.countChallengeParticipants`는 별에 속한 여러 신호의 회원을 DISTINCT로 합친다. [165 변경 근거](../changes/2026-09-W4/2026-09-21.md#s15p21c206-165-공개-판단챌린지-참여-수-공통-조건과-소비-계약)를 따른다.
- **미구현:** P1 개인·전체·비교 API와 잡, `global_stats`는 없다. V1의 `stats_snapshots`는 날짜·scope·round·metrics만 가지며 같은 날짜/범위 중복 방지와 기능 전용 앱 권한이 없다. 테이블 존재를 구현 완료로 보지 않는다.
- 기존 신호 통계는 결과·History·공식 스레드·출처 카드의 실시간 조회다. P1 전체 통계를 대신하지 않으며, P1을 이유로 기존 공개 트랜잭션에 MV 갱신이나 일별 집계를 추가하지 않는다.

## 3. 지표 사전

### 공통 표기

`S`는 저장 성공한 submissions, `C`는 그중 submission_kind=candidate, `F`는 회원×matched_candidate_id별 matched/matched_harmonic의 첫 행, `A`는 user_candidate_achievements, `P`는 공개 조건을 통과한 published_analyses→analysis_histories→submissions의 회원×신호별 최신 제출이다. `F`는 `(created_at,id) ASC`, `P`는 같은 키 DESC로 선택한다. 기간 필터로 과거 첫 매칭을 잘라 새 첫 매칭을 만들지 않는다. 공개 P는 유효성을 먼저 거르고 대표를 고른다. 단순 최신 제출이나 공개 시각으로 대체하지 않는다.

`L`은 기준 시각 이전 누적, `W8`은 T1의 8주, `R`은 현재 운영 active 챌린지 대상 별이다. 정렬은 시각 동률에 ID를 포함하며 기간은 시작 포함·끝 제외다. 내 값은 본인 회원으로 제한하고, 전체는 표의 키로 다시 집계한다. 별 수에 회원×별 합과 고유 TIC 수를 함께 명시하며 둘을 같은 이름으로 보내지 않는다.

시각 `Q`는 실시간 읽기 기준, `M`은 전체 MV가 읽은 원천의 기준, `D`는 비교 Snapshot의 배타적 종료 경계다. 모든 행은 해당 `asOf`와 기간을 반환한다. 집계 완료 시각은 `generatedAt`으로 분리한다. 정정 `현재`는 다음 성공 집계에서 원천의 현재 상태를 반영하되, 외부 라벨 변경으로 기존 성과 유형과 과거 Snapshot을 바꾸지 않는다는 뜻이다. 임의 과거 재계산은 하지 않는다. 공개 상태의 과거 이력이 없는 P는 D 시점 상태를 사후 복원했다고 주장하지 않는다.

| 챌린지 판단 분포·제안 | R의 P, 참여 건·% | 판단별 회원×신호 / 전체 회원×신호 | 별 참여자 ‘명’과 분모가 다름을 표시. 임의로 회원당 마지막 신호 하나 선택 금지 | 분모 0 null; 현재; M |
| 관측 회차별 진행률·제안 | observation_datasets + star_unlocks + user_star_progress, % | 해당 Sector에 관측이 있는 완료 회원×TIC / 발견 회원×TIC | 현재; 원천 버전 중복은 Sector×TIC로 제거. 여러 Sector의 같은 별은 각 회차에 포함하며 회차끼리 더하지 않음 | 분모 0 null; 현재; M |

채점형 전체 일치율은 F의 분자 합/분모 합이며 회원별 비율의 평균이 아니다. 비교는 회원별 지표의 중앙값으로 별도 계산한다. 공개 전체 분포는 여러 신호에 참여한 한 회원이 여러 번 기여하므로 ‘고유 참여자 명’ 대신 ‘회원×신호 참여 건’을 쓴다. 백분율은 계산 중 반올림하지 않고 표시 때 소수 첫째 자리로 반올림하는 안을 권장한다. 비율 합을 100으로 맞추기 위해 한 판단을 임의 보정하지 않는다.

재도전·근거 지표의 당시 라벨/판정은 제출 저장 응답·History의 보존 필드를 177에서 대조한다. 없는 필드를 현재 판정으로 채우지 않는다. 관측 회차 진행률의 제공 대상·튜토리얼 포함 여부와 AI 구간의 버전 선택은 위 권장안을 승인하거나 대안을 확정한 뒤 구현한다. 다음 목표·개선 힌트 문구는 값의 원인을 단정하지 않고, 유효 표본이 없으면 자료 부족으로 표시한다.

## 4. 기준 시각·갱신·응답 인계안

**확정:** 전체 10분 갱신과 비교 일별 저장을 구분한다. 아래 필드와 실패 처리는 **제안**이며 [서비스 API 12장](../../apps/backend/docs/service-api-spec.md#statistics-policy)의 후보 경로에 적용한다.

- 공통 메타데이터: `asOf`, `generatedAt`, `timeZone`, `periodStart/periodEnd`, `policyVersion`, `status`(READY/STALE/UNAVAILABLE). 내 통계·전체·비교가 다른 시점이면 각 블록에 따로 둔다. 단일 최신 시각으로 포장하지 않는다.
- 비율·평균은 `value`, `numerator`, `denominator`를, 비교는 `myValue`, `median`, `sampleCount`, `cohortMemberCount`, `snapshotDate`, `cohortStart/cohortEnd`를 전달하는 안이다. 필드명·JSON 형식은 177·178 승인 시 고정한다. 전체/비교 응답과 Snapshot에는 회원 ID·닉네임·회원별 원자료를 넣지 않는다. 본인 값은 본인 인증 경로에서만 제공한다.
- D는 계산 실행일이 아니라 비교의 배타적 종료 시각이다. `snapshotDate`는 마지막 완료 일자 D-1로 제안한다. 예: D=2026-09-21이면 snapshotDate=2026-09-20이다. 집계가 다음 날 재실행되어도 D를 바꾸지 않는다.
- 전체 MV는 성공한 원천 기준 시각 M을 표시한다. 10분은 갱신 주기이지 장애 때 최대 지연 보장이 아니다. 다음 예정 갱신이 끝나지 않으면 직전 성공본에 STALE과 원래 M을 유지한다. 첫 성공본이 없으면 UNAVAILABLE과 값 null로 표시하며 0건으로 꾸미지 않는다. 일별 Snapshot도 같은 원칙을 적용한다.
- 일별 잡은 D 이후 실행 시점과 읽기 일관성, D까지 커밋된 입력을 어떻게 닫을지 178에서 확정한다. 진행 상태·공개 상태처럼 시각 필터만으로 복원되지 않는 값은 실행 시점 조회를 D 값으로 위장하지 않는다. 지연 재실행의 원천을 재현할 수 없으면 해당 날짜를 UNAVAILABLE로 남기는 안을 권장한다.
- 같은 `(snapshotDate,scope,roundId)`의 성공본은 재실행으로 중복 생성·덮어쓰기하지 않는 안이다. 실패한 시도는 성공본을 대체하지 않는다. 정책 변경·정정 backfill은 별도 승인·버전·대체 이력이 필요하다. 외부 라벨 자동 갱신은 backfill 사유가 아니다.
- 178 후속 설계: MV 정의와 CONCURRENTLY 요건을 만족하는 UNIQUE 인덱스, 최초 적재, REFRESH 실행 권한/잡 역할, 읽기 앱 권한, Snapshot global의 null roundId를 포함한 멱등 키, 잡 중첩 방지와 실패 복구를 검증한다. 이 문서는 DDL·권한 부여·스케줄 활성화를 승인하지 않는다.
