## 1. 주간 요약

이번 주는 설계·문서 단계에서 실제 구현 단계로 넘어간 주였다. 인증·별지도·별 상세·커뮤니티·분석의 백엔드 API와 프론트 화면이 각각 병합됐고, 프론트가 로컬 백엔드에 실제로 붙어 동작하는 것까지 확인했다. 천문 처리 쪽은 BLS 격자·게이트 벤치마크와 반복 제거 루프, transit 모델·제출 매칭·Gold 적재 계약을 실측과 함께 확정했다. 인프라는 HDFS HA 설치부터 수동 장애 복구, YARN·Spark 실환경 검증, EC2 PostgreSQL 단일 인스턴스 구성까지 진행했다.

동시에 "구현 완료"와 "실제 연결·배포 검증 완료"가 다르다는 점이 여러 파트에서 같은 형태로 드러났다. 가상 응답으로 통과한 검사가 실제 서버 계약에서 깨지고, 소유자 계정으로 도는 테스트가 앱 계정 권한 결손을 가렸으며, 조정 단계에서 얻은 벤치마크 이득이 평가 단계에서 재현되지 않았다. 다음 단계는 통합·배포 검증을 개별 기능 티켓에서 분리해 별도로 추적하는 것이다.

## 4. 주간 회고

### Keep

- 리뷰 지적을 그대로 받지 않고 원문·코드·실행으로 근거를 확인한 뒤 반영했다. 실제 Tomcat 기동, 없는 계정으로 기동, 결함 주입 같은 방법으로 주장 자체를 검증했다.
- 테스트가 무엇을 지키는지 테스트로 확인했다. 안전 가드를 하나씩 제거한 변이 시험 6건과 조건을 일부러 틀리게 바꾸는 결함 주입으로, 통과하면 안 되는데 통과하는 테스트를 찾아냈다.
- 계약과 규칙을 구현 전에 글로 먼저 맞췄다. 113·112·128번 계약 결정을 회의 없이 문서로 끝냈고, 댓글 커서 페이지네이션은 기존 `SkyCursor`·`StarListCursor` 규약을 그대로 따라 새 규약을 만들지 않았다.
- 추정 대신 실측 수치를 썼다. MAST 공식 목록을 직접 세고, 타일 크기별 전송량을 재고, 색 대비를 세 표면에서 측정하고, 프론트 검사 347개를 돌려 결과를 기록했다.
- 완료와 미완료를 과장 없이 구분했다. 실행하지 않은 Worker 3 실제 장애, 10만 별 성능 미달, 보류한 GPU 기본 적용을 완료로 적지 않았다.

### Problem

- 검증 경로와 실제 사용 경로가 달라 결함이 숨었다. 소유자 계정 테스트가 앱 역할 GRANT 결손을, compose 환경변수 검증이 Flyway 비밀번호 문제를, localhost 직결 검증이 프록시 문제를, 개발용 fixture가 서버 계약 불일치를 각각 가렸다.
- 벤치마크를 과대 해석했다. 조정 단계에서 씨앗 1개로 본 50k 격자 이득(+0.07)이 평가 4별에서 재현되지 않았고, 잡음 씨앗 간 편차(0.03~0.13)가 효과보다 컸다.
- 실행 시간을 반복해서 낮게 봤다. 짧은 별 하나로만 smoke를 돌려 163일 별에서 설정 하나에 84분이 걸렸고, 평가 5별 약 7시간을 예측하지 못해 한 별을 남겼다.
- 선행 브랜치가 병합되지 않은 상태에서 후속 브랜치를 쌓아, 같은 계약 수정을 다섯 브랜치에 반복 반영하고 브랜치마다 통합 검사를 다시 돌려야 했다.
- 열린 MR을 서로 확인하지 않아 같은 파일명의 마이그레이션 V11이 두 곳에서 작성됐다. 먼저 적용되는 쪽에 따라 체크섬 불일치로 기동이 막힐 수 있었다.
- 개별 티켓에 통합·배포 검증이 중복으로 들어가 기능이 구현돼도 계속 진행 중으로 남았고, 실제 기능 누락과 외부 환경 대기를 구분하기 어려웠다.

### Try

- 검증을 한 번은 실제 사용 경로로 돌린다. 앱 계정으로 접속한 상태, 환경변수 없는 로컬, 프록시 헤더가 붙은 요청, 서버 계약에서 생성한 fixture 중 해당하는 것을 고른다.
- 벤치마크 표에는 평균과 함께 씨앗 최소–최대 폭을 적고, 그 폭보다 작은 차이는 효과 없음으로 판정한다. 실행 시간이 관측 기간·점 수에 비례하는 설정은 가장 큰 별로 먼저 시간을 잰다.
- 브랜치·커밋·마이그레이션을 만들기 전에 해당 가이드를 열고, 열린 MR에 같은 번호나 같은 대상이 있는지 확인한다.
- 겹치는 브랜치는 공통 수정을 가장 아래 브랜치에 먼저 넣어 위로 흘려보내고, 병합이 끝난 브랜치는 정리해 반복 범위를 줄인다.
- 통합·배포 검증은 개별 기능 티켓에서 분리해 216·244번에서 추적하고, 이관한 항목은 다른 테스트 통과만으로 완료 처리하지 않는다.
- 중요한 안전 가드에는 정상 테스트와 함께 그 가드를 제거한 변이 시험을 한 건 이상 붙인다.

## 5. 다음 주 우선 과제

1. **P0 통합 검증 분리 추적**
   - 216번에서 실제 API·배포 환경·지원 브라우저 인수를 한곳에서 확인한다.
   - 기능 누락과 외부 환경 대기를 구분해 기록하고, 이관한 항목은 완료로 표시하지 않는다.

2. **실제 사용 경로 검증 정착**
   - 앱 계정 권한, 프록시 헤더, 환경변수 없는 로컬 기동을 각 파트의 회귀 검사에 포함한다.
   - 프론트 fixture를 서버 계약 문서에서 생성하도록 바꾸고, 계약이 바뀌면 fixture부터 고친다.

3. **커뮤니티·프로필 남은 기능**
   - 피드(F05·13)와 핫 토픽(218번)을 구현하고, 댓글 수는 페이지 단위로 한 번에 읽는 방식을 유지한다.
   - OAuth 로그인 픽스처를 분리해 회원·게시글·댓글 테스트를 기능별 클래스로 옮긴다.

4. **BLS 파이프라인 다음 단계**
   - holdout 4별 실행과 DEC-03 승인을 마치고 111번 MR을 올린다.
   - 112번(고조파 배수 집합·겹침 쌍) 설계를 시작하고, SDE 재검토는 243번으로 분리해 진행한다.

5. **데이터 플랫폼 전체 경로 연결**
   - HDFS·YARN·Spark 검증 위에 Gold 적재와 공개 판 전환을 순서대로 확인한다.
   - Node 1 `/tmp` 잔여 파일 정리를 75번 완료 조건에 따라 처리한다.
