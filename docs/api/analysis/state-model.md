## 2. 편집 단계와 제출 가능 조건

| 단계 | 필요한 상태·사용자 행동 | 다음 단계로 가기 전 확인 |
|---|---|---|
| 봉우리 선택 | 현재 곡선과 해당 주기도가 준비됨. 주기도에서 주기를 선택 | 전 점·고정 Bundle 기준 시각을 사용한 브라우저 접기가 성공해야 이후 입력 가능 |
| 주기 맞추기 | 현재 봉우리의 서버 제공 최소·최대·step 범위에서 미세 조정 | 접기 작업 중에는 구간 선택·판단·제출 비활성. 주기 변경만으로 BLS·잔차 API를 호출하지 않음 |
| 구간 선택 | 접힌 곡선의 두 핸들로 위상 구간 확정 | 유한한 양수 주기, 유효 위상 범위·폭, 관측 범위 안 epoch 산정 가능 여부 확인 |
| 판단 | 세 판단 중 하나 필수; 네 유효 근거·메모는 선택 | 중심 위치는 데이터 없음·선택 불가. 시간 영역 곡선의 transit 띠는 읽기 전용 |
| 제출값 확인 | 원본 period·phase_start/end·판단과 파생값 미리보기 확인 | 제출은 현재 곡선 문맥과 원본 위상값 기준. 서버 재계산·검증 성공이 최종값의 근거 |

`phase_end > 1`인 경계 통과는 정상일 수 있다. `0 ≤ phase_start < 1`, `phase_start < phase_end < phase_start + 1`을 적용하고 epoch·duration 숫자 직접 입력은 두지 않는다(EXP-06·07, SUB-01·02).

## 3. 변경 전후: 초기화·유지·복구

| 행동 | 성공 후 바뀌는 값·단계 | 유지할 값 / 실패 시 행동 |
|---|---|---|
| 새 봉우리로 주기 재선택 | 새 주기로 접기; 위상·파생값·판단·근거·메모 초기화; 접힌 x축 ×1; 주기 맞추기로 이동 | Bundle·곡선 단계·제거 조합·주기도 확대/이동 범위 유지 |
| 같은 봉우리에서 미세 조정 | 새 주기로 접기; 위상·파생값·판단·근거·메모 초기화; 주기 맞추기로 이동 | 위 문맥·주기도 범위와 접힌 x축 확대 배율만 유지. x축 위치·y축 범위·transit 밴드는 새 접기 기준으로 재설정 |
| 접힌 곡선 더블클릭 / `0` | x축 확대 배율 ×1 | 주기 변경이 아니다. y축 범위나 제출 입력을 초기화하는 행동으로 사용하지 않음 |
| 재접기 실패 / 허용 범위 이탈 | 실패 입력과 오류 안내 | 마지막 성공 주기·곡선·확대 배율·작성 중 입력으로 함께 복구; 실패한 새 주기와 이전 접힌 곡선을 함께 쓰지 않음 |
| 다음 곡선 요청 | 대상 문맥으로 잔차 작업 시작; 전체 준비 성공 후 곡선·주기도를 함께 전환 | 준비 전에는 마지막 정상 곡선 유지. 계산 실패가 이미 저장한 제출·매칭·성과·완료를 취소하지 않음 |
| 원본 / 이전 곡선 보기 | 해당 Bundle의 선택한 곡선 문맥으로 이동 | 누적 매칭·기성과·완료·히스토리 보존. 미제출 입력의 문맥별 유지 범위는 아래 확인 질문 참고 |
| 일시적 통신 오류 복구 | 같은 TIC·Bundle·곡선 문맥·원본 입력·주기도 범위·접기 배율 복원 | 미제출 파생값은 다시 계산; 제출·히스토리 표시는 서버 최종값 사용 |
| 제출 기록에서 다시 풀기 | 그 제출의 Bundle·제출 전 곡선 단계·제거 조합·원본 입력·표시 상태를 새 초안으로 복원 | 자동 정정값으로 원본을 덮어쓰지 않음. 단순 복원은 새 제출·성과를 만들지 않음 |

초기화는 성공한 입력 변경으로 이후 입력이 무효가 된 경우이고, 복구는 실패 직전의 일관된 성공 상태로 돌아가는 경우다. 화면 이동 자체에 주기 재선택 초기화를 일괄 적용하지 않는다(EXP-08·10·12·13, SUB-10).

클라이언트 구현 제안: 새 접기 요청마다 revision을 증가시키고 요청 시 곡선 문맥과 함께 기록한다. 현재 요청에 해당하는 성공 결과만 적용하며 이전 요청 결과는 버린다. 최신 요청이 실패해도 뒤늦은 이전 요청을 대신 적용하지 않고 마지막 확정 성공 상태를 복구한다.

## 4. 서버 잔차 계산 전이

`QUEUED → RESIDUAL_CALCULATING → RESIDUAL_READY → PERIODOGRAM_CALCULATING → COMPLETED`를 표시하며 작업 실패는 `FAILED`로 안내한다(EXP-09).

| 관측한 상태 | 표시·가능 행동 | 전환 기준 |
|---|---|---|
| 요청 전 / 캐시 있음 | 매칭 후 남은 탐색 가능 신호가 있으면 다음 곡선; 동일 문맥 캐시는 재사용 가능 | 캐시를 받더라도 Bundle·제거 조합·계산 버전이 맞는 결과만 사용 |
| 대기·계산 중 | 현재 정상 곡선과 단계별 진행·대기 안내 표시 | 주기도가 잔차보다 먼저 준비된 것으로 처리하지 않음 |
| RESIDUAL_READY | 잔차 준비 사실 표시 | 곡선 선노출 여부는 벤치마크 미결. 전체 준비 전 다음 분석 단계로 확정 전환하지 않음 |
| COMPLETED | 해당 목표 곡선·주기도로 전환 | 현재 요청 문맥과 일치하는 결과인지 확인; 이전 작업 응답이 현재 문맥을 덮지 않게 하는 것은 클라이언트 제안 |
| FAILED / 목표 시간 초과 | 오류·대기 안내와 재시도 제공; 마지막 정상 곡선 유지 | 같은 Bundle·제거 조합으로 재시도. 단순 지연과 서버의 명시적 실패는 구분 |

매칭됐다고 잔차가 이미 준비된 것은 아니며 잔차 실패가 매칭 실패도 아니다. 진행 중 새 Bundle이 공개되어도 현재 세션에 섞지 않는다. 대기 목표 수치는 DEC-16, 계산·캐시의 상세는 DAT-14·DEC-35를 따른다.

## 5. 제출 결과별 표시와 다음 행동

아래에서 ‘다음 곡선’은 남은 탐색 가능 신호가 있을 때의 행동이다. 모두 매칭했다면 결과 보기·재도전·선택 공개를 제공한다. 완료 자체에는 보상이 없다.

| 결과 조합 | 함께 표시할 상태 | 가능한 다음 행동·주의 |
|---|---|---|
| 확정 매칭 + LIKELY / FP 매칭 + UNLIKELY | 매칭·판단 일치·미인정 신호면 최초 성과; 마지막이면 완료 | 해설, 다음 곡선 또는 결과 보기. FP 여러 건도 별 등급 최대 A이며 추가 FP마다 등급 상승을 만들지 않음 |
| 마지막 확정 + UNLIKELY / 마지막 FP + LIKELY | 탐색 완료 + 판단 불일치 + 이번 성과 미인정; 기성과 보존 | 현재 매칭 신호 상세 보기, 다시 풀기, 결과 보기. 마지막이 아니면 잔차 탐색도 가능 |
| 확정 또는 FP + UNSURE | 매칭 + 판단 보류 + 이번 성과 미인정; 마지막이면 완료 | 현재 신호 상세 보기, 다시 풀기; 남은 신호가 있으면 다음 곡선. 판단 불일치로 쓰지 않음 |
| 미확정 매칭 + 세 판단 중 하나 | 매칭·내 판단·미게시·성과 미인정; 마지막이면 완료 | 다음 곡선, 분석 공개 검토, 나중에, 결과 보기. UNSURE도 공개·최초 성과 가능 |
| matched_harmonic | 매칭 성공과 원본·정정 주기·배율·사유 | 해당 확정/FP/미확정 규칙 적용. 같은 신호의 다른 고조파를 신규 성과로 계산하지 않음 |
| duplicate | 다시 매칭됨·이번 판단·추가 성과 없음·기존 성과 유지 | 미확정 새 기록은 선택 공개 가능하나 추가 성과 없음. 이전에 미인정으로 끝난 신호는 duplicate로 막지 않음 |
| not_matched | 후보표와 일치하지 않음·개인 기록 저장; 진행·제거 조합·성과 변화 없음 | 상세 보기(대상 없으면 비활성), 다시 풀기, 선택형 일반 토론. 후보 AI·판단 분포를 임의 연결하지 않음 |
| ambiguous_match | 복수 후보가 모호함; 입력·기록 보존; 임의 후보 선택·성과 없음; 기존 진행 유지 | 구분 정보 또는 재제출 안내. 특정 신호의 해설·공개 가능 상태로 임의 전환하지 않음 |
| no_candidate → none_wrong | 더 찾을 신호가 남아 있다는 안내; 성과·완료 변화 없음 | 상세 보기·다시 풀기. 주기·위상·판단 필수인 candidate 제출과 구분; 공식 공개 분석 생성 없음 |
| 서버가 탐색 완료 판정 | all_found 또는 undiscoverable_only와 재개 대기 | 더 없음 제출을 강제하지 않음. 완료된 별에서도 과거 기록 재도전·나중 공개 가능 |
| 튜토리얼 skipped | 건너뜀 완료 사유·다음 순번 열림·성과 없음 | 서버 설정과 튜토리얼 조건을 충족할 때만 표시; 후보 매칭 성공으로 취급하지 않음 |

무신호 별(채택 신호 0개)은 제공 대상이 아니며 진입 완료·보상 예외가 없다. 채택 신호가 있지만 모두 탐색 불가능한 경우는 SUB-11의 별도 경계다. 향후 재개 이벤트는 DEC-27을 따르며 완료 후 재도전과 구분한다.

근거: SUB-03~12, RES-01~11, GRD-02~04. 채점형 인정 참여자 판단 분포와 미확정 공개 분석 통계는 모수·기준 시각을 구분한다(RES-11·COM-14).

## 6. 상세 보기·재도전·재전송

- **매칭 후 불일치·보류 상세:** 방금 매칭한 고유 신호의 값·해설·출처·AI를 보여준다. 남은 신호 힌트로 바꾸지 않는다.
- **not_matched·none_wrong 상세:** 해당 제출의 Bundle·곡선 단계에서 제거되지 않은 탐색 가능 후보 중 BLS 품질이 가장 높은 하나. 누적 미매칭 집합을 쓰지 않는다. 대상 0개면 상세 보기 비활성·해설 없음 안내다.
- 상세 열람은 `answer_viewed`에 기록하며 성과를 감점하지 않는다. 미확정 후보값을 정답이라고 부르지 않는다(RES-09).
- [다시 풀기]는 추가 해설 없이 당시 문맥·입력을 복원한다. 완료된 별의 이미 제거한 신호도 당시 단계에서 다시 비교하며 현재 누적 완료를 과거 상태로 덮지 않는다(SUB-10).
- 새로 판단·제출하면 새 요청 ID의 Submission·AnalysisHistory를 만든다. 오판 정정의 최초 성과와 이미 인정된 신호의 duplicate를 구분한다.
- 응답 유실로 **같은 제출 요청**을 재전송하면 같은 요청 ID로 기존 결과를 받는다. 결과 미확인을 이유로 새 요청 ID를 자동 발급하지 않는다(SUB-09).
- 개인 히스토리 원본과 서버 최종 파생값은 불변이다. 복원 실패 시 다른 Bundle로 몰래 대체하지 않는다(EXP-01·10, HIS-02·06).

## 7. 선택 공개와 부분 실패

| 행동·결과 | 공개 상태의 전이 | 매칭·완료·성과에 미치는 영향 |
|---|---|---|
| 개별 / 모두 게시 검토 | 미확정 신호별 대표 기록 선택; 기본은 미공개 중 최신 제출 | 검토만으로 공개·성과 없음. 현재 공개 중인 동일 기록은 제외하되 새 제출은 선택 가능 |
| 게시 요청 | 선택 항목별 게시 중 → 공개됨 또는 게시 실패 | 신호별 최초 공식 스레드 확보·분석 등록·최초 성과를 함께 확정; SYSTEM이 스레드를 생성 |
| 일부 성공 | 성공 항목 유지, 실패 항목은 미게시·실패 사유 표시 | 성공분만 통계·최초 성과 반영. 완료는 유지; 등급 상승·별 열림은 순차 인정과 동일한 서버 결과 표시 |
| 실패 항목 재시도 / 나중에 | 실패분만 재시도하거나 개인 기록으로 보존 | 성공한 스레드·분석·성과를 중복 생성하지 않음; 공개를 미뤄도 탐색 계속 가능 |
| 본인 공개 취소 / 운영 숨김·복원 | 본인 공개 여부와 운영 숨김을 별도로 반영 | 기성과·히스토리·완료 보존. 운영 복원이 본인 취소를 되돌리지 않음 |
| 공식 스레드 숨김 중 새 공개 | 게시 실패·미게시 유지; 숨김 스레드 재생성 금지 | 새 공개 성공·최초 성과 없음. 부모가 숨겨진 하위 분석·토론·링크 내용도 노출하지 않음 |

공개 통계는 유효 공개 집합에서 사용자×고유 신호당 제출 서버 접수 시각이 최신인 한 건, 동률이면 서버 제출 순번으로 선택한다. 취소·숨김 후 남은 공개 중 최신으로 다시 계산하며 새 제출만으로 통계를 바꾸지 않는다. 세 판단을 모두 분모에 포함하고 0명은 공개 분석 없음으로 표시한다(COM-14·18·19).

## 8. 담당자 확인 질문과 Mock 검증 기준

1. 프론트·백엔드: 원본/이전 곡선 이동 때 문맥별 미제출 초안 유지 범위와 [다시 풀기] 최초 화면 단계는 무엇인가? 어떤 선택이든 다른 곡선의 입력과 섞지 않는다.
2. 백엔드·데이터: 보존 Bundle·복원 자료가 만료되거나 접근 불가하면 어떤 오류와 재시도 가능 여부를 주는가? 구버전 재현을 현재 데이터로 대체하지 않는 복구 화면이 필요하다.
3. 백엔드·프론트: RESIDUAL_READY 곡선 선노출 여부와 목표 대기 시간은 어떤 벤치마크로 결정하는가? 정본의 미결 범위 안에서 확정한다(EXP-09, DEC-16·35).

Mock은 최소한 접기 응답 역전·실패 복구, 마지막 오판/UNSURE, 미인정 정정과 duplicate, ambiguous_match, no_candidate, 완료 별 과거 단계 복원과 상세 대상 0개, 잔차 실패, 공개 부분 성공·재시도를 분리해 검증한다. 수용 근거는 AT-90~101·103·105·107~109이며 이 문서 작성은 해당 서비스 테스트 실행을 뜻하지 않는다.
