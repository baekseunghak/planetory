## 1. 이 디렉터리의 적용 범위

`README.md`·`state-model.md`·`examples/*.json`은 `77e4121`의 요구사항 v0.12를 바탕으로 만든 실험 기록이다. 기존 프로토타입이 예제 JSON을 가져오므로, 이번 문서 정리에서 필드 일부만 최신 규칙으로 바꾸어 구판 화면과 혼합하지 않는다. `validate-examples.cjs`도 당시 시나리오의 구조·상태·계산 일관성을 검사한다.

새 화면과 서버 연동은 [프론트 상세 명세](../../development/analysis-frontend-spec.md)를 출발점으로 삼는다. 현재 계약을 확정할 때는 아래 차이를 반영한 새 fixture와 UI 어댑터를 함께 작성하고, 현재/구판 fixture의 기준 버전을 구별해야 한다. SRS에 정해진 정책을 다시 미결로 돌리지는 않으며, 전송 형식·경합 처리 등 미합의 인터페이스만 상세 명세 12장의 Q 항목으로 남긴다.

완료·판단·성과·공개를 분리하는 원칙, 무신호 별 제공 제외, 마지막 오판이어도 탐색 완료 표시, 선택적 공개·부분 실패·동일 요청 재전송 구분은 계속 활용할 수 있다. 다만 같은 시나리오 이름이어도 최신 데이터 판·성과·통계 계약으로 다시 검증해야 한다.

## 3. 검증 결과를 읽는 방법

저장소 루트에서 실행한다.

```text
node docs/api/analysis/validate-examples.cjs
```

이 명령은 구판 합성 시나리오 10개·HTTP 예제 54개와 문서 링크를 검사하고 잘못된 변형 6개를 거절하는지 확인한다. 서버 요청, 브라우저 동작, DB 트랜잭션, 실제 BLS·AI·성능은 실행하지 않는다. manifest의 `contract_status=historical-fixture-only`가 이를 명시한다.

v1.0 연동 완료 판단에는 상세 명세 13장의 해당 FAV와 SRS 수용 조건을 사용한다. 특히 판 변경·현재 판 재도전·근거 3종·누적 성과 등급·첫 매칭 통계·공개 동률·재전송은 서버와 공유한 새 fixture 및 실제 통합 검증이 필요하다. 구판 검증기의 PASS를 해당 작업의 완료 증거로 재사용하지 않는다.
