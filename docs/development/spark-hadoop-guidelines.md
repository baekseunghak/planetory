# Hadoop·Spark 개발 규칙

- 대규모 데이터에 무분별하게 `collect()` 또는 전체 로컬 변환을 사용하지 않습니다.
- 파티션 수, `repartition`, `coalesce` 변경에는 데이터 규모와 변경 근거를 남깁니다.
- 불필요한 shuffle, wide transformation과 반복 연산을 리뷰합니다.
- 가능한 경우 UDF보다 Spark 기본 제공 함수를 우선합니다.
- 조인 전략이나 캐시를 변경할 때 메모리 및 성능 영향을 확인합니다.
- 처리 로직은 작은 고정 샘플로 빠르게 검증할 수 있어야 합니다.
- 로그에 자격 증명, 개인정보 또는 불필요한 원본 레코드를 출력하지 않습니다.
- 출력 형식, 스키마, 파티션 기준 및 저장 모드를 명시합니다.
- 성능 개선 MR은 가능한 한 동일한 데이터와 EC2 사양에서 변경 전후를 비교합니다.

## 작업 유형별 검증 자료

| 작업 유형 | 필요한 자료 |
| --- | --- |
| 데이터 수집 | 데이터 출처, 적재 방법, 샘플 결과, 실패 및 중복 처리 검증 |
| 스키마 | 필드 정의, 타입, nullable 여부, 변경 영향과 호환성 |
| Spark/Hadoop 작업 | 실행 방법, 입력·출력 예시, 테스트 결과와 로그 |
| 성능 개선 | 데이터 규모와 환경을 포함한 변경 전후 비교 |
| 데이터 품질 | 검증 규칙, 허용 기준, 실패 처리와 검증 결과 |
| 분석 및 실험 | 데이터 범위, 조건, 설정값, 측정 결과, 결론과 다음 행동 |
