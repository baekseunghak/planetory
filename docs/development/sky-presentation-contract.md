## 0. 합의한 모습과 문서 적용 기준

2026-09-15 하서진은 개인 시제품을 서비스의 시각 기준으로 지정하고 두 권장안을 채택했다. 전체 은하의 색·크기는 연출로 유지하고 행성 수·완료·성과·등급은 호버/포커스 정보·상세·목록의 문자로 표시한다. 행성·회색 궤도는 별을 선택한 근접 뷰에서만 표시한다. 이 결정은 사용자 승인된 변경안이며 팀의 API/DB 교차 리뷰와 MR 병합·실제 구현 검증은 별도다.

[원본 화면 4장·재현 자료](sky-reference/README.md)를 외형 인수 기준으로 사용한다. 204의 비교용 합성 좌표, 과거 방사형 PoC, 옛 와이어프레임만으로 대체하지 않는다. 스크린샷은 외형 기준이며 스크린샷의 예시 TIC 이름·임시 API·상태 문구·가상 계정 기능까지 운영 계약으로 채택하지 않는다. 요구사항의 동작·권한, 이 문서의 배치/표현, 탐사 API의 전송 형식, ERD의 저장 제약을 같은 v1.3 변경안으로 적용한다.

## 1. 은하 배치·연출·개별 별 조회

### 1.1 별의 정체와 배치 책임

- 화면의 별은 인증 회원이 해금한 실제 TIC다. 시각 비교 JSON만 합성 TIC를 쓴다. 적은 별로 은하가 성기게 보이는 것을 허용하며 미발견 별을 채워 넣지 않는다.
- 어떤 TIC을 발견하는지는 기존 OPS-08·성과/튜토리얼/챌린지 규칙이 정한다. 어디에 놓는지는 별도의 은하 배치 함수가 정한다. 부모·원인 성과는 이력이며 부모 바깥·세대 반지름을 강제하지 않는다. 반지름/각도 자체는 나선 계산에 사용하는 수학적 값이다.
- 서버가 발견 트랜잭션에서 회원별 layout_ordinal(0부터의 안정된 정수 순번)을 배정하고 world_x/world_y/depth_z/layout_version과 함께 저장한다. 모든 발견 종류가 같은 순번 공간을 쓴다. UNIQUE(user_id,tic_id), UNIQUE(user_id,layout_ordinal), 기존 성과 멱등 제약을 지킨다.
- 회원 행 잠금 등 기존 9.2절 직렬화 안에서 다음 순번을 확보한다. 카운터 또는 인덱스 끝값으로 배정하며 프레임별/발견별 전체 별 순회는 하지 않는다. 중복 요청에는 새 순번을 확정하지 않고 실패 트랜잭션은 발견·좌표·순번 배정을 함께 롤백한다.
- 지도·타일·locate·상세는 동일 회원/TIC의 저장 좌표·layoutOrdinal·layoutVersion을 사용한다. 다른 회원이 같은 순번의 같은 좌표를 사용해도 무방하다. TIC 식별과 스레드 연결은 좌표가 아닌 TIC로 한다.

### 1.2 배치 참조 구현과 초기 준비

배치 버전은 personal-spiral-v1이다. [reference.mjs](sky-reference/reference.mjs)의 layout이 언어 간 비교 기준이다. 원본 개인 시제품의 position(index)를 안정 순번으로 옮긴다. 순번의 20%는 중앙부 가우스 분포, 나머지는 4개 나선 팔과 제한된 분산/일부 분산별로 구성한다. 처음 6개 자리는 원본의 기준 자리를 사용하되 아직 해금하지 않은 순번의 별은 표시하지 않는다. 특정 TIC를 튜토리얼/챌린지로 하드코딩하지 않는다.

32비트 부호 없는 난수 연산, 수식·상수·난수 호출 순서를 참조 구현에 고정한다. Java 등 제공자는 [좌표 검증 벡터](sky-reference/vectors.json)와 x/y 절대오차 1e-6, depthZ 1e-9 이내인지 확인한다. 한 번 저장한 값은 재계산하지 않고 API마다 같은 DB 값을 반환한다. x/y는 RA/Dec가 아닌 서비스 월드 좌표다. depthZ는 원본 z를 256으로 나누어 [-1,1]로 제한한 단위 없는 값이며, 렌더링은 z=depthZ×256으로 복원한다. 원본 1,000개 예시에서 제한에 의한 변화는 없다.

가까운 별이나 투영상 겹침은 허용한다. 시각 간격을 강제하려고 기존 별을 옮기거나 공간 인덱스로 후보를 계속 밀어내지 않는다. 개별 인스턴스/TIC와 목록 선택을 보존한다. 서버 공간 인덱스는 조회·캐시 갱신에 사용한다. 전체 별 수/현재 화면 크기를 배치 함수에 넣지 않으므로 n→n+1에서도 기존 n개의 자리는 같다.

현재 보존할 운영 좌표 데이터는 없다. 출시 전 개발·테스트 행을 초기화하거나 unlocked_at·tic_id 숫자 오름차순으로 안정 순번을 배정해 현행 배치로 한 번 변환한다. 이 준비는 운영 개시 전에만 수행하고 이후 기존 좌표·순번을 바꾸지 않는다. 모든 열린 별의 좌표·순번·버전은 NOT NULL이며 한 계정에 구 방사형/구 은하 배치 버전을 섞지 않는다. generation/angle_deg/radius_jitter는 nullable 폐기 예정 열로 두되 신규 계산/조회에 쓰지 않는다. 실제 저장 열/제약 마이그레이션은 135번(C04-2), 배치 함수·초기 좌표 준비는 136번(C05-1), 발견 트랜잭션 연결은 139번(C07)·144번(C11)에서 수행한다. V1 checksum을 바꾸지 않고 후속 마이그레이션으로 적용한다.

### 1.3 프론트 연출과 카메라

표현 버전 personal-galaxy-v1의 appearance는 저장 x/y와 layoutOrdinal만으로 색과 기준 크기를 계산한다. 중심은 따뜻한 금빛, 외곽은 푸른빛/일부 보랏빛을 사용한다. 배열 순서·페이지 번호·현재 적재 수·진행/성과/행성 수는 입력이 아니다. 페이지 재정렬·추가 발견·상태 갱신으로 같은 별의 연출이 바뀌지 않는다. 색은 실제 온도/분광형이나 행성 수를 의미하지 않는다. 선택 강조는 테두리/광량 변화로 하되 행성 수에 따른 재색칠을 하지 않는다.

지도에는 별과 필요한 튜토리얼/챌린지 마커만 그린다. 별 이름은 호버/키보드 포커스/선택 때 표시한다. 행성 수·완료·성과·등급은 상세/목록의 문자와 개수로 보여 주고 호버/포커스 정보도 같은 의미를 쓴다. 지도 타일에 없는 등급 등은 본인 상세 조회 후 표시하며 추정하지 않는다. 마커 숨김·튜토리얼 순차 열림은 기존 규칙을 유지한다. 범례는 연출과 정보의 구분·마커·조작을 설명하며 행성 수별 색상표를 제공하지 않는다.

화면 투영은 reference.mjs의 project를 비교 기준으로 삼는다. 깊이 환산을 셰이더·CPU 투영·히트 테스트·뷰포트 역투영 모두에 동일하게 적용한다. 데스크톱 기본 yaw=0.12, tilt=1.0, roll=-0.28 라디안이며 축척=min(캔버스 폭/3100,높이/2020)×zoom이다. 기울기는 ±1.42, 줌은 0.001~10000의 유한 범위다. 물리적 우주 비행이나 무한 정밀도를 주장하지 않는다. 전체 보기는 실제 저장 경계를 투영한 범위를 여백과 함께 담으며 새 별 수에 맞춰 월드 좌표를 재배치하지 않는다. 회전/기울기/줌은 카메라 상태다.

원본 별 셰이더의 작은 코어와 약한 발광을 유지한다. 캡처 기준 DPR=1, 캔버스 1440×836이다. 원본의 가우스 코어(exp(-d×22)+exp(-d×4.5)×0.22), 본체 강도 0.88, 별도 발광 강도 0.048/크기 8배를 출발값으로 쓰며 최종 비교는 같은 카메라·DPR·데이터로 한다. GPU별 미세 픽셀 차이는 허용하지만 중앙 밀도·팔의 방향/폭·전체 색감·개별 별 선명도를 임의로 바꾸지 않는다. 검증 방법과 원본 해시는 재현 자료를 따른다.

원본처럼 드래그 회전·기울기와 팬·휠 확대/축소·전체 보기를 모두 제공한다. 기본 드래그는 회전, 이동 모드 또는 Shift+드래그/우클릭 드래그는 팬이다. 조작 안내와 키보드 경로를 함께 제공하고, 드래그 종료를 별 클릭으로 처리하지 않는다. SRS의 과거 ‘선택적 회전’은 이 시각 기준 채택으로 제공 범위에 포함된다.

### 1.4 조회·상세·성능 경계

모든 배율에서 실제 발견 TIC 각각을 독립된 점/별 본체로 렌더링한다. 성운·구름·대표 노드로 합치지 않고 고정 개수 예산을 맞추려고 생략하지 않는다. 페이지 크기는 화면 표시 개수 상한이 아니다. 표현 상세도는 점 크기·광량·마커 등만 조절한다. 은하 전체 보기에서는 궤도/행성 인스턴스가 0개이며 별을 선택한 근접 뷰에서만 해당 회원의 planets.items 전부를 표시한다.

서버의 월드 타일·공간 인덱스·변경 영역 캐시는 유지한다. 뷰포트 각 변에 20% 여백을 둔 화면 직사각형(폭/높이 1.4배)을 깊이 [-1,1] 전체를 포함해 역투영하고 월드 bbox를 요청한다. 정규화 깊이를 월드 z로 바꾸는 같은 256 배율을 사용해 기울어진 화면 가장자리의 별을 누락시키지 않는다. 서버 요청 범위/페이지/버전·재시도는 탐사 API 4.1절을 따른다.

부분 적재/실패는 정상 영역과 카메라·선택을 보존하고 재시도를 제공한다. 전체 발견 수·적재 수·가시 수를 구분하며 메타·타일·상세의 version이 다르면 최신 상태로 다시 받는다. 로그아웃/회원 전환에는 캐시를 격리한다. 구 representation·누락된 표현/배치 버전은 빈 지도로 위장하지 않는다.

GPU 일괄 그리기·화면 밖 컬링·변경 사건 단위 공간 인덱스 갱신·DOM/버퍼 재사용을 적용한다. 10만 별 시드의 가시 페이지가 모두 적재된 후 p95≤16.7ms, 최악≤33ms, 첫 실제 별 표시≤2초, 힙≤300MB를 실제 브라우저에서 검증한다. 시드 전체에 내 행성 항목 5,000개를 분산하되 전체 지도에서 5,000개 궤도를 동시에 그리는 시험은 하지 않는다. 선택 장면에서 0/1/4개 초과 행성 및 가장 많은 행성의 별을 검증한다. 시각/기능·페이지 계약·최종 성능은 서로 다른 인수다.

## 2. 첫 방문 안내와 사용법 다시 보기

| 구분 | 첫 방문 안내 | 사용법 다시 보기 | 튜토리얼 별 5개 |
|---|---|---|---|
| 화면 | 실제 별 선택·분석 조작 위 말풍선 | 마이페이지에서 여는 GIF+텍스트 안내 | 서로 다른 5개 별을 순차 탐색 |
| 종료 | 1번 별 첫 제출 성공 또는 안내 닫기 성공 | 언제든 닫기 | 서버가 각 별 완료/건너뛰기를 인정 |
| 상태 | onboardingDone은 true로만 변경 | 완료 상태·진행 기록 변경 없음 | tutorialCompleted 및 각 별의 진행 |

서비스 API `PATCH /api/v1/me/settings`의 `onboardingDone=true`만 허용하는 계약을 유지한다. false/null은 400이며 true 재요청은 같은 결과다. 안내 닫기와 SUB-12의 튜토리얼 별 건너뛰기는 다른 동작이다. 최초 안내 완료 저장 실패는 재노출될 수 있는 기존 규칙을 따른다.

다시 보기는 매번 1단계에서 열고 현재 단계/총 5단계·이전·다음·닫기를 제공한다. 마지막은 [닫기]이며 제출/보상 버튼처럼 표현하지 않는다. GIF는 실제 서비스 조작을 설명하는 자료이고 기록을 만들지 않는다.

| 순서 | GIF가 보여줄 행동 | 같이 읽을 설명 |
|---|---|---|
| 1 별 선택 | 열린 튜토리얼 별 선택 후 분석 진입 | 먼저 열린 별을 고른다 |
| 2 봉우리 | 주기도의 봉우리 선택과 접힌 곡선 변화 | 반복되는 감광 주기를 찾는다 |
| 3 구간 | 접힌 곡선의 감광 구간 시작·끝 지정 | 밝기가 줄어든 범위를 고른다 |
| 4 판단 | 행성 같음/아님/모르겠음과 근거 선택 | 신호에 대한 자신의 판단을 남긴다 |
| 5 제출 | 입력 검토·제출·결과 항목 확인 | 탐색 완료와 성과 인정은 서로 다르다 |

GIF가 로드되지 않아도 단계 제목·텍스트·이전/다음/닫기는 사용할 수 있게 한다. 모션 줄이기 환경에서는 정지 프레임과 텍스트로 제공한다. 기록 변경 없이 닫아 마이페이지로 돌아온다. 5단계 열람만으로 튜토리얼 완료나 별 발견을 표시하지 않는다.

하서진은 안내 화면·단계 이동·에셋 연결을 맡고 백지웅은 분석 화면의 실제 조작과 GIF/문구가 맞는지 검토한다. 이번 MR은 내용/계약 명세이며 실제 GIF 제작이나 화면 구현 완료가 아니다. 검증은 SRS AT-86·119와 최초 안내의 분석 연결을 각각 수행한다.

## 3. 같은 은하 캔버스에서 내 행성으로 확대

별 선택 → 해당 별 근접 뷰(내 행성 공전) → 행성/목록 선택 → 해당 행성 확대·정보 표시 순서다. 별 선택 전에 카메라 위치·회전·기울기·배율을 보관한다. [별 전체 보기]는 선택 별과 그 별의 내 행성을 담고, [은하로 돌아가기] 또는 빈 하늘 클릭은 선택을 해제하며 원래 지도 카메라로 돌아간다. 별도의 분석 페이지나 외부 NASA 뷰어로 이동하는 동작이 아니다.

### 표시 대상과 데이터

`GET /api/v1/me/stars/{ticId}`의 `planets.items`만 렌더링한다. 인증 회원+해당 TIC로 제한하고 candidateId로 중복을 제거한다. 표시 수는 성과 인정 수와 다르다. 미확정의 표시 판단은 탐사 API 6.3절의 후보별 최신 판단 재계산 규칙을 사용한다. 과거에 행성 같음으로 판단했어도 최신 판단이 아님/모르겠음이면 현재 행성 표시에 포함하지 않는다.

| 내 매칭 신호 | 표시 | 성과와의 차이 |
|---|---|---|
| 확정 행성 | 포함 | 판단이 틀려 성과 미인정이어도 표시 |
| 미확정 + 행성 같음 | 포함 | 공개 분석/성과 인정 전이어도 표시 |
| FP | 제외 | FP 성과가 인정되어도 행성으로 그리지 않음 |
| 미확정 + 아님/모르겠음 | 제외 | 탐색 완료 여부와 별개 |
| 아직 못 맞춘 신호·다른 회원의 발견 | 제외 | 전체 후보표/외부 카탈로그로 채우지 않음 |

후보 배열은 candidateId의 문자열 오름차순으로 안정 정렬하고, 화면 공전 슬롯과 목록은 candidateId를 키로 유지한다. 기존 candidateId·kind·periodDays·depthPpm으로 객체/목록/확대 대상을 연결하고 식별자·종류·반복 주기(일)·감광 깊이를 표시한다. ppm→%는 10000으로 나눈다. 한 번 받은 전체 items를 행성 선택에도 사용하여 새 행성 API는 필요하지 않다. 행성 목록과 근접 뷰에 4개 상한을 두지 않는다.

별의 TIC·관측 회차·밝기 등급·발견 경로·진행 상태, 분석/결과/스레드 링크는 유지한다. 외부 이름·질량·행성 반지름·실제 궤도 거리 등 현재 계약에 없는 값은 필수로 요구하거나 임의 값으로 표시하지 않는다. null 수치는 "정보 없음"으로 표시한다.

3D의 행성 색/표면·크기·궤도 간격·공전 속도는 서비스 연출이다. 실제 관측 사진·NASA 제공 이미지·정확한 물리 축척으로 표기하지 않는다. 화면에 "표면과 궤도는 이해를 돕기 위한 시각화입니다"를 제공하고 같은 candidateId의 연출 외형은 재접속 때 바뀌지 않도록 한다. 실제 데이터 수치와 연출 값을 별도로 관리한다.

### 상태·접근성·렌더링

- 0개: 별만 표시하고 "아직 표시할 내 행성이 없어요". 완료된 별도 행성이 실제로 없다고 단정하지 않는다.
- 로딩/실패: 임의 행성을 채우지 않는다. 데이터 대기/재시도와 은하 복귀를 제공한다. 빠른 별 변경 시 이전 별의 늦은 응답을 무시한다.
- count/items 불일치·중복 ID: 계약 오류로 처리하고 가짜 행성을 만들어 수를 맞추지 않는다.
- WebGL 미지원·렌더러 실패: 동일한 행성 목록과 정보·분석 이동을 제공한다. 모션 줄이기에서는 공전을 멈추고 즉시 카메라 전환하되 데이터 접근은 같다.
- 마우스 호버 외에 탭/엔터로 행성 목록과 복귀 조작에 접근한다. 전체 지도는 위 개별 별·가시 타일·실측 예산 계약을 따르고, 상세 3D는 선택 별 하나에만 적용한다.

### 검증 분담

하서진: 근접 뷰·공전/확대·목록·정보·복귀·빈/실패/접근성 상태. 강재민: 개인/TIC 범위·중복 제거·표시 조건·수치/개수 일치. 백승학: 기존 완료 설정과 공개·성과가 이 조회에 미치는 영향 교차 검토. 분석·결과 페이지 구현은 백지웅 담당을 유지한다. 수용 검증은 SRS AT-120~122이며 NFR-20/AT-71의 기존 성능 목표를 낮추지 않는다.

## 4. 이 문서 MR과 후속 구현 구분

이번 MR은 SRS·API·ERD·상태표·와이어프레임의 변경안이다. 런타임·운영 DB·실제 계정·배포를 변경하지 않는다. 병합 전 관련 제공자/소비자의 교차 리뷰를 받고, 후속 구현에서 은하 배치 함수/상수·저장 열·초기 좌표 생성·서버 공간 인덱스/페이지 조회·API 응답·GIF 에셋·행성 렌더링을 적용하고 AT를 실행한다. 문서 정적 확인과 와이어프레임 렌더 확인을 제품의 기능·성능 검증 완료로 대체하지 않는다.
