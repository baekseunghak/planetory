## 1. 은하 형태를 유지하는 새 별 배치

### 요구사항과 역할

- 별은 회원이 발견한 실제 TIC만 표시한다. 적은 별로 은하가 성기게 보이는 것은 허용하며 가짜 발견 별을 채워 넣지 않는다.
- 보상 대상 TIC은 기존 OPS-08대로 선택한다. 선택한 TIC을 화면 어디에 놓을지는 별도의 은하 배치 함수가 결정한다.
- 중앙부의 밀도, 여러 나선 팔을 따르는 위치, 팔이 흐트러지지 않는 제한된 분산으로 현재 은하 시각 방향을 유지한다. 배치의 제한된 난수는 허용하되 화면 전체 균일 무작위 분포는 사용하지 않는다.
- 부모 별 바깥/부모 각도/다음 세대 반지름 조건은 해제한다. 부모 TIC·원인 성과·발견 경로는 기존대로 기록한다.
- 서버가 발견 트랜잭션 안에서 한 번 계산하고 `world_x, world_y, depth_z, layout_version`을 저장한다. API는 `x, y, depthZ`로 전달한다. x/y는 천문학적 RA/Dec가 아닌 서비스 표현용 월드 좌표이고, `depth_z`/`depthZ`는 천문학적 거리나 x/y 단위가 아닌 -1.0 이상 1.0 이하의 단위 없는 정규화 깊이다.
- 프론트는 저장 좌표에 카메라 이동·회전·기울기·배율만 적용한다. 화면 크기/현재 별 수 변화로 전체 자리를 다시 만들지 않는다.

### 계산 구현이 지켜야 할 조건

회원과 신규 발견 기록을 구분하는 안정된 시드/순번을 사용하고 알고리즘·상수 세트를 배치 버전으로 고정한다. 난수 호출마다 또는 브라우저 진입마다 배치를 새로 생성하지 않는다. 서버의 회원별 발견 직렬화·중복 방지 규칙은 탐사 API 9.2절을 따른다.

배치 함수는 중앙부/나선 팔의 후보 자리를 계산하고 근접 여부를 공간 인덱스로 확인한다. 혼잡하면 신규 별의 후보 반경/팔 내 위치를 제한된 횟수로 조정한다. 기존 별 이동, 전 별 순회, 무제한 재시도 또는 좌표 없는 발견 확정을 사용하지 않는다. 실패 시 발견 트랜잭션을 원자적으로 롤백한다. 수식·상수·재시도 상한과 혼잡 시 처리의 구체값은 후속 배치 구현에 코드/예제로 남기고 10만 별 검증을 통과해야 한다. 이는 시각 방향을 다시 결정하는 것이 아니라 그 방향을 구현하는 작업이다.

기존 은하 PoC는 시각 참고 자료이며 종전 방사형 `placeStar` 함수를 그대로 운영에 쓰라는 뜻이 아니다. 자리의 동일성 범위는 `(user_id, tic_id)`다. 같은 회원의 같은 TIC는 전체 지도·타일·위치 찾기·별 상세·근접 뷰·새로고침·재접속·다른 기기에서 StarUnlock에 저장된 동일한 `world_x`·`world_y`·`depth_z`를 사용한다. 회원이 다르면 같은 TIC의 자리가 달라도 되며, 공개 스레드와 별 식별은 자리와 무관하게 `tic_id`로 연결한다.

### 초기 좌표 생성과 호환

ERD v1.2의 `world_x`·`world_y`·`layout_version` 추가는 백엔드 구현 변경 대상이다. 현재 보존해야 할 운영 좌표 데이터가 없으므로 종전 방사형 좌표를 복원·유지하는 이관은 하지 않는다. 출시 전 개발·테스트 행은 초기화하거나 모든 열린 별의 좌표를 현행 은하 배치 함수로 다시 생성한 뒤 좌표 열의 NOT NULL과 `depth_z` 범위 제약을 적용한다. 이 일회성 준비는 v1.2 최초 제공 전에만 수행하며 서비스 시작 뒤 저장된 좌표에는 적용하지 않는다.

모든 계정의 열린 별은 하나의 현행 `layout_version`과 은하 배치 규칙을 사용한다. 한 회원 응답에 방사형 좌표와 은하형 좌표 또는 서로 다른 배치 버전을 섞지 않는다. 기존 `generation`·`angle_deg`·`radius_jitter`는 nullable 폐기 예정 열로 남아 있을 수 있지만 신규 좌표 계산과 API 응답에는 사용하지 않으며, 열 제거는 별도 백엔드 스키마 정리에서 처리한다.

### 개별 별 표현과 데이터 로딩 (v1.3)

모든 배율에서 실제 발견 TIC 각각의 저장 좌표를 렌더링한다. 여러 별을 성운·구름·대표 노드 하나로 대체하지 않는다. 멀리서 작은 점으로 보여도 각 별은 독립된 데이터/렌더 인스턴스다. 작은 발광 효과는 허용하지만 은하 팔과 별들을 흐린 덩어리로 덮지 않도록 AT-123에서 확인한다. 기존 0.8/46px 군집, 최소 5단계 군집 트리, 군집 호버 구성/클릭 확대를 제거한다.

서버 월드 타일·공간 인덱스는 유지한다. 새 발견/진행 상태 변경 시 해당 위치의 인덱스·타일 캐시와 회원 지도 버전을 갱신한다. 프론트는 뷰포트+20% 역투영 bbox로 개별 별 타일을 받고 큰 응답은 cursor 페이지로 받는다. 메타에는 군집 overview나 전체 별 목록을 싣지 않는다. 범위/페이지·회원·버전 격리와 재시도는 탐사 API 4.1절을 따른다. 최대 축소로 전체 은하가 가시 범위가 되면 그 범위의 별 전체가 순차 적재될 수 있으며 이를 단일 전체 목록 요청과 구분한다.

표현 LOD는 점/별 본체·광량·궤도·배지의 상세도만 조절한다. 별 400·궤도 표시 별 60·성운 80의 고정 상한은 제거한다. 숫자를 맞추려고 별을 누락시키지 않는다. 가시 별 GPU 인스턴싱, 화면 밖 컬링, 이벤트 단위 인덱스 갱신, DOM/버퍼 재사용은 유지한다. 웹 워커는 투영·히트 테스트를 보조할 수 있다. 구체 예산은 성능 실측으로 정하며 데이터 페이지 크기를 화면 별 수 상한으로 해석하지 않는다. 선택 별 하나의 내 행성은 모두 보여준다.

로딩 도중에는 적재 중임을 알리고, 일부 실패는 정상 영역·선택·카메라를 유지한 채 재시도를 제공한다. 전체 발견 수, 현재 적재 수, 실제 가시 수를 구분한다. 첫 실제 별 표시와 전체 가시 범위 적재 완료는 별도 측정한다. NFR-20/AT-71의 p95·최악 프레임·첫 표시·힙 목표를 임의 완화하지 않는다. 작은 시드 비교는 10만 별 성능 인수 근거가 아니다.

### 구현 인수 기준

- 1·10·100·1,000·100,000개 계정에서 반환 TIC/별 수가 일치하며 다수 별은 중앙부·나선 팔 구조를 보인다.
- n개에서 n+1개로 늘어도 기존 n개의 저장 좌표가 같고 새로고침·재접속에서도 같다.
- 부모보다 안쪽에 놓이는 경우도 허용하고 발견 원인 관계는 유지한다.
- 중복/동시 성과와 좌표 할당 실패를 확인하고, 초기화된 개발·테스트 계정에 방사형 좌표가 남거나 서로 다른 `layout_version`이 섞이지 않는지 검증한다.
- NFR-20/AT-71 성능 기준은 실제 구현 후 측정한다. 문서 리뷰만으로 통과했다고 기록하지 않는다.

## 2. 첫 방문 안내와 사용법 다시 보기

| 구분 | 첫 방문 안내 | 사용법 다시 보기 | 튜토리얼 별 5개 |
|---|---|---|---|
| 화면 | 실제 별 선택·분석 조작 위 말풍선 | 마이페이지에서 여는 GIF+텍스트 안내 | 서로 다른 5개 별을 순차 탐색 |
| 종료 | 1번 별 첫 제출 성공 또는 안내 닫기 성공 | 언제든 닫기 | 서버가 각 별 완료/건너뛰기를 인정 |
| 상태 | onboardingDone은 true로만 변경 | 완료 상태·진행 기록 변경 없음 | tutorialCompleted 및 각 별의 진행 |

서비스 API `PATCH /api/v1/me/settings`의 `onboardingDone=true`만 허용하는 계약을 유지한다. false/null은 400이며 true 재요청은 같은 결과다. 안내 닫기와 SUB-12의 튜토리얼 별 건너뛰기는 다른 동작이다. 최초 안내 완료 저장 실패는 재노출될 수 있는 기존 규칙을 따른다.

다시 보기는 매번 1단계에서 열고 현재 단계/총 5단계·이전·다음·닫기를 제공한다. 마지막은 [닫기]이며 제출/보상 버튼처럼 표현하지 않는다. GIF는 실제 서비스 조작을 설명하는 자료이고 기록을 만들지 않는다.

| 순서 | GIF가 보여줄 행동 | 같이 읽을 설명 |
|---|---|---|
| 1 별 선택 | 열린 튜토리얼 별 선택 후 분석 진입 | 먼저 열린 별을 고른다 |
| 2 봉우리 | 주기도의 봉우리 선택과 접힌 곡선 변화 | 반복되는 감광 주기를 찾는다 |
| 3 구간 | 접힌 곡선의 감광 구간 시작·끝 지정 | 밝기가 줄어든 범위를 고른다 |
| 4 판단 | 행성 같음/아님/모르겠음과 근거 선택 | 신호에 대한 자신의 판단을 남긴다 |
| 5 제출 | 입력 검토·제출·결과 항목 확인 | 탐색 완료와 성과 인정은 서로 다르다 |

GIF가 로드되지 않아도 단계 제목·텍스트·이전/다음/닫기는 사용할 수 있게 한다. 모션 줄이기 환경에서는 정지 프레임과 텍스트로 제공한다. 기록 변경 없이 닫아 마이페이지로 돌아온다. 5단계 열람만으로 튜토리얼 완료나 별 발견을 표시하지 않는다.

하서진은 안내 화면·단계 이동·에셋 연결을 맡고 백지웅은 분석 화면의 실제 조작과 GIF/문구가 맞는지 검토한다. 이번 MR은 내용/계약 명세이며 실제 GIF 제작이나 화면 구현 완료가 아니다. 검증은 SRS AT-86·119와 최초 안내의 분석 연결을 각각 수행한다.

## 3. 같은 은하 캔버스에서 내 행성으로 확대

별 선택 → 해당 별 근접 뷰(내 행성 공전) → 행성/목록 선택 → 해당 행성 확대·정보 표시 순서다. 별 선택 전에 카메라 위치·회전·기울기·배율을 보관한다. [별 전체 보기]는 선택 별과 그 별의 내 행성을 담고, [은하로 돌아가기] 또는 빈 하늘 클릭은 선택을 해제하며 원래 지도 카메라로 돌아간다. 별도의 분석 페이지나 외부 NASA 뷰어로 이동하는 동작이 아니다.

### 표시 대상과 데이터

`GET /api/v1/me/stars/{ticId}`의 `planets.items`만 렌더링한다. 인증 회원+해당 TIC로 제한하고 candidateId로 중복을 제거한다. 표시 수는 성과 인정 수와 다르다. 미확정의 표시 판단은 탐사 API 6.3절의 후보별 최신 판단 재계산 규칙을 사용한다. 과거에 행성 같음으로 판단했어도 최신 판단이 아님/모르겠음이면 현재 행성 표시에 포함하지 않는다.

| 내 매칭 신호 | 표시 | 성과와의 차이 |
|---|---|---|
| 확정 행성 | 포함 | 판단이 틀려 성과 미인정이어도 표시 |
| 미확정 + 행성 같음 | 포함 | 공개 분석/성과 인정 전이어도 표시 |
| FP | 제외 | FP 성과가 인정되어도 행성으로 그리지 않음 |
| 미확정 + 아님/모르겠음 | 제외 | 탐색 완료 여부와 별개 |
| 아직 못 맞춘 신호·다른 회원의 발견 | 제외 | 전체 후보표/외부 카탈로그로 채우지 않음 |

기존 candidateId·kind·periodDays·depthPpm으로 객체/목록/확대 대상을 연결하고 식별자·종류·반복 주기(일)·감광 깊이를 표시한다. ppm→%는 10000으로 나눈다. 한 번 받은 전체 items를 행성 선택에도 사용하여 새 행성 API는 필요하지 않다. 4개 이상 색 단계가 있어도 행성 목록과 근접 뷰를 4개로 자르지 않는다.

별의 TIC·관측 회차·밝기 등급·발견 경로·진행 상태, 분석/결과/스레드 링크는 유지한다. 외부 이름·질량·행성 반지름·실제 궤도 거리 등 현재 계약에 없는 값은 필수로 요구하거나 임의 값으로 표시하지 않는다. null 수치는 "정보 없음"으로 표시한다.

3D의 행성 색/표면·크기·궤도 간격·공전 속도는 서비스 연출이다. 실제 관측 사진·NASA 제공 이미지·정확한 물리 축척으로 표기하지 않는다. 화면에 "표면과 궤도는 이해를 돕기 위한 시각화입니다"를 제공하고 같은 candidateId의 연출 외형은 재접속 때 바뀌지 않도록 한다. 실제 데이터 수치와 연출 값을 별도로 관리한다.

### 상태·접근성·렌더링

- 0개: 별만 표시하고 "아직 표시할 내 행성이 없어요". 완료된 별도 행성이 실제로 없다고 단정하지 않는다.
- 로딩/실패: 임의 행성을 채우지 않는다. 데이터 대기/재시도와 은하 복귀를 제공한다. 빠른 별 변경 시 이전 별의 늦은 응답을 무시한다.
- count/items 불일치·중복 ID: 계약 오류로 처리하고 가짜 행성을 만들어 수를 맞추지 않는다.
- WebGL 미지원·렌더러 실패: 동일한 행성 목록과 정보·분석 이동을 제공한다. 모션 줄이기에서는 공전을 멈추고 즉시 카메라 전환하되 데이터 접근은 같다.
- 마우스 호버 외에 탭/엔터로 행성 목록과 복귀 조작에 접근한다. 전체 지도는 위 개별 별·가시 타일·실측 예산 계약을 따르고, 상세 3D는 선택 별 하나에만 적용한다.

### 검증 분담

하서진: 근접 뷰·공전/확대·목록·정보·복귀·빈/실패/접근성 상태. 강재민: 개인/TIC 범위·중복 제거·표시 조건·수치/개수 일치. 백승학: 기존 완료 설정과 공개·성과가 이 조회에 미치는 영향 교차 검토. 분석·결과 페이지 구현은 백지웅 담당을 유지한다. 수용 검증은 SRS AT-120~122이며 NFR-20/AT-71의 기존 성능 목표를 낮추지 않는다.

## 4. 이 문서 MR과 후속 구현 구분

이번 MR은 SRS·API·ERD·상태표·와이어프레임의 변경안이다. 런타임·운영 DB·실제 계정·배포를 변경하지 않는다. 병합 전 관련 제공자/소비자의 교차 리뷰를 받고, 후속 구현에서 은하 배치 함수/상수·저장 열·초기 좌표 생성·서버 공간 인덱스/페이지 조회·API 응답·GIF 에셋·행성 렌더링을 적용하고 AT를 실행한다. 문서 정적 확인과 와이어프레임 렌더 확인을 제품의 기능·성능 검증 완료로 대체하지 않는다.
