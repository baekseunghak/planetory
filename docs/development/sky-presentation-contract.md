# 별지도 표현 계약 v1.2 변경안

- 날짜: 2026-09-14
- 대표 Task: S15P21C206-33
- 근거: [요구사항 명세서](../requirements/planetory-requirements-spec.md), [탐사 API](../../apps/backend/docs/exploration-api-spec.md), [서비스 API](../../apps/backend/docs/service-api-spec.md), [ERD](database-erd.md).
- 상태: 지도 담당 하서진의 사용자 결정 반영안. API/저장 계약은 관련 담당자 교차 리뷰 후 적용한다. 이 문서는 서비스 코드·운영 DB·기존 사용자 데이터 변경이나 성능 검증 완료를 뜻하지 않는다.

## 1. 은하 형태를 유지하는 새 별 배치

### 요구사항과 역할

- 별은 회원이 발견한 실제 TIC만 표시한다. 적은 별로 은하가 성기게 보이는 것은 허용하며 가짜 발견 별을 채워 넣지 않는다.
- 보상 대상 TIC은 기존 OPS-08대로 선택한다. 선택한 TIC을 화면 어디에 놓을지는 별도의 은하 배치 함수가 결정한다.
- 중앙부의 밀도, 여러 나선 팔을 따르는 위치, 팔이 흐트러지지 않는 제한된 분산으로 현재 은하 시각 방향을 유지한다. 배치의 제한된 난수는 허용하되 화면 전체 균일 무작위 분포는 사용하지 않는다.
- 부모 별 바깥/부모 각도/다음 세대 반지름 조건은 해제한다. 부모 TIC·원인 성과·발견 경로는 기존대로 기록한다.
- 서버가 발견 트랜잭션 안에서 한 번 계산하고 `world_x, world_y, depth_z, layout_version`을 저장한다. API는 `x, y, depthZ`로 전달한다. 좌표는 천문학적 RA/Dec가 아닌 서비스 표현용 월드 좌표다.
- 프론트는 저장 좌표에 카메라 이동·회전·기울기·배율만 적용한다. 화면 크기/현재 별 수 변화로 전체 자리를 다시 만들지 않는다.

### 계산 구현이 지켜야 할 조건

회원과 신규 발견 기록을 구분하는 안정된 시드/순번을 사용하고 알고리즘·상수 세트를 배치 버전으로 고정한다. 난수 호출마다 또는 브라우저 진입마다 배치를 새로 생성하지 않는다. 서버의 회원별 발견 직렬화·중복 방지 규칙은 탐사 API 9.2절을 따른다.

배치 함수는 중앙부/나선 팔의 후보 자리를 계산하고 근접 여부를 공간 인덱스로 확인한다. 혼잡하면 신규 별의 후보 반경/팔 내 위치를 제한된 횟수로 조정한다. 기존 별 이동, 전 별 순회, 무제한 재시도 또는 좌표 없는 발견 확정을 사용하지 않는다. 실패 시 발견 트랜잭션을 원자적으로 롤백한다. 수식·상수·재시도 상한과 혼잡 시 처리의 구체값은 후속 배치 구현에 코드/예제로 남기고 10만 별 검증을 통과해야 한다. 이는 시각 방향을 다시 결정하는 것이 아니라 그 방향을 구현하는 작업이다.

기존 은하 PoC는 시각 참고 자료이며 종전 방사형 `placeStar` 함수를 그대로 운영에 쓰라는 뜻이 아니다. 선택한 별의 근접 뷰와 전체 지도는 동일 좌표 식별자를 공유한다.

### 저장·이관과 호환

ERD v1.2의 world_x/world_y/layout_version 추가는 백엔드 구현 변경 대상이다. 실제 이관은 기존 행을 만든 종전 알고리즘·설정으로 x/y를 정확히 복원하고 기존 depth_z와 함께 저장하여 화면상의 자리를 보존한다. 이전 값이 복원되지 않으면 임의 좌표를 만들지 않고 해당 이관을 실패 처리한다. 새 컬럼을 채운 뒤 NOT NULL을 적용하고 읽기 경로를 전환한다. 기존 generation/angle_deg/radius_jitter는 nullable 과거 메타로 보존하며 신규 자리를 계산하는 근거로 사용하지 않는다.

새 은하 배치는 신규 발견에 적용한다. 이미 저장된 방사형 지도를 한 번에 은하로 재배치하는 별도 일괄 작업은 이번 계약에 포함하지 않는다. 순수 은하 형태의 시각 검증은 새 계정 시드로 수행한다. 과거 데이터의 기존 위치 보존과 새 배치 적용을 서로 다른 검증으로 기록한다.

월드 좌표 타일, 군집/LOD 5단계 이상, 뷰포트+20% 역투영, WebGL 대체, NFR-20 및 AT-71의 성능 기준은 유지한다. 상세 행성 애니메이션은 선택된 별만 렌더링하여 전체 지도 별 수와 곱해 늘리지 않는다.

### 구현 인수 기준

- 1·10·100·1,000·100,000개 계정에서 반환 TIC/별 수가 일치하며 다수 별은 중앙부·나선 팔 구조를 보인다.
- n개에서 n+1개로 늘어도 기존 n개의 저장 좌표가 같고 새로고침·재접속에서도 같다.
- 부모보다 안쪽에 놓이는 경우도 허용하고 발견 원인 관계는 유지한다.
- 중복/동시 성과, 좌표 할당 실패, 과거 좌표 이관의 원자성과 재현성을 확인한다.
- NFR-20/AT-71 성능 기준은 실제 구현 후 측정한다. 문서 리뷰만으로 통과했다고 기록하지 않는다.

## 2. 첫 방문 안내와 사용법 다시 보기

| 구분 | 첫 방문 안내 | 사용법 다시 보기 | 튜토리얼 별 5개 |
|---|---|---|---|
| 화면 | 실제 별 선택·분석 조작 위 말풍선 | 마이페이지에서 여는 GIF+텍스트 안내 | 서로 다른 5개 별을 순차 탐색 |
| 종료 | 1번 별 첫 제출 성공 또는 안내 닫기 성공 | 언제든 닫기 | 서버가 각 별 완료/건너뛰기를 인정 |
| 상태 | onboardingDone은 true로만 변경 | 완료 상태·진행 기록 변경 없음 | tutorialCompleted 및 각 별의 진행 |

서비스 API `PATCH /api/v1/me/settings`의 `onboardingDone=true`만 허용하는 계약을 유지한다. false/null은 400이며 true 재요청은 같은 결과다. 안내 닫기와 SUB-12의 튜토리얼 별 건너뛰기는 다른 동작이다. 최초 안내 완료 저장 실패는 재노출될 수 있는 기존 규칙을 따른다.

다시 보기는 매번 1단계에서 열고 현재 단계/총 5단계·이전·다음·닫기를 제공한다. 마지막은 [닫기]이며 제출/보상 버튼처럼 표현하지 않는다. GIF는 실제 서비스 조작을 설명하는 자료이고 기록을 만들지 않는다.

| 순서 | GIF가 보여줄 행동 | 같이 읽을 설명 |
|---|---|---|
| 1 별 선택 | 열린 튜토리얼 별 선택 후 분석 진입 | 먼저 열린 별을 고른다 |
| 2 봉우리 | 주기도의 봉우리 선택과 접힌 곡선 변화 | 반복되는 감광 주기를 찾는다 |
| 3 구간 | 접힌 곡선의 감광 구간 시작·끝 지정 | 밝기가 줄어든 범위를 고른다 |
| 4 판단 | 행성 같음/아님/모르겠음과 근거 선택 | 신호에 대한 자신의 판단을 남긴다 |
| 5 제출 | 입력 검토·제출·결과 항목 확인 | 탐색 완료와 성과 인정은 서로 다르다 |

GIF가 로드되지 않아도 단계 제목·텍스트·이전/다음/닫기는 사용할 수 있게 한다. 모션 줄이기 환경에서는 정지 프레임과 텍스트로 제공한다. 기록 변경 없이 닫아 마이페이지로 돌아온다. 5단계 열람만으로 튜토리얼 완료나 별 발견을 표시하지 않는다.

하서진은 안내 화면·단계 이동·에셋 연결을 맡고 백지웅은 분석 화면의 실제 조작과 GIF/문구가 맞는지 검토한다. 이번 MR은 내용/계약 명세이며 실제 GIF 제작이나 화면 구현 완료가 아니다. 검증은 SRS AT-86·119와 최초 안내의 분석 연결을 각각 수행한다.
