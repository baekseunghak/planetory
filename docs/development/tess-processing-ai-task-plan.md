# 천문 데이터 처리·AI 후속 Task 계획

작성일: 2026-09-10 / 담당: 윤성용 / Jira: `S15P21C206-46` / 기준: 요구사항 명세서 v1.0, ERD v1.0, [역할 명세](tess-processing-ai-role-spec.md), [갭 분석](tess-pipeline-gap-analysis.md) 5.7·9절 / 상태: 팀 Epic 정리 전 제안

이 문서는 `S15P21C206-29` 기획에서 나온 천문 데이터 처리·AI 역할의 후속 Task 를 두 층으로 나누고 우선순위·선행 관계·Epic 묶음 제안을 정리한다. Epic 구조와 티켓 생성은 팀이 정하며, 여기 표는 그 입력이다.

## 1. 두 종류의 Task

명세서 v1.0 은 구조와 규칙은 확정했고 수치는 DEC 항목으로 비워 두었다. 그래서 Task 를 두 종류로 나눈다.

| 종류 | 하는 일 | 산출물 | 리뷰에서 보는 것 | 넘겨받는 사람 |
|---|---|---|---|---|
| 실험 | 고정 fixture 에 합성 신호를 심고 설정을 바꿔 비교해 수치와 근거를 낸다 | 비교표·제안값·문서 | 비교가 공정했는가, 제안값에 근거가 있는가 | 팀 (DEC 항목 결정) |
| 구현 | 결정된 값을 기본 설정으로 갖는 커널 코드와 fixture 회귀 테스트를 만든다 | 함수·테스트·계약 예시 데이터 | 테스트가 있는가, 계약대로 출력하는가 | 김동혁 (Spark 실행), 강재민·백지웅 (스키마 계약) |

실험 하나가 끝나면 대응하는 구현을 이어서 진행한다. 커널은 기존 PoC 처럼 Spark 의존성 없는 순수 함수로 유지한다.

## 5. 실험 Task

기간은 "예상 / 상한". 예상은 Claude 가 코드를 준비하고 담당자가 직접 실행·해석하는 시간, 상한은 리뷰 대기까지 포함한 목표다.

| # | P | Task | 예상 / 상한 | 선행 | 산출물 | 채우는 결정 | 함께 확인 |
|---|---|---|---|---|---|---|---|
| 1 | P1 | 42 전처리·detrending 벤치마크 | 2~3일 / 5일 | 41 | 품질 마스크·구간 분리·창 길이별 신호 보존·잡음 표, 기본값 제안 | 품질 bit 정책, detrending 방법·창 | 김동혁 |
| 2 | P1 | A. BLS 탐색 격자·품질 게이트 벤치마크 | 2~3일 / 5일 | 42 | 격자·period 범위·SDE/SNR 기준별 회수율·오검출·시간, 전체 탐색 대 사전 선별 | DEC-03 | 김동혁 |
| 3 | P1 | B. 반복 제거·제거 QA·고조파 병합 벤치마크 | 2~3일 / 5일 | A | 반복 종료 조건, 제거 QA 수치, P/2·2P 처리, 후보 동일성 허용 오차 | DEC-05·06, ERD 미결 2 | 강재민 |
| 4 | P1 | C. transit_model 스키마·잔차 모델 규약 | 1~2일 / 4일 | B | JSONB 필드·shape·residual_model_version, 고정 모델 제거 규칙 | 잔차 모델 계약 | 강재민 (공동) |
| 5 | P2 | D. 세그먼트·10분 비닝·discoverable 실측 | 2~3일 / 5일 | 42, B | 최단 통과 대비 bin 수, 봉우리 판정 기준, fixture 범위 무신호 별 비율 | DAT-07, ERD 미결 10, DEC-01 일부 | 강재민, 백지웅 |

| 8 | P2 | 43a AstroNet 평가 세트 구성·입력 변환 | 2일 / 4일 | 41 | PC/EB/junk 세트, TIC 단위 분리 근거, 201/61 입력 변환 결과 | - | - |
| 9 | P2 | 43b AstroNet 성능 평가·선별 기준 제안 | 2~3일 / 5일 | 43a | 단일 vs ensemble 지표, PC/EB 구분 대안, 라이선스 판단, 점수 분포 | DEC-02·04 | 팀 |

**Task 별 목적 (티켓 설명 첫 줄용)**

- 42: 품질 마스크·구간 분리·detrending 방법과 창 길이를 fixture 에서 비교해 서비스 전처리 기본값을 제안한다.
- A: 탐색용 BLS 의 격자·주기 범위·품질 게이트 기준을 회수율·오검출·시간으로 비교해 DEC-03 채택 임계값 후보를 제안한다.
- B: Silver 내부 반복 제거의 종료 조건·제거 QA 수치·고조파 병합·판 사이 후보 동일성 허용 오차를 실측한다.
- C: 후보표의 transit_model JSONB 필드·shape·모델 버전과 "고정 모델 제거" 잔차 규칙을 강재민과 확정한다.
- D: 별·섹터 세그먼트 10분 비닝이 최단 통과에 충분한지 실측하고, 제공 해상도 기준 discoverable 봉우리 판정 기준을 제안한다.
- E: 외부 카탈로그 실제 export 필드를 대조해 조인 키·스냅샷·매칭 허용 오차를 검증한다.
- F: Gold 배열 적재 예제를 만들고 같은 transit_model 로 Silver 와 EC2 잔차·주기도가 허용 오차 안에서 일치하는지 검증해 DEC-35 근거를 제공한다.
- 43a: AstroNet-Triage 평가용 PC/EB/junk 세트를 TIC 단위로 분리해 구성하고 Planetory BLS 후보를 모델 입력으로 변환한다.
- 43b: 단일 checkpoint 와 ensemble 의 재현율·정밀도·PR-AUC 를 측정해 잡음 후보 1차 선별 모델로서의 채택 여부와 기준 논의 자료를 만든다.

핵심 경로는 42 → A → B → C 다. 이 줄이 늦으면 강재민의 Candidate·transit_model API 계약이 밀린다. D·E·F·43a·43b 는 옆에서 병행한다. C·E·F 는 상대 일정에 따라 상한을 넘길 수 있고, 그 경우 다음 실험을 먼저 진행한다.

- 구현 2: A 에서 정한 격자·품질 게이트로 탐색 BLS 를 실행하고 후보 지표를 내는 함수를 만든다.
- 구현 3: B·C 규칙대로 반복 제거·고조파 병합·원본 재검증을 수행하고 후보표와 transit_model 을 생성한다.
- 구현 4: D 규칙대로 세그먼트 분할·비닝·binning_revision·discoverable 판정을 수행한다.
- 구현 5: E 계약대로 외부 카탈로그 스냅샷을 받아 후보와 조인한다.
- 구현 6: F 계약대로 세그먼트·주기도·후보표·manifest 를 직렬화하고 QA 를 통과시킨다.
- 구현 7: 43b 에서 채택된 모델의 입력 어댑터와 배치 추론을 만든다.
- 구현 8: 구현 1·2 커널을 Spark Worker 에서 실행하고 재처리 단위를 확인한다.

## 7. Task 명세 작성 규칙

- 형식: 목적 / 작업 범위 / 제외 범위 / 완료 조건 / 연결. 완료 조건은 "무엇이 어디에 있으면 끝"으로 확인 가능하게.
- 제목 접두: [데이터] [분석] [AI] [Spark].
- Task 하나 = 브랜치 하나 = MR 하나. 두 사람이 걸치면 "공동" 표기하고 담당은 한 명.
- 연결에 선행 Task 키와 요구사항·결정 ID(DAT-xx, DEC-xx, ERD 미결 n)를 적는다.
- 실험 스크립트는 실행하면 터미널에 진행 상황과 핵심 수치를 출력하고, 실행마다 manifest(`S15P21C206-41` 스키마)를 남긴다.
