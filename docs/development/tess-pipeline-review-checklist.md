## 명세 기준과 팀 결정 안건

기준은 [요구사항 명세서 v0.9](../requirements/planetory-requirements-spec.md)와 [팀 역할 분배](../team-role-allocation.md)다. 상태표 v0.11의 이전 규칙을 구현 근거로 사용하지 않는다.

### 이미 명세에 기록된 기준

- **최신 팀 합의:** 배치 단계별 잔차 곡선·주기도와 잔차 BLS Candidate를 생성하지 않는다. 사용자용 잔차·주기도는 후보 매칭 뒤 EC2에서만 요청 시 계산하며 Gold에 미리 저장하지 않는다.
- Gold에는 원본 정제곡선 전 점·품질 마스크, 원본 주기도, 후보별 transit model 파라미터와 관련 버전을 제공한다.
- Gold 후보 모델 검증 기준과 EC2 잔차 계산은 같은 `residual_model_version`을 사용하며 허용 오차 안의 일치를 검증해야 한다.
- DAT-15: 신규 TESS 곡선으로 후보가 추가되거나 `discoverable`이 false→true로 바뀌면 완료 별 재개 이벤트를 만든다. TCE/TOI 갱신은 v1에서 후보 상태 등을 갱신하며 기존 성과·등급·통계 스냅샷을 바꾸지 않는다.

### 확정으로 취급하면 안 되는 내용

- **확인된 문서 충돌:** SRS 전체 흐름·DAT-05~07에는 배치 자동 반복이, DAT-11에는 단계별 잔차 포함이 남아 있고 Jira 완료 조건도 반복 제거·종료를 요구한다. 최신 팀 합의에 맞춰 정합성 수정 담당자·반영 문서·리뷰 결과를 기록해야 한다.
- BLS 품질·매칭 임계값, 고조파 처리, 원본에서 평가할 peak 수, 온라인 잔차 모델, 대표 주기 정렬, AI 모델과 승인·보류 임계값 등의 초안 수치·선택은 근거와 합의 여부를 확인하기 전까지 제안/TBD로 표시한다.
- EC2 계산 위치, 캐시 저장소, 동시 실행 상한, 계산 시간 목표, Gold 용량과 세부 구현은 DEC-35의 별도 아키텍처 결정 범위다. 29번에서 과학적 계약과 검증 기준을 제안하되 단독 확정하지 않는다.

## 협업 규칙 적용

- [Git·Jira 컨벤션](../git-jira-convention.md): Jira가 작업 관리 기준이며 MR 리뷰 중에는 진행 중을 유지한다. 병합·인수 조건·결과물 등록이 모두 끝나야 완료다.
- 29번 산출물은 Jira 키 없는 일반 문서 예외가 아니다. [Docs MR 템플릿](../../.gitlab/merge_request_templates/Docs.md)을 사용하고 MR 설명에서 대표 Jira만 평문, 참고 Jira는 각각 백틱으로 표시한다.
- [데이터 관리 및 재현성](data-guidelines.md): 원본은 불변으로 유지하고 원본 데이터·대용량 결과·비밀정보는 Git에 넣지 않는다. 스키마와 재현 근거를 함께 기록한다.
- 사용자 요청에 따라 브랜치 전환·add·commit·pull·push는 사용자가 직접 수행한다. 이번 작업에서는 해당 명령과 환경 변경·PoC 실행을 하지 않았다.
