## 1. 목적과 작성 방법

회원·커뮤니티·통계 백엔드의 기능을 하나씩 검토하고, 구현할 조건과 제외할 조건을 결정한다. 기능명만 나열하지 않고 누가 어떤 상태에서 요청했는지, 무엇을 저장·공개하는지, 실패·중복·변경 시 어떤 결과를 보장하는지까지 정한다.

표기 규칙:

- **기준 확정:** SRS v1.0에 이미 명시된 정책. 다시 선택하지 않는다.
- **결정 질문:** 구현 전에 답해야 할 누락·모호함. 질문의 선택지는 확정 정책이 아니다.
- **충돌:** 기준 문장들을 동시에 적용하기 어려운 경우. 관련 담당자와 정리한다.
- **계약 초안:** API·데이터·이벤트에 담아야 할 의미. URL·응답은 제안이며 테이블은 ERD v1.0을 따른다. 메시지 제품 도입을 뜻하지 않는다.
- **검증 사례:** 결정 후 기대 결과까지 채워 인수 조건으로 사용한다. 미결정 사례는 현재 통과 조건이 아니다.

각 기능은 `기준 확인 → 결정 질문 답변 → 포함/제외 범위 확정 → 계약 작성 → 사례 검토 → 합의 완료` 순서로 진행한다. 결정 기록은 [공통 계약과 인수 조건](contracts-and-acceptance.md) 7장에 남기고 해당 기능에 반영한다. 적용 순서: SRS v1.0 → 팀 결정 → 담당자 제안(SB-D). SB-D 중 SRS와 다르거나 SRS 미결(DEC)을 채우는 항목은 **제안**이며, 팀 결정 전에는 확정하지 않는다(역할 분배 문서 5장). 제안은 명시한 항목에만 적용하며 미결정 사항은 합의 전 확정하지 않는다. 별도 보충 결정이 없는 상태표와의 충돌은 SRS를 따른다.

### 이번 작업의 범위

- 포함: 정책, 논리 데이터 관계, 권한, 상태 전이, API·이벤트·집계 계약, P0/P1 범위, 후속 MR 분해.
- 제외: OAuth/Spring Security 설정, DB 엔티티·API·Job 코드, 배포·메일 발송 환경, 프론트 구현.
- v1 제외 확정: 회원 차단, UserBlock, 차단 연동 자동 언팔로우, 순위·백분위.
- 도구 선택 별도: Swagger, Testcontainers, Jenkins/GitLab CI, 세션 Redis 사용, Outbox 구현 방식 등. 여기서는 해당 도구로 보장할 업무 조건을 먼저 정한다.
