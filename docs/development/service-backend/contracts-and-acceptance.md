## 4. 공통 권한·상태·데이터 계약

| 자원·행동 | 본인 인증 회원 | 다른 인증 회원 | 운영자 |
|---|---|---|---|
| 일반 글 수정/삭제 | 본인만, 별 변경 시 자료 재검증 | 불가 | 서비스 대리 수정 API 없음 |
| 공식 스레드 생성 | 본인 분석 공개 요청으로 유발 | 동일 | 운영자 로그인·수동 생성 조건 아님 |
| 공식 원글 수정/삭제 | 불가 | 불가 | DB 숨김/복원, 서비스 관리 API 없음 |
| 공개 분석 등록/취소/재공개 | 본인 History만, 운영 숨김 해제 불가 | 불가 | DB 개별 숨김/복원; 본인 취소 유지 |
| 유효 공개 분석·출처 열람 | 선택 공개 필드만 | 동일 | 업무상 비공개 열람 범위 별도 |
| 개인 History 원본 | 본인 가능 | 불가 | 권한 있는 운영자만 |
| 일반 Post 반응 | 본인 글 포함 가능 | 가능 | 동일 인증 조건; 공식 분석 자동 반응 없음 |
| 신고 | v1 미제공 | v1 미제공 | 관련 운영 API 없음 |
| 비공개 별 목록 | 본인 가능 | 불가 | 업무상 범위 미정 |

SYSTEM은 로그인 가능한 운영자 역할이 아니라 자동 생성의 처리 주체다. F22의 최초 유효 공개 요청에서만 공식 스레드 생성을 수행하며, SYSTEM 표기 자체가 숨김·복원·개인 History 열람 권한을 부여하지 않는다. 운영 변경은 DB 권한으로 제한하며 서비스 관리 API·감사 사건은 v1에 없다. 신고도 v1 제외다.

비인증은 로그인/콜백 외 보호 자원에 접근 불가. 401 재로그인·기본 403 안내는 SB-D03 유지, 존재 비노출 404 대상은 미정이다. 상위 스레드 숨김은 하위 직접 조회·검색·첨부·출처 카드에도 적용한다.

**논리 데이터 관계**
- users.provider/provider_user_id UNIQUE, users↔user_settings 1:1(P1); ERD 기준.
- TIC↔고유 신호↔공식 공간 1개; Bundle/고조파별로 공간을 나누지 않는다.
- 작성자+History↔공개 기록 1개. 새 제출은 별도 기록, 취소·재공개는 기존 재사용.
- 공개 기록은 본인 공개 여부·운영 숨김을 독립 보존, 상위 공간 상태와 함께 유효 공개 판정.
- 일반 Post/Comment의 본인 History 첨부와 공식 공개 등록 및 공개 출처 참조는 서로 다른 관계.
- 사용자×고유 신호 성과는 최초 한 번. 공개 최신 판단·누적 수치 매칭·완료 상태와 분리.
- History는 판정 당시 Bundle ID·절대값·제거 조합·viewport·버전을 기록하고 현재 판으로 재현. 재도전은 새 초안/새 제출로 처리.
- 팔로우·알림·스냅샷은 ERD 관계를 따르고 세부 계약만 합의. 신고·감사 테이블은 v1 제외.

**교차 검증:** 동일 공개 동시 요청, 숨김 직전 등록, 공개 취소와 운영 복원, 최신 분석 취소, 과거 제출 늦은 공개, 탈퇴 경합, 응답 유실, 일괄 일부 실패. 클라이언트 상태만 신뢰하지 않고 저장/조회 시 서버가 자격을 검사한다.

## 5. 도메인 간 계약 검토

이벤트 이름은 설명용이며 메시지 브로커 도입을 뜻하지 않는다.

| 계약 | 제공 → 소비 | 합의할 내용 |
|---|---|---|
| 공식 공개 등록·최초 인정 | 서비스 ↔ 탐사 | 회원/History/Submission/신호/TIC/Bundle, 공개 자격, 신호별 원자성, 최초 성과, 중복 처리 |
| 개별·일괄 공개 결과 | 서비스 → 프론트 | 항목별 성공/실패·공개 ID·최초 성과·재시도; 성공분 유지, 실패분만 재시도 |
| 공개 취소·숨김·복원 | 서비스·운영 → 공개 통계·조회 | 유효 공개 집합·제출 시각/id 재선택, 상위 차단, 기성과 유지 |
| 채점형 재제출 | 탐사 → 채점형 분포 | 첫 매칭 회원 집합·첫 판단 고정·성과 독립. 재제출로 채점형 일치율 변경 금지 |
| 튜토리얼 완료·건너뛰기 | 탐사 → 발견·챌린지 제공 | 다음 순번, 5개 완료 자격, 멱등 발견; skipped 성과 없음 |
| 별 재개 | 탐사 → 알림·퀘스트 | 번들·사유·대상·완료 복귀; 기존 성과 유지 |
| 외부 라벨 변경 | 데이터·탐사 → 서비스 | 표식·출처 유지, 기존 스레드/분석 보존, 성과/과거 스냅샷 유지 |
| 콘텐츠 변경 | 서비스·운영 → 출처·검색·알림 | 원본 및 상위 공개 상태, 캐시 차단; 링크가 원본을 복제 공개하지 않음 |
| 탈퇴 | 회원 → 연관 기능 | SB-D04의 작성 확정 순서, P1 보관 정책; 기존 확정 데이터와 신규 반영 구분 |

사건 ID·유형/버전·대상·발생 시각·원 요청 ID·대상 버전과 중복/실패/순서 역전 계약을 정한다. 최신 공개 판단 순서는 사건 도착 시각이나 공개 시각이 아니라 원 Submission 접수 시각/id이다.

## 적용 기준과 변경 이력

**2026-09-20 검색 정합화:** SRS·ERD v1.1에 따라 검색·핫 토픽은 P0이며, 핫 토픽 산식(SB-D16)은 DEC-09로 팀 확정했다. COM-03 범위 검색(SB-D24), 세션 로그인 확정, 브라우저별 챌린지 안내, 탈퇴 정책 보류는 보충 결정으로 유지한다. 현재 두 문서의 계약 초안은 구현·팀 승인 완료를 뜻하지 않는다.

| 결정·영역 | 현재 적용 | 이전 결정 처리 |
|---|---|---|
| SB-D01~03 회원 | 초기 제공자 연결 제외, 이메일 수정 미제공, 인증 401·권한 기본 403 | 유지, 404 대상·세션 세부 미정 |
| SB-D04·05 탈퇴 | DB 확정 순서 정책 유지, 데이터 정책 P1·API 시점 보류 | 탈퇴 선행 구현 강제 안 함 |
| SB-D05·06·09 신고·운영 | 신고·운영 화면/API·감사 v1 제외, hidden 접근 판정 P0 | 과거 신고 P1·운영 API P0 계획 대체 |
| SB-D07 실행 | 단일 Spring Boot 전제 유지. PostgreSQL Gold 배열·Redis 파생 캐시 반영 | 과거 Gold 파일/필수 공유 세션 전제 폐기. 인스턴스는 1개다. 세션은 2026-09-17 리뷰 반영으로 EC2-A `redis-session`에 두며(계산 캐시는 별도 `redis-cache`), 목적은 공유가 아니라 재시작 생존이다. `redis-session` 장애 시 인증은 503이고 `redis-cache` 장애는 인증에 영향이 없다([진입·장애 전환 경계](../../architecture/ec2-service-entry-failover.md) D10, 구현 `S15P21C206-237`) |
| SB-D08·10 검색 | **P0 확정(SRS v1.1):** 일반 글·공식 스레드 포함. 검색 세부는 SB-D24와 [170 공통 표본](../../api/community/README.md)으로 교차 검토 | P0 재승인 제외. 핫 토픽 세부는 SB-D16 적용 |
| SB-D11·14 로그인 | 세션·인증 요청 기준 30분·폴링 포함·현재 세션 로그아웃·다중 로그인 확정 | 5분 조작 갱신안 대체. 세션 저장소는 SB-D07에서 확정, 쿠키·CSRF 세부는 미정 |
| SB-D12 챌린지 | P0 브라우저별 회차 안내, P1 일반 알림 | 서버 확인 테이블/API 제안 폐기. 기기 간 1회 보장 없음 |
| ERD 정합화 | 공개 설정 P1, 수정 version 요구 없음, 부모+History 첨부 조회 | API·상세·요약에 함께 반영 |
| 성과·통계 | 성과당 별 발견, FP 상한 없음, 첫 매칭 채점형, 전체 10분·비교 일별 | 등급별 발견·성과 자격 최신 제출·전체 일별 계획 폐기 |
