# 제공 해상도 discoverable 판정 실험

Jira `S15P21C206-115` / 담당 윤성용. 상태: **9별 실측·검산 완료, 규칙 승인 전**.
운영 커널 123의 구현 완료나 Gold 게시 승인을 의미하지 않는다.

## 설계와 고정 입력

[114 비닝 규칙](../../contracts/gold/README.md#41-s15p21c206-114-비닝-운영-채택안)과
[113 모델 규약](../../libs/astro-kernel/README.md#d06113-결정-사항)을 적용한다.
Sector별 10분 mean, 제외점을 포함한 시간 범위, 빈 bin 보존, 중심 시각에서 모델 평가를 사용한다.
114 실험 함수를 참조하되 간격 자동 확대가 발생하면 중단한다. 123 브랜치의 미병합 커널에는 의존하지 않는다.

제공 격자는 ERD periodograms의 0.5일 시작·최소 40일 및 최장 후보 주기 포괄·로그 5,000점을 따른다.
탐색용 20,000점 결과로 제공 해상도의 판정을 대신하지 않는다. BLS duration 목록 1.2·1.92·2.88·4.8시간,
likelihood·global MAD 오차·oversample 10은 기존 120 계산을 재사용한다. 이 duration 목록의 제공용 적합성은 리뷰 대상이다.

9별 각각 realclean 무주입 1개와 등록된 쌍 주입 3개, 총 36곡선에서 122 `iterate_bls`를 실행한다.
이는 111에서 이관된 커널의 현재 후보를 만드는 실험이며 과거 111 CSV 자체의 재생은 아니다.
원본 SNR 재검증 실패 후보는 `candidate_invalid`/판정 null이다. 제거 QA 등으로 끝난 곡선의
`source_complete=false`와 종료 사유를 보존하므로, 남은 후보의 실험 결과만으로 해당 곡선의 게시를 허용하지 않는다.

각 후보를 검사할 때 원 제공 곡선에서 그 후보보다 먼저 채택한 모델만 나눈다.
후보 자신의 모델이나 나중 후보를 미리 제거하지 않는다. 원 주기도와 발견 직전 잔차·주기도를 저장한다.
2분 원본에서 모델을 먼저 제거한 뒤 비닝하는 방식과 구분한다.

## 판정 검토안 v1

설정 정본은 [discoverability_v1.json](../../experiments/tess-bench/configs/discoverability_v1.json)이다.
현재 `experimental_not_approved`이며 결과 확인 후 같은 버전의 설정을 변경하지 않는다.

1. 주기도 양옆보다 엄격히 높은 내부 국소 최대를 봉우리로 본다. 끝점·평탄 plateau는 제외한다.
2. 해당 봉우리의 SNR ≥ 7, SDE ≥ 6, 유한 관측점이 있는 통과 ≥ 2를 모두 요구한다.
3. 후보와 봉우리의 로그 주기 차이가 제공 격자 3칸 이내이고, 후보 주기로 순환한 epoch 차이가 두 duration 중 큰 값의 반폭 이내이면 일치로 본다.
4. 상위 N 추천 개수 제한과 고조파 추천 억제는 적용하지 않는다. 고조파 주기만으로 같은 후보라고 판정하지 않는다.
5. 입력 부족·MAD 0·계산 실패는 판정 null이며 정상 계산의 봉우리 기준 미달 false와 구분한다.

7·6은 기존 탐색 게이트에서 가져온 **검토 시작값**이지 제공 해상도에 최적임이 입증된 값이 아니다.
3칸·epoch 허용 폭·엄격한 국소 최대·직접 주기만 인정하는 정책도 이번 리뷰에서 검토한다.
결과에 근거해 변경하면 새 규칙 버전·새 실행이 필요하며 검증 표본 재사용 한계를 명시한다.

## 집계와 범위

`measurements.json`은 원본/후보 단계, 모델, 앞서 제거한 모델, 봉우리, 판정, 원본 후보 파일과 NPZ를 연결한다.
후보 발견률은 측정 가능한 후보와 실패를 별도로 집계한다. 무신호 표현은 물리적 신호 부재가 아니라
**현재 규칙의 품질 봉우리 없음**을 뜻한다.

주요 대조 비율은 realclean 무주입 원본의 `품질 봉우리 없음 / 정상 측정 곡선`이다.
분자·분모·전체 대조군 수를 함께 기록한다. Archive 행성을 제거한 realclean이므로 실제 별 전체의 무신호 비율이 아니다.
쌍 주입 곡선을 별 수에 더하지 않는다. 서비스 모집단 외삽·최종 오탐률 주장은 109 범위와도 구분한다.

## revision 재평가

실험 evaluation_revision은 입력·구현 checksum, 대상/그룹, 고정 설정과 실제 격자 끝으로 만든다.
실행 시각을 재료로 넣지 않으며 123 운영 binning_revision을 대신하지 않는다.
합성 사례는 seed 20260922, 10분·40일 곡선, 주기 2.731일·깊이 2,000ppm·duration 2.88시간,
백색 잡음 표준편차 500ppm이다. 동일 모델을 로그 64점과 5,000점으로 재평가한다.
64점은 감도 확인용으로 운영 채택 이력이 있는 격자가 아니다.

`revision-probe.json`에 실제 양쪽 판정과 false→true 목록을 남긴다. 전이가 없으면 해당 완료 근거는 미충족이다.
입력 실패 null, 새 후보, 은퇴 후보는 기존 후보의 false→true로 세지 않는다. 실제 후보 ID 동일성은 112/122 연결 책임이다.
이 실험은 회원별 알림·재개 트랜잭션을 실행하지 않는다.

## 실행과 검산

실제 실험은 사용자가 실행한다. 코드·설정은 실행 전에 커밋으로 보존하는 것을 권한다.
원본 FITS는 기존 fixture 위치를 사용하며 다운로드·Git subprocess를 실행하지 않는다.

```powershell
cd experiments/tess-bench
uv run --locked python -m tess_bench.discoverability --targets l98_59
uv run --locked python -m tess_bench.discoverability
```

첫 명령은 한 별 점검, 둘째는 전체 9별이다. 두 실행은 별도 폴더에 남긴다.
다른 FITS 위치는 `--raw <경로>`로 전달한다. 실행 전 plan을 고정하고 종료 직전 입력 변경을 검사한다.
실패 시 failure.json만 남기며 completed manifest를 만들지 않는다. manifest에 NPZ·후보표·집계·probe의 SHA-256을 기록한다.
결과는 Git 제외 `results/discoverability/run-*`에 저장한다.

검증: tess-bench 전체 **219 passed** 후 revision 기록 테스트 3개를 추가하여 신규 테스트 **16 passed**를 확인했다. 실제 FITS 실행·검산 결과는 아래 9별 실측 절에 기록한다.
실행 후 대상별 판정·실패·품질 봉우리 없음·revision 전이와 소형 검토 자료를 정리한다.
최종 봉우리/격자 기준의 승인 후 123에 운영 버전과 재평가 규칙을 이관한다.
