# 114 세그먼트·비닝 해상도 실험

담당: 윤성용 / Jira: S15P21C206-114 / 상태: 9별 실측·3차 화면 검토 완료, 운영 채택안 보완·처리 리뷰 재승인 대기.

## 목적과 경계

기본 10분 비닝에서 짧은 통과의 깊이·형태와 관측 공백이 얼마나 보존되는지 비교한다. 110 BLS 승인과 독립적인 실험이다. 전처리는 42의 `biweight_1.0d`를 그대로 재사용한다. 앞부분은 원 실행의 **실험 규칙**이며 상한 자동 확대를 포함한다. 아래 운영 채택안은 이를 구분하여 10분 평균·상한 초과 실패를 선택한다. 115 discoverable 판정, 123 운영 구현과 분리하며 MR !101 재승인 전 확정·구현 완료로 해석하지 않는다.

정본: [ERD](../architecture/database-erd.md)의 light_curve_segments, [Gold 계약](../../contracts/gold/README.md), [고정 모델 커널](../../libs/astro-kernel/README.md). 저장 시각은 bin 시작이고 모델 비교는 bin 중심이다. Gold의 빈 bin은 NULL, gaps는 인덱스 폐구간이다. 실험 NPZ의 NaN은 결측 표현일 뿐 게시 가능한 Gold 배열이 아니다.

## 실행 전에 고정하는 비교 설계

- 입력: 기존 9별의 23 FITS. 원천 checksum과 TIC/Sector를 검사한다. holdout 4별은 사용하지 않는다.
- 전처리: 기존 설정 파일의 `biweight_1.0d` 파라미터와 코드 checksum을 manifest에 기록한다. 전처리 구간 분리와 Gold의 별·Sector 세그먼트를 혼동하지 않는다.
- 비교: 2·5·10·20분 × 평균·중앙값. 2분도 재비닝 비교군이며 원본 배열과 같다고 가정하지 않는다.
- 실제 신호: 고정 `references.csv`의 통과 행성 period·epoch·duration. 비통과·기하 누락 행은 사유를 기록하고 제외한다. EB의 행성 참고값을 만들지 않는다. CM Dra는 곡선·합성 주입 비교에 포함한다.
- 합성 신호: 전처리 **후** 같은 곡선에 곱셈 box 주입. 주기 2일, 깊이 1,000ppm, 지속시간 0.5·0.8·2·8시간, Sector 첫 유효 관측+0.5일에 0·2.5·5·7.5분을 더한 epoch. 16사례이며 난수를 쓰지 않는다. 기존 41 주입 격자 1.1.0과 다른 **비닝 전용 격자**다.
- 주입 전후 곡선을 같은 bin으로 각각 집계하고 차이를 비교한다. 실제 별의 기존 통과·변동을 깊이 보존으로 잘못 세지 않도록 한 쌍의 변화량을 측정한다. 전처리 손실이나 BLS 회수율을 측정하는 실험이 아니다.
- 같은 점 집합의 평균은 `mean(injected) − mean(original) = mean(injected − original)`이지만 중앙값에는 이 선형성이 없다. 중앙값 쌍 차감은 통과 안·밖 점이 섞인 부분 bin에서 기존 변동과 집계의 상호작용을 포함하므로, 배경이 완전히 상쇄된 순수 비닝 효과라고 해석하지 않는다.
- 단계별 튜닝/독립 평가 구분을 주장하지 않는다. 9별은 이미 사용한 개발 fixture다. 결과 확인 후 설정 변경은 새 버전·재실행으로 구분한다.

## 비닝 후보 규칙과 지표

Sector의 첫 QUALITY/유한값 필터 통과 시각을 고정 anchor로 쓰고 `[시작, 끝)` bin을 만든다. detrending에서 제외된 점도 시간 범위에는 남겨 결측을 드러낸다. 부동소수점상 정확한 경계는 1e-8 bin 이내에서 정수로 맞춘다. 마지막 관측이 경계에 놓이면 다음 bin에 포함한다. 빈 bin은 보간하지 않고 연속 빈 인덱스를 `[start,end]`로 기록한다. 일부 점만 있는 bin도 집계하되 counts를 보존한다.

20,000점을 넘으면 요청 간격의 정수배 중 상한을 만족하는 최소 간격으로 확대한다. 요청·실제 간격을 모두 남긴다. 한 Sector를 관측 공백으로 쪼개 여러 Gold 행으로 만드는 방식은 쓰지 않는다. 산포 후보는 유한한 비닝 flux 전체의 `1.4826 × MAD`다. 식·변동이 포함되므로 순수 측정 오차 또는 통과 밖 잡음과 같다고 주장하지 않는다.

깊이는 `통과 밖 중앙값 − 통과 안 중앙값`이다. 안쪽은 순환 위상 거리 `< D/2`, 바깥은 `D ≤ 거리 < min(2D,P/2)`다. 안·밖 각각 최소 3점이 없으면 NaN/측정 불가로 남긴다. 분모인 원본 깊이가 양수가 아닌 경우도 비율을 만들지 않는다. 측정 불가를 깊이 0이나 성공으로 바꾸지 않는다. 점 수는 여러 통과를 합한 수이며 한 번의 통과 해상도는 `D×60 / 실제 bin_minutes`라는 명목 지표로 별도 기록한다.

실제 신호의 깊이 비율은 잡음·동반 행성 때문에 비닝만의 인과효과가 아니다. 합성 쌍 비교와 함께 해석한다. 짧은 신호는 bin 위치·평균/중앙값에 민감하다. 최댓값이나 전체 중앙값 하나로 채택하지 않고 별·Sector·지속시간·epoch offset별로 확인한다. 사후 임의의 합격 문턱을 만들지 않는다.

`binning_revision`은 실험 접두 `bin-exp-v1-`와 원천·구현 checksum 및 전처리/집계/간격/상한 규칙의 정렬 JSON hash로 만든다. 입력·규칙 변경은 다른 revision이 되며 재실행 시각은 넣지 않는다. 운영 버전 명명·채택은 123 인계 때 별도 검토한다.

## 실행

Git Bash, 저장소 루트에서 필요한 입력을 먼저 받는다. 실험은 사용자가 실행한다.

```bash
cd experiments/tess-fixture
uv sync --locked --python 3.11
uv run --locked python -m tess_fixture download --target wasp62 --target toi451 --target pi_men
cd ../tess-bench
uv sync --locked --python 3.11
uv run --locked python -m tess_bench.binning --check-inputs
uv run --locked python -m tess_bench.binning --target l98_59
```

1별 결과와 시간을 확인한 후 전체 실행:

```bash
uv run --locked python -m tess_bench.binning
```

L 98-59는 전체 실행에 다시 포함되고 결과 폴더는 별도로 생성된다. 전체 실행 시간은 실제 측정 전 미정이다. 승인 대기인 111 코드를 합치거나 BLS를 실행할 필요가 없다. 실측 전 코드·설정을 커밋하여 manifest의 dirty 상태를 없앤다.

산출물은 `experiments/tess-bench/results/binning/run-<UTC>-<id>/` 아래에 생성한다.

| 파일 | 내용 |
| --- | --- |
| segments.csv | 별·Sector·8가지 설정의 범위, 실제 간격, 원본/잔존/빈 점 수, 산포, gaps, revision, 전처리 실패 |
| metrics.csv | 실제 신호·주입 16사례의 깊이·비율·통과 안/밖 점 수·측정 가능 여부 |
| *.npz | 원본 전처리 시각/flux, bin 중심/flux/counts. 로컬 생성물, Git 제외 |
| *.svg | 기본 10분 평균/중앙값의 실제 신호 및 0.5/0.8시간 주입(offset 0) 접힌 곡선. 위상순 최대 1,500점씩 미리보기이며 수치는 전 점으로 계산 |
| skipped-references.json | 참고값 제외 사유 |
| manifest.json | 원천·참고값·설정·코드·환경, 실행 명령·시간, 모든 출력 checksum |

진행은 별별 소요 시간으로 출력된다. 중도 실패 폴더는 완성 manifest가 없으며 완료 실행으로 세지 않는다. SVG는 위상별 점을 이어 붙이지 않아 공백을 곡선으로 메우지 않는다. 세로 범위는 개별 그림 기준이므로 그림 간 절대 깊이는 CSV 수치와 함께 비교한다.

SVG 선택 조건은 현재 코드에 고정돼 있으며 설정과 자동 연동되지 않는다. `binning_v1.json`의 `bin_minutes`·`duration_hours`·`epoch_offset_minutes`를 변경할 때는 `binning.py`의 10분·0.5/0.8시간·`offset0.0` 조건도 함께 확인하고 예상 SVG 수를 검사한다. 10분을 빼면 SVG가 없고, 해당 지속시간이나 offset 표현을 바꾸면 주입 SVG가 빠질 수 있다. 특히 JSON의 `0.0`을 정수 `0`으로 바꾸면 현재 문자열 매칭에 걸리지 않는다. 기본 설정 테스트의 SVG 존재 검사는 변경된 격자까지 보장하지 않는다. 이번 리뷰 반영은 이 제약을 문서화하며, plot 설정 분리·수치 offset 비교·격자 변경 테스트는 후속 개선 항목으로 남긴다.

중앙값 집계 열에는 앞서 설명한 비선형 쌍 차감의 배경 상호작용도 포함된다. 평균과 중앙값의 차이를 순수한 비닝 희석량 차이로만 해석하지 않는다.

재집계는 `tess-bench` Python 환경에서 아래와 같이 원 NPZ를 읽는다(작업 디렉터리 `experiments/tess-bench`). 기존 그림 ZIP에는 원 NPZ가 포함되지 않으므로 이 재집계에는 원 실행 디렉터리가 필요하다.

```python
import csv, hashlib, json
from pathlib import Path
import numpy as np

p = Path("results/binning/run-20260919T120741Z-84d4cc93")
m = json.loads((p / "manifest.json").read_text(encoding="utf-8"))
expected = {Path(x["path"]).name: x["sha256"] for x in m["outputs"]}
groups = {}
assert hashlib.sha256((p / "segments.csv").read_bytes()).hexdigest() == expected["segments.csv"]
with (p / "segments.csv").open(encoding="utf-8", newline="") as stream:
    for row in csv.DictReader(stream):
        if float(row["requested_minutes"]) != 10 or row["reducer"] != "mean":
            continue
        file = p / row["array_file"]
        assert hashlib.sha256(file.read_bytes()).hexdigest() == expected[file.name]
        with np.load(file, allow_pickle=False) as data:
            counts = data["counts"]
        histogram = np.array([(counts == k).sum() for k in range(1, 5)] + [(counts >= 5).sum()])
        groups[row["target"]] = groups.get(row["target"], np.zeros(5, dtype=int)) + histogram
groups["total"] = sum(groups.values())
for target, values in groups.items():
    print(target, values.tolist(), values.sum(), (100 * values / values.sum()).tolist())
```

**부분 bin 결정:** 모든 비어 있지 않은 bin을 유지하고 counts는 배치 진단에만 보존한다. 점 수 기각 기준의 이득을 측정하지 않았으므로 임의의 NULL 문턱을 새로 만들지 않는다. 1점 bin도 관측된 flux이며, 이를 정상 5점 bin과 같은 오차로 주장하지 않는다. Gold의 목적은 관측된 평균 곡선·모델 비교이고 점별 오차 추정 계약은 아니다. counts 없이 오차 가중치나 신뢰구간을 복원하는 사용은 허용하지 않는다는 한계를 함께 인계한다. 이 선택은 기존 mean 계산을 바꾸지 않아 원 결과를 재사용할 수 있다.

**산포 결정:** 유한 비닝 flux 전체의 1.4826 × MAD를 세그먼트 robust 산포로 선택한다. 통과·별 변동 포함이며 측정 오차 대표값으로 부르지 않는다. `qa-tolerances.v0.json`의 수치 허용 오차는 `pending-measurement` 그대로다.
