### HDU와 컬럼: 공식 형식과 현재 사용 범위

HDU는 FITS 파일 안에서 헤더와 데이터를 묶는 단위다. 공식 예제의 LC는 PRIMARY(0), LIGHTCURVE 이진 표(1), APERTURE 이미지(2)로 구성된다. APERTURE는 측광에 사용한 픽셀 등의 정보를 담고 있으며 시간별 밝기 표와 다르다. [MAST LC 읽기 문서](https://spacetelescope.github.io/mast_notebooks/notebooks/TESS/beginner_how_to_use_lc/beginner_how_to_use_lc.html)

| 위치·필드 | 공식 형식·의미 | 기존 PoC / 운영 Bronze |
|---|---|---|
| HDU 0 PRIMARY | 파일 메타데이터 | TICID·SECTOR 읽음 |
| HDU 1 LIGHTCURVE | 관측 시각별 데이터 표 | `hdul[1].data` 사용 |
| TIME | 64-bit 실수, BJD−2457000 기준의 day | 기존 PoC는 float64만 전달. Bronze는 float64 배열과 TIMESYS·BJDREFI·BJDREFF·TIMEUNIT·TIMEDEL을 함께 보존 |
| PDCSAP_FLUX | 32-bit 실수, 보정된 밝기, e-/s | Bronze에서 float64 배열과 원천 단위를 보존. 정규화하지 않음 |
| QUALITY | 32-bit 정수, 관측 품질 비트 플래그 | Bronze에서 int64 배열을 필터 없이 보존. 기존 `clean`의 QUALITY=0 필터는 후속 처리 규칙 |
| PDCSAP_FLUX_ERR | 32-bit 실수, 보정 밝기 오차, e-/s | Bronze에서 float64 배열로 보존 |
| SAP_FLUX / SAP_FLUX_ERR | 32-bit 실수, 단순 개구 측광 밝기·오차, e-/s | 현재 로더에서 읽지 않음 |
| CADENCENO | 32-bit 정수, 관측 cadence 번호 | Bronze에서 int64 배열로 보존 |
| HDU 2 APERTURE | 측광 픽셀 정보 이미지 | 현재 로더에서 읽지 않음 |

컬럼 타입·단위의 근거는 위 MAST 공식 예제다. 실제 제품은 컬럼 정의와 헤더로 재확인해야 한다. PDCSAP은 이미 계통 효과를 보정한 광도곡선이므로 여기서 '원천'은 우리 파이프라인에 들어오는 원본 제품이라는 뜻이다. 검출기에서 직접 얻은 미처리 픽셀 데이터와 동일하지 않다. [MAST 제품 구조·보정 설명](https://spacetelescope.github.io/mast_notebooks/notebooks/TESS/beginner_tour_lc_tp/beginner_tour_lc_tp.html)

### 서비스 입력 계약과 남은 확인

- **구현:** TIC·Sector뿐 아니라 전체 제품명, Raw bundle·offset, PROCVER, 원본 SHA-256과 파일별 snapshot을 Bronze에 보존한다.
- **구현:** TIME을 그대로 보존하면서 TIMESYS·BJDREFI·BJDREFF·TIMEUNIT·TIMEDEL과 flux 단위를 기록한다. 필수 헤더·열·단위가 누락되거나 지원 계약과 다르면 제품 오류로 격리하고 Sector final을 만들지 않는다.
- **제안:** 원천 PDCSAP_FLUX의 e-/s와 전처리 후 정규화된 상대 flux를 별도 필드·단위로 구분한다.
- **구현:** PDCSAP_FLUX_ERR·CADENCENO는 Bronze에 보존한다. 후속 활용 범위와 품질 비트 선택 정책은 여전히 TBD다. QUALITY=0은 기존 PoC 구현 사실이며 서비스 확정 정책이 아니다. 공식 예제도 모든 품질 비트를 무조건 제외할 필요는 없다고 설명한다.
- **실제 파일 확인:** Sector 3·4·5 모두 아래 기록으로 확인했다. BLS 재계산은 실행하지 않았다.

### Sector 3 파일 구조 확인

기존 `download_toi270.py`의 `PRODUCTS[0]`과 `download_product`를 사용해 공식 MAST 제품 하나만 받았다. 파일은 Git 제외 경로인 `experiments/tess-bls/sample_raw/tess/toi270/`에 있다. Python 3.11.9와 Astropy FITS reader로 읽었으며 패키지 설치나 PoC 환경 변경은 하지 않았다. 이 확인은 전체 PoC 실행 검증이 아니다.

| 확인 항목 | 실제 값 |
|---|---|
| 파일 | `tess2018263035959-s0003-0000000259377017-0123-s_lc.fits` |
| 크기 | 1,998,720 bytes |
| TICID / SECTOR | 259377017 / 3 |
| CAMERA / CCD | 3 / 4 |
| PROCVER / DATA_REL | `spoc-5.0.20-20201120` / 42 |
| HDU 구성 | PRIMARY / LIGHTCURVE / APERTURE |
| LIGHTCURVE | 19,692행 × 20컬럼. TIME·PDCSAP_FLUX·QUALITY 등 위 표의 컬럼·타입·단위 확인 |
| APERTURE | 11 × 11, int32 |
| TIMESYS / TIMEREF | TDB / SOLARSYSTEM |
| BJDREFI / BJDREFF / TIMEUNIT | 2457000 / 0.0 / d |
| TIMEDEL | 0.001388888888888889일 = 120초. 헤더상 cadence이며 관측 공백이 없다는 뜻은 아님 |
| TIME의 NaN / Inf | 280 / 0 |
| PDCSAP_FLUX의 NaN / Inf | 6,709 / 0 |

첫 행(0-based index 0)은 TIME=1382.0358510192934, PDCSAP_FLUX=NaN, QUALITY=136이다. NaN은 밝기 0이 아니라 값이 비어 있음을 뜻한다. QUALITY 값은 비트 조합이며 여기서는 개별 비트 원인까지 판정하지 않았다. 12,974행은 품질·유한값 조건을 확인한 수이며 detrending·clipping까지 마친 최종 정제 행 수가 아니다. 시간·밝기의 NaN은 같은 행에 겹칠 수 있으므로 개수를 단순 합산해 제외 행 수로 사용하지 않는다.

## 5.2 전처리 첫 단계 — 품질·결측 필터 확인

2026-09-07에 세 FITS를 읽고 `pipeline.py`의 `clean` 첫 필터 식을 동일하게 적용했다. 코드·원본 파일을 변경하지 않고 메모리에서 집계했으며, 정규화·detrending·clipping·BLS는 실행하지 않았다.

```python
df = df[df["quality"] == 0].dropna(subset=["flux", "time"])
```

`quality`는 FITS의 QUALITY, `flux`는 PDCSAP_FLUX, `time`은 TIME을 읽은 값이다. 먼저 QUALITY=0인 행을 남긴 뒤, 그중 시간 또는 밝기가 NaN인 행을 제외한다. 같은 행을 두 번 제외한 것으로 세지 않도록 아래 수치는 순서대로 집계했다.

| 단계 | Sector 3 | Sector 4 | Sector 5 | 합계 |
|---|---:|---:|---:|---:|
| 원본 행 수 | 19,692 | 18,684 | 18,944 | 57,320 |
| QUALITY≠0으로 제외 | 6,718 | 2,278 | 1,809 | 10,805 |
| 품질 필터 후 남음 | 12,974 | 16,406 | 17,135 | 46,515 |
| 남은 행 중 시간·밝기 결측으로 추가 제외 | 0 | 1,962 | 0 | 1,962 |
| 두 조건 적용 후 남음 | 12,974 | 14,444 | 17,135 | 44,553 |

Sector 4의 원본 1699번 행(0-based index)은 QUALITY=0이지만 TIME과 PDCSAP_FLUX가 모두 NaN이었다. 이는 품질 필터와 결측 필터를 별도로 적용해야 하는 실제 예다. Sector 3·5의 추가 제외가 0이라는 것은 원본에 결측이 없다는 뜻이 아니라, 이 파일에서는 품질 필터를 통과한 행에 결측이 없다는 뜻이다.

### 품질 필터 비교 준비

현재 PoC의 `QUALITY=0`을 비교 기준 A로 둔다. 비교 기준 B는 MAST 문서가 낮은 품질일 가능성이 높은 시작점으로 제시한 비트 1·2·3·4·5·6·8·10·13·15를 제외하는 마스크다. 이 비트의 합산 마스크 값은 21183이다. 기준 B는 공식적인 Planetory 확정 정책이 아니며, 다른 과학 목적에는 다른 선택이 필요할 수 있다.

두 기준 모두 TIME과 PDCSAP_FLUX가 유한한 행에서 비교했다.

| Sector | A: QUALITY=0 | B: 선택 비트 제외 | B에서 추가로 남는 점 |
|---|---:|---:|---:|
| 3 | 12,974 | 12,983 | 9 |
| 4 | 14,444 | 14,444 | 0 |
| 5 | 17,135 | 17,135 | 0 |
| 합계 | 44,553 | 44,562 | 9 |

추가된 9점은 모두 Sector 3의 QUALITY=8192(비트 14, Planet Search Exclude)다. Sector 4·5에서 유한값을 가진 비영(0이 아닌) 품질 행은 각각 1개·3개였고 모두 QUALITY=512(비트 10, cotrending 전 제거된 순간 이상치)이어서 기준 B에서도 제외된다.

이 결과만으로 기준 B를 선택하지 않는다. 다음 후속 실험에서는 8192의 9점이 어느 시각에 있고 감광 구간·관측 공백·BLS 결과와 어떤 관계가 있는지 확인한다. 동일한 정규화·구간 분리·디트렌딩 설정에서 A와 B만 바꾸어 관측점 유지, 감광 보존, 잡음과 오검출을 비교한다. 비교 결과와 데이터 범위를 기록한 뒤 품질 정책을 결정한다.

2026-09-07 위치 확인 결과, 이 9점은 원본 행 2809~2817에 2분 간격으로 연속되어 있고 TIME 1385.937327~1385.948438(약 18분 범위)에 있다. 파일의 첫 TIME 1382.035851부터 약 3.901일 동안 PDCSAP_FLUX가 유효하지 않은 구간이 이어진 뒤 나타나는 첫 유효 flux 묶음이며, 바로 다음 2818번 행부터 QUALITY=0이다. 따라서 곡선 내부에 고립된 9점이 아니라 사용 가능 구간의 시작 경계로 해석한다.

다음 QUALITY=0 구간 99점의 중앙값은 9404.824 e-/s, MAD 기반 robust scatter는 약 11.289 e-/s였다. 9점은 이 중앙값에서 약 -2.11~+1.34 robust scatter 범위에 있어 밝기만 보면 극단적인 이상치로 보이지 않는다. 다만 이 국소 비교는 독립적인 정상성 검정이나 포함 승인 기준이 아니다.

기존 QUALITY=0 정제곡선으로 계산한 BLS에서 알려진 세 주기의 가장 가까운 격자점과 비교했을 때, 9점은 해당 BLS 상자 감광 구간 안에 들지 않았다. 가장 가까운 감광 중심과도 약 28시간 이상 떨어졌다. 이는 외부 천체력으로 검증한 결과가 아니라 해당 데이터와 기존 PoC 설정으로 얻은 내부 기준이며, 9점이 다른 신호·계통 오차에 무관하다는 뜻은 아니다.

현재 판단은 **보류**다. 9점은 관측점 확보 효과가 매우 작고 구간 시작 경계에 있으므로, 포함 여부는 다른 대상·Sector의 QUALITY=8192 사례와 경계 왜곡 및 BLS 오검출 비교까지 수행한 뒤 결정한다. 이 확인 결과로 서비스 품질 정책을 확정하지 않는다.

확인 범위와 후속 결정:

- 현재 코드는 필터 뒤 전체 입력이 기본 500점 미만이면 `too_few_points`를 반환한다. 로더는 세 Sector를 합쳐 `clean`에 전달하므로 이 조건을 Sector별 최소 500점 기준으로 해석하지 않는다. 이번 집계의 44,553점은 이 수량 기준 이상이다.
- `dropna`는 무한대(Inf)를 제외하는 검사가 아니다. 이번 세 파일에서 해당 두 컬럼의 Inf는 없었지만, 서비스 유한값 검증 도입 여부는 별도 제안으로 유지한다.
- QUALITY=0 사용은 기존 구현 사실이다. 허용 품질 비트와 최소 관측점 수를 서비스 확정 기준으로 승인한 것은 아니다.
- 이 단계에서는 밝기가 낮다는 이유로 관측점을 제외하지 않는다. 파일에서 행을 삭제한 것도 아니며, 분석용 메모리 표에서 사용할 행을 골랐다.
- 원본 인덱스·원래 QUALITY·제외 사유를 보존하는 서비스 계약은 여전히 필요하다. 기존 `clean`의 최종 반환은 정제된 배열과 요약 통계이며 이 단계별 제외 내역을 반환하지 않는다.

## 5.3 전처리 두 번째 단계 — Sector별 중앙값 정규화

2026-09-07에 5.2절과 동일한 품질·결측 필터 후, 기존 `clean`의 Sector별 시간 정렬·중앙값 계산·나눗셈을 메모리에서 수행했다. 원본 FITS와 과학 처리 코드는 변경하지 않았다. 아래는 기존 구현의 동작 확인이며 서비스 최종 정책 승인이 아니다.

계산식: `normalized_flux = PDCSAP_FLUX / 해당 Sector의 필터 후 flux 중앙값`. 원천 flux와 중앙값의 단위는 e-/s이며, 나눈 결과는 단위 없는 상대 밝기다. 세 Sector 전체의 공통 중앙값으로 나누지 않는다.

| Sector | 사용 행 수 | 원천 flux 중앙값(e-/s) | 정규화 후 중앙값 |
|---|---:|---:|---:|
| 3 | 12,974 | 9406.927734375 | 1.0 |
| 4 | 14,444 | 9555.7783203125 | 1.0 |
| 5 | 17,135 | 9547.08203125 | 1.0 |

각 중앙값은 유한한 양수여서 기존 코드의 정규화 조건을 통과했다. 결과 44,553개 값은 모두 유한하며, 이 단계에서 관측점을 추가로 제외하지 않았다.

| Sector / 원본 행 번호(0-based) | 원래 밝기(e-/s) | 정규화 밝기(반올림) |
|---|---:|---:|
| 3 / 2818 | 9416.251953125 | 1.000991208 |
| 3 / 2819 | 9389.62890625 | 0.998161054 |
| 4 / 1 | 9556.5673828125 | 1.000082574 |

예를 들어 Sector 3의 2819번 행은 자기 Sector의 중앙값보다 약 0.184% 낮다. 이 한 점을 행성 감광으로 판정한 것은 아니다. 정규화는 밝기 척도를 맞추는 과정이며 완만한 추세·잡음을 제거하거나 실제 신호 보존을 검증한 결과가 아니다.

재현 순서: 기존 Python 3.11.9/Astropy 환경에서 FITS를 readonly로 열기 → TIME·PDCSAP_FLUX를 float64, QUALITY를 int64로 읽기 → QUALITY=0 필터와 시간·flux dropna → Sector별 시간 정렬 → `np.median(flux)`가 유한하고 양수인지 확인 → flux를 중앙값으로 나누기 → 결과 중앙값·유한값·행 수 확인. 전체 정규화 배열은 별도 저장하지 않았고 요약과 예시만 이 문서에 기록했다. detrending·clipping·BLS·전체 테스트는 이번 단계에서 실행하지 않았다.

## 5.4 전처리 세 번째 단계 — Sector 경계와 관측 공백 분리

2026-09-07에 5.2절의 QUALITY=0·결측 필터를 통과한 시간축을 Sector별로 정렬하고 인접 시각 차이를 계산했다. 정규화·detrending·clipping·BLS는 이번 검사에서 다시 실행하지 않았다.

기존 `_segments`는 전체 결합 시간축에서 인접 시각 차이가 기본 0.5일보다 큰 곳을 경계로 삼는다. Sector 번호를 직접 확인하지 않는다. 이번 TOI-270 샘플에서는 Sector 사이의 간격도 0.5일보다 커서 결과적으로 서로 섞이지 않았다.

| 구분 | 시간 간격 | 기존 0.5일 기준 결과 |
|---|---:|---|
| Sector 3 내부 | 1394.618035 → 1396.641676, 약 2.024일 | 분리 |
| Sector 3 → 4 | 약 4.689일 | 분리 |
| Sector 4 내부 | 1418.489126 → 1421.215522, 약 2.726일 | 분리 |

| Sector 5 내부 | 1450.076492 → 1451.557027, 약 1.481일 | 분리 |

|---|---:|---|

이번 샘플의 큰 공백은 모두 1.48일보다 크므로 공백 기준을 0.25일·0.5일·1.0일로 바꿔도 같은 7개 구간이 나온다. 따라서 이 샘플만으로 0.5일이 최적이라는 결론을 낼 수 없다.

**서비스 설계 제안:** `(tic_id, sector, product_id)`로 먼저 나눈 뒤, 각 그룹 안에서 시간 정렬·중복 검사를 수행하고 내부 공백 기준으로 다시 연속 구간을 나눈다. Sector가 바뀌면 실제 시간 간격이 짧거나 일부 시간이 겹치더라도 같은 detrending 구간으로 합치지 않는다. Sector·카메라·CCD와 처리 조건이 달라질 수 있기 때문이다.

구간 메타데이터에는 `segment_id`, Sector, 첫·마지막 시각, 관측점 수, 앞선 공백 길이와 분리 사유(`sector_boundary`, `time_gap` 등)를 기록하는 안을 제안한다. 원본 행과 시각을 삭제하거나 이어 붙이지 않는다.

TBD는 공백 기준값, 너무 짧은 구간의 최소 관측점·시간 범위, 짧은 구간의 중앙값 처리 또는 보류 방식이다. 비교 실험에서는 0.5일을 기존 기준으로 두고 다른 대상에서 공백 분포를 조사한 뒤 후보 기준을 정한다. 구간 경계 주변에 합성 감광을 주입해 깊이·지속시간 왜곡과 가짜 변화를 비교한다.

## 5.5 전처리 네 번째 단계 — 디트렌딩 설계

작성일: 2026-09-07. 상태: **윤성용 검토 전 제안, 팀 미승인**. 목표는 별의 완만한 변화와 장비 계통 추세를 줄이되 수 시간 규모의 감광 깊이·지속시간·중심 시각을 보존하는 것이다. 보기 좋은 평탄한 곡선만 만드는 것을 성공으로 보지 않는다.

### 기존 PoC 동작과 실제 적용

현재 `clean`은 Sector별 중앙값 정규화 후 모든 관측점을 시간순으로 합치고, 0.5일 초과 공백에서 구간을 나눈다. 전체 시간축의 중앙 cadence로 2일에 해당하는 홀수 창 길이를 계산해 각 구간에 2차 Savitzky–Golay 필터를 적용한다. 구간이 창보다 짧으면 그 구간의 중앙값 하나를 trend로 사용한다. `detrended_flux = normalized_flux / trend`를 계산한 뒤, 전체 곡선의 MAD 기반 scatter보다 위쪽으로 5배 이상 큰 점만 제외한다.

TOI-270 세 Sector의 cadence는 약 2분이고 기존 2일 창은 1,441점이다. 7개 구간 중 Sector 4의 두 번째 구간은 771점·약 1.074일이어서 Savitzky–Golay 대신 중앙값으로 처리된다. 나머지 6개 구간에는 2일 창을 적용할 수 있다.

| 창 후보 | 점 개수 | Savitzky–Golay 적용 구간 | 중앙값 대체 구간 | 실제 곡선의 MAD 잡음(ppm) | 상방 5-sigma 제외점 |
|---|---:|---:|---:|---:|---:|
| 1일 | 721 | 7 | 0 | 약 1,344 | 3 |
| 2일(현재) | 1,441 | 6 | 1 | 약 1,355 | 2 |
| 4일 | 2,881 | 6 | 1 | 약 1,346 | 3 |

위 잡음과 제외점 차이는 매우 작고, 실제 감광이 얼마나 보존됐는지를 측정하지 않았으므로 어느 창이 더 좋다는 근거가 되지 않는다. 2일 실행에서 총 44,553점 중 2점이 상방 clipping으로 제외되어 [6절](validation-and-reprocessing.md)에 기록한 최종 44,551점과 일치한다.

### 서비스 처리안 제안

1. 5.4절처럼 Sector·제품 경계를 먼저 분리하고 각 Sector 내부의 연속 구간별로 trend를 계산한다.
2. Savitzky–Golay 2차 필터를 기존 비교 기준으로 유지한다. 1·2·4일 창은 초기 비교 후보일 뿐 최종 선택값이 아니다.
3. DAT-02에 따라 창 길이는 예상 최대 감광 지속시간의 3배 이상이어야 한다. 현재 PoC의 BLS 지속시간 범위는 0.5~8시간이며 후보 창과 최대 지속시간의 비율을 실행 설정에 기록한다. 3배보다 큰 실제 창과 최대 감광 지속시간은 주입 실험으로 정한다.
4. 구간이 창보다 짧을 때 중앙값으로 조용히 대체하지 않는다. `detrend_method=segment_median`, 사용 창, 구간 길이와 fallback 사유를 기록한다. 너무 짧아 검증할 수 없는 구간은 보류하는 대안도 비교한다.
5. trend가 NaN·Inf·0 이하이면 해당 구간을 성공 결과로 내보내지 않고 실패 사유를 기록한다. 나눗셈 결과도 유한값인지 확인한다.
6. 디트렌딩과 이상치 처리를 별도 단계로 기록한다. 상방 clipping은 우주선·플레어성 밝아짐의 영향을 줄이는 비교 기준으로 유지하고, 감광을 지울 수 있는 하방 clipping은 자동으로 추가하지 않는다.
7. 결과에는 각 점의 원본 위치, segment_id, normalized_flux, trend, cleaned_flux, 처리 방법·설정 버전과 제외 사유를 연결한다. trend의 Gold 제공 여부는 별도 데이터 계약에서 결정한다.

### 신호 보존 비교 실험안

실제 곡선의 모양만 보고 최적 창을 선택하지 않는다. 같은 입력 곡선에 알려진 감광 신호를 전처리 전에 넣고, 정답과 처리 후 회수값을 비교한다.

| 바꿀 조건 | 초기 후보 제안 | 측정 결과 |
|---|---|---|
| 감광 지속시간 | 0.5·1·2·4·8시간 | 회수 깊이 비율, 지속시간·중심 시각 오차 |
| 감광 깊이 | 얕음·중간·깊음의 최소 3수준. 구체 ppm은 실제 대상 범위 확인 후 고정 | 깊이별 보존율과 BLS 회수 여부 |
| 위치 | 긴 구간 중앙, 공백 직전·직후, Sector 시작·끝, 짧은 구간 | 경계별 왜곡과 실패 여부 |
| 디트렌딩 | Savitzky–Golay 1·2·4일, 짧은 구간 중앙값/보류 | 감광 보존, 감광 밖 robust scatter, 처리 가능 구간 |
| 신호 모양 | PoC와 같은 box를 기준으로 시작하고 경사가 있는 합성 transit 추가 | 단순 상자 신호에만 맞춘 선택인지 확인 |

한 번에 창·품질 마스크·공백 기준을 함께 바꾸지 않는다. 우선 5.2~5.4절의 기준을 고정하고 디트렌딩 조건만 비교한다. 설정 선택용 TIC와 최종 평가용 TIC를 분리하며, 동일 TIC의 Sector가 양쪽에 섞여 결과가 낙관적으로 보이지 않게 한다.

### 1차 주입 실험 결과

2026-09-07에 위 설계의 위험을 먼저 확인하는 소규모 실험을 수행했다. QUALITY=0·유한값 필터와 Sector 중앙값 정규화를 고정하고, 7개 연속 구간 각각의 시작·중앙·끝에 0.5·1·2·4·8시간 box 감광을 곱했다. 깊이는 1,000ppm과 5,000ppm, 창은 1·2·4일을 사용해 총 630조건을 비교했다. 원본 FITS·코드·정규화 배열은 변경하거나 저장하지 않았다.

처리하지 않은 동일 곡선도 같은 방식으로 디트렌딩한 뒤, 주입 곡선과의 비율로 회수 깊이를 측정했다. 이 방식은 실제 별의 기존 밝기 변동이 측정값에 섞이는 영향을 줄이기 위한 1차 비교다.

| 창 | 전체 조건 깊이 보존율 최솟값 | 중앙값 | 최댓값 |

| 2일 | 24.0% | 82.6% | 99.7% |

| 0.5시간 | 95.3% | 97.7% | 98.8% |

### 2단계 디트렌딩 비교안

1차 결과를 바탕으로 탐색용과 후보 정밀화용 처리를 구분해 비교하는 안을 추가한다.

- **1차 탐색 곡선:** transit 위치를 모르는 상태에서 2일·4일 Savitzky–Golay와 이상치에 덜 민감한 대안을 비교한다. 동일 BLS 설정으로 주입 주기 회수율과 오검출을 평가한다. 새 라이브러리 도입은 대안의 효과가 확인된 뒤 검토한다.
- **후보 정밀화 곡선:** 1차 BLS가 제시한 주기·중심·지속시간 주변을 trend 계산에서 임시 제외하고, 주변 비감광 점으로 trend를 다시 계산한 뒤 원본 정규화 flux에 적용한다. 이 곡선으로 깊이·지속시간을 다시 측정한다.
- **마스크 오차 검증:** 정답 위치를 그대로 사용하는 실험만으로 평가하지 않는다. 후보 중심과 지속시간을 의도적으로 어긋나게 하고, 부분 마스킹·겹친 후보·구간 경계·관측점 부족에서 결과가 어떻게 실패하는지 기록한다.
- **정밀화 제한:** 후보마다 결과가 유리해지도록 무제한 재적합하지 않는다. 정밀화 횟수·허용 범위·사용한 모델 버전을 고정하고 원본 정제곡선에서 최종 재검증한다. 승인된 transit model은 Silver 내부 반복 BLS의 제거 입력으로 사용하되, 제거 QA가 실패하면 이후 반복 후보를 공개하지 않고 직전 정상 단계로 복구한다.

이 안은 감광 위치를 미리 알아야 하는 마스킹을 최초 탐색에 사용할 수 없다는 점을 반영한다. 최초 탐색의 신호 보존과 후보가 생긴 뒤 파라미터 편향을 줄이는 문제를 별도로 검증한다.

통과 수치는 TBD다. 실험 착수 전에 최소 감광 깊이 보존율, 허용 지속시간·epoch 오차, 잡음 감소 또는 증가 허용 범위와 처리 실패 기준을 잠정 등록한다. 결과를 본 뒤 유리하게 기준을 바꾸면 변경 이유와 재평가 결과를 남긴다.
