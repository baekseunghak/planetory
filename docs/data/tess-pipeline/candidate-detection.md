## 5.6 BLS 후보 생성·품질 기준 설계 v0.1

작성일: 2026-09-07. 상태: **윤성용 검토 전 제안, 팀 미승인**. BLS는 주기적으로 반복되는 상자 모양의 감광을 period·epoch·duration·depth로 근사해 후보를 찾는 도구다. BLS 통과는 행성 확정이나 AI 승인을 뜻하지 않는다. 식쌍성·항성 활동·계통 오차와 고조파도 후보가 될 수 있다.

### 기존 PoC에서 확인한 사실

| 항목 | `bls_periodogram` | `bls_features` | 설계상 문제 |
|---|---|---|---|
| 최소 주기 | 0.5일 | 0.5일 | 동일 |
| 최대 주기 | `min(baseline/2.5, 30일)` | `min(baseline/3, 100일)` | 같은 입력에 서로 다른 탐색 범위 |
| 주기 격자 | 선형 8,000개 | 선형 20,000개 | 정밀도·비용·재현 버전이 분리됨 |
| 지속시간 | 0.5~8시간 12개 | 1.2·1.92·2.88·4.8시간 | 후보 화면과 feature 계산의 후보군이 다름 |
| BLS 목적함수 | Astropy 기본 likelihood | Astropy 기본 likelihood | 목적함수를 결과에 기록하지 않음 |
| 출력 | 전체 power, 각 격자의 period·t0·duration·depth | 최강 후보의 SNR·홀짝 깊이 차·secondary·통과 수 | SDE·Sector 일관성·마스크 편중 없음 |
| 피크 정리 | 관측 baseline의 주파수 분해능으로 인접 피크 묶음, 최대 10개 | 최강 후보 1개 | P·2P·P/2는 별개로 남으나 대표 후보 병합 규칙 없음 |

Astropy는 BLS 격자 선택에 결과가 민감할 수 있다고 설명하며, `autoperiod`는 관측 baseline과 최소 duration을 이용한 주파수 균일 격자를 제공한다. `compute_stats`는 홀짝 깊이, 반 주기 위상 깊이, transit별 점 수·우도 등 후보 검증 통계를 제공한다. 기존 선형 주기 격자와 이 방법을 같은 주입 데이터에서 비교한다. 최초 periodogram 상위에는 5.6595일 외에 약 11.3205일과 2.8308일도 나타났다. 각각 강한 후보의 약 2배·1/2배이므로 고조파/별칭 관리가 필요하다. 11.3795일 부근의 별도 피크도 있어, 주기 비율만으로 모든 2배 후보를 같은 신호로 합치면 실제 다른 신호를 잃을 수 있다.

### 후보 처리 상태 제안

```text
raw_peak
  → quality_evaluated (각 지표와 실패 사유 계산)
  → quality_pass / quality_fail / review
  → transit_model_fit
  → transit_model_validated
  → original_curve_verified
  → discoverable 판정
  → 후보 병합·외부·AI 연결
```

`quality_fail`도 진단 자료로 Silver에 보존할 수 있지만 사용자 매칭 후보표에는 올리지 않는다. 홀짝 차이·secondary가 큰 식쌍성형 신호는 행성이 아닐 가능성을 나타내는 정보이지 신호 자체가 없다는 뜻은 아니다. Planetory는 FP형 분석도 다루므로 이 지표만으로 무조건 제거하지 않고 별도 품질·분류 근거로 기록한다. AI 결과도 BLS 후보 포함 여부의 게이트로 사용하지 않는다.

### 탐색 격자와 필수 출력 제안

- period 최소값은 현재 요구사항과 PoC의 0.5일을 비교 기준으로 둔다. 최대값은 실제 데이터 범위(DEC-01)와 최소 관측 transit 수를 함께 사용해 결정한다.
- 현재 TOI-270 baseline은 약 77.72일인데 두 함수의 최대 주기는 약 25.91일과 30일로 다르다. EXP-04의 화면 주기축 최소 40일 요구와도 분리해 정리해야 한다. 계산 격자 범위와 화면 표시 범위를 각각 버전으로 기록한다.
- 0.5~8시간 지속시간 격자를 초기 비교 기준으로 사용하되 실제 대상의 별 반지름·주기·cadence 범위를 확인한 후 확장 여부를 결정한다.
- 선형 period 격자와 Astropy의 주파수 기반 `autoperiod`를 주입 신호 회수율·주기 오차·계산량으로 비교한다. 격자 방식, 점 수 또는 frequency factor, oversample과 목적함수를 `periodogram_config_version`에 포함한다.
- 후보마다 period·epoch·duration·depth뿐 아니라 raw power, 명시적으로 정의한 SDE·SNR, 깊이 오차, 전체/감광 안 점 수, 고유 transit 수, Sector·연속 구간별 지지 정도와 마스크 편중을 저장한다.
- 원본 `PDCSAP_FLUX_ERR`를 사용할지, 정제곡선의 국소 scatter로 오차를 산정할지 비교한다. 현재 수동 SNR 식과 Astropy `objective='snr'`의 값은 같은 이름으로 섞지 않는다.

TESS SPOC의 7.1σ TCE 기준은 외부 비교값으로 조사하되 Planetory SNR에 그대로 복사하지 않는다. SPOC TPS와 현재 Astropy BLS·전처리·잡음 정의가 다르기 때문이다. Planetory 임계값은 동일한 정의로 계산한 라벨·주입 데이터의 회수율과 오검출률을 보고 정한다.

### 고조파·중복 후보 처리 제안

- 1/2배·2배는 요구사항 SUB-04의 기본 고조파 관계로 검사한다. 1/3배·3배 등 추가 배율은 DEC-05로 남긴다.
- 주기 비율만 맞는다고 같은 후보로 병합하지 않는다. 순환 위상, duration 비율, 실제 감광 창 중첩과 원본 재검증을 함께 비교한다.
- 동일 신호의 고조파로 확인되면 하나의 고유 candidate ID 아래 대표 주기와 alias 목록을 둔다. 원래 원본 periodogram의 raw peak와 병합 근거를 잃지 않는다.
- 배율 1로 다른 후보와 직접 일치하면 그 후보를 우선한다. 대표 주기는 단순 최고 power가 아니라 원본 재검증·관측 횟수·Sector 일관성을 함께 비교한다.
- 비슷한 깊이의 주극소·부극소가 있는 식쌍성은 실제 공전주기의 1/2가 더 강할 수 있다. 기존 CM Draconis 설명과 합성 테스트가 이 사례를 보여주므로 자동으로 행성 주기로 해석하지 않는다.

### Silver 내부 반복 BLS와 처리 종료 — v1.0 기준

배치는 2분 원본 정제곡선의 BLS를 `iteration=0`으로 시작한다. 이 반복은 후보를 **찾는** 탐색 계산이며 사용자 제공 해상도와 무관하다. 각 반복에서 최강 독립 피크의 품질을 평가하고, 통과하면 transit model을 적합해 현재 곡선에서 나눈다. 제거 전후 power 감소, 모델 경계 돌출, 다른 후보 훼손, 겹친 transit 왜곡과 NaN/Inf 발생을 검사한 뒤 정상 잔차에서 다음 BLS를 실행한다. 각 단계 후보는 최종 공개 전에 원본 정제곡선에서 다시 검증하고 고조파·중복 후보를 하나의 고유 candidate ID로 병합한다.

반복 종료 사유는 실행마다 명시적으로 기록한다.

- `no_quality_peak`: 현재 곡선의 최강 독립 피크가 품질 기준을 통과하지 못함
- `insufficient_observations`: 유효 관측점·baseline·관측 transit 수가 탐색에 부족함
- `duplicate_or_harmonic_only`: 새 피크가 기존 고유 후보의 중복·고조파뿐임
- `removal_qa_failed`: 제거가 경계 돌출·다른 후보 훼손·비유한값 등 검증에 실패함
- `candidate_validation_failed`: 잔차에서 찾았으나 원본 재검증 또는 필수 파라미터 검증에 실패함
- `numerical_failure`: periodogram·특징·모델 계산 자체가 실패함
- `max_iterations_reached`: 안전 상한에 도달함. 상한값은 벤치마크 뒤 설정 버전으로 확정

`removal_qa_failed`이면 실패 제거 결과와 그 이후 후보를 공개하지 않고 직전 정상 단계까지의 후보만 유지한다. 품질 미달과 계산 실패를 모두 후보 0개로 합치지 않는다. AI 결과는 BLS 후보의 생성·제거 기준으로 사용하지 않는다.

사용자 분석의 잔차 단계는 이 배치 반복 이력의 재생이 아니다. EC2는 현재 판의 비닝 세그먼트와 사용자가 실제로 매칭한 후보의 `transit_model` 파라미터 조합을 받아 잔차곡선을 먼저 계산하고, 그 잔차로 주기도를 계산한다. 이 온라인 계산은 Candidate·외부 매칭·AI 결과를 추가하지 않는다.

### discoverable 판정 — DAT-07 v1.0 기준

`discoverable`은 사용자가 그 후보를 **찾을 수 있는지**의 판정이며 탐색 BLS와 목적·해상도가 다르다. 명세서 v1.0 DAT-07은 판정 조건을 "사용자에게 제공되는 것과 같은 조건"으로 확정했다. 2분 원본 해상도로 판정하지 않는다.

- 입력: 후보가 발견된 단계의 잔차 주기도를 **Gold와 같은 비닝 간격의 세그먼트**, 같은 `transit_model`·`residual_model_version`, 같은 주기 격자·`periodogram_config_version`으로 다시 계산한다. 발견 단계란 그 후보의 `removal_step` 이전 후보들을 모두 제거한 상태다.
- 판정: 그 주기도에서 대표 주기 또는 허용 alias(1/2·2배) 근처에 봉우리가 잡히면 `true`. 봉우리 판정 기준(국소 최대·주변 대비 power 비율·허용 근접도)은 벤치마크 후 `candidate_quality_version`에 포함한다.
- 원본 재검증 상태와 실패 사유는 별도로 기록하며, 재검증 실패 후보는 후보표에 올리지 않으므로 discoverable 대상도 아니다.
- 이 규칙을 지키지 않으면 화면 주기도에 봉우리가 없는 신호가 미매칭으로 남아 사용자의 탐색 완료(SUB-11)를 막는다. 반대로 SNR이 높다는 이유만으로 자동 `true`로 두지 않는다.
- 비닝 간격이나 격자 규칙이 바뀌면 새 `binning_revision`의 세그먼트·주기도·후보표를 함께 만들어 원자적으로 전환하고 discoverable을 다시 계산한다. 값이 바뀐 후보는 DAT-15의 재개 이벤트로 처리한다.

비닝 후 짧은 통과(1시간이면 10분 bin 약 6점)가 주기도 봉우리와 위상 접기 화면에서 살아남는지는 ERD 미결 10의 비닝 간격 실측과 같은 실험에서 확인한다. 화면 축약(200-bin 등)은 v1.0에서 분석 원본이 아니므로 판정 조건에서 제외한다.

### 검증 계획과 결정 대기 사항

단일·다중 행성, 같은 신호의 1/2·2배, 식쌍성, 항성 변동, 무신호, 관측 공백·마스크 편중과 한 Sector만 지지하는 합성/라벨 데이터를 포함한다. period·duration·depth·관측 횟수 구간별 회수율, 반복 단계별 신규 고유 후보 회수율·거짓 후보 수, 고조파 대표값 정확도, 제거 QA 실패율과 계산 시간을 보고한다.

TBD는 period/duration 범위, 격자 방식·밀도, SDE 정의, SDE·SNR 임계값, 최소 transit·점 수, Sector 일관성·마스크 편중 기준, 추가 고조파, 대표 후보 선정, 판 사이 후보 동일성 허용 오차, 반복 안전 상한·종료 임계값, 제거 QA 수치, 비닝 간격, 사용자 주기도 격자(범위·로그 등간격·5,000점) 정의, 미세 조정 허용 폭, 온라인 잔차 모델 검증 수치와 discoverable 봉우리 판정 기준이다. 각 값은 탐색용 `bls_config_version`, 제공용 `periodogram_config_version`, `residual_model_version`, `candidate_quality_version`으로 결과에 연결한다. 무신호 별 비율(DEC-01)이 높으면 BLS 채택 임계값(DEC-03)을 함께 조정한다.

## 5.7 BLS 기준값 벤치마크 실험 설계 v0.1

작성일: 2026-09-07. 상태: **윤성용 검토 전 제안, 팀 미승인**. 이 실험의 목적은 BLS가 신호를 찾을 수 있는지와 잘못된 후보를 얼마나 만드는지를 같은 조건에서 비교해 DEC-03·05·06의 기준값을 정할 근거를 만드는 것이다. 특정 행성을 잘 맞히는 설정이나 가장 높은 SNR 하나를 찾는 것이 목표가 아니다.

### 먼저 이해할 핵심 질문

벤치마크는 아래 네 질문에 답하도록 구성한다.

1. 신호가 있을 때 BLS가 올바른 주기 또는 설명 가능한 고조파를 찾는가?
2. 신호가 없을 때 품질 기준을 통과하는 가짜 후보가 얼마나 생기는가?
3. 관측 공백·품질 마스크·Sector 차이와 여러 신호가 있어도 결과가 유지되는가?
4. 사용자가 선택한 후보 모델로 만든 온라인 잔차와 주기도가 안정적이고 순서에 무관한가?

### 실험 단계와 설정 잠금

| 단계 | 목적 | 입력과 수행 | 다음 단계로 넘어가는 조건 |
|---|---|---|---|
| 0. 재현 확인 | 실행 환경과 측정 코드가 같은지 확인 | 고정된 TOI-270 Sector 3·4·5와 현재 PoC 기본값으로 5.6절 결과·기존 테스트 재현 | 입력 checksum, 코드·의존성·설정 버전, 핵심 수치와 실패 여부 기록 |
| 1. 작은 기능 확인 | 지표·고조파·실패 분류가 의도대로 계산되는지 확인 | 무잡음 단일 box, 같은 깊이의 주·부극소, 무신호, 두 신호, 공백·마스크 집중 사례를 소수 실행 | 정답 매칭·고조파 분류·반복 종료 상태가 사람이 계산한 기대와 일치 |
| 2. 조정 세트 | 격자·품질 임계값의 후보를 좁힘 | 아래 합성 주입과 라벨 있는 실제 표본의 조정용 TIC에서 회수율·가짜 후보·비용 비교 | 선택 이유와 탈락한 설정을 함께 기록하고 임시 설정 버전 잠금 |
| 3. 고정 평가 세트 | 선택한 설정의 일반화 확인 | 조정에 쓰지 않은 TIC·Sector와 난수 seed에서 임시 설정을 변경하지 않고 1회 평가 | 전체·구간별 지표와 실패 사례 공개. 결과를 보고 설정을 바꾸면 새 버전으로 단계 2부터 재실행 |

단계 2와 3의 TIC는 별 단위로 분리한다. 같은 TIC의 다른 Sector나 같은 원본 곡선에 다른 신호를 주입한 자료가 조정 세트와 평가 세트 양쪽에 들어가지 않게 한다. 난수 seed와 주입 목록도 실행 전에 고정한다.

### 평가 데이터 구성안

| 묶음 | 반드시 포함할 사례 | 용도와 주의점 |
|---|---|---|
| 합성 단일 신호 | period 1·5·20일, duration 0.5·2·8시간, depth 500·1,000·3,000·10,000ppm, 시작·중앙·끝 위상 | 탐색 범위와 강도별 회수 경계를 확인하는 초기 대표점. 최종 범위는 실제 대상 분포 검토 후 확정 |
| 합성 다중 신호 | 강한 신호와 약한 신호, 비슷한 세기의 두 신호, transit이 일부 겹치는 신호 | 반복별 회수 순서, 약한 후속 신호 회수율, 제거 왜곡·중복 후보와 종료 사유 확인 |
| 고조파·식쌍성 | 단일 신호의 P/2·2P 피크, 깊이가 같은/다른 주극소·부극소 | 대표 주기 선택, alias 보존, 홀짝·secondary 지표가 신호 품질과 분류를 혼동하지 않는지 확인 |
| 관측 조건 스트레스 | 단일 Sector, Sector별 깊이 차이, 시작·끝 경계, 큰 시간 공백, 예상 transit 일부 또는 대부분 마스킹 | Sector 일관성·마스크 편중을 pass/review/fail로 나눌 근거 확보 |
| 무신호 대조군 | 같은 cadence·공백·마스크를 유지한 잡음 곡선, transit을 넣지 않은 실제 정제곡선의 안전한 대조 입력 | TIC당 품질 통과 가짜 후보 수 측정. 실제 곡선은 알려지지 않은 신호가 있을 수 있어 순수 음성 정답으로 단정하지 않음 |
| 라벨 있는 실제 표본 | 확인된 다중 행성, 얕은 transit, 식쌍성, 항성 변동·계통 오차 사례 | 합성 box에만 잘 맞는 설정을 거름. 외부 라벨과 자체 BLS 대표값은 별도 열로 유지 |

초기 합성 단일 신호의 전체 조합은 `3 period × 3 duration × 4 depth × 3 phase = 108`개다. 서로 다른 잡음·공백 바탕곡선 두 종류에 같은 목록을 주입하면 설정당 216개가 된다. 모든 전처리·격자·임계값 조합에 216개를 곱하지 않고 다음 순서로 한 요인씩 비교한다.

1. 전처리 비교에서는 BLS 설정을 현재 기준값으로 고정한다.
2. 격자 비교에서는 선택된 전처리와 느슨한 후보 저장 기준을 고정한다.
3. 품질 임계값 비교에서는 같은 periodogram과 후보 지표를 재사용한다.
4. 온라인 잔차 계산 실험은 앞 단계에서 고정한 후보 모델과 periodogram 설정을 사용한다.

주입 신호는 가능한 경우 원천에 가까운 Sector별 정규화 flux에 넣고 전처리부터 다시 실행한다. 이미 디트렌딩된 곡선에만 넣은 결과는 BLS 자체 성능 보조 실험으로 구분한다. 각 행에는 원본 TIC·Sector, 주입 전 처리 단계, period·epoch·duration·depth, 난수 seed와 주입 ID를 기록한다.

### 감광 구간 사전 선별 비교안

전체 TIC에 정밀 BLS를 바로 실행하기 전에 값이 아래로 내려간 감광 사건을 빠르게 찾아, 반복 사건이 있는 TIC를 먼저 처리하면 계산량을 줄일 가능성이 있다. 시간축을 한 번 훑는 사건 탐지는 큰 period·duration 격자를 계산하는 BLS보다 싸게 만들 수 있다. 다만 개별 transit은 잡음보다 약하고 여러 회차를 같은 주기로 접어 합쳤을 때만 검출될 수 있으므로, `눈에 보이는 하강 2회 미만`을 곧바로 BLS 제외 조건으로 사용하지 않는다.

다음 세 경로를 같은 입력에서 비교한다.

| 경로 | 처리 방식 | 확인할 위험과 장점 |
|---|---|---|
| A. 전체 BLS | 전처리 통과 TIC 전체에 같은 정밀 BLS 실행 | 회수율 비교 기준. 계산량이 가장 큼 |
| B. 강제 사전 제외 | 빠른 감광 사건 탐지에서 독립 사건 2회 미만이면 BLS 생략 | 가장 빠를 수 있으나 얕은·장주기·마스크 영향 신호의 미회수 위험 측정 |
| C. 2단계 우선순위 | 반복 감광이 보이면 정밀 BLS, 불명확하면 저밀도 coarse BLS 후 유망한 TIC만 정밀 BLS | 약한 신호의 완전 제외를 줄이면서 계산량 절감 가능성 비교 |

사건 탐지는 디트렌딩된 시계열에서 duration 후보에 해당하는 이동 구간의 중앙값 또는 평균이 주변 robust scatter보다 얼마나 낮은지 계산하고, 서로 겹친 점이 아니라 시간상 분리된 감광 창의 개수를 센다. 단일 낮은 관측점, Sector 경계, 품질 마스크 직전·직후와 같은 구간은 별도 사유로 기록한다. 하강 깊이·연속 관측점·사건 간 최소 간격의 임계값은 **TBD**이며 조정 세트에서만 선택한다.

사전 선별은 다음 지표로 평가한다.

- 선별 통과율: 전체 TIC 중 정밀 BLS 또는 coarse BLS 대상으로 남은 비율
- 선별 회수율: 주입 신호가 있는 TIC 중 사전 단계에서 제외되지 않은 비율
- BLS 절감률: 전체 BLS 기준 대비 계산하지 않은 periodogram 수와 실제 wall time 감소
- 전체 회수율: 사전 선별부터 품질 게이트까지 완료한 뒤 direct/alias로 회수된 주입 신호 비율
- 구간별 미회수: depth·period·duration·관측 transit 수·마스크 비율별 사전 제외 건수

계산 시간만 줄고 전체 회수율이 크게 낮아지면 강제 제외는 채택하지 않는다. C 경로가 비슷한 회수율을 유지한다면 감광 사건 수를 삭제 조건이 아니라 처리 우선순위와 coarse-to-fine 계산 조건으로 사용하는 안을 검토한다. 현재 PoC의 `period_max=baseline/3`은 최소 반복 관측을 주기 탐색 범위에 간접 반영하지만, 개별 감광이 사전에 눈에 띄어야 한다는 뜻은 아니다.

### 정답 매칭 규칙 제안

BLS의 최고 피크가 주입 주기와 숫자상 가깝다는 이유만으로 회수 성공으로 세지 않는다. 각 주입 신호와 후보를 다음 순서로 비교한다.

- 대표 주기 직접 회수: 후보 period가 주입 period 허용 오차 안에 있고, 실제 관측점이 있는 예상 transit 창의 겹침 조건을 만족한다.
- 고조파 회수: P/2 또는 2P 허용 오차 안에 있고 transit 창·위상 관계가 설명될 때 별도 `alias_recovered`로 기록한다. 직접 회수와 같은 성공으로 합산한 수치도 함께 제공하되 둘을 숨기지 않는다.
- 잘못된 주기: 가까운 정수비가 아니거나 위상·관측 transit 창이 맞지 않는 품질 통과 후보다.
- 미회수: 원본 periodogram에서 저장한 상위 후보 어디에도 직접 또는 고조파 매칭되지 않는다.
- 중복 회수: 같은 주입 신호에 여러 후보가 매칭되면 고유 신호 회수는 1건, 나머지는 중복/alias 건수로 기록한다.

주기 허용 오차와 transit 창 최소 중첩 수·비율은 이 벤치마크로 결정할 대상이므로 먼저 넓은 진단 범위를 고정해 원시 오차 분포를 저장한다. 평가할 때 허용 오차를 계속 바꿔 성공 여부만 남기지 않는다.

### 필수 평가 지표

| 지표 | 계산 단위 | 의미 |
|---|---|---|
| 직접 주기 회수율 | 주입 신호 중 `direct_recovered` 비율 | 대표 주기를 정확히 선택하는 능력 |
| alias 포함 회수율 | 주입 신호 중 direct 또는 설명 가능한 alias 비율 | 신호 자체를 놓치지 않는 능력. 직접 회수율과 함께 보고 |
| 미회수율 | 주입 신호 중 어떤 후보와도 매칭되지 않은 비율 | 신호 손실 |
| 가짜 후보 수 | 무신호 입력 TIC당 품질을 통과한 고유 후보 수 | 서비스 후보표에 불필요한 신호가 쌓이는 정도 |
| 중복·고조파 잔존율 | 하나의 정답에 둘 이상 고유 후보 ID가 남은 비율 | 후보 병합 규칙의 실패 정도 |
| 파라미터 오차 | period 상대오차, epoch 순환 오차, duration·depth 상대오차 | 사용자가 볼 대표값과 제거 모델의 정확성 |
| 구간별 회수율 | depth·period·duration·Sector 수·관측 transit 수·마스크 비율별 | 전체 평균에 가려진 약한 신호·장주기 실패 확인 |
| 온라인 잔차 안정성 | 선택 후보 제거 전후의 관측점·scatter·최대 편차, 제거 순서별 차이, 잔차 주기도 재현성 | 사용자에게 제공하는 잔차·주기도의 수치 안정성 확인. 새 후보 회수율로 해석하지 않음 |
| 계산 비용 | TIC당 wall time, periodogram 점 수, 최고 메모리, 성공/실패 수 | Spark·EC2 운영 가능성 비교. 정확도와 별도 보고 |

라벨 있는 실제 데이터에서는 미등록 신호가 있을 수 있으므로 `precision`을 절대 정답처럼 보고하지 않는다. 합성·검증된 라벨 범위에서는 후보 단위 정밀도를 계산하고, 실제 미라벨 피크는 자동 오검출 대신 `unknown_review`로 분리한다.

### 품질 기준 선택 절차

SDE와 SNR 임계값을 각각 따로 고른 뒤 조합하지 않는다. 조정 세트에서 후보별 SDE·SNR·transit 수·Sector 지지·마스크 편중 원시값을 모두 저장하고, 후보 게이트 조합별로 다음을 비교한다.

1. 무신호 TIC당 가짜 후보 수를 허용 범위 안으로 제한한다.
2. 그 조건을 만족하는 조합 중 직접 회수율과 약한·장주기 구간 회수율을 비교한다.
3. 전체 평균이 좋아도 특정 depth·period·관측 횟수 구간이 급격히 무너지면 `review` 구간 또는 별도 규칙을 검토한다.
4. 2회 transit과 3회 이상, 단일 Sector와 다중 Sector를 나누어 본 뒤 최소 관측 규칙을 정한다.
5. 선택한 규칙을 `candidate_quality_version`으로 잠그고 고정 평가 세트에서 다시 계산한다.

정확한 허용 목표는 팀 리뷰 전 **TBD**다. 비교표에는 최소한 `SNR 단독`, `SDE 단독`, `SNR+SDE`, 여기에 관측 횟수·마스크·Sector 규칙을 순서대로 추가한 결과를 보여준다. 가장 복잡한 규칙이 조금 더 좋은 경우 운영 복잡도와 개선 폭을 함께 보고한다.

### 온라인 잔차 계산 벤치마크

사용자가 후보를 매칭한 상황을 재현해 Gold의 **비닝 세그먼트**에 선택 후보의 `transit_model` 파라미터로 생성한 고정 모델을 적용하고, EC2가 잔차곡선과 잔차 주기도를 계산한다. Silver가 같은 비닝·모델·격자 설정으로 계산한 기준 결과와 수치가 일치하는지 검증하되, EC2 요청 자체는 새 Candidate를 찾거나 AI를 다시 실행하지 않고 모델을 재적합하지도 않는다.

- 빈 선택: 제거 후보가 없으면 세그먼트 배열·판별 원본 주기도와 일치한다.
- 단일 선택: 선택 후보의 모델만 적용되고 `start_btjd`·`bin_minutes`·`n_points`·NaN 위치가 보존된다.
- 복수 선택: A+B와 B+A의 잔차·주기도가 허용 오차 안에서 같다.
- 겹친 transit: 두 모델을 곱해 나누며 겹친 bin을 삭제하지 않는다.
- 왜곡 검증: 모델 경계 밖 scatter·최대 편차와 새 NaN/Inf를 확인한다.
- 실패 처리: 알 수 없는 shape·잘못된 파라미터·`residual_model_version` 불일치는 곡선 대신 명시적 실패를 반환한다.

box 모델과 더 실제적인 transit model은 같은 고정 후보에서 잔차 안정성·계산 비용으로 비교할 수 있다. 선택 모델은 `residual_model_version`으로 Silver·Gold·EC2에 동일하게 적용한다. PoC의 `joint_refit`(승인 후보 공동 재적합)은 이 계약과 다르므로 온라인 커널로 그대로 채택하지 않는다.

### 실행 결과 산출물 제안

원본 FITS와 대용량 중간 배열은 Git에 넣지 않는다. 실행마다 내부 저장소에 상세 결과를 두고 리뷰용으로 다음 작은 산출물을 만든다.

| 산출물 | 최소 내용 |
|---|---|
| `benchmark-manifest` | run ID, 입력 snapshot/checksum, TIC 분할, 주입 목록·seed, 코드·의존성, 전처리/BLS/품질/제거 버전 |
| 후보별 결과 표 | 입력·주입 ID, 원본 peak rank, period·epoch·duration·depth, power·SDE·SNR, transit·Sector·마스크 지표, 매칭 종류, 품질 상태·사유 |
| TIC별 BLS 결과 표 | 반복 수·단계별 peak·신규 고유 후보 수, 종료 사유, 처리 시간, 실패 단계 |
| 요약 보고서 | 전체·구간별 지표, 설정 비교, 대표 성공·실패 그림, 선택안·TBD·알려진 한계 |

작은 요약 CSV/JSON과 보고서만 MR에 포함할지는 데이터 관리 규칙과 팀 리뷰로 정한다. 어떤 결과도 `bls_config_version`, `candidate_quality_version`, `residual_model_version` 없이 비교하지 않는다.

### 이 설계로 결정할 것과 결정하지 않는 것

이 벤치마크는 BLS 격자, 품질 게이트, 반복 제거·종료, 제거 QA, 고조파·중복 처리와 Silver–EC2 잔차 수치 검증의 근거를 만든다. AI가 행성 후보인지 판정하는 임계값, 외부 TOI/TCE의 disposition, 사용자의 정답 판정은 별도 평가 대상이다. BLS가 품질을 통과했다는 사실만으로 행성이라고 확정하지 않는다.
