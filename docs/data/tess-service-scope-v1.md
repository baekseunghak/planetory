### 5.1 109 예비 측정과 최종 판정의 구분

상태: **최초 BLS 예비 실측·산출물 대조 완료, 최종 채택 미확정**. 2026-09-20 작업에서 사용자 다운로드
`sample-59a8e48a`의 45파일(89.9 MB)을 확인했다. 로컬 45파일 SHA-256은 저장소의 고정 checksum과 모두 일치한다.
이는 다운로드 무결성 확인이며 BLS 검증 완료가 아니다.

실행 방법과 산출물은 [tess-bench README](../../experiments/tess-bench/README.md)의 109 절을 따른다.
기존 biweight 1일 전처리와 선형 20,000점 BLS의 최초 상위 5피크에 잠정 게이트
`SNR ≥ 7 & SDE ≥ 6 & 관측 통과 수 ≥ 2`를 적용한다. 설정·구현·입력·출력 checksum을 manifest로 고정한다.
110 승인 전 예비 결과로 취급하며, 기존 BLS 설정 파일의 채택 상태를 변경하지 않는다.

- 무작위 40개에서 정상 처리된 별 중 게이트 통과 피크가 없는 별의 분자/분모를 보고한다.
  실패·대체 처리 별은 별도 집계하고 무검출로 바꾸지 않는다. 행성 보유 비교군 5개는 별도 집계한다.
- 최초 탐색의 `no_gate_peak`는 실제 무신호, 반복 제거 후 채택 후보 0개 또는 서비스 discoverability와 다르다.
  위양성·별칭·장주기/짧은 지속시간의 탐색 범위 밖 신호와 실제 신호 미검출 가능성이 남는다.
- 첫 N개 시간 확인 결과는 부분 실행이다. 전체 40개 결과가 있어도 Sector 3 SPOC 대상 별에 대한 소표본 예비치다.
  이를 전체 Sector의 공급량·DEC-16 충족 여부로 곧바로 외삽하지 않는다.
- Jira 109 최종 완료에는 110/D04 확정 설정, 115/D07-2 discoverable 규칙, 116/D08 외부 라벨 검증과
  튜토리얼 5 TIC의 교육 역할 검토가 남는다. 이 명령은 해당 완료 조건을 대신하지 않는다.
- 대표 표본 고정과 초기 대규모 수집 B 승인은 별개다. 이 실행은 7절의 B 미승인 상태를 변경하지 않는다.

**부족 시 대응 순서**

1. 처리 누락·재시도 가능한 실패·게시 누락을 먼저 확인한다. 데이터 또는 코드 오류를 수정하면 같은 버전 비교 또는 새 버전 실행으로 구분해 재집계한다. QA 보류를 임의로 풀지 않는다.
2. 실제 부족이 확인되면 S1~13 확대 목표 안에서 추가 Sector의 비용·처리 시간·기존 대상과의 중복을 검토해 수집 범위를 별도 승인받는다. 추가 Sector 수와 공급 증가량을 소표본에서 자동 산정하지 않는다.
3. 기한·예산상 확대가 불가능하면 **일반 탐사 초기 공개를 연기**하는 것을 기본안으로 한다. 튜토리얼만 시연하거나 최소 공급량을 낮추는 대안은 기능 범위 변경이므로 지웅님의 별도 승인과 소비자 구현 확인 후 적용한다. 이를 이번 결정으로 미리 승인하지 않는다.
4. ‘축소’는 앞으로 처리·공개할 Sector 범위 또는 일반 탐사의 공개 시점을 조정한다는 뜻이다. 검증된 별을 성능 수치에 맞춰 숨기거나, 기존 회원 데이터·성과를 삭제하거나, stars_per_achievement를 변경하는 뜻이 아니다. 품질 임계값·QA 기준은 공급량을 맞추기 위해 낮추지 않는다.

**예산 초과와 재측정**

6절의 예산 숫자는 실측 승인 전 잠정값이다. 담당자가 승인한 저장·비용·처리 시간 상한을 넘으면 추가 수집·범위 확대를 멈추고 범위/일정을 재승인한다. 진단 열·제외 사유 삭제를 자동 대응으로 실행하지 않는다.

S3·4·5 운영 처리 결과 최초 확보, Sector/제품/릴리스 또는 checksum 변경, 전처리·탐색 quality_version·반복 제거 QA·비닝/discoverable 규칙 변경, 외부 라벨/공개 자격 정책 변경 시 재측정한다. 단순 재게시도 공급 집계 snapshot을 갱신한다. 109의 기본 품질 버전 실측을 243의 새 품질 버전 결과로 간주하지 않는다.
