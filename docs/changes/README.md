# 변경 이력 안내

문서 정본과 큰 기술 결정이 왜 바뀌었는지 검색하고 같은 오류를 반복하지 않기 위한 주요 변경 기록이다. 현재 기준은 담당 정본, 진행 중인 충돌은 `docs/project/`, 팀 회고는 `docs/daily-report/`, 일반 작업 내역은 Git·Jira에서 관리한다.

## 기록이 필요한 경우

- 정본 문서의 책임·내용·결정 상태가 바뀐 경우
- 시스템 아키텍처, API·데이터 계약, 운영 방식이 크게 바뀐 경우
- 문서 디렉터리, 소유권이나 탐색 경로를 바꾼 경우
- 기존 결정을 수정·폐기하거나 반복된 오류의 방지 규칙을 정한 경우

오탈자·링크만 고친 작업, KPT, 자동 생성 결과, 일반 커밋 요약과 변경 이력 문서 자체의 수정은 기록하지 않는다.

## 주차 인덱스

| 기간 | 인덱스 | 상태 |
| --- | --- | --- |
| 2026-09-14 ~ 2026-09-20 | [2026년 9월 3주차](2026-09-W3/README.md) | 현재 |
| 2026-09-07 ~ 2026-09-13 | [2026년 9월 2주차](2026-09-W2/README.md) | 이전 |

## 저장 규칙

```text
docs/changes/
└─ YYYY-MM-Wn/
   ├─ README.md
   └─ YYYY-MM-DD.md
```

- 디렉터리는 `2026-09-W2`처럼 연도·월·월내 주차를 함께 적는다.
- 1주차는 매월 1일부터 첫 번째 일요일까지이며 이후는 월요일부터 일요일까지다.
- 기록할 변경이 있는 날만 날짜 파일 하나를 만든다.
- 같은 날 중요한 변경이 여러 개면 날짜 파일 안에서 Jira 또는 주제별 제목으로 나눈다.
- 전체 명세나 diff를 복사하지 않고 정본·Jira·MR을 링크한다.
- 주차 `README.md`에는 날짜, 주요 변경, Jira, 검색 키워드, 상태와 일별 기록 링크만 한 줄로 등록한다.

## 일별 기록 형식

```markdown
# YYYY-MM-DD 주요 변경

## [JIRA-KEY] 변경 요약

- 수정자: 이름 또는 도구와 작업 주체
- 유형: 문서 구조 | 아키텍처 | 요구사항 | API | 데이터 | 운영 | 오류 정정
- 상태: 제안 | 채택 | 구현 완료 | 검증 완료 | 대체 | 정정
- 변경 범위: 파일 또는 구성요소
- 목적: 변경 목적 한 줄
- 결정·근거: 핵심 판단 한두 줄
- 검증: 실행한 검증과 결과
- 관련 문서: 정본·Jira·MR 링크
- 후속 작업: 없음 또는 남은 항목
```

항목이 없으면 `없음`이라고 적는다. 과정을 나열하지 말고 향후 검색과 재발 방지에 필요한 결론만 남긴다. 각 변경은 짧은 목록으로 작성하고 상세 내용은 정본·Jira·MR을 참조한다.

## 에이전트 탐색·갱신 순서

1. `rg -n "<Jira 키|문서 경로|키워드>" docs/changes`로 먼저 검색한다.
2. 검색된 주차 인덱스와 일별 기록만 읽고 전체 이력을 한 번에 불러오지 않는다.
3. 현재 정본과 실제 구현을 확인한 뒤 변경한다.
4. 중요한 변경이면 해당 날짜 파일을 만들거나 기존 날짜 파일에 짧은 항목을 추가한다.
5. 해당 주차 `README.md`에 한 줄을 추가하고 상대 링크와 `git diff --check`를 검증한다.

기존 기록이 틀렸거나 결정이 바뀌면 조용히 덮어쓰지 않는다. 변경한 날짜에 정정·대체 항목을 남기고 이전 날짜 기록을 링크한다.
