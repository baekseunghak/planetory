- 변경 범위: Sector·coverage 감사, Node 1 조정기 재기동 조건, HDFS 존재 검사, coverage 소비 계약, GitLab 검증
- 목적: 완료된 Sector 1~13 증거를 정본에 반영하고, coverage 표식만으로 원본 바이트 일치와 독립 재감사를 우회할 수 있던 경계를 닫는다.
- 결정·근거: Sector audit는 제품 수와 원본 바이트를 모두 coverage와 대조한다. 독립 CoverageCommit은 13개 final의 checksum·manifest·RF2·FSCK와 Parquet success를 전수 재검사하고, 직전 전수 감사를 동기적으로 마친 조정기만 중복 감사를 생략한다. HDFS 조회 오류를 부재로 처리하지 않으며 run 내부 Sector·Worker 중복과 중첩 Parquet 산출물을 거부한다. 완료 표식이 생긴 unit은 재부팅 때 다시 실행하지 않는다.
- 검증: 실환경은 247,824개·474,185,704,320바이트, coverage SHA-256 `df6bfa638a0d70913b0d0bade11f0c5335bf9c505a9fbe256fa8552f0623bd94`, 13개 ready·Parquet success, FSCK `HEALTHY`, RF2, under/missing/corrupt 0, Live DataNode 5개, HA `active:standby`, uploader 65개 success와 조정기 exit 0·재시작 0을 확인했다. 후속 방어는 Python 변형·회귀 21개와 PowerShell parser·계약으로 검증하며 새 CodeRelease 실배치는 하지 않았다.
