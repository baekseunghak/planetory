- 결정·근거: 사용자가 별도 테스트 환경이 없음을 확인하고 로컬 통합 검증을 선택했다. 기존 일회용 DB와 MockMvc를 재사용하며 운영 코드·인증 우회 경로·새 의존성은 추가하지 않았다.
- 변경 범위: NotificationTest의 두 계정 HTTP 연계·1,000명 수신 기록 검증, 기존 음성 요청 검증의 CSRF를 브라우저와 같은 헤더 방식으로 정정, F15.8 검증 범위 기록.
- 검증: PostgreSQL 18.6의 NotificationTest 22건, 합성 응답 서버의 Chrome 알림/설정 3건 통과. Gold 사건→설정→비소급→읽음 소유권→목적지 차단을 확인했다. 로컬 단일 측정은 1,000명 대기 기록 생성 포함 커밋 41.5ms·한 회원 발행/조회 11.9ms다. 운영 부하 기준으로 일반화하지 않는다. 기존 전체 관련 회귀 93건 결과와 이번 22건 재실행은 중복 합산하지 않는다.
- 관련 문서: [F15.8 로컬 인수·규모 관찰](../../development/service-backend/community.md#notification-producer-contract).
- 후속 작업: 실제 OAuth·Backend 연결 브라우저·Publisher 실행 경로·운영 규모 부하 인수. 운영 적용·commit/push/MR/Jira 변경은 실행하지 않았다.

## [S15P21C206-175] 탐사 코어 리뷰 보완과 후속 검증 명시

- 수정 주체: 서비스 백엔드 작업
- 유형: 검증, 문서
- 상태: 리뷰 보완 검증 완료, 보존·동시 잠금·운영 튜토리얼 정책은 258 후속.
- 변경 범위: V23 정책 주석, NotificationTest, F15.8 및 후속 티켓 인계.
- 결정·근거: 원천 기록에 알림함 90일을 삭제 TTL로 적용하지 않는다. SQL만 활성 튜토리얼 수 기준으로 바꾸지 않고 Java와 동일한 기존 5개 정책을 유지한다. 후보 팬아웃은 수신자 팬아웃과 분리해 측정하며 행별 트리거의 전역 잠금 순서는 미보장임을 명시한다.
- 검증: 일회용 PostgreSQL 18.6에서 NotificationTest 23건 통과. 활성 0/4/5개·재개 후 완료 시각 보존의 Java/트리거 자격 일치 확인. 후보 1/100/1,000개·수신자 0명·AI/외부 판정 없는 최초 기준 생성 커밋은 로컬 단일 측정 19.8/40.8/160.2ms. 운영 수용량·실제 후보 수·교착 검증 완료로 일반화하지 않는다.
- 관련 문서: [F15.8 리뷰 보완](../../development/service-backend/community.md#notification-producer-contract).
- 후속 작업: 258에서 원천 정리·중복 근거 보존, 실제 후보 분포·동시 반대 순서 잠금·재시도, 활성 튜토리얼 운영 정책을 검증한다. 운영 DB 적용 없음.

## [S15P21C206-180] 탈퇴 방향 승인과 쓰기·공개 조회 경계 일부 반영

- 수정 주체: 서비스 백엔드 작업
- 유형: 요구사항, API
- 상태: 부분 구현·격리 검증 완료. 탈퇴 실행·데이터 정리·세션 일괄 폐기는 미구현.
- 변경 범위: 회원 쓰기 잠금, 공개 분석·History 첨부·반응 조회, 글·댓글 작성자 응답과 프론트 링크, 정책 `available:false` GET, DEC-11·서비스 API 계약.
- 결정·근거: W1~W4와 FE222 요청·영수증의 방향은 승인됐다. 기간·재가입·C 완료·마지막 발견자·소수집단·정책 버전은 특정되지 않아 실행 API를 제공하지 않는다. SB-D04의 T 선행 차단을 회원 행 잠금으로 보강하고 탈퇴한 회원의 새 공개 조회에서 개인 분석·첨부·반응을 제외한다. 일반 글·댓글의 본문은 남기고 작성자 ID·이전 이름·프로필 이동을 제거한다.
- 검증: 일회용 PostgreSQL 18.6의 PostReactionTest·SubmissionLookupTest·PublicAnalysisTest·HistoryAttachmentTest·HotTopicsTest·CommunityReadTest 통과. 프론트 타입 검사와 단위 447건 통과. 실제 탈퇴 API·Redis 세션 폐기·복원 시험은 수행하지 않았다.
- 관련 문서: [DEC-11](../../requirements/planetory-decision-register.md#dec-11), [180 인수](../../requirements/planetory-acceptance-criteria.md#withdrawal-180), [서비스 API](../../../apps/backend/docs/service-api-spec.md).
- 후속 작업: 처리 근거·기간과 정책 버전 확정, T/C·세션·재시도·재가입 및 격리 종단 인수. 운영 DB 적용·commit·push·MR·Jira 변경 없음.

## [S15P21C206-180] 권장 탈퇴 계약의 격리 구현

- 수정 주체: 서비스 백엔드 작업
- 유형: 요구사항, 데이터, API, 운영
- 상태: 구현·격리 검증 완료, 운영 활성화 보류.
- 결정·근거: 사용자가 DEC-11 권장값을 구현 목표로 선택했다. DB 확정 T와 개인 자료 정리 C를 분리하고, T 이후 보호 접근을 차단한다. 일반 글·댓글은 공통 작성자로 연결을 끊고 1년 뒤 본문을 지우며, 영수증은 신청 후 90일로 제한한다. 같은 제공자 재가입은 C 뒤 새 회원으로 허용한다.
- 변경 범위: V24 게시판 공개·탈퇴 요청/정리·보관 만료, 회원/공개/관계/통계 조회, Redis 세션 일괄 폐기, prepare·confirm·영수증·재시도 API, FE222 T 이후 상태 표시와 계약 문서. `planetory.withdrawal.enabled` 기본값은 false다.
- 검증: 일회용 PostgreSQL에서 인증·Redis·게시판·핫 토픽·통계·앱 역할 84건과 공개 분석·History 첨부·제출 조회·팔로우·알림·반응 119건, 대상별 합계 203건 통과. 탈퇴 C 실패 뒤 T 차단 유지와 재시도 완료를 포함한다. 프론트 타입 검사·운영 빌드·단위 447건 통과. Chrome 상태 분기 3건은 본문 검증에 통과했으나 Playwright 종료 시간 초과로 명령은 실패했다. 전체 Backend 테스트 명령은 장시간 실행 중 중단해 통과로 간주하지 않는다.
- 관련 문서: [DEC-11](../../requirements/planetory-decision-register.md#dec-11), [180 인수](../../requirements/planetory-acceptance-criteria.md#withdrawal-180), [서비스 API](../../../apps/backend/docs/p1-service-contract.md#5-탈퇴-확인-화면--222--s26s27-인계-제안), [DB 구조](../../architecture/database-erd.md).
- 후속 작업: 개인정보 처리방침·본문 식별 정보 삭제 요청 절차, 실제 연결 브라우저·Redis/운영 복원·24시간 정리 인수 후 기능을 켠다. 운영 DB 적용·commit·push·MR·Jira 변경 없음.
