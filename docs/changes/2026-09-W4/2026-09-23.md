## [S15P21C206-235] prod 쿠키·격리 DB 중단 인증 응답 실측

- 수정자: S15P21C206-235 작업 담당
- 유형: 운영 | 오류 정정
- 상태: 격리 실측 완료, DB 장애 응답 계약 미충족
- 변경 범위: 인증 런타임 테스트·기존 합성 제공자 등록 도우미·운영 검증 보고서·운영 문서 지도.
- 목적: 240·84 병합 후 실제 HTTPS 쿠키와 DB 중단 응답을 운영 인수와 구분해 기록한다.
- 결정·근거: prod+전용 PostgreSQL+서로 다른 Redis+실제 nginx 라우팅에서 SESSION 속성을 확인한다. DB 중단 중 /me가 500·공통 코드 없는 본문을 반환하는 결함과 콜백 503을 authentication_failed로 바꾸는 239 문제를 분리 보고하며 앱을 수정하지 않는다. 자동 할당 DB 포트가 재시작 시 바뀌는 환경 문제는 명시적 시험 포트로 교정하고 같은 주소의 기존 세션 200 복구를 확인한다.
- 검증: 최종 15건 중 기존 회귀 14건 통과·235 계약 검사 1건 실패·건너뜀 0. 실패 기대를 500으로 낮추지 않는다. 쿠키 값·토큰·개인정보는 결과에서 제외한다. 상대 링크·diff 확인은 운영 보고서를 따른다.
- 관련 문서: [인증 런타임 실측](../../operations/auth-runtime-verification-235.md), [Jira 235](https://ssafy.atlassian.net/browse/S15P21C206-235)
- 후속 작업: /me DB 장애 예외 경계와 239 표시 분리의 별도 수정·재검증, 운영 Redis 구성·헤더 신뢰 경계·실제 제공자/브라우저 인수. Jira 최신 직접 재조회는 도구 시작 오류로 미수행이다.

## [S15P21C206-235] 인증 트랜잭션 시작 실패를 503으로 처리

- 수정자: S15P21C206-235 작업 담당
- 유형: 오류 정정 | API
- 상태: 수정·격리 검증 완료
- 변경 범위: SessionAuthenticationFilter, OAuthLoginSuccessHandler, 인증 검증·OAuth 오류 테스트, OAuth 설정 안내·235 보고서.
- 목적: DB 연결을 얻지 못해 인증 트랜잭션 시작이 실패할 때 500으로 빠지는 경로를 기존 503 계약으로 복구한다.
- 결정·근거: 사용자가 같은 브랜치에서 백엔드 결함 수정을 요청했다. 실제 격리 DB 중단 회원 조회에서 CannotCreateTransactionException을 확인하고 인증·콜백의 기존 DataAccessException 분기에 해당 예외만 추가한다. 다른 트랜잭션 오류를 일괄 503으로 바꾸지 않는다. 앞선 분리 보고 단계의 앱 미수정·14통과/1실패 상태를 갱신한다.
- 검증: prod·TLS nginx·전용 PostgreSQL·별도 Redis 두 인스턴스에서 15건 모두 통과, 실패·건너뜀 0. 중단 직후·지속 중단 /me와 인증 CSRF 503, 복구 대기 503 및 기존 세션 200 복구, OAuth 세션 정리·안전 로그와 나머지 인증 회귀를 확인했다.
- 관련 문서: [인증 런타임 실측·수정 후 재검증](../../operations/auth-runtime-verification-235.md), [OAuth 계약](../../../apps/backend/docs/oauth-setup.md)
- 후속 작업: 239 콜백 표시 분리, 운영 Redis·프록시 신뢰 경계·실제 제공자 인수는 별도다. 운영 설정·신규 마이그레이션·공유 DB 변경·배포·commit·push는 수행하지 않았다.
