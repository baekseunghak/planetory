- 유형: 운영·파이프라인·오류 정정
- 상태: 운영 배포·첫 deferred 재개 검증 완료, 장시간 회귀 미검증

- 목적: `reschedule` 대기 Task에서 관찰된 실패 경로를 줄이고 LocalExecutor 슬롯 점유 없이 Worker 완료를 기다린다.
- 결정·근거: Worker 완료 marker 확인은 기존 SSH·무결성 게이트를 유지하고, 5분 Temporal Trigger가 대기만 담당한다. Task의 14일 deadline은 최초 시작 시점 기준으로 보존한다.
- 검증: `python -m unittest discover -s distributed-system/airflow/tests -v` 16건 통과, Git Bash `bash -n`, 새 이미지 격리 DAG import 통과. Node 1 불변 release `20260922T170848Z`에서 Scheduler·DAG Processor·API Server·Triggerer를 기동했고 API health의 metadatabase·scheduler·triggerer·dag_processor가 모두 healthy이며 import 오류는 0건이다. Sector 20 `check_download`는 `18:04:22 UTC`에 deferred가 된 뒤 `18:09:25 UTC`에 다시 deferred로 전환됐고 Triggerer 최근 로그에는 만료 서명·인증 오류가 없었다.
- 관련 문서: [DAG 계약](../../../distributed-system/airflow/dags/README.md), [Airflow 운영 절차](../../../infra/distributed-system/README.md#airflow-db), [Jira](https://ssafy.atlassian.net/browse/S15P21C206-252)
- 후속 작업: Sector 19 Raw와 Sector 20 다운로드를 기존 감시 정책으로 계속 관찰한다. 새 대기 방식의 장시간·재부팅 회귀는 별도 운영 관찰 결과로 남긴다.

## [S15P21C206-252] Triggerer 배포 후 토큰 만료 재발 정정

- 수정자: Codex
- 유형: 운영·오류 정정
- 상태: 재발 확인, 근본 원인 미해결
- 변경 범위: Airflow 3.2.2 Sector 21·22 다운로드 Task와 발견 Task의 운영 검증 상태
- 목적: 앞선 첫 5분 deferred 재개 성공을 토큰 만료 해결로 확대 해석하지 않도록 정정한다.
- 결정·근거: Sector 21 `check_download`는 18:45 UTC, Sector 22는 19:16 UTC에 `Invalid auth token: Signature has expired`로 실패했다. 발견 `reconcile`도 Sector 21과 같은 시각 재시도됐다. 실패는 LocalExecutor가 queued Task를 실행 API에 연결하는 경로에도 나타나므로 센서 방식만의 오류로 단정하지 않는다.
- 검증: Airflow Scheduler 로그와 metadata Task·DagRun 상태를 읽기 전용으로 대조했다. 19:22 UTC 기준 서비스 health·HDFS HA·YARN과 HDFS 용량은 정상이고, Sector 21 Raw와 Sector 20 Bronze는 계속 진행 중이었다. Sector 19 Raw·cleanup·Bronze는 성공했다.
- 관련 문서: [임시 핸드오프](../../project/tess-airflow-handoff-2026-09-23.md), [DAG 계약](../../../distributed-system/airflow/dags/README.md), [Jira](https://ssafy.atlassian.net/browse/S15P21C206-252)
- 후속 작업: 실행 토큰 만료 경로를 규명·수정하고 15~20분 이상 대기·실행 회귀를 운영에서 확인한다. 완료 후 임시 핸드오프를 삭제한다.
