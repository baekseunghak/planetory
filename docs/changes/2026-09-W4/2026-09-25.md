- 결정·근거: systemd의 시작 시각·결과는 재부팅하면 사라지므로 완료 판단을 attempt 상태 파일로 옮겼다. retry가 같은 run ID를 쓰므로 attempt에 unit 이름을 기록해 unit별로 구분한다. 재시작 6회와 SSH 연속 실패 6회를 상한으로 두었다(각각 5분 간격, 약 30분). 2026-09-24 실측에서 CPU 플랫폼 혼재(AMD Rome·Intel Broadwell)와 메모리 기준 배치 편중으로 작업당 24~64분 차이가 났고 executor 실제 메모리는 약 2.2 GiB였으므로, 컨테이너를 7 GiB로 줄여 노드별 3개(worker-2는 2개)로 고르게 배치한다.
- 검증: `pytest` 364 passed·5 skipped, WSL Airflow 3.2.2 `unittest discover` 30개 통과와 `DagBag` import 오류 0건, `test-tess-silver.ps1`·`test-tess-bronze.ps1`·`validate.py` 통과. 배치 수는 YARN 메모리 계산으로만 검증했고 실클러스터 처리량은 측정 전이다.
- 관련 문서: [Silver DAG 안내](../../../distributed-system/airflow/dags/README.md), [78 인계](../../project/s15p21c206-78-handoff.md)
- 후속 작업: 새 release로 DAG Canary를 실행해 executor 배치를 확인하고, 다음 전체 run 첫 1~2시간의 작업 시간으로 효과를 측정한다. Intel worker 교체(P3)는 비용·VM 중지 결정이 필요하다.
