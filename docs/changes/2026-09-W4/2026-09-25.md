## [S15P21C206-84] develop 백엔드 테스트 실패·정지 정정

- 담당: 서비스 백엔드(Claude Code)
- 유형: 오류 정정
- 상태: 검증 완료
- 변경 범위: `GoldCatalogSchemaTest`, `StatisticsMigrationTest`, `StatisticsCommandTest`, `SourceCardTest`, `PlanetoryApplicationCommandModeTest`. 운영 코드·마이그레이션 파일은 바꾸지 않았다.
- 목적: 깨끗한 develop에서 `./gradlew test`가 실패하거나 끝나지 않던 테스트를 현재 계약에 맞춘다.
- 결정·근거(반복 마이그레이션): Flyway `target`은 버전 마이그레이션만 제한한다. 2026-09-18에 들어온 `R__table_comments.sql`은 빈 스키마의 첫 migrate에서 함께 실행되어 `migrationsExecuted`에 1건을 더한다. 기준 버전을 만드는 단계는 `category`가 `Versioned`인 항목만 센다. 반복 마이그레이션을 끄지 않은 이유는 이전 버전 스키마에서도 R__의 존재 확인 분기가 도는지 함께 검증하기 위해서다.
- 결정·근거(최소 공개 모집단): 180이 `StatisticsSnapshotService.latest()`에 공개 모집단 10명 미만 비공개([DEC-11](../../requirements/planetory-decision-register.md#dec-11))를 넣었고 `StatisticsCommandTest`만 갱신되지 않았다. 코드가 명세와 맞으므로 기동 시 스냅샷 생성을 보는 이 테스트에 `planetory.statistics.min-public-cohort=0`을 준다. 10명 미만 비공개는 `StatisticsAggregationTest`가 계속 검증한다.
- 결정·근거(회원 잠금): 180이 글 수정의 첫 잠금으로 회원 행 `FOR UPDATE`를 넣은 뒤, 저장 도중 같은 회원의 공개 취소를 다른 스레드로 실행하던 `SourceCardTest`는 끝나지 않았다. 취소가 회원 행 잠금을 기다리는 동안 테스트 스레드는 `ExecutorService.close()`에서 작업 종료를 무기한 기다린다. 같은 회원의 취소는 이제 저장 뒤로 직렬화되므로, 다른 회원이 쓴 글에서 공개 분석을 인용하게 해 경쟁을 재현한다.
- 결정·근거(한글 경로): Java 런처는 `@` 인자 파일을 시스템 기본 인코딩으로 읽는다. UTF-8로 쓴 클래스패스가 한글 경로에서 깨져 자식 JVM이 `ClassNotFoundException`으로 끝났다. 인자 파일을 `native.encoding`으로 쓴다.
- 재발 원인: CI `backend:build`는 `bootJar`만 실행하고 테스트는 돌리지 않는다. 180 기록도 전체 Backend 테스트가 중단되어 통과로 보지 않았다.
- 검증: 수정 전 세 클래스에서 3건 실패를 재현했고 수정 후 11건 통과했다. 수정 전 `SourceCardTest`는 27분 동안 멈췄고 수정 후 14건이 32초에 통과했다. 한글 경로에서 `PlanetoryApplicationCommandModeTest` 5건이 통과했다. 한글 작업 경로에서 로컬 PostgreSQL 15432와 일회용 컨테이너로 전체 `./gradlew -PskipLocalDb test`를 돌려 71개 클래스, 746건 중 실패 0건을 확인했다. 건너뛴 1건은 환경 변수로 켜는 `LocalSeedSmokeTest`다.
- 관련 문서: [Jira 84](https://ssafy.atlassian.net/browse/S15P21C206-84), [통계 실행 런북](../../operations/statistics-runbook.md)
- 후속 작업: CI에서 Backend 테스트를 돌릴지는 `backend:build` 주석의 기존 과제로 남는다.
