## [S15P21C206-78] 최초 BLS 재사용·반복 탐색 연결

- 수정자: S15P21C206-78 작업 / Codex
- 유형: 데이터
- 상태: 구현·로컬 검증, 실제 YARN Canary 전
- 변경 범위: `astro_kernel.bls`·`iteration`, Silver 배치·제어기·계약 검사, 커널/Spark/데이터 정본
- 목적: 같은 TIC의 최초 20,000점 BLS를 중복 실행하지 않으면서 반복 제거 QA를 별도 Silver stage에 기록한다.
- 결정·근거: 최초 결과는 입력 배열·Sector·baseline·버전·count를 묶은 SHA-256이 일치할 때만 첫 반복에서 재사용한다. 제거 후 탐색은 새로 계산한다. `iteration` 결과와 stage별 manifest·READY 감사는 완료·미완료·실패를 분리하며 DB 후보 ID·Gold 공개는 생성하지 않는다. 기존 v2 attempt와 혼동하지 않도록 출력 계약은 v3로 올린다.
- 검증: 커널·Spark 회귀 230건 통과, Silver 계약 스크립트 19건 중 18건 통과·별도 시스템 Python의 Astropy 미설치로 1건 건너뜀(`.venv`에서는 통과). 실제 Spark/PySpark·YARN 실행은 수행하지 않는다.
- 관련 문서: [122 공용 커널](../../../libs/astro-kernel/README.md#반복-bls제거-qa후보-출력-122), [Spark Silver](../../../distributed-system/spark/README.md#tess-bronze--silver-최초-탐색-s15p21c206-78), [Jira](https://ssafy.atlassian.net/browse/S15P21C206-78)
- 후속 작업: 1~5 TIC 실제 YARN Canary·장시간 성능 검사, 승인된 245 운영 마스크 manifest, Publisher의 이전 bundle·예약 ID·승인 근거를 통한 후보 동일성 인수.

## [S15P21C206-78] Silver Airflow 수동 실행 경계와 YARN 경합 방지

- 수정자: S15P21C206-78 작업 / Codex
- 유형: 데이터·운영
- 상태: 구현·로컬 검증, 운영 배포 전
- 변경 범위: Silver DAG·입력 계약·제한 sudo 설정, Bronze/Silver 제어기 실행 잠금, Canary 선택 스캔
- 목적: 현재 1~13 Bronze coverage의 Silver 실행을 Airflow에서 안전하게 제어하고 수집·Bronze와의 경합을 막는다.
- 결정·근거: 252의 14+ Sector `_READY`는 1~13 전체 coverage가 아니므로 자동 Silver로 연결하지 않는다. 78 DAG는 무스케줄·일시정지·명시적 coverage, 252 drain 확인과 `tess_yarn` Pool을 사용한다. 새 Bronze/Silver release는 Node 1 공통 잠금으로 YARN 제출 전체를 직렬화한다. 14+ 누적 snapshot·변경 TIC·혼합 버전 계약은 80에서 별도 승인한다.
- 검증: 커널·Spark·Airflow 순수 계약 246건과 12 subtest 통과, Silver 스크립트 21건 중 20건 통과·시스템 Python의 Astropy 미설치로 1건 건너뜀. 서버 Airflow 2.10.5 인메모리 import, Bash 및 sudoers 문법 통과. 실제 DAG 배포·Pool/sudo 적용·YARN 실행은 미수행.
- 관련 문서: [Silver DAG](../../../distributed-system/airflow/dags/README.md), [Spark Silver](../../../distributed-system/spark/README.md), [Jira 78](https://ssafy.atlassian.net/browse/S15P21C206-78), [Jira 80](https://ssafy.atlassian.net/browse/S15P21C206-80)
