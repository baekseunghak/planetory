## [S15P21C206-237] 별도 Redis 세션 저장소와 장애 경계

- 수정 주체: 서비스 백엔드 인증 작업
- 유형: 아키텍처 · 운영 · 오류 정정
- 상태: 구현 완료, 격리 통합 검증 완료
- 변경 범위: Spring Session Redis 의존성·두 연결·저장 경계·오류 필터·인증 서비스·테스트·OAuth/회원/아키텍처 정본
- 목적: 단일 앱 재시작 후 로그인 유지와 계산 캐시 장애의 인증 경로 분리를 구현한다.
- 결정·근거: 사용자 승인 2026-09-22. 세션 상태는 Redis에만 보관하며 단일 앱의 저장·삭제·활동 갱신만 같은 잠금으로 처리한다. 30분 idle·활동 시각/TTL 단조 증가와 늦은 저장의 세션 재생성 차단을 유지한다. 두 연결·잠금 대기 타임아웃은 각각 2초다. 다중 앱은 범위 밖이다.
- 검증: 전체 백엔드 build와 608개 테스트가 통과했다. 일회용 PostgreSQL·별도 Redis 두 개에서 실제 HTTP Google형 OIDC/SSAFY형 OAuth 교환, 인가중·로그인후 앱 컨텍스트 종료/재기동, 토큰/로그아웃/만료, 늦은 저장·ID 교체·활동 시각 역전, 캐시 장애 중 인증 조회/쓰기, 세션 읽기·응답 직전 저장 장애503을 검증했다. 합성 authorized client의 Redis 저장/조회 직렬화도 통과했다. 세션 장애 중 병렬 3요청은 15초 이내 503으로 완료했다. 응답 전체 복사를 제거하고 Spring Session 기본 커밋 훅으로 1MiB 응답 정상·저장 실패를 확인했다.
- 선행 변경: 234의 SecurityConfig·AuthIntegrationTest·서비스 API·OAuth 설정·account 문서 5파일을 선행 패치로 복사했다. 234의 프론트 테스트·변경 이력은 중복 복사하지 않았다. 237 고유 변경과 선행 패치는 별도로 인계한다.
