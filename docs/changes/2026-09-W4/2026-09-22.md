## [S15P21C206-84] MR 단계 마이그레이션 검사가 실행되지 않던 결함 수정

- 수정자: 김동혁, Claude
- 유형: 운영
- 상태: 수정·MR 파이프라인 통과 확인
- 변경 범위: `.gitlab/ci/apps/backend.yml`, `docs/project/service-deploy-status.md`
- 목적: MR !161이 `backend:schema` 하나 때문에 계속 실패하던 것을 없애고, 마이그레이션 검사가 실제로 동작하게 한다.
- 결정·근거: `alpine/git` 이미지의 `ENTRYPOINT`가 `["git"]`이라 Runner가 붙이는 셸이 `git sh -c ...`로 조립되고 `git: 'sh' is not a git command`로 죽었다. 스크립트가 한 줄도 실행되지 않아 검사가 있으나 마나였다. 이미지를 바꾸는 대신 `entrypoint: [""]`로 비웠다. 타깃 브랜치의 마이그레이션 번호를 대조해야 하므로 git이 있는 이미지는 그대로 필요하다. 같은 함정이 있는 이미지가 더 있는지 전체 job의 image 지정을 훑었고 이것뿐이다.
- 검증: 서버에서 `docker inspect`로 `Entrypoint=["git"]`을 확인하고, 셸을 붙이면 실패하고 entrypoint를 비우면 `git version 2.45.2`가 나오는 것을 재현했다. 수정 후 MR 파이프라인이 통과했고 `backend:schema` 로그에서 타깃 브랜치를 가져와 develop의 최대 버전 `V19`와 대조한 뒤 「버전 선점 검사 통과」·「마이그레이션 검사 통과」가 찍혔다. `glab ci lint` 통과.
- 한계: 선점 충돌이 실제로 발생한 상황에서 이 검사가 MR을 막는 것은 아직 관찰하지 않았다. 로컬 재현으로만 확인했다.
- 관련 문서: [서비스 배포 현재 상태](../../project/service-deploy-status.md), [CI/CD](../../operations/cicd.md)
- 후속 작업: 없음. MR !161 리뷰로 이어진다.

## [S15P21C206-84] Runner 동시 실행을 3으로 올리고 Runner 대수를 정정한다

- 수정자: 김동혁, Claude
- 유형: 운영
- 상태: 적용·실측 완료
- 변경 범위: `docs/operations/cicd.md`, 빌드 노드의 Runner 설정(저장소 외부)
- 목적: job을 `needs: []`로 병렬 설계해 두었는데 실제로는 전부 직렬로 돌던 것을 해소한다.
- 결정·근거: GitLab의 제약이 아니라 Runner의 `concurrent`가 등록 기본값 `1`로 남아 있었다. Runner는 job을 실행하는 셸이 아니라 job마다 컨테이너를 띄우는 관리 프로세스이므로, 한 대로도 여러 job을 동시에 처리한다. 따라서 Runner를 추가하지 않고 `concurrent`만 `3`으로 올렸다. `4`는 쓰지 않는다. 빌드 노드가 vCPU 4개이고 dind와 레지스트리가 같은 노드에 있어 경합이 커지면 벽시계 이득이 줄고 레지스트리 응답이 밀린다. 문서가 적어둔 「Runner 두 대」는 현재와 다르다. 실제로는 한 대가 `amd64-docker` 태그와 `run_untagged=true`로 전체 job을 받고 있어 목표 배치와 현재 상태를 구분해 적었다.
- 검증: 같은 MR 파이프라인의 job 8개로 전후를 쟀다. 동시 실행 최대가 1개에서 3개로, 벽시계가 202초에서 126초로 줄었다(38% 단축). job 소요 합계는 201초에서 250초로 늘어 경합도 함께 확인했다. job 로그의 컨테이너 이름이 `concurrent-0`·`concurrent-1`·`concurrent-2`로 나뉘는 것과, 8개 job이 모두 `planetory-docker-runner` 한 대에서 돈 것을 확인했다. 두 파이프라인 모두 통과했다.
- 한계: 벽시계 하한은 가장 긴 `backend:image` 약 106초다. 더 줄이려면 이미지 레이어 캐시가 필요하며 이 작업 범위가 아니다. `concurrent` 값은 서버 설정이라 저장소가 보장하지 않는다. 되돌릴 백업은 빌드 노드의 `config.toml.bak-concurrent-20260922`다.
- 관련 문서: [CI/CD](../../operations/cicd.md)
- 후속 작업: aarch64 CI 노드를 붙일지 여부는 별도로 정한다. 붙이면 태그 분리가 실제로 동작한다.
