# 2026-09-26 주요 변경

## [S15P21C206-86] Publisher 재시도 요약 규칙을 적재로 옮기고 적재 DB 테스트·CI 검사 추가

- 수정자: 김동혁(Claude Code 보조)
- 유형: 데이터
- 상태: 검증 완료(GitLab 브랜치 파이프라인 통과, MR 전)
- 변경 범위: `distributed-system/publisher/publisher/load.py`(`payload_digest` 추가, `publish_star`), `distributed-system/publisher/test_load.py`(신규), `.gitlab/ci/distributed-system/publisher.yml`(`validate:publisher`), [Publisher README](../../../distributed-system/publisher/README.md), [CI/CD](../../operations/cicd.md) 「설정·계약 검사」
- 목적: 86 완료 조건(DB 재시도 키, 같은 키 다른 내용 충돌, 세그먼트 재사용, 부분 실패 rollback, 동시 실행)을 실제 PostgreSQL 검사로 고정한다.
- 결정·근거:
  - 재시도 요약(`payload_digest`) 규칙을 입력 어댑터가 아니라 적재가 가진다. 262까지는 어댑터가 계산한 값을 그대로 믿어서, HDFS Gold reader가 다른 식으로 요약하면 같은 판을 다른 판으로(또는 반대로) 판정할 수 있었다. 식은 로컬 시드·목업과 같게 둬서 이미 적재된 행과 맞는다. 어댑터가 준 값이 다르면 쓰기 전에 `PUBLISH_REJECTED`로 멈춘다.
  - 테스트는 로컬 시드와 같은 방식(일회용 스키마에 저장소 마이그레이션 전체를 Flyway 없이 적용)이지만, 실험 코드를 옮기지 않고 Publisher의 표준 라이브러리 `unittest`로 새로 썼다. 의존성은 늘리지 않았다.
  - 동시 게시 검사는 TIC 잠금을 먼저 쥐고 두 게시가 모두 기다리는 것을 `pg_locks`로 확인한 뒤 놓는다. 스레드를 동시에 출발시키는 방식은 겹침을 보장하지 않는다.
  - 후보 동일성 대조는 86 범위 밖이다([후보 병합·분리 정정 계약](../../architecture/candidate-correction-contract.md), C18·C19).
  - 86의 "배열 길이/단위"는 DB CHECK(V1: `cardinality(flux) = n_points`, `cardinality(power) = n_periods`, `bin_minutes > 0`, `0 < period_min_days < period_max_days`)가 강제하고, 위반 시 앞서 넣은 행까지 전부 rollback됨을 테스트로 고정했다. manifest에 단위 메타데이터가 없어 적재가 단위를 따로 대조하지 않는다. `base_days`·후보 수치 범위는 게시 전 QA 범위로 남긴다.
- 검증: 로컬 일회용 `postgres:18.6-alpine`에서 Publisher 테스트 21건 통과(기존 10, 적재 11). CI와 같은 `python:3.12-slim` 컨테이너와 서비스 별칭 `publisher-db` 구성으로 job 스크립트를 그대로 돌려 21건 통과. TIC 잠금 제거와 요약 대조 제거 두 변이에서 각각 동시 게시·내용 충돌 테스트가 실패하는 것을 확인했다. DB 주소가 없으면 적재 테스트는 건너뛴다. GitLab 브랜치 파이프라인 `223029`에서 `validate:publisher`(job `641674`, `planetory-docker-runner`)가 성공했고 21건 모두 ok였다.
