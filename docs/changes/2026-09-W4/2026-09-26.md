## [S15P21C206-94] GCP Docker 배포 job 제거와 release 방식 유지

- 수정자: Claude(김동혁 요청)
- 유형: 운영
- 상태: 구현 완료(MR 전)
- 변경 범위: `.gitlab-ci.yml`, `.gitlab/ci/common.yml`, `.gitlab/ci/distributed-system/`, `docs/operations/cicd.md`, `docs/operations/docker.md`, `infra/distributed-system/README.md`, `docs/architecture/gcp-distributed-infrastructure.md`
- 목적: 실제 GCP 실행이 쓰지 않는 CI Docker 배포 경로를 걷어내고, 정본을 현재 배포 방식(불변 release)에 맞춘다.
- 결정·근거: 수집·HDFS 적재·Spark Bronze는 release 디렉터리를 호스트 Python·systemd로, Spark 제출은 digest를 고정한 공개 이미지로, Airflow는 Node 1이 release에서 빌드한 로컬 이미지로 돈다. CI의 ingestion·spark-job·airflow 레지스트리 이미지와 GCP 배포 job 7개는 사용처가 없었다. `S15P21C206-262`에서 정한 GCP 배포 버튼 보호 방식(빌드 `interruptible: false`, 노드별 `environment`, 자동 취소 방식 변경)은 쓰지 않는다. `build:publisher`는 EC2-A `gold-mock`이 쓰므로 남긴다.
- 검증: GitLab CI Lint dry-run(`ref=develop`) `valid: true`. 변경 전 develop 설정 대비 job 10개(GCP 배포 7·빌드 3)만 빠지고 15개는 그대로, 추가 0. 실제 파이프라인은 병합 뒤 확인한다.
- 관련 문서: [CI/CD 「GCP 분산 시스템」](../../operations/cicd.md), [S15P21C206-94](https://ssafy.atlassian.net/browse/S15P21C206-94)
- 후속 작업: release에 커밋 SHA 기록(94 원래 범위), 쓰는 곳이 없는 `compose.worker.yaml`과 `deploy.sh` 복수 서비스 분기 정리 여부, GitLab 프로젝트 변수 `GCP_NODE_*_HOST`·`GCP_NODE_*_DEPLOY_PATH` 정리, 94 티켓 범위 수정
