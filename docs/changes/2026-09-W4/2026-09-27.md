- 상태: 수정·로컬 검증 완료. 첫 운영 게시(ready 4,916) 전에 반영한다.
- 변경 범위: `distributed-system/publisher/publisher/notify.py`·`__main__.py`(`exit_code`)·`load.py`(`publish_star` 별 upsert, `publish_outcome`), `test_notify.py`·`test_load.py`·`test_run_source.py`, [Publisher README](../../../distributed-system/publisher/README.md) 「배치 run」, [코드 구조](../../architecture/gold-batch-publish.md) 6장, [EC2 서비스 배포](../../../infra/service/README.md#node-1-실행)

- 결정·근거
  - 알림: Backend 응답을 기다리다 난 시간 초과(`TimeoutError`)·연결 끊김(`RemoteDisconnected`)은 `URLError`로 감싸지지 않아 publish-run을 멈췄다. 이제 그 판의 실패로 남긴다.
  - 종료 코드: 알림 일부 실패는 0이다. 1로 두면 같은 알림 실패에 1.35 GB 재수신과 전체 재실행이 되풀이되다 DAG가 실패한다. DB current가 정본이고 실패한 판은 `notify`로 다시 보낸다.
  - 예외 범위: `publish_outcome`은 `InterfaceError`를 일시 장애로, 그 밖의 예상 밖 오류를 그 별의 `PUBLISH_REJECTED`로 기록한다. 이전에는 run 기록 없이 run 전체가 멈췄다.
  - 기존 별 속성: 배치 run은 별 속성(teff·radius·tmag) 원천이 없어 NULL을 보낸다. current 판이 없는 기존 별의 값을 NULL로 덮지 않게 `COALESCE`로 둔다.
  - 반영하지 않은 지적: 재실행 때 ALREADY_PUBLISHED 판도 다시 알리는 것은 그대로 둔다(앞선 실행이 알림 전에 끊겼을 수 있다). 알림을 차례로 보내는 것도 첫 게시에서 시간을 잰 뒤 정한다.
