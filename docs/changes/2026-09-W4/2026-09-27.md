## [S15P21C206-85] Publisher의 Node 1 → EC2-A 서비스 DB 적재·알림 경로 결정

- 수정자: Claude(김동혁 요청)
- 유형: 아키텍처 | 운영
- 상태: 채택(운영 적용·검증 전)
- 변경 범위: `infra/service/compose.yaml`(`service-db` `127.0.0.1:5432`), `infra/service/README.md`, `docs/architecture/system-architecture.md` 7·10장, `docs/operations/tailscale-team-access.md`, `distributed-system/publisher/README.md`, `infra/distributed-system/README.md`
- 목적: 배치 사슬이 끝난 뒤 실제 Gold를 운영 DB에 넣는 경로를 연다. 10장 미확정 항목을 해소한다.
- 결정·근거: A안(tailnet 상시 경로)을 채택했다. DB·Backend는 loopback에만 바인드하고 `tailscale serve --tcp 5432·8080`으로 넘긴다. tailnet IP 직접 바인드는 부팅 때 IP가 늦게 붙으면 `service-db`가 뜨지 못해서 택하지 않았다. serve가 출발지를 가리므로 `pg_hba`로 Node 1을 가려낼 수 없다. 출발지 통제는 Tailscale ACL 하나이고, Node 1에는 `planetory_publisher` 비밀번호만 둔다. 알림은 같은 경로를 쓰고 실패하면 `notify --bundle`로 다시 보낸다. 비밀 값은 Node 1 root 전용 env 파일에 둔다.
- 검증: `docker compose config -q` 문법 확인만 했다. 운영 적용·ACL 변경·접속 거절·끊김 롤백은 확인하지 않았다.
- 관련 문서: [EC2 서비스 배포](../../../infra/service/README.md) 「Publisher 운영 적재 경로」, [시스템 아키텍처](../../architecture/system-architecture.md) 7장
- 후속 작업: EC2-A `service-db` 재생성과 `tailscale serve` 설정, Admin Console ACL 변경, Node 1 env 파일 배치, 완료 조건 검증

## [S15P21C206-85] Publisher 적재 경로 운영 적용·ACL 분리·검증

- 수정자: Claude(김동혁 요청)
- 유형: 운영
- 상태: 검증 완료(MR 병합 전)
- 변경 범위: EC2-A 배포 경로 `compose.yaml`·`service-db`·`.env`(`INTERNAL_SERVICE_TOKEN`)·Backend 재생성·`tailscale serve`, Tailscale ACL(`tag:service`·`tag:publisher`), Node 1 env 파일, `infra/service/README.md`, `docs/operations/tailscale-team-access.md`, `docs/project/service-deploy-status.md`
- 목적: 결정한 경로를 운영에 열고 완료 조건을 실측한다.
- 결정·근거: ACL은 허용만 있어 `ec2-a`를 `tag:hadoop`에서 `tag:service`로 옮겨야 5432·8080을 닫을 수 있었다. 멤버·CI의 SSH 22와 `ec2-a`의 Registry pull은 새 규칙으로 옮겼다. `ec2-b`의 `tag:hadoop`은 이 작업과 무관해 그대로 뒀다. 목업 재실행은 `ALREADY_PUBLISHED`에도 알림을 보낸다(코드 `notify_targets`). 이와 다르던 README 서술을 고쳤다.
- 검증: node-1만 5432·8080 연결(멤버 PC·EC2-B·node-2 시간 초과), 공인 주소 5432·8080·3000 시간 초과, 임시 hidden 별 게시·재실행 `ALREADY_PUBLISHED`·알림 200 두 번, 판 INSERT 대기 중 연결을 끊었을 때 관측·세그먼트·판 0행·current 5개 유지, 로그·이미지에 비밀 값 없음. 시험 데이터는 모두 지웠다.
- 관련 문서: [EC2 서비스 배포](../../../infra/service/README.md) 「Publisher 운영 적재 경로」, [서비스 배포 현재 상태](../../project/service-deploy-status.md)
- 후속 작업: MR 병합 전까지 `service-db` 재생성 금지(포트 소실). 공인 주소 22번 개방은 85 이전부터의 상태로, 보안그룹 출발지 제한 여부 미확인. 「손으로 넣은 데이터」 표가 운영 DB와 다름(더미 별·목업 판 없음)
