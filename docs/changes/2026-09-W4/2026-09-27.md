## [S15P21C206-272] 전환 SQL이 보상 별의 회원 기록을 남기는 문제

- 수정자: 김동혁(Claude Code 보조)
- 유형: 오류 정정
- 상태: 스크립트 보완과 회귀 테스트 로컬 검증 완료, 운영 영향 없음 확인, develop 병합 전
- 변경 범위: `distributed-system/publisher/publisher/tutorial_switch.sql`(머리 주석, 멈춤 검사 추가), `distributed-system/publisher/test_load.py`(`TutorialSwitchTest`), [Publisher](../../../distributed-system/publisher/README.md) 「튜토리얼 5종」
- 목적: 옛 1번 성과로 열린 별에 회원이 이어서 탐사했으면, 전환이 접근 권한·진행도만 지우고 제출·분석 기록·성과를 남긴다. 그러면 회원은 접근할 수 없는 별의 기록을 갖고, 개요의 성과 합계는 그대로인데 발견한 별 수만 준다(!226 백승학 P2, 강재민 보강).
- 결정·근거:
  - 머리 주석의 "외래 키가 막아 rollback된다"는 틀렸다. 그 기록들은 `star_unlocks`·`user_star_progress`를 참조하지 않는다(V1).
  - 지우지 않고 멈춘다. 회원이 실제로 한 작업이라 게시글·공개 분석처럼 사람이 정할 대상이다. 멈추므로 보상 별의 성과 알림까지 넓혀 지울 필요도 없다.
- 검증: 일회용 PostgreSQL 18.6(CI `validate:publisher`와 같은 이미지)에 마이그레이션 전체를 적용하고 `test_load`를 돌려 13건이 통과했다. 새 테스트는 수정 전 SQL에서 실패한다(`RaiseException not raised`).
- 운영 영향: 없다. 2026-09-27 운영 DB 읽기 전용 조회에서 접근 권한(`star_unlocks`) 없는 별에 남은 제출·분석 기록·성과가 각각 0건이었다. 성과로 열린 별은 0개, 별은 6개(튜토리얼 5종과 숨긴 `261136679`)다. 더미 별 삭제 일회성 SQL이 더미 별의 제출·분석 기록·성과가 있으면 멈추게 돼 있었는데 오류 없이 끝난 것과도 맞는다.
