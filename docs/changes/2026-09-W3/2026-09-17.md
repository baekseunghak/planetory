## [S15P21C206-71] GCP 운영 접속을 tailnet 기본 경로로 전환

- 수정자: Codex (사용자 요청)
- 유형: 운영 · 문서
- 상태: 구현·실환경 접속 검증 완료
- 변경 범위: Tailscale 접근 가이드, GCP 운영·프로비저닝 절차, HDFS 다중 노드 설치 호출
- 목적: GCP 직접 SSH 대신 승인된 tailnet을 일상 로그인·점검·파일 전송과 설치 자동화의 기본 경로로 사용한다.
- 결정·근거: VM·디스크·VPC 등 GCP 제어 영역은 `gcloud`로 관리하되 원격 셸은 `tailscale ssh`, 파일 전송은 먼저 Tailscale 호스트 키를 검증한 뒤 같은 MagicDNS 이름의 `scp`를 사용한다. `gcloud compute ssh`는 최초 Tailscale 등록과 tailnet 장애 복구에만 남긴다.
- 검증: `SSAFY@node-1`은 `master-1`, `planetory-admin@node-2`부터 `node-6`은 각각 `worker-2`부터 `worker-6`으로 `tailscale ssh ... hostname -s`가 성공했다. HDFS 호출 스크립트의 오프라인 회귀 검사와 정적 계약 검사를 별도로 수행했다.
- 관련 문서: [Tailscale 팀 서버 접근](../../operations/tailscale-team-access.md), [GCP 노드 운영 런북](../../operations/gcp-node-runbook.md), [분산 시스템 운영 절차](../../../infra/distributed-system/README.md), Jira `S15P21C206-71`
- 후속 작업: 신규 노드는 GCP 비상 경로로 Tailscale을 최초 등록한 직후 tailnet 접속을 검증하고, 이후 운영 명령은 tailnet 경로로 수행한다.
