## [S15P21C206-149] 완료·재개 대기 판정 함수

- 수정자: Codex (강재민 요청)
- 유형: API · 구현
- 상태: 구현 완료
- 변경 범위: `ExplorationCompletionPolicy`, `ExplorationCompletionRepository`, `ExplorationCompletionService`, 완료 판정 테스트, 탐사 API 9.3절
- 목적: 제출·분석 진입·판 전환 후처리가 같은 완료 조건을 사용하도록 순수 판정과 상태 반영 경계를 공통 서비스로 고정한다.
- 결정·근거: 활성 후보가 0건이면 완료하지 않는다. 탐색 가능한 미발견 후보가 없고 탐색 불가능한 미발견 후보만 남으면 `undiscoverable_only` 완료와 재개 대기를 함께 기록하며, 미발견 후보가 전혀 없으면 `all_found`로 완료한다. 판단 정답 여부와 성과 획득 여부는 완료 조건에서 제외하고, 판이 바뀌어도 후보 ID가 유지되므로 회원의 모든 판 제출에서 누적 매칭을 센다. 재개 뒤 재완료해도 최초 `completed_at`은 보존한다.
- 부수 효과 경계: 함수 자체는 성과나 새 별을 만들지 않는다. `no_candidate` 제출은 호출자가 완료 판정을 호출하지 않는다.
- 검증: 최신 `develop`(Jira `S15P21C206-139` 병합 포함)에서 순수 판정과 PostgreSQL 집계·잠금·상태 전환, 이전 판의 누적 매칭을 포함해 백엔드 전체 테스트 189건 통과(실패 0, 오류 0). MR 리뷰를 반영해 배음·중복 매칭 제외, `current` 판 확인 제거, 진행 행 `FOR UPDATE` 제거 결함을 각각 주입했을 때 대응 테스트가 실패하는 것도 확인했다.
- 관련 문서: [탐사 API 명세](../../../apps/backend/docs/exploration-api-spec.md) 9.3절, Jira `S15P21C206-149`
- 후속 작업: Jira `S15P21C206-140` 분석 진입, `S15P21C206-143` 제출 처리, `S15P21C206-150` 판 전환 후처리에서 이 서비스를 각 쓰기 트랜잭션 안에서 호출한다.
