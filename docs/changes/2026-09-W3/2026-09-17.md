- 결정·근거: (1) 회차 전환은 Jira 초안의 스케줄 작업 대신 운영자가 회차를 `active`로 바꾼 뒤 실행하는 전용 명령(`--planetory.command=challenge-unlock`)으로 한다. 앱은 DB 직접 변경을 알 수 없고 사용자가 주기 실행을 두지 않기로 정했다. 명령은 웹 서버 없이 뜨므로 `SecurityConfig`를 서블릿 앱에만 적용한다. (2) 튜토리얼 완료는 사용 중인 튜토리얼 별 5개를 모두 완료한 적이 있는지(진행 단계 completed 또는 `completed_at`)로 판정한다. 새 판 재개가 진행 단계를 되돌려도 이미 받은 챌린지 별은 남으므로 완료와 다음 회차 자격도 유지해야 어긋나지 않는다. 운영 중 튜토리얼 별은 바꾸지 않는다는 전제다. (3) 챌린지 빨간 느낌표는 발견 경로가 아니라 퀘스트 `challenge.ticId`(진행 회차 대상 별)로 그린다. 경로 기준이면 성과로 먼저 찾은 회원에게는 붙지 않고 지난 회차 별에는 계속 남는다. 회차 전환·종료는 회원 지도 버전을 바꾸지 않아 타일 표식으로는 갱신되지 않으므로 4.1절 `marker`에서 challenge를 뺐다. 대상 별을 이미 발견한 회원의 경로는 새로 기록하지 않는다(서비스 F17-Q2 제안). (4) `newDiscoverableCount`는 재개 이벤트 저장이 정해질 때까지(S15P21C206-150) null로 둔다. (5) 가입 초기화가 이미 열린 별에도 지도 버전을 올리던 결함을 공통 함수에서 고쳤다. 회차 전환처럼 다시 실행하는 경로가 생겨 프론트가 바뀌지 않은 지도를 다시 받게 되기 때문이다.
- 검증: 백엔드 전체 테스트 165건 통과. 신규 34건은 동시 가입, 사유별 다음 순번과 성과 없음, 같은 사건 재처리, 다음 순번 미설정 503, 회차 전환 재실행·탈퇴 회원 제외, 다섯 번째 완료와 회차 전환 동시 실행, 처리 도중 회차 종료, 재개된 튜토리얼 별의 완료·자격 유지, 퀘스트 패널 계약·JSON 형태, 지도·상세·목록 표식에 챌린지가 없음, 명령 모드 기동·종료 코드를 본다. 결함 주입 16건을 모두 검출했다. 빌드한 jar를 로컬 DB 일회용 스키마에서 명령으로 실행해 진행 회차 없음 2, 처리 완료 0, 재실행 시 새로 연 회원 0명, 처리 도중 회차 종료 1, 재실행 시 남은 회원만 여는 것을 확인했다. `node docs/development/sky-reference/validate.mjs`·`node docs/api/exploration/validate.cjs` 통과, `git diff --check`와 변경 문서 상대 링크를 확인했다.
