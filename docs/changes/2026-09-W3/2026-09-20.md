## [S15P21C206-246] 별·회원 경로 식별자 형식 정합과 500 응답 정정

- 수정자: 강재민 (Claude 보조)
- 유형: 오류 정정 · API
- 상태: 구현·검증 완료 · 리뷰 대기
- 변경 범위: `StarController`, `ExplorationIds`, 탐사 API 4.2·4.4·4.5절
- 목적: 회원 API가 주는 `u-{id}`를 타인 별 목록 경로에 그대로 넣으면 500이 나던 문제를 고친다. S15P21C206-216 실제 연결 검증에서 발견했다.
- 결정·근거: 경로·쿼리 값을 숫자 타입으로 받으면 변환 실패가 `MethodArgumentTypeMismatchException`이 되고 전역 처리기가 500으로 덮는다. 문자열로 받아 직접 판별한다. 회원 식별자는 서비스 API와 같은 `u-{id}`만 받고 숫자 단독은 같은 회원을 가리키는 다른 문자열이라 거절한다. 형식이 다른 TIC은 없는 별과 같은 응답(403·404)으로 덮어 별 존재가 드러나지 않게 한다. S15P21C206-140의 분석 API가 이미 쓰던 방침이다.
- 검증: 실제 회원 ID와 운영 로그인 경로로 만든 세션을 쓰는 HTTP 테스트 7개. 공개 목록 200, 비공개 403 `STAR_LIST_PRIVATE`, 계약 밖 식별자·`size` 400, 형식이 다른 TIC 403·404를 확인했다. 수정 전 코드로 되돌리면 7개 중 6개가 실패한다. 백엔드 전체 테스트 통과.
- 관련 문서: [탐사 API 4.2·4.4·4.5절](../../../apps/backend/docs/exploration-api-spec.md#42-선택한-별내-행성-상세), [Jira](https://ssafy.atlassian.net/browse/S15P21C206-246)
- 후속 작업: 없는 회원의 별 목록이 지금은 공개 기본값을 타 200 빈 목록이다. 프로필 조회(404)와 다르고 비공개 회원(403)과도 갈려 회원 존재가 드러난다. 계약을 정해 함께 맞춘다.
