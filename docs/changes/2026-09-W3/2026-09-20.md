## [S15P21C206-187] 거절된 제출을 고쳐서 다시 낼 수 있게 함

- 수정자: 백지웅 (Claude 보조)
- 유형: 오류 정정
- 상태: 구현 완료 · 실제 API 인수 대기
- 변경 범위: 요청 ID 저장·예약, 제출 훅, [분석 제출 개발 안내](../../../apps/frontend/docs/analysis-submission.md), 단위·화면 회귀.
- 목적: MR 리뷰가 짚은 P2를 고친다. **P1을 고치면서 만든 회귀다.**
- 발견: 400 거절 뒤 저장 기록이 `pending`으로 남아, `reserveRequestId`가 고친 본문에 자리를 내주지 않았다. 화면이 「결과를 확인하지 못한 제출이 있어 이번 제출을 보내지 않았습니다」로 막아 **입력을 고쳐도 다시 낼 수 없었다.**
- 결정·근거: 막는 기준을 「끝나지 않음」에서 **「결과를 모름」**으로 바꾼다. 상태에 `rejected`를 더해, 서버가 응답으로 거절한 제출은 미접수가 확정이므로 다른 본문에 자리를 내준다.
- 결정·근거: 403·404는 `rejected`로 두지 않는다. 앞선 전송이 응답만 잃고 접수돼 그 별이 완료됐을 수도 있어, 같은 4xx라도 입력이 틀렸다는 답과 성격이 다르다. 결과를 모르는 실패(5xx·타임아웃)도 그대로 `pending`이다.
- 결정·근거: 기록을 **지우지 않는다.** 같은 본문을 그대로 다시 내면 같은 ID로 보내 서버가 같은 답을 주고, 고쳐서 내면 지문이 달라 새 ID를 받는다. 미해결 기록을 일괄로 지우면 복구 경로가 사라진다.
- 검증: 타입 검사·운영 빌드 통과, 단위 276개, Chrome 회귀 149개 통과(GPU 3건 건너뜀). 화면 회귀가 400 → 입력 수정 → 재제출에서 **두 번째 POST가 실제로 나가고 ID가 다른 것**을 본다. 고치기 전 코드로 돌려 이 검사가 리뷰의 증상 그대로 실패하는 것을 확인했다. 유실 응답·404 복구가 같은 ID를 쓰는 기존 검사는 그대로 통과한다.
- 관련 문서: [탐사 API 2.2](../../../apps/backend/docs/exploration-api-spec.md), [분석 제출 개발 안내](../../../apps/frontend/docs/analysis-submission.md), Jira `S15P21C206-187`.
- 후속 작업: 없음.
