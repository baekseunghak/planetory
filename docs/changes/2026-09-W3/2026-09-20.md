# 2026-09-20 주요 변경

## [S15P21C206-76] Sector 1~13 HDFS coverage와 원자 커밋 보강

- 수정자: Codex (사용자 요청)
- 유형: 데이터 · HDFS 운영 · 오류 정정
- 상태: 구현 완료 · 오프라인 검증 완료 · 실환경 검증 대기
- 변경 범위: TESS HDFS plan·감사·커밋 도구, Sector 1~13 runner, Hadoop 용량 설정과 데이터 운영 문서
- 목적: 75의 두 Run 최종 coverage를 76의 유일한 입력으로 연결하고, 기존 Sector 3~5를 재사용하면서 Sector 1·2·6~13을 같은 불변·감사 계약으로 적재한다. 동시에 final 경로가 이미 존재할 때 HDFS `mv`가 하위 디렉터리로 중첩할 수 있는 경쟁 조건을 제거한다.
- 결정·근거: FinalCoverage의 schema·sidecar·전체 247,824개·Sector 1~13·기존/확장 Run 분리를 검증해 Sector별 원천 run·release·source SHA·개수·바이트를 plan v2에 고정한다. 기존 v1 Sector 3~5 marker는 호환 재감사하고, 신규 bundle은 첫·중간·마지막 레코드를 복원한다. 확정은 Java `FileContext.rename(..., Rename.NONE)`만 사용하며 13개 Sector가 모두 성공한 뒤 각 `_READY.json` digest를 묶은 HDFS coverage marker를 별도 원자 확정한다. SequenceFile compression은 원본 바이트 복원 단순성을 위해 `NONE`을 유지하고 benchmark 전에는 바꾸지 않는다.
- 용량·복구 경계: Sector마다 적재 직전 safe mode·Live DataNode·RF2·Worker 가용 공간을 다시 확인하고 RF2 예상 사용률 70% 이하를 요구한다. `dfs.datanode.du.reserved`는 DataNode당 100GiB로 선언·검사한다. uploader의 `NRestarts`는 0을 불변 조건으로 두지 않고 관측값으로 기록하며, 재시작 뒤 최종 감사 통과 여부로 완료를 판정한다.
- 검증: Python 단위 검사 8개와 PowerShell parser·계약 검사를 통과했다. FinalCoverage lineage·중복/누락 Sector, plan cache exact match, first/middle/last 복원, 알 수 없는 artifact 거부, legacy marker, HDFS coverage와 `Rename.NONE` 계약을 검사했다. 실제 Hadoop cluster에서의 Java 컴파일·설정 rollout·DataNode 재시작·Sector 1~13 적재는 실행하지 않았다.

- 후속 작업: 75의 FinalCoverage 완료와 SHA-256을 확인한다. 기존 DataNode에 100GiB 예약 설정을 통제된 순서로 반영·재시작하고 Preflight를 통과한 뒤 Sector 1~13 RunAll과 최종 HDFS coverage 감사를 수행한다.
