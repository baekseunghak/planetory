- 결정·근거: **ID 폐기를 사다리에서 들어냈다.** 2.2절이 새 ID 발급을 사용자의 선택으로 정했으므로, `BUNDLE_CHANGED`의 [최신 자료 불러오기]와 `IDEMPOTENCY_CONFLICT`의 [별도 제출로 보내기]를 눌렀을 때만 버린다. `submitAnalysis`의 `releaseRequestId` 인자가 죽은 코드가 되어 없앴다.

- 결정·근거: 거절(`STAR_LOCKED`·`STAR_ALREADY_COMPLETED` 등)도 ID를 버리고 있었다. **앞선 전송이 응답만 잃고 접수돼서 그 별이 완료됐을 수도 있다.** 확인할 길이 그 ID뿐이므로 버리지 않는다.
- 발견(재발 방지): **새로고침이 미해결 요청을 지웠다.** 요청 ID는 저장소에 남는데 화면이 늘 `idle`로 시작해 복구 경로가 사라지고, 다른 제출이 그 기록을 덮어썼다. 저장 기록에 `kind`·`body`·`state`·`sentAt`을 더해 판 2로 올리고 진입 때 되살린다. **`state`가 없으면 되살릴 수 없다** — 접수에 성공해도 기록은 남으므로 기록의 존재만으로는 미확인인지 알 수 없다.
- 발견(계약): `SUBMISSION_CONTEXT_NOT_READY`(409)가 이름 없는 거절로 떨어져 ID를 버렸다. 계약은 `keep`이며 `residual`로 잔차 준비를 안내한 뒤 같은 본문·ID로 재전송이다.
- 검증: 타입 검사·운영 빌드 통과, 단위 274개, Chrome 회귀 148개 통과(GPU 3건 건너뜀). 화면 검사가 유실→새로고침→복구, 404 뒤 같은 ID·본문 재전송, 충돌 뒤 별도 제출, 판 교체 후 실제 재조회를 각각 따라간다.
- 관련 문서: [탐사 API 2.2·2.3](../../../apps/backend/docs/exploration-api-spec.md), [분석 제출 개발 안내](../../../apps/frontend/docs/analysis-submission.md), Jira `S15P21C206-187`.

- 관련 문서: [제출 결과·해설 개발 안내](../../../apps/frontend/docs/analysis-result.md), [Figma 탐색안](https://www.figma.com/design/8UxcdnpcIfalyXQaf2RjEM/?node-id=13-2), Jira `S15P21C206-188`.
- 후속 작업: 없음. 1024px 화면에서 축 칸의 긴 줄이 두 줄로 접히는 것은 의도한 동작이다.

## [S15P21C206-188] 상세 보기를 비교표에 합침

- 수정자: 백지웅 (Claude 보조)
- 유형: UI
- 상태: 구현 완료 · 실제 API 인수 대기
- 변경 범위: 결과 화면의 상세 보기·비교표, 접수 대화상자, 화면 회귀, [제출 결과·해설 개발 안내](../../../apps/frontend/docs/analysis-result.md).
- 목적: 상세 보기를 열면 되살아나던 세로 스크롤을 없앤다.
- 결정·근거: **상세가 비교표와 같은 수치를 다시 싣고 있었다.** 매칭한 결과에서는 접수 응답의 신호가 정본이고 표가 이미 들고 있다. 상세가 새로 알려 주는 것은 설명 문장과 판단 일치 여부뿐이라 그것만 남긴다.
- 결정·근거: 미매칭은 신호를 **상세를 눌러야** 안다(6.7절). 그 값으로 별도 덩어리를 만들지 않고 표의 비어 있던 오른쪽 칸을 「이 단계의 신호」로 채운다. 내가 낸 값 옆에 있어야 견줄 수 있다.
- 결정·근거: 높이 상한을 86vh → 88vh로 올린다. 성과가 가장 많은 결과에 상세까지 연 경우가 668px이고 768px 높이 화면에서 86vh는 660px이라 10px이 모자랐다.
- 검증: 타입 검사·운영 빌드 통과, 단위 299개, Chrome 회귀 176개 통과(GPU 3건 건너뜀). 상세를 열었을 때 매칭 611 → 610px, 미매칭 490 → 522px, 최악 668px이며 1440×1080·1024×768 모두 넘침 0. 화면 검사가 「깊이」가 한 번만 나오는 것과 미매칭에서 칸이 둘 → 셋으로 느는 것을 본다.
- 관련 문서: [탐사 API 6.7](../../../apps/backend/docs/exploration-api-spec.md), [제출 결과·해설 개발 안내](../../../apps/frontend/docs/analysis-result.md), Jira `S15P21C206-188`.
- 후속 작업: **개발용 fixture가 신호의 주기를 제출값에서 만든다.** `signal.bls.periodDays = 제출 주기 × 배율`이라 비교표의 두 칸이 늘 같거나 정확히 배수다. 실제 서버는 Gold 후보 행의 값을 주므로 허용 오차만큼 다르다. 상세 응답은 별개로 `11.7346`을 고정으로 주어 같은 후보를 두 값으로 말한다. 화면이 아니라 fixture 문제이며 별도로 정리한다.
