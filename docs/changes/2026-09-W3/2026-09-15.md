- 목적: Spark 배치 반복 탐색(122)과 EC2 온라인 Worker(88, 김동혁)가 같은 수식으로 잔차곡선을 만들도록 순수 함수 하나로 고정한다.

PoC `residual_after_candidates` 의 수식은 옮기되 `joint_refit` 는 고정 모델 계약과 달라 제외했다. 모델 곱셈 순서를 정렬로 고정해 A+B/B+A 를 허용 오차 없이 같은 값으로 만들었다(같은 환경에서 비트 동일, 다른 언어·CPU 는 131 허용 오차). 시각 NaN 은 결측이 아니라 `invalid_time` 실패로 두어 "빈 제거는 flux 보존" 과 충돌하지 않게 했고, 유효 flux 위치에서 새 NaN·Inf·0 이하 결합 모델(곱셈 underflow 포함)은 부분 결과 없이 실패한다. 경계 `<`·깊이 하한·bin 시작/중심 평가·비유한 시각·baseline·버전 혼용은 v0 초안으로 두고 113 결정 항목으로 README 에 남겼다. ERD 의 `start_btjd = 첫 bin 시작 시각` 은 확정 사실이며 그대로 구현했다.

## [S15P21C206-134] Gold 적재·전환과 온라인 Worker 책임 경계 확정

- 수정자: 김동혁
- 유형: 아키텍처 · 데이터 · 문서 정합화
- 상태: 결정 반영 완료, 구현·운영값 검증은 후속 작업
- 결정: Publisher가 `planetory_gold_writer`로 Gold를 PostgreSQL에 직접 적재하고 `staging → current → archived` 전환까지 한 트랜잭션으로 처리한다. 커밋 후 Backend에는 `bundleId`만 멱등 알림하며, DB `current`를 정본으로 유지한다.
- 온라인 계산: Backend가 현재 판의 곡선 배열·고정 모델·버전을 별도 Python Worker에 전달한다. Worker는 DB·Redis를 직접 읽지 않고 `libs/astro-kernel`로 계산하며, Backend가 결과 채택 전에 current를 다시 확인한다. 상태·결과·키별 잠금은 Redis에 둔다.
- 후처리: Backend는 알림을 계기로 archived 판 Redis 캐시 정리, 완료 별 재개 판정, 외부 라벨 갱신 표식을 실행한다. Kafka는 현재 범위에 추가하지 않는다.
- 남은 값: Publisher DB 접속·알림 인증, Redis TTL·메모리 상한, 동시 계산 상한·시간 목표, Silver 보존과 수치 허용 오차.
