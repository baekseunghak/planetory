- 상태: 구현 완료 (계약은 v0 초안. D06 `S15P21C206-113` 승인과 88 담당자 계약 리뷰 전)
- 변경 범위: `libs/astro-kernel/` (패키지 `astro_kernel`, 테스트, `examples/` 계약 예제, README), `libs/README.md` 등록 행
- 목적: Spark 배치 반복 탐색(122)과 EC2 온라인 Worker(88, 김동혁)가 같은 수식으로 잔차곡선을 만들도록 순수 함수 하나로 고정한다.
- 결정·근거: 저장소 구조 문서의 "두 실행체가 공유하기로 확정될 때만 `libs/astro-kernel` 을 만든다" 조건을 121 의 목적(배치·온라인 공유)과 88·122 인계 관계가 충족한다. PoC `residual_after_candidates` 의 수식은 옮기되 `joint_refit` 는 고정 모델 계약과 달라 제외했다. 모델 곱셈 순서를 정렬로 고정해 A+B/B+A 를 허용 오차 없이 같은 값으로 만들었다(같은 환경에서 비트 동일, 다른 언어·CPU 는 131 허용 오차). 시각 NaN 은 결측이 아니라 `invalid_time` 실패로 두어 "빈 제거는 flux 보존" 과 충돌하지 않게 했고, 유효 flux 위치에서 새 NaN·Inf·0 이하 결합 모델(곱셈 underflow 포함)은 부분 결과 없이 실패한다. 경계 `<`·깊이 하한·bin 시작/중심 평가·비유한 시각·baseline·버전 혼용은 v0 초안으로 두고 113 결정 항목으로 README 에 남겼다. ERD 의 `start_btjd = 첫 bin 시작 시각` 은 확정 사실이며 그대로 구현했다.
- 검증: `uv run pytest -q` 회귀 통과(JSON·직접 생성 객체 파싱 실패 27종, 정확한 이진 경계 양쪽, 손계산 8점 예제, 빈 제거·6순열 비트 비교, 겹침·부분집합, 2·10·30분 해상도, flux NaN 보존과 time NaN 실패, underflow 로 Inf/0 실패, 예제 fixture 의 패키지 출력·순수 파이썬 독립 계산 일치). Codex 정적 리뷰 지적 5건(검증 우회, NaN 계약 모순, 새 NaN·Inf, 경계 테스트 정확성, 문서 정합) 반영.
- 관련 문서: [astro-kernel README](../../../libs/astro-kernel/README.md), [저장소 구조](../../architecture/repository-structure.md), [ERD](../../architecture/database-erd.md), [TESS 파이프라인 분석](../../data/tess-pipeline/README.md) 5절, Jira `S15P21C206-121`
