# 2026-09-18 주요 변경

## [S15P21C206-73] YARN 호스트 준비와 Spark HDFS sample 실환경 검증

- 수정자: Codex (사용자 요청)
- 유형: 운영 · 오류 정정
- 상태: 검증 완료
- 변경 범위: YARN 설정·systemd 설치·단계형 기동·UFW·Spark sample·정적 검증, 분산 인프라·운영·진행 상태 문서
- 목적: Node 1 ResourceManager와 Node 2~6 NodeManager를 안전하게 설치·기동하고 Spark 3.5.5 cluster mode가 HDFS를 읽고 쓰는 경로와 Node 2 자원 상한을 검증한다.
- 결정·근거: 서버 기본 파일이던 `capacity-scheduler.xml`을 단일 `root.default` queue 정본으로 저장소에서 관리한다. Node 1의 Docker 설치 책임은 제출 경로를 소유한 73번에 포함한다. Spark driver는 `7078`, block manager는 기본 재시도 범위 `7079~7095`로 고정하고 Worker 사설 IP 사이에서만 허용한다. 단일 `7079`만 허용하면 같은 노드의 추가 executor가 증가된 포트를 사용해 remote broadcast fetch가 멈췄다. Hadoop 3.5 daemon PID 실제 이름 `hadoop-yarn-*`과 unit 기대값 불일치, 고정 3초 준비 대기, HDFS 기본 staging 권한도 설치·기동·sample 스크립트에서 바로잡았다.
- 검증: ResourceManager 1개와 NodeManager 5개가 active이며 `worker-2`~`worker-6`은 모두 `RUNNING`이다. `application_1789675115055_0005`는 5개 Worker에 executor를 하나씩 배치해 HDFS 입력을 읽고 part 5개와 checksum을 남긴 뒤 `SUCCEEDED`, 로그 집계 `SUCCEEDED`로 끝났다. Node 2의 16GiB/2 vCore 한도에서 executor 1개 실행 중 호스트 used 약 2.7GiB, available 약 32.5GiB, swap 0, OOM 없음과 Standby NameNode RSS 약 556MiB를 확인했다. 성공 run 시작 뒤 6개 YARN daemon 로그의 새 ERROR·FATAL은 0건이고 HDFS Active/Standby·Live DataNode 5개도 유지됐다. Python 정적 검사, PowerShell parser, Bash 구문, 원격 변경 없는 회귀 검사도 통과했다.

- 후속 작업: 실제 Sector workload의 메모리·처리시간 상한과 재시도를 별도 PoC에서 측정한다. Node 2~6 Docker 설치는 수집 컨테이너 배포 작업에서 수행하고, YARN unit 부팅 자동 시작은 HDFS 재부팅·수동 Active 절차와 함께 운영 결정한다.
