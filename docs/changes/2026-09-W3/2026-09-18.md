# 2026-09-18 주요 변경

## [S15P21C206-228] GCP 6계정 quota·비용·크레딧·예산 알림 실측 기록

- 수정자: 김동혁 (Claude 보조)
- 유형: 운영
- 상태: 검증 완료 (6개 프로젝트 실측, 예산 알림 6개 계정 통일, 퍼블릭 IP·Cloud NAT 확인, 09-17 하루 사용액 정정)
- 변경 범위: `docs/operations/gcp-node-runbook.md` 7절
- 목적: 6개 GCP 프로젝트의 실제 quota·비용·크레딧·예산 상태를 확인하고, 2026-10-09까지 무료 크레딧 안에서 운영이 가능한지 판정한다.
- 결정·근거: 프로젝트 소유자 IAM만으로는 결제 계정을 조회할 수 없어(결제 계정은 프로젝트 하위 리소스가 아닌 별도 리소스) 각 결제 계정에 `roles/billing.admin`(4개)·`roles/billing.costsManager`(1개, 이후 admin으로 승격)를 추가로 받아 조회했다. 인스턴스·디스크·quota는 `gcloud`로, 크레딧 잔액과 만료일은 콘솔 크레딧 화면에서 확인했다. `planetory-0002`·`0003`·`0006`은 리전 `DISKS_TOTAL_GB` quota가 99%로 여유가 없다. 6개 계정 모두 크레딧 만료일이 목표 기한(2026-10-09)보다 늦어 만료가 아니라 소진 속도가 제약이다. 예산은 처음에 크레딧 총액을 모르는 5개 계정에 보수값 ₩380,000으로, `planetory-0001`은 기존 매월 리셋 중복 예산과 함께 만들어 6개 계정 기준이 갈렸다. 이후 전 계정 크레딧 총액을 확인해 각 계정 1개, 실제 크레딧 총액(0001 ₩435,523 / 나머지 ₩414,984), 기한 10-09, `EXCLUDE_ALL_CREDITS`, 50/80/100%로 통일하고 `planetory-0001`의 매월 리셋 중복 예산은 삭제했다. `EXCLUDE_ALL_CREDITS`가 없으면 크레딧 적용 후 금액(₩0)을 기준으로 삼아 크레딧을 다 쓸 때까지 알림이 오지 않는다. VM 생성일(9월 9-10일) 기준 27일 규칙은 10월 6-7일로 목표 기한(10-09)보다 이르다. 사용자 질의로 퍼블릭 IP와 예약 고정 IP를 혼동하지 않도록 6대 모두 외부 IP를 갖고 있음(master-1만 예약 static, 나머지는 임시)을 확인했고, 6개 프로젝트 모두 Cloud Router·NAT가 없어 이 외부 IP가 유일한 인터넷 아웃바운드 경로이며 NAT 없이 해제하면 Tailscale SSH와 `gcloud compute ssh` 비상 경로가 모두 끊긴다는 것을 확인했다. 임시 외부 IP 자체의 실측 과금은 0에 가까워 비용 정리 목적의 해제 실익도 없다.
- 정정: 09-17에 기록한 계정별 하루 사용액(`정가` 월 합계 ÷ 대략적인 가동일수, ₩11,587-13,819로 계정마다 제각각)은 계산 오류였다. 결제 보고서를 날짜별로 그룹화해 최근 안정 구간(9월 12일부터 16일까지)의 일별 실측값으로 다시 계산한 결과, `planetory-0003`·`0004-508301`·`0005`·`0006`의 하루 사용액은 ₩13,274-13,374로 사실상 동일했다(같은 인스턴스·같은 디스크 구성). `planetory-0002`만 ₩13,735-13,827로 metadata용 pd-balanced 100GB의 이론가(₩450-500/일)만큼 높았다. `planetory-0001`은 최근 3일 서비스별 내역에서 `Kubernetes Engine`·`Cloud Monitoring`이 ₩0으로 확인돼 완전히 해제됐고(API도 disabled), 9월 1일부터 8일까지 있었던 하루 ₩8,340-8,800 사용은 이 VM(생성 9-10) 이전의 별도 GKE 사용으로 이미 소진되어 현재 잔액에 반영된 매몰 비용이다. 현재 안정 하루 사용액 ₩10,035는 워커 기준(₩13,321/일)과의 차이(₩3,285/일)가 pd-standard 1,800GB(2030GB-230GB) 차이의 이론가(₩3,240/일)와 1.4% 오차로 일치해, 디스크를 줄여 둔 효과로 설명된다. 09-18 기준 재조회한 잔액도 `planetory-0003`·`0004-508301`·`0005`가 서로 300원 이내로 거의 같았는데, 0005는 생성일이 하루 빠르지만 첫날 실측 사용액이 정상 가동일의 약 5시간 분량(₩2,788)뿐이라 하루 일찍 생성된 효과가 상쇄됐고, 0006은 정상 가동이 하루 더 빨라 이 셋보다 잔액이 하루치(약 ₩10,000)만큼 적었다. 21일 재계산 결과 `planetory-0002`가 여전히 가장 위험하며(여유 7%, 소진 예상 10-10) 나머지는 13-31% 여유로 확인됐다.
- 검증: `gcloud billing projects describe`·`compute instances/disks/addresses list`·`compute regions/project-info describe`·`compute routers list`, 콘솔 결제 계정 크레딧·보고서 화면(날짜별 그룹화로 재조회), `gcloud billing budgets list/update/delete`로 6개 프로젝트·6개 결제 계정을 모두 직접 조회하고 예산을 정리했다. 코드·운영 설정은 바꾸지 않았고 예산 알림 신규 생성 5건·금액 갱신 5건·매월 리셋 예산 삭제 1건만 실행했다(그 외 조회 전용, 인스턴스·디스크·방화벽·네트워크 변경 없음). 삭제와 5개 계정 일괄 수정은 자동 모드 분류기가 막아 사용자 승인을 받은 뒤 실행했다. 상대 링크 검사와 `git diff --check`는 0건이다.
