## [S15P21C206-236] 분석 단계 병합과 주기 미세 조정 정밀도

- 수정자: 백지웅 (Claude 보조)
- 유형: 요구사항 변경 · 프론트 UI
- 상태: 구현 완료 · 디자인 확인과 서버 인수 대기
- 변경 범위: 분석 단계 파생·주기 선택 로직, 분석 프론트 명세 §5.2, 프론트 디자인 토큰 문서
- 목적: 봉우리를 골라도 단계가 넘어가지 않게 하고, 주기 미세 조정을 소수점 넷째 자리 아래로 세분한다.
- 결정·근거: 사용자 요청으로 Figma의 1·2단계를 한 단계로 합쳐 4단계로 둔다. 미세 조정 간격은 서버 격자 한 칸을 128등분(fixture 기준 8.0e-5일, 768단계)한다. 128은 2의 거듭제곱이라 서버 격자 칸과 봉우리 원래 주기가 격자 위에 남고, 1440px에서 슬라이더 1픽셀이 약 한 단계여서 포인터 드래그가 화면 주사율을 넘지 않는다. 주기도 확대·이동과 전체 보기 버튼은 유지하기로 했다. 주기 범위는 명세의 0.5~최소 40일을 그대로 둔다.
- 검증: 타입 검사·운영 빌드 통과. 단위 170개 통과(미세 간격·격자 정렬 검사 1개 추가). Chrome 회귀 105개, GPU 회귀 8개 통과. axe 6상태 위반 0건. 실측으로 ArrowRight 8.040e-5일, PageUp 1.021e-2일, 봉우리 재선택 시 단계 유지 확인.
- 관련 문서: [구현·검증 기록](../../../apps/frontend/docs/analysis-design.md), [분석 프론트 정본](../../development/analysis-frontend-spec.md), [디자인 토큰](../../../apps/frontend/docs/design.md), [Jira](https://ssafy.atlassian.net/browse/S15P21C206-236)
- 정정: 같은 날 패널 범례 배치를 함께 고쳤다. 주기도 범례가 `.analysis-periodogram p`의 13px에 덮여 카드 밖으로 나갔고, 시간 곡선 범례는 axe 대응으로 높이 제한을 푼 뒤 1024px에서 두 줄이 되어 넘쳤다. 두 카드를 `min-height` + `align-self: stretch`로 바꿔 행 높이가 1440px 278px·1024px 286px가 되었다. Figma 258px과 달라 디자인 확인이 필요하다.
- 정정: 미세 조정 중 ‘이 주기로 구간 선택’이 프레임마다 깜빡이던 문제를 함께 고쳤다. 접기 한 번이 10ms 남짓이라 `!ready`를 그대로 표시한 탓이다. 진행 안내가 쓰던 1초 지연 규칙을 버튼에도 적용해 잠금은 즉시, 표시는 계산이 길어질 때만 한다(`fold-progress.ts`의 `useSustained`). 실패·취소는 그대로 즉시 잠근다.
- 후속 작업: 서버가 보낼 실제 `periodStepDays`에서도 128등분이 적절한지 인수 때 확인한다. 미세 조정 연속 드래그의 접기 부하는 실제 관측 데이터로 재측정한다. API·테이블·SRS 버전 변경 없음.
