# 2026-09-18 주요 변경

## [S15P21C206-71] tailnet 접속을 전 서버 `tailscale ssh`로 통일

- 수정자: 김동혁 (Claude 보조, 사용자 요청)
- 유형: 운영
- 상태: 검증 완료(실측)
- 변경 범위: [Tailscale 팀 서버 접근 가이드](../../operations/tailscale-team-access.md) 2·3절
- 목적: GCP 노드에만 적용돼 있던 `tailscale ssh` 기본 경로를 `donh-vnic`·`ec2-a`·`ec2-b`까지 넓혀 접속 방법을 하나로 맞춘다.
- 결정·근거: 2026-09-17 `fde9198`이 GCP `node-1~6`만 `tailscale ssh`로 바꾸고 EC2·CI 노드는 OpenSSH 표기로 남겨 두 방식이 섞여 있었다. `tailscale ssh`는 대상에 개인 SSH 키를 배포하지 않아도 되고 접속 주체가 tailnet 신원으로 남으므로 관리 접속의 기본으로 통일한다.
- 검증(실행한 것): `tailscale ssh <계정>@<이름> hostname -s`를 실제로 실행해 `donh-vnic`·`ec2-a`·`ec2-b`가 모두 응답하는 것을 확인했다. 표기만 바꾼 것이 아니라 세 대상에서 Tailscale SSH 서버가 실제로 켜져 있음을 확인한 뒤 반영했다. 호스트명·사설 IP는 문서에 적지 않는다.
- 검증(실행하지 않은 것): `node-2`~`node-6`은 이번에 다시 확인하지 않았다. 2026-09-17 `fde9198`의 기록을 그대로 따른다.
- 후속 작업: `tailscale ssh` 실패 시 확인 순서(대상의 `tailscale up --ssh` 여부)를 3절에 적었다. ACL 허용과 대상의 SSH 서버 활성화는 별개라는 점이 실패 원인 대부분이다.
- 관련 문서: [Tailscale 팀 서버 접근 가이드](../../operations/tailscale-team-access.md), Jira `S15P21C206-71`
