## [S15P21C206-82] Redis를 `redis-session`·`redis-cache` 두 인스턴스로 분리 — MR !55 리뷰 반영

- 목적: 계산 캐시의 eviction이 로그인 세션을 지우는 경로를 없앤다.
- 결정·근거: 백승학님 지적대로 `maxmemory`와 `maxmemory-policy`는 **인스턴스 단위 설정**이라 키 접두사나 논리 DB(`SELECT 0/1`)로는 메모리 예산과 eviction이 분리되지 않는다. 한 인스턴스에 두면 `allkeys-*`는 세션을 후보로 삼고 `volatile-*`도 세션이 30분 TTL(SB-D14)을 가져 그대로 후보다. 증상이 「로그인한 회원이 이유 없이 튀김」이라 재현도 진단도 어렵다.
- 추가로 확인한 이득: **분리가 D10의 대가를 일부 되돌린다.** 세션을 Redis로 옮기며 「Redis 장애 = 인증 전면 중단」을 수용했는데, 나누면 그 범위가 `redis-session` 장애로 좁아지고 **`redis-cache` 장애는 이관 전과 똑같이 온라인 계산만 멈춘다.** 4장 장애표의 Redis 행을 두 행으로 나눈 이유다.

- 유형: 오류 정정 · 계약
- 상태: 구현 완료 · 실제 서버 인수 대기
- 변경 범위: `periodogram-data.ts`, 개발용 주기도 fixture와 단위·브라우저 회귀
- 목적: 정상적인 미계산 주기도 응답이 파서 오류가 되던 것을 바로잡는다.
- 결정·근거: `AnalysisViews.Periodogram`은 202에도 같은 주기도 본문을 유지하고 `power`만 null로 보낸다. `code`·`segments` 필드는 존재하지 않는데 `decodePendingPeriodogram`이 둘 다 요구했다. 호출부(`load-periodogram.ts`)는 이미 HTTP 202로 분기하므로 파서는 본문 모양만 확인하도록 좁혔다. 곡선(5.2절)과 주기도(5.3절)의 대기 응답 모양이 다르다는 점을 문서에 남긴다.
- 검증: 타입 검사·운영 빌드 통과. 단위 149개, Chrome 회귀 46개 통과. `power`가 남아 있으면 대기로 받아들이지 않는 검사를 추가했다.
- 관련 문서: [주기도 데이터 개발 안내](../../../apps/frontend/docs/periodogram-data.md), [탐사 API 5.3](../../../apps/backend/docs/exploration-api-spec.md), [Jira](https://ssafy.atlassian.net/browse/S15P21C206-183)
- 후속 작업: 실제 서버 HTTP 연결 검사는 아직 하지 않았다.

## [S15P21C206-236] 서버 계약 수정 반영과 판 버전 표시 정정

- 수정자: 백지웅 (Claude 보조, MR !88·!89 리뷰 반영)
- 유형: 오류 정정 · 프론트 UI
- 상태: 구현 완료 · 실제 서버 인수 대기
- 변경 범위: `AnalysisPage.tsx` 판 버전 표시, 182~185 수정의 누적 반영
- 목적: 182~185에서 고친 서버 계약 수정을 받아오고, 문자열이 된 판 버전의 표시를 바로잡는다.
- 결정·근거: `bundleVersion`이 `v7`처럼 접두사를 포함한 문자열이 되면서 단계 표시줄의 `데이터 v{bundleVersion}`이 `데이터 vv7`로 그려진다. 서버 값에 이미 접두사가 있으므로 표시의 `v`를 뺀다. 그 외 이 브랜치의 추가 수정은 없다.
- 검증: 타입 검사·운영 빌드 통과. 단위 210개, Chrome 회귀 107개, 개발용 GPU 회귀 8개 통과. 대비 검산 통과. axe 6상태 위반 0건.
- 관련 문서: [구현·검증 기록](../../../apps/frontend/docs/analysis-design.md), [Jira](https://ssafy.atlassian.net/browse/S15P21C206-236)
- 후속 작업: 실제 서버 HTTP 연결 검사는 아직 하지 않았다. 나머지 미확정 사항은 위 항목과 같다.
## [S15P21C206-238] 회원·커뮤니티 앱 역할 권한 결손 해소

- 수정자: 백승학
- 유형: 데이터 · 오류 정정
- 상태: 구현 완료 · 검증 완료
- 변경 범위: V11 회원·커뮤니티 GRANT, `MemberCommunityPermissionTest`, [EC2 서비스 진입·장애 경계](../../architecture/ec2-service-entry-failover.md) 5·7절
- 목적: DB 계정 분리 시 회원·커뮤니티 접근이 42501로 실패하는 결손을 백엔드 소유 마이그레이션에서 해소하고 회귀를 막는다.
- 결정·근거: 현재 접근 경로가 있는 `users`·`user_settings`·`posts`·`comments`에는 SELECT·INSERT·UPDATE를, `published_analyses`에는 SELECT만 부여한다. 물리 삭제 경로가 없으므로 DELETE·TRUNCATE는 회수하고, 코드 참조가 없는 7개 테이블은 구현 티켓에서 동사를 확정할 때까지 권한을 추가하지 않는다.
- 검증: 일회용 PostgreSQL에서 전체 마이그레이션을 적용하고 `planetory_app` 로그인 계정으로 회원·설정·글·댓글의 실제 생성·갱신, `users` 행 잠금, 물리 삭제와 공개 분석 쓰기의 42501 거절을 확인한다. 기존 Gold·탐사 권한 테스트도 함께 실행한다.
- 관련 문서: [EC2 서비스 진입·장애 경계](../../architecture/ec2-service-entry-failover.md), Jira `S15P21C206-238`·`S15P21C206-83`
- 후속 작업: 83은 V11을 중복 소유하지 않고 계정 생성·접속·볼륨·배포 경로와 운영 인수 검증만 맡는다.
