# 2026-09-19 주요 변경

## [S15P21C206-187] 분석 제출 요청 ID·복구 계약 확정

- 수정자: 백지웅 (Claude 보조)
- 유형: API
- 상태: 채택 · 구현 전
- 변경 범위: [분석 제출 개발 안내](../../../apps/frontend/docs/analysis-submission.md) 신규.
- 목적: 제출 응답 12종을 프론트가 어떻게 처리하고 요청 ID를 보존·폐기·재발급할지 한 표로 고정한다.
- 결정·근거: 요청 ID 규칙이 코드 여러 곳으로 흩어지면 어긋나므로 응답별로 ID 처리를 같은 행에 적었다. **새 ID는 사용자가 본문을 바꿔 의도적으로 다시 제출할 때와 `BUNDLE_CHANGED`·`IDEMPOTENCY_CONFLICT`로 본문을 새로 만들 때만** 생성하고, 응답 유실·`REQUEST_IN_PROGRESS`·by-request 404·타임아웃·새로고침은 모두 같은 ID를 유지한다. 미해결 ID가 남아 있는 동안 초안을 잠근다. 잠그지 않으면 사용자가 메모를 고친 뒤 복구 재전송이 `IDEMPOTENCY_CONFLICT`가 되어 이미 접수된 결과를 확인할 길이 사라진다.
- 결정·근거: 요청 ID는 `sessionStorage`에 `planetory:analysis-draft:` 접두사를 공유해 저장한다. 기존 로그아웃 정리가 함께 지우므로 공용 파일 [`session-draft-storage.ts`](../../../apps/frontend/src/auth/session-draft-storage.ts)를 수정하지 않는다. 저장값에 본문 지문을 함께 두고 복구 재전송 직전에 대조한다.
- 발견(계약 불일치): 탐사 API 6.2절 예제와 [C02 계약 예제](../../api/exploration/contracts.json)는 `fieldErrors[]`를 `{field, message}`로 적지만, 구현된 [`ErrorResponse.FieldError`](../../../apps/backend/src/main/java/com/planetory/backend/global/error/ErrorResponse.java)는 `(field, reason)`이고 공용 프론트 클라이언트도 `reason`을 읽는다. **구현을 정본으로 보고 문서 예제 쪽 정정이 필요하다.**
- 정리(충돌 아님): 명세 6.6절의 「404 미접수, 같은 ID로 재전송」과 Jira A06-1의 「조회 404를 무조건 미접수로 단정하지 않는다」는 같은 결론이다. 어느 쪽이든 새 ID를 만들지 않고 같은 ID로 재전송하면 접수돼 있었으면 200 재현, 아니면 201이 온다. 지킬 것은 404를 근거로 "제출되지 않았습니다"라고 단정해 안내하지 않는 것이다.
- 검증: 문서 확정 단계이므로 실행 검증 없음. 근거는 저장소의 명세·계약 예제·백엔드 DTO 원문 대조다.
- 관련 문서: [탐사 API 2.2·2.3·6.1~6.6](../../../apps/backend/docs/exploration-api-spec.md), [분석 제출 개발 안내](../../../apps/frontend/docs/analysis-submission.md), Jira `S15P21C206-187`.
- 후속 작업: 실제 제출 엔드포인트가 아직 없어(C10 = `S15P21C206-142`·`143` 「해야 할 일」) fixture로 구현한다. 메모 상한(명세 2,000 vs 구현 200)과 요청 ID 보존 기간은 C10 연동 때 확정한다.
