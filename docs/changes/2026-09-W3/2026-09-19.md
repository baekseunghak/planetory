# 2026-09-19 주요 변경

## [S15P21C206-144] 신호별 성과 인정·새 별 발견 공통 함수와 성과 조회

- 수정자: 강재민 (Claude 보조)
- 유형: API
- 상태: 구현 완료 · 리뷰 대기
- 변경 범위: 탐사 API 9.1·9.2절, 성과 인정 함수와 `GET /me/achievements`, 발견 공통 함수, 탐사 요약 집계, 운영 규칙 런북
- 목적: 제출(S15P21C206-143)과 공개 등록(S08)이 같은 트랜잭션에서 부를 성과 인정·별 열림 함수와 9.1절 성과 조회를 제공한다.
- 결정·근거: 시드 정책 `hash-user-achievement-seq-v1`을 계산식으로 정했다. SHA-256(`회원:성과:순번`) 앞 8바이트를 부호 없는 정수로 읽고, TIC 오름차순 후보에서 `seed mod 후보 수`번째를 고른다. 후보 수 세기와 고르기는 한 SQL 문장에서 해 둘이 어긋나지 않는다. 별 저장의 충돌 대상은 9.4절과 같은 `(user_id, tic_id)`다. PostgreSQL은 충돌 대상을 하나만 받고, 같은 성과의 재처리는 성과 INSERT 충돌에서 이미 멈추므로 `UNIQUE(trigger_achievement_id, seq)`는 위반 시 예외를 내는 안전망으로 둔다. 성과 행은 앱이 지울 수 없어(V5) 인정 근거를 넣기 전에 검사한다. `/me` 요약과 9.1절 `summary`는 한 집계를 쓴다.
- 검증: 백엔드 전체 테스트 309개 통과. 새 테스트 26개가 인정·재인정·등급·제외 규칙·부족·별 저장 실패 롤백·동시 실행 3종·앱 역할 권한·조회·커서를 본다.
- 관련 문서: [탐사 API 9장](../../../apps/backend/docs/exploration-api-spec.md#9-성과등급별-열림완료재개), [운영 규칙 런북](../../operations/operation-rule-runbook.md), [Jira](https://ssafy.atlassian.net/browse/S15P21C206-144)
- 후속 작업: 제출(S15P21C206-143)·공개 등록(S08)의 호출 연결과 S08 공동 통합 테스트. `relabel.newDisposition`의 값 대응(`pc`·`none` → `UNCONFIRMED`)은 6.4절 `signal.disposition`을 구현할 때 같은 규칙으로 맞춘다.

## [S15P21C206-144] 발견 좌표가 유효숫자 15자리로 저장되던 문제 정정

- 수정자: 강재민 (Claude 보조)
- 유형: 오류 정정
- 상태: 검증 완료
- 변경 범위: `StarDiscoveryService`(가입·튜토리얼·챌린지·성과 발견 공통)
- 목적: 저장 좌표를 배치 함수가 계산한 값과 비트 단위로 같게 한다(S15P21C206-139 리뷰 후속).
- 결정·근거: 좌표를 double로 바인딩하면 PostgreSQL의 float8→NUMERIC 변환이 유효숫자 15자리로 반올림한다(18.6에서 `(1/3::float8)::numeric` = `0.333333333333333`). `BigDecimal.valueOf`로 넘겨 최단 10진 표현을 그대로 저장한다. 이미 저장된 좌표는 API가 같은 저장값을 읽으므로 고치지 않는다.
- 검증: 배치 함수의 순번 0~5는 정수 고정 좌표라 반올림이 드러나지 않는다. 그래서 회귀 테스트는 순번 6 이상까지 열어 비트 단위로 비교한다. double 바인딩으로 되돌리면 이 테스트가 실패하는 것을 확인했다.
- 관련 문서: [Jira](https://ssafy.atlassian.net/browse/S15P21C206-144)
- 후속 작업: 없음
