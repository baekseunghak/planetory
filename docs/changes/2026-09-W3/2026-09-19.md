## [S15P21C206-76] Sector 3 HDFS Raw 완료 조건 재검증

- 수정자: Codex (사용자 요청)
- 유형: 데이터 · HDFS 운영 · 검증
- 상태: Sector 3 완료 조건 검증 완료 · 전체 승인 범위 미완료
- 변경 범위: TESS HDFS Raw 운영 문서와 Sector 3 실환경 검증 증거
- 목적: Jira 76의 byte-identical 복원, 같은 run 멱등성, 실패 staging 비노출과 RF2 조건을 현재 HDFS에서 다시 확인한다.
- 결정·근거: 같은 RunId Commit은 481.7초에 `COMMIT_CACHED`로 끝났고 전후 인벤토리 SHA-256과 61개 bundle·marker·manifest, 논리·물리 사용량이 같았다. Worker별 무작위 표본 5/5의 복원본과 실제 로컬 FITS 크기·SHA-256이 일치했고, 실패 `.part` canary는 Raw에 0건 노출된 뒤 정확한 validation staging만 삭제했다.
- 검증: `manifest.parquet` 12필드·15,993행, null·중복 0과 lineage·Worker별 합계를 Spark로 확인했다. FSCK는 370블록 전부 `Live_repl=2`, 5개 DataNode, missing·corrupt·under 0이며 HA `active:standby`, safe mode OFF, HDFS 사용률 1%다. `yarn` 읽기와 uploader 5개 `success`·재시작 0도 통과했다. 보조 검사 초안은 Dead DataNode 0행 생략과 `%A` 출력 형식을 잘못 가정했으나 실제 형식에 맞춘 재검사는 통과했고 데이터 영향은 없었다.
- 관련 문서: [TESS HDFS Raw 적재](../../../distributed-system/ingestion/hdfs/README.md), [Jira S15P21C206-76](https://ssafy.atlassian.net/browse/S15P21C206-76), [2026-09-18 최초 적재 기록](2026-09-18.md)
- 후속 작업: Sector 4·5는 final·staging·활성 uploader가 없어 전체 55,986개 중 15,993개·29.49%만 HDFS에 확정됐다. 두 Sector를 같은 절차로 적재·검증하기 전에는 티켓 전체 완료로 전환하지 않는다.

## [S15P21C206-76] Sector 3~5 자동 연속 적재 완료

- 수정자: Codex (사용자 요청)
- 유형: 데이터 · HDFS 운영 · 자동화
- 상태: 전체 승인 범위 적재·검증 완료
- 변경 범위: TESS HDFS Raw runner의 `RunAll`, 회귀 계약, 실행 문서와 실환경 Sector 4·5 적재
- 목적: 단일 단계 수동 호출로 Sector 3에서 멈춘 실행 경로를 고쳐, 전체 선행 gate와 실패 중단·재실행 경계를 유지하면서 Sector 3→4→5를 자동 처리한다.
- 결정·근거: 기존 `Preflight`, `Install`, `Build`, `Upload`, `Audit`, `Commit`을 재사용하고 uploader systemd 상태만 대기하는 최소 orchestration을 추가했다. 세 Sector download audit을 변경 전에 모두 검사하고, final이 있는 Sector는 `Commit` 재감사로 건너뛴다. 신규 Sector는 다섯 uploader가 모두 success일 때만 Audit과 Commit으로 진행하며 실패나 3시간 timeout이면 다음 Sector를 시작하지 않는다.
- 검증: 오프라인 PowerShell parser·필수 계약·WhatIf와 Python 4개 검사가 통과했다. 실환경 `RunAll`은 86.7분에 완료됐고 Sector 3은 `COMMIT_CACHED`, Sector 4·5는 각각 19,997·19,996개와 75·75 bundle을 `COMMIT_OK`로 확정했다. Sector 4·5 upload는 937.7·868.9초였고 10개 unit 모두 success·exit 0·재시작 0이다. 최종 release 55,986개 원본 범위는 논리 108,471,409,680바이트·RF2 물리 216,942,819,360바이트이며 FSCK `HEALTHY`, 1,259 blocks, under·missing·corrupt 0, HA `active:standby`, Live DataNode 5개다. 세 staging은 모두 없다.
- 관련 문서: [TESS HDFS Raw 적재](../../../distributed-system/ingestion/hdfs/README.md), [Jira S15P21C206-76](https://ssafy.atlassian.net/browse/S15P21C206-76)
- 후속 작업: 없음. Jira 상태 변경·commit·push·MR은 이번 요청 범위에 포함하지 않는다.
