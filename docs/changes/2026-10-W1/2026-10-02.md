## ec2-a 긴급 보존과 donh-vnic 격리 DB 복원

- 수정자: Codex(사용자 요청)
- 유형: 운영
- 상태: 격리 DB 복원·검증 완료. 앱 기동·트래픽 전환 미실행
- 변경 범위: donh-vnic의 보호된 이관 디렉터리와 새 PostgreSQL 볼륨·격리 컨테이너, 서비스 배포 상태 문서
- 목적: 원본 초기화 전에 DB·비밀 설정·세션을 보존하고 ARM64 목적지에서 DB를 복원한다.
- 결정·근거: 민감 payload 전송과 새 DB 복원은 각각 사용자 명시 승인 후 실행했다. SQL 역할 멤버십의 GRANTED BY를 보존하기 위해 원본과 같은 최초 관리자 계정으로 초기화했다. 다른 최초 관리자에 원본 계정을 추가하는 방식은 PostgreSQL 18에서 권한 부여 오류가 났다.
- 검증: 전체 SQL 복원 정상 종료, COPY 테이블 48개·87,165행과 시퀀스 28개 덤프 비교 일치, public 테이블·뷰 49개·Flyway V30·미검증 제약 0개, 서비스 계정 비밀번호 인증과 역할 권한 확인
- 관련 문서: [서비스 배포 현재 상태](../../project/service-deploy-status.md), [PostgreSQL GRANT](https://www.postgresql.org/docs/18/sql-grant.html)
- 후속 작업: Jira 키 미지정, 앱 산출물 전송 승인 대기, ARM64 앱 기동·세션 복원·Publisher/CI 연결·단일 Tunnel 전환과 최종 쓰기 보존 확인, 실패한 격리 복원 자원 정리

## donh-vnic ARM64 앱·세션·문서 내부 검증

- 수정자: Codex(동일 이관 요청 후속)
- 유형: 운영
- 상태: ARM64 앱 9개 내부 기동·검증 완료. 공개 트래픽·Publisher·CI 전환 미실행
- 변경 범위: 사용자 승인한 현재 앱 산출물·Worker 실행 커밋 소스·문서 전송, 목적지 ARM64 이미지와 새 Redis·문서 볼륨, 서비스 배포 상태 문서
- 목적: 기존 목적지 서비스를 유지하며 원본 앱을 ARM64에서 실행할 수 있음을 검증한다.
- 결정·근거: 사용자 앱 전송·ARM64 준비·검증 명시 승인. Backend JAR·프론트 번들은 원본 산출물을 재사용하고 Worker는 실행 커밋으로 빌드한다. 공개 connector는 제외하며 DB 볼륨은 단일 컨테이너에서만 사용한다. 공개 정적 디렉터리는 tar data 필터·umask로 생긴 700 권한을 755로 맞춰 Nginx 읽기 실패를 해결했다.
- 검증: 원본·목적지 JAR 해시 일치, 9개 실행 이미지 ARM64, frontend renderer·Backend health·문서 3개·Backend→Worker health HTTP 200, Worker 기존 회귀 20개 통과, 기존 freqtrade·gitlab-runner 실행 유지. Tailscale 실제 필터의 5432·8080 Node 1 전용 범위 확인
- 관련 문서: [서비스 배포 현재 상태](../../project/service-deploy-status.md)
- 후속 작업: 최종 운영 전환 승인, 원본 쓰기 중단·최신 DB·세션 복사, 목적지 리스너·단일 Tunnel·Publisher·ARM64 CI 전환과 운영 검증. 현재 복원은 긴급 덤프 시점이며 무손실 최종 전환 완료를 뜻하지 않는다.

## donh-vnic 최신 데이터·Cloudflare·Publisher 최종 전환

- 수정자: Codex(사용자 공개 연결 마무리 지시)
- 유형: 운영
- 상태: 원본 10개 서비스·최신 데이터·공개 경로·Publisher 전환 검증 완료. CI 배포 설정 전환 미실행
- 변경 범위: 원본 Planetory 쓰기 중단·10개 컨테이너 정지, 목적지 별도 최종 DB/세션 볼륨·단일 Cloudflare connector, 대상 Tailscale 전달 5432·8080, Node 1 Publisher host 설정과 Publication DAG pause 복구, 운영 배치·상태·아키텍처·접근·CI 상태 문서
- 목적: 긴급 덤프 이후 쓰기를 보존하고 현재 공개 서비스를 donh-vnic으로 전환한다.
- 결정·근거: 사용자 최종 공개 연결 지시 이후 실행. 게시 DAG의 기존 pause 값을 기록하고 실행 중 게시가 없는 상태에서 원본 앱·쓰기를 중단한다. 최신 dump를 별도 볼륨에 복원하며 이관용 원본 read-only 설정만 목적지에서 제외한다. 기존 Tunnel의 ingress·DNS 배치는 유지하고 connector 실행 위치를 바꾼다. 원본·검증·최종 볼륨은 삭제하지 않는다.
- 검증: 최종 48개 COPY 테이블·87,165행·28개 시퀀스 비교 일치, Flyway V30·권한·read-only off 확인, 최종 세션 RDB 해시 일치. 공개 hostname 5개·renderer HTTPS 200, 익명 API 401 JSON, Google/SSAFY OAuth 시작 302와 HTTPS callback 확인. 대상 등록 connection 4개와 외부 검증 요청의 대상 프론트 도달 확인. Publisher DB 인증·writer 역할·Backend health·서비스 토큰 무변경 probe 검증, 원래 DAG pause=false 복구. 비-Publisher의 DB/알림 포트 차단, 기존 target 443/Web·freqtrade·gitlab-runner 유지 확인
- 관련 문서: [운영 배치](../../../infra/service/README.md#현재-운영-배치-2026-10-02), [서비스 배포 상태](../../project/service-deploy-status.md)
- 후속 작업: GitLab 배포 목적지·ARM64 빌드·공용 Compose의 최종 볼륨 보존 대응. 실제 사용자 OAuth 로그인 완료는 미검증. 운영 쓰기가 발생한 목적지에서 source로 단순 재기동 롤백하지 않는다.

## ec2-b 회수 전 보존과 donh-orc2 CI·Registry 이관

- 수정자: Codex(사용자 요청)
- 유형: 운영
- 상태: 전체 레지스트리·Runner·관찰 이관 및 실제 CI 검증 완료
- 변경 범위: 사용자 지정 `ubuntu@donh-orc2`의 Docker·ARM64 Runner·TLS Registry·보호된 원본 보존본·관찰 cron, GitLab 레지스트리 변수, Node 1 Publisher 이미지 호스트, 정리 스크립트 계정 설정·회귀, CI 주석·운영 배치 문서
- 목적: ec2-b의 사용자 요청 경로 밖 인프라를 새 서버에 보존하고 계속 운영한다. Jira 키는 미지정이다.
- 결정·근거: 사용자 민감 설정 전송·기존 자동화 이관 명시 승인. 기존 Runner를 pause·정지하고 원본 cron·Registry를 정지한 뒤 읽기 전용 rsync로 전체 파일을 복사했다. ARM64 호스트에는 native Registry·동일 버전 Runner와 QEMU를 사용해 기존 amd64 빌드를 지원한다. source 회수 전 전체 파일 검증을 마쳤고 이후 사용자가 관리자의 인스턴스 회수를 알렸다. 이미지 digest·Runner 등록 정보·자동화 주기는 유지한다.
- 검증: 레지스트리 1,779개 파일·8,733,699,542 bytes·전체 SHA-256 일치, 원본 11개 저장소·112개 태그 TLS 조회 200, Docker 27.5 DinD amd64 build·push·실행, Runner 인증·online·ARM64 manager와 [실제 계약 job #665128](https://lab.ssafy.com/s15-bigdata-dist-sub1/S15P21C206/-/jobs/665128) 성공, Node 1 Publisher 동일 이미지 pull·CLI 기동, 새 CI 신원의 서비스 SSH·Docker 접근, 정리 회귀 8개·실제 모의 정리·관찰·인증서 갱신 확인
- 관련 문서: [CI 노드 운영 위치](../../../infra/service/ec2-b/README.md#현재-운영-위치-donh-orc2-2026-10-02), [CI/CD](../../operations/cicd.md), [배포 상태](../../project/service-deploy-status.md)
- 후속 작업: 앱 CI의 ARM64 이미지·서비스 배포 목적지·공용 Compose 최종 데이터 볼륨 보존. 앱 전체 build/test/deploy와 QEMU 컴파일 성능은 미검증. 원본 인스턴스로 돌아갈 수 없으며 전체 이관 데이터와 설정은 목적지 보호 경로에 보존한다. commit·push는 실행하지 않았다.

## 서비스 앱 CI ARM64·donh-vnic 배포 대응

- 수정자: Codex(사용자 요청)
- 유형: 운영·구현
- 상태: CI 코드·운영 기반 설정 준비와 실제 빌드·기동·롤백 검증 완료. 사용자 긴급 Git 게시·MR 생성 승인 완료. develop 반영·새 운영 앱 배포 미실행
- 변경 범위: 앱 3개의 ARM64 이미지 job·태그·아키텍처 검사, donh-vnic 수동 deploy·환경 변수, 기존 운영 Compose 보존, 배포 health·보호 로그와 회귀, 관련 운영 문서
- 목적: 이관한 ARM64 서비스와 CI 노드를 사용하며 최종 DB·세션 볼륨을 보존한다. Jira 키는 미지정이다.
- 결정·근거: 앱은 native ARM64, 기존 Publisher는 amd64를 유지한다. 새 목적지 변수는 환경 범위 donh-vnic에 두고 이전 EC2-A 변수는 유지한다. 운영 Compose를 덮어쓰지 않고 이미지 변수만 갱신한다. 기존 Dockerfile의 ARM64 기반 이미지를 확인해 Dockerfile 변경은 하지 않았다.
- 검증: 실제 native ARM64 앱 3개 build·inspect·Registry push, Frontend Nginx·renderer 200, Worker 회귀 20개, Backend 임시 DB의 계정 분리·Flyway V30·health 200, Docker 27.5 DinD·Compose 2.33.0 정상 교체·unhealthy 롤백·영속 볼륨 보존, GitLab server dry-run lint 오류·경고 0개. 운영 Compose 변경 전후 서비스 정의·컨테이너 ID·최종 볼륨 이름 동일
- 관련 문서: [CI/CD](../../operations/cicd.md), [배포·롤백](../../../infra/service/README.md#배포와-롤백), [배포 상태](../../project/service-deploy-status.md)
- Git 게시: 사용자가 Jira 없이 긴급 commit·push·MR 생성을 명시 승인했다. 기능 커밋 `a913dd1a`와 [MR !259](https://lab.ssafy.com/s15-bigdata-dist-sub1/S15P21C206/-/merge_requests/259)를 게시했다. 실제 GitLab 검증 결과는 MR 파이프라인을 따른다.
- 후속 작업: develop 병합은 별도 승인·리뷰 절차를 따른다. 검증용 태그를 운영에 배포하지 않았다.
