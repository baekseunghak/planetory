## Keep

- Jira 238번에서 회원·커뮤니티 테이블의 앱 역할 GRANT 결손을 V11로 해소하고, `planetory_app` 로그인 계정으로 실제 생성·갱신·행 잠금·권한 거절을 확인하는 Testcontainers 회귀 테스트를 붙였다. 모든 마이그레이션 뒤 앱이 읽지 못하는 테이블이 코드 참조 0건인 7개뿐임을 확인하고 병합했다.
- Jira 181번 별 목록 공개 설정(`PATCH /api/v1/me/settings`)과 242번 가입일 응답을 구현했다. 공개일 때 받은 cursor로 비공개 전환 뒤 이어 읽지 못하는 경우, 설정 행이 없을 때 새로 만드는 경우까지 테스트로 고정했고, F03-Q4의 우회 경로 점검을 확정으로 닫았다.
- 어제 Try대로 수정 전에 실패하는 테스트를 먼저 확인하고 고쳤다. MR 73번의 숫자 아닌 TIC 500과 오류 응답 `details` 키 충돌을 이 방식으로 고쳐 작성자 브랜치에 올렸다.
- 리뷰 주장을 코드 읽기가 아니라 실행으로 확인했다. 240번은 실제 Tomcat을 띄워 `:8080`이 Tomcat에서 나오지 않는다는 것과 `framework` 전략이 클라이언트가 보낸 `Forwarded` 헤더를 신뢰한다는 것을 보였다. MR 86번은 없는 계정을 넣어 기동해 Boot 4가 `flyway.user`만으로도 별도 연결을 만든다는 것을 확인했다.
- 남의 브랜치에 올릴 때는 원격에 새 커밋이 없는지 확인해 fast-forward로만 올리고, 작성자 판단이 필요한 부분은 건드리지 않고 댓글로 남겼다.

## Problem

- 238번 V11과 83번 V11이 같은 파일명으로 따로 작성됐다. 실행 SQL은 같고 주석만 달라 어느 한쪽이 DB에 먼저 적용되면 다른 쪽이 체크섬 불일치로 기동을 막을 수 있었다. ADR은 GRANT 작성을 238에 배정했지만 열린 MR을 서로 확인하지 않았다.
- 오늘 본 결함 세 건이 모두 검증 경로와 실제 사용 경로가 달라서 숨어 있었다. GRANT 결손은 소유자 계정으로 도는 테스트에, 83번 Flyway 비밀번호 문제는 환경변수를 넘기는 compose 검증에, 84번 프록시 문제는 localhost 직결 검증에 가려졌다.
- 181번 테스트를 또 `AuthIntegrationTest`에 넣었다. 어제 Try로 남긴 OAuth 로그인 픽스처 분리를 아직 Task로 올리지 못했다.
- 181번은 처음 올릴 때 설정 행이 없는 경우의 테스트와 F03-Q4 확정이 빠져 리뷰 뒤에 보완했다.
