# 2026-09-18 KPT

## Keep

- HDFS HA 환경에서 계획 전환, Node 1 장애, Worker 4 장애와 복구를 실제로 수행하고 결과를 수치와 로그로 남겼다.
- 리뷰에서 발견된 JournalNode quorum, split-brain 방지, Worker 3 복구 순서 등을 회귀 검사로 고정했다.
- 안전 계약을 하나씩 제거한 변이 시험 6건을 실행해 테스트가 실제 회귀를 잡는지 확인했다.
- 정적 검증과 실환경 검증을 구분하고, 실행하지 않은 Worker 3 실제 장애는 완료로 과장하지 않았다.
- 운영 절차, 검증 결과, 한계와 후속 작업을 README·런북·변경 이력에 함께 기록했다.

## Problem

- 처음에는 256MiB 0바이트 표본의 고정 SHA-256을 데이터 보존 증거처럼 기록했다. 해시 자체는 로컬에서도 재현되므로 증거 범위를 더 엄격하게 봤어야 했다.
- Worker 3이 JournalNode 역할을 겸한다는 점을 초기 장애 시나리오에서 충분히 고려하지 못해 정지 전 quorum 검사와 복구 단계가 빠졌다.
- HDFS 검증 경로의 정리 절차는 추가했지만 Node 1의 `/tmp` 파일 약 768MiB가 run마다 남는 문제는 마지막 리뷰에서야 발견했다.
- 기능이 정상 동작하는지만 확인하는 데 그치지 않고, 테스트 코드 자체가 가드 삭제를 잡아내는지도 처음부터 확인했어야 했다.

## Try

- 장애 테스트를 설계할 때 `중지 전 조건 → 장애 중 서비스 → 복구 순서 → 최종 상태 → 임시파일 정리` 체크리스트를 먼저 작성한다.
- 다중 역할 노드는 일반 Worker와 분리해 quorum, 기동 순서, 최종 감사 항목을 별도로 확인한다.
- checksum은 재현 가능한 상수 대신 무작위 입력의 원본 값을 Prepare 단계에서 기록해 FinalAudit까지 전달한다.
- 중요한 안전 가드는 정상 테스트와 함께 해당 가드를 제거한 변이 시험을 한 건 이상 추가한다.
- 생성되는 HDFS·로컬 임시파일의 크기, 보존 목적과 삭제 시점을 작업 시작 단계에서 정한다.
- 남은 `/tmp` 정리 문제는 Jira `S15P21C206-75`에 인계한 완료 조건에 따라 처리한다.
