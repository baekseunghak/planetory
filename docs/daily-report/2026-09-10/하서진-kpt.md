## Problem

- 많은 별을 한 번에 보여주는 시연과 사용자가 첫 별부터 탐사를 시작하는 흐름은 달랐다. 처음부터 성장 과정과 화면별 담당 범위를 더 구체적으로 정리할 필요가 있었다.
- 성과 인정과 탐색 완료의 차이가 처음에는 명확하지 않아, 각각 어떤 별을 열고 어떤 상태를 바꾸는지 다시 정리해야 했다.
- 로컬에서 동작하고 자동 테스트를 통과한 것만으로는 다른 컴퓨터에서도 렌더링이 원활하다고 판단할 수 없다. 은하형 표현과 명세의 배치·군집·성능 기준 차이도 남아 있다.
- 반복해서 처음부터 검토하려면 서버를 멈추고 저장 파일을 백업해야 해 초기화 과정이 번거롭다. 페이지 안의 초기화 버튼은 아직 구현하지 않았다.

## Try

- 분석 프론트 담당자와 분석 시작 시 전달할 별 ID, 결과 반영 시 필요한 성과·완료·새로 열린 별 정보, 지도 복귀 방식을 맞추겠다.
- 별이 적을 때와 많을 때를 나누어 확대·축소·회전·선택 반응을 확인하고, 팀원들의 컴퓨터에서도 렌더링 성능을 측정하겠다.
- 페이지에서 검토 진행을 초기화할 수 있는 버튼과 확인 절차를 추가해, 첫 방문부터의 흐름을 반복해서 확인하기 쉽게 만들겠다.
- 이번 성장 화면을 팀에 공유해 사용 흐름과 명세에서 달라지는 부분을 검토하고, 실제 서비스에 적용할 범위와 운영 API 연동 작업을 구분하겠다.
