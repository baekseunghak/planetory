## Keep

- **완료 조건 대비 점검부터 시작했다.** 구현 전에 Task의 목적·작업 내용·완료 조건과 현재 결과물을 1:1로 대조해 빠진 항목(CI 미연결, 테스트의 DB 의존, 미확정 스키마 V1 포함)을 먼저 찾았다. 범위 조정(CI 후속 분리, ERD 담당자 스키마 선병합 후 V2 보완)도 문서와 Jira에 근거를 남겼다.
- **말로 끝내지 않고 실제 실행으로 검증했다.** 수정할 때마다 `clean build`, 빈 DB에서 기동 → 재기동 시 `No migration necessary`, prod 프로필에서 로컬 비밀번호가 적용되지 않는지까지 직접 돌려 확인했다.
- **리뷰 지적을 그대로 받지 않고 근거를 확인했다.** 5건 중 4건(표준 예외 500 변환, 댓글 인덱스, 통계 CHECK, 테이블 수 하드코딩)은 수정했고, rule_version FK는 ERD 원문을 확인해 "ERD 담당자 결정 사항"으로 분리했다.
- **팀원 입장에서 실행 과정을 줄였다.** 로컬 기본값 통일(`ssafy`/15432), Gradle에서 DB 자동 기동, 기본 프로필 local로 `./gradlew bootRun` 한 번이면 뜨게 만들고 README를 빠른 시작·문제 해결 중심으로 다시 썼다.
- **패키지 구조·오류 응답 규칙을 기능 구현 전에 정했다.** JobUp 구조를 참고하되 `ErrorCode` enum 방식으로 바꿔 두 담당자가 같은 핸들러 파일을 동시에 고치지 않게 했다. JPA·JdbcClient 병행 기준도 문서화했다.
- **커밋을 성격별로 나눴다.** chore·build·docs로 분리하고, 한 파일에 섞인 변경도 커밋별로 나눠 각 커밋이 단독으로 일관되게 했다.

## Problem

- **환경 설정 문제로 시간을 가장 많이 썼다.** 비밀번호 인증 실패(28P01)가 여러 번 반복됐는데 원인이 매번 달랐다.
  - 변수 이름을 `POSTGRES_*` → `DATABASE_*`로 바꿨는데 IDE 실행 구성은 옛 이름을 사용
  - `launch.json`에 새 설정을 `configurations` 배열 밖에 넣어 무시됨
  - 볼륨이 옛 비밀번호로 이미 초기화돼 설정만 바꿔서는 반영 안 됨
  - 이 PC에 PostgreSQL이 직접 설치돼 5432로 붙으면 컨테이너가 아닌 다른 DB로 접속
  - 터미널 세션에 남아 있던 옛 환경변수가 기본값보다 우선
- **설정 변경의 영향 범위를 한 번에 파악하지 못했다.** 변수 이름 하나를 바꾸면서 문서·IDE·Compose·팀원 PC까지 연쇄로 영향이 가는 걸 뒤늦게 발견해 여러 번 되돌아갔다.
- **처음 세팅이 "내 PC에서만" 동작했다.** 15432 포트, 개인 JDK 경로, 로컬 비밀번호가 문서에 섞여 있어 다른 팀원이 바로 재현하지 못했다.
- **V1 마이그레이션을 수정해 로컬 DB를 두 번 초기화했다.** 병합 전이라 허용됐지만, 병합 후였다면 V2로 고쳐야 했고 팀원 DB에도 영향이 갔을 것이다.
- **범위 결정이 늦었다.** CI 연결, 도메인 스키마 범위를 작업 도중에 조정해 문서와 Task 정의가 한동안 어긋나 있었다.

## Try

- **환경 문제는 원인부터 좁힌다.** 에러가 나면 설정을 먼저 고치지 말고 ① 어느 서버가 응답했는지(DB 로그), ② 어떤 값이 실제로 주입됐는지(환경변수·실행 명령), ③ 볼륨이 언제 만들어졌는지 순서로 확인한다.
- **설정 이름·기본값을 바꿀 때 체크리스트를 쓴다.** 코드(properties) → Compose → `.env.example` → IDE 실행 구성 → README·문서 → 팀원 공지(볼륨 초기화 필요 여부)까지 한 번에 확인한다.
- **"새 PC에서 README만 보고 실행"을 완료 기준에 넣는다.** MR 리뷰어에게 빠른 시작 재현을 요청하고, macOS 팀원 결과도 받는다.
- **마이그레이션은 병합 전 리뷰를 먼저 받는다.** 인덱스·CHECK·FK 누락처럼 리뷰에서 나올 항목은 V1 병합 전에 ERD 담당자와 한 번 더 대조한다.
- **Task 시작 시 범위 확정을 먼저 한다.** 이번 Task에서 할 것/후속으로 넘길 것을 착수 전에 Jira에 적고 시작한다.
- **남은 후속 작업을 Task로 등록한다.** GitLab CI 백엔드 빌드·테스트 연결(테스트 DB 방식 결정 포함), `operation_settings` seed 및 rule_version FK(ERD 담당자), Docker backend 이미지 실행 검증.
