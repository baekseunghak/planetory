## Keep

- 요구사항 명세서와 와이어프레임을 비교하면서 담당 프론트 화면의 흐름과 예외 상황을 점검했다.
- 탐색 완료, 사용자 판단, 성과 인정 조건을 분리해서 정리했다.
- ERD를 최신 요구사항과 대조해 구현 전에 보완할 데이터 구조와 제약 조건을 확인했다.

## Problem

- 논의한 정책이 문서에 모두 반영되지 않아 게시 여부와 다음 탐색, 완료 후 재도전 조건에 혼선이 있었다.
- 결과별 안내와 후속 행동이 충분히 정의되지 않아 구현 단계에서 추가 판단이 필요한 부분이 남았다.
- 기존 Gold 데이터 용량 추정은 변경된 저장 요구사항을 반영하지 못했다.

## Try

- 합의된 정책을 요구사항 명세서·상태표·와이어프레임에 함께 반영한다.
- 제출 결과별 표시 내용과 가능한 행동을 표로 정리하고, 예외 상황을 포함한 Mock 데이터를 준비한다.
- ERD 수정 우선순위를 정하고, 실제 Gold 샘플을 기준으로 저장 용량을 다시 산정한다.
