# 2026-09-09 KPT

## Keep

- Gold 데이터(광도곡선·주기도)를 PostgreSQL 배열 열에 저장하도록 ERD를 v0.3으로 다시 짰다. 별당 560KB·전체 110GB로 잡히던 용량을 10분 비닝, 계산되는 배열(시각·주기 격자) 미저장, 곡선을 판이 아니라 별·섹터에 묶는 방법으로 별당 70KB·약 14GB까지 줄였다.
- 공개 데이터 판이 바뀌면 이전 판을 남기지 않고 진행 중인 회원을 최신 판으로 올리기로 정했다. 후보표는 값만 갱신되기 때문에 이전 판 화면을 보여주면 화면과 판정이 어긋난다.
- 탐색 가능성을 사용자가 보는 것과 같은 비닝 해상도로 판정해야 한다는 걸 발견해 명세서 v0.15에 반영했다. 2분 원본으로 판정하면 화면에 봉우리가 없는 신호가 미매칭으로 남아 탐색 완료를 막는다.
- 33개 테이블 ERD와 다이어그램을 문서로 정리하고 미결 11건을 표로 남겨, 팀원이 어디까지 확정인지 볼 수 있게 했다.

## Problem

- 아키텍처 문서는 아직 Gold를 EC2 파일로 두는 전제다. 인프라 PoC 계획에도 "Gold 파일 스키마와 용량 결정"이 남아 있어 같은 데이터를 두 문서가 다르게 설명하고 있다.
- 비닝 10분, 주기 격자 5,000점, 총 14GB가 전부 추정치다. 대상 별의 가장 짧은 통과 지속시간을 재기 전에는 확정할 수 없다.
- 아직 판단이 서지 않은 사항까지 문서에 먼저 반영해서 무엇이 확정이고 무엇이 제안인지 뒤섞였다.

## Try

- 아키텍처 문서의 데이터 소유권과 용량 추정을 ERD v0.3에 맞춰 고치고, 인프라 담당자와 Gold 적재 방식을 먼저 정한다.
- 한 섹터 PoC에서 통과 지속시간을 실측해 비닝 간격을 확정하고, 비닝 후 탐색 가능성을 다시 계산해 완료 판정이 막히지 않는지 확인한다.
- 백승학과 공개 분석·성과 인정·판단 통계의 테이블과 트랜잭션 경계를 맞춘다. 확정한 것만 문서에 반영한다.
