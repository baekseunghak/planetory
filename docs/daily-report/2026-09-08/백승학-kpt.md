## Keep

- ERD 초안을 검토하고, 회원·커뮤니티 데이터와 Gold 메타데이터의 관계 및 보충이 필요한 제약조건을 정리했다.
- Gold 데이터의 예상 용량과 조회 방식을 바탕으로, 곡선 파일과 RDB 요약·색인 정보를 나누어 저장하는 구성을 검토했다.

## Problem

- 사용자 데이터와 Gold 메타데이터를 동일 DB에서 관리할지 확정되지 않아, 외래키와 트랜잭션 경계를 추가로 협의해야 한다.
- ERD의 운영 숨김 상태, 중복 방지 제약, 유형별 등급과 과거 후보 데이터 보존 방식에 보충이 필요하다.
- Gold 데이터 축약 기준과 새 버전 배포 시 필요한 저장 공간이 아직 검증되지 않았다.

## Try

- DB 설계 담당자와 데이터 저장 위치 및 관계를 맞추고, 담당 기능에 필요한 제약조건을 구체화하겠다.
- 데이터 담당자와 화면용 축약 데이터·계산용 데이터의 범위를 구분하고, 실제 용량과 조회 성능을 확인하겠다.
