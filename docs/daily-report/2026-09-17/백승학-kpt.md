# 2026-09-17 KPT

## Keep

- Jira 158번 일반 게시글 CRUD를 구현하고 병합했다. 변경 필드만 저장하는 PATCH는 `JsonNode`로 받아 "필드 없음"과 "값이 null"을 구분했고, 삭제 후 수정 거부와 반복 삭제 204를 통합 테스트로 확인했다. 어제 Try로 남긴 세 항목을 모두 닫았다.
- 138번이 병합되면서 별 게시판 자격 검증을 `StarService`의 공개·발견 판정에 연결했다. 판정을 탐사 도메인 한 곳에만 두고 게시글 쪽은 호출만 한다.
- Jira 159번 댓글 CRUD를 구현했다. 부모 종류·공개 상태·소유권과 본문 2,000자를 서버에서 검사하고, 생성 시 부모 글 행을 잠가 부모 삭제가 먼저 확정되면 댓글이 저장되지 않게 했다.
- 댓글 목록에 커서 페이지네이션을 넣으면서 규약을 새로 만들지 않고 136·138번의 `SkyCursor`·`StarListCursor`를 그대로 따랐다. 불투명 커서, 요청 조건에 묶어 불일치 시 400, `{items, nextCursor, hasNext}` 응답까지 같은 모양이다.
- 글 상세의 댓글 수 때문에 게시글·댓글 서비스가 서로를 참조하던 것을 `GET /me`가 회원과 탐사 요약을 합치는 방식대로 컨트롤러 조립으로 바꿨다. 서비스 계층이 한 방향이 되어 반응·첨부가 붙어도 의존이 쌓이지 않는다.
- MR 67·72번을 리뷰하면서 지적한 내용을 결함 주입으로 직접 확인했다. 조건을 일부러 틀리게 바꿔도 테스트가 통과하는지 보고, 통과하면 그 자리를 지적했다.

## Problem

- 커서 동률 처리에서 내가 쓴 주석이 검증하지 못하는 내용을 주장하고 있었다. 댓글을 요청 5번으로 만들어 생성 시각이 모두 달랐는데 "동률을 id로 가르는지 함께 본다"고 적어 두었다. 리뷰에서 결함 주입으로 잡혔고, 시각을 강제로 같게 만드는 테스트를 추가해 고쳤다.
- 158번 브랜치 이름에 한글을 써서 브랜치 가이드와 어긋났다. 커밋을 쌓기 전에 발견해 새 이름으로 옮겼지만 처음부터 가이드를 확인했어야 했다.
- 글 상세를 만들 때 상세 1건만 보고 댓글 수 집계 위치를 정했다. 피드가 목록 N건에 같은 값을 요구한다는 걸 나중에 확인했다. 결과적으로 카운터 열은 필요 없다고 결론 났지만, 소비처를 먼저 세어 보고 정했어야 했다.
- 회원·게시글·댓글 세 티켓의 테스트가 `AuthIntegrationTest` 한 파일에 쌓였다. 탐사 도메인은 이미 기능별 테스트 클래스를 쓰고 있어 기준이 어긋난다.
- 게시글·댓글 모두 반응·첨부·출처가 고정값이라 응답이 "없다"고 단언한다. 명세에 미구현임을 적었지만 소비하는 쪽에서 오해할 여지가 남아 있다.

## Try

- 테스트가 실제로 무엇을 지키는지 결함 주입으로 확인한 뒤에 주석과 검증 항목을 적는다. 주석이 주장하는 내용과 테스트가 잡는 내용이 어긋나면 주석이 아니라 테스트를 고친다.
- 브랜치와 커밋을 만들기 전에 해당 가이드를 먼저 연다.
- 피드(F05·13) 구현에서 댓글 수를 페이지 id 목록으로 한 번에 묶어 읽고, `author` 필터가 현재 닉네임 정확 일치라는 점과 공식 스레드 제외 조건을 함께 확인한다.
- OAuth 로그인 픽스처를 공용으로 분리해 회원·게시글·댓글 테스트를 기능별 클래스로 옮기는 작업을 별도 Task로 올린다.
- 159번 MR에서 댓글 목록 정렬을 최신순으로 유지할지 확인받는다. 최신순은 페이지를 넘기는 동안 목록 앞이 밀리고, 오래된순이면 새 댓글이 뒤에만 붙어 더 안정적이다.
