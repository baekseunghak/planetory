## 2. C02-R1: 은퇴 후보의 세 경로

공통 입력: 원 제출 제거 조합 `{A,B}`, 현재 판에서 B 은퇴, 현재 진행 문맥 `{A,C}`. A와 C는 본인이 매칭한 활성 후보이고 재도전 대상 D는 활성·제거 집합 밖이라고 가정한다. 누적 매칭 집합과 현재 진행 문맥은 다른 값이다. 아래는 원본과 각 제거 조합의 캐시가 준비됐다는 조건이다.

| 경로 | 기존 문서가 말하는 결과 | 비교할 배열·안내 |
|---|---|---|
| 분석 복귀 5.1 | 기존 API: `{A}`, step 1 | `{A}` 잔차, `notice=STEP_NOT_RESTORABLE` |
| 재도전 SUB-10 | SRS: 현재 진행 `{A,C}`, step 2 | `{A,C}` 잔차, 이전 단계 복원 불가 안내 |
| 재도전 6.8 | 기존 API: `{A}`, step 1 | `{A}` 잔차, `restored.step=false`, `restored.notice=STEP_NOT_RESTORABLE` |
| History HIS-03·8.3 | SRS와 8.3: `{}`, step 0 | 현재 원본, `residualReproducible=false`, `fallbackReason=RETIRED_CANDIDATE` |
| History를 6.8의 일괄 규칙으로 읽은 경우 | `{A}`, step 1 | 8.3의 원본 대체 설명과 충돌 |

**검토 제안:** 경로를 구분한다. 재도전은 SUB-10의 현재 진행 `{A,C}`, History CURRENT는 HIS-03의 원본 `{}`, 분석 복귀는 현재 진행을 따를지 기존 제거 조합의 활성 부분 `{A}`를 유지할지 명시적으로 결정한다. History SUBMITTED는 `curve=null`과 당시 snapshot을 유지한다. 단일 공통 fallback 함수를 적용하기 전에 경로별 결과부터 승인해야 한다.

배열 예시: 원본 `[1,0.99,0.98]`, A 모델 `[1,0.99,1]`, C 모델 `[1,1,0.98]`이면 A 제거 `[1,1,0.98]`, A+C 제거 `[1,1,1]`이다. B는 은퇴했으므로 현재 B 모델을 만들어 사용하지 않는다. 이 값은 경로 차이를 드러내는 합성 예시이며 과학 모델 승인값이 아니다.

캐시가 없으면 조회로 작업을 생성하지 않는다(D-14). 대상 D 자체가 은퇴한 재도전은 대체하지 않고 409 `CANDIDATE_RETIRED`. 조회로 누적 매칭·완료·원 제출을 변경하지 않는다.

결정 담당: 강재민·백지웅, 공개/첨부 그래프 경계 백승학. 인계: A07·A08-1·A09, C02. **미결: 세 경로의 선택안과 승인 기록 없음.**

## 3. C02-R2: 기준 시각의 저장 범위와 환산

SRS v1.2 DAT-11·PublicationBundle은 세그먼트별 기준 시각으로 읽히지만 EXP-06·AT-95는 Bundle 공통값을 한 번 저장한다고 명시한다. ERD publication_bundles와 API 2.5·5.1도 Bundle 공통값이다. SRS 내부 표현까지 함께 정합화해야 한다.

| 대안 | 저장·산정 | 필요한 변경 |
|---|---|---|
| Bundle 공통값 | 해당 판에 포함된 품질 통과 원본의 유한 time/flux 관측 시각 전체 중앙값 | SRS 세그먼트별 표현 정정, manifest와 API 공통값 전달 |
| 세그먼트별 값과 공통 접기 좌표 변환 | 세그먼트 원본 관측별 중앙값 저장, 공통 접기 기준 산정·변환을 별도 정의 | ERD/API에 세그먼트 기준 및 변환 계약 추가, 제출의 공통 좌표·기록 범위 명시 |

둘 다 가능한 대안이다. Bundle 공통안은 현재 API와 맞지만 담당 합의 없이 채택하지 않는다. 산정 입력은 비닝된 시각이나 세그먼트 중앙값들의 단순 평균으로 임의 대체하지 않는다. 예를 들어 세그먼트 원본 시각 `[100,102]`, `[110,112,114]`의 전체 중앙값은 110이고 세그먼트 중앙값의 평균은 106.5다. 중복 관측 포함 기준·짝수 표본 중앙값·빈 입력 실패·품질 마스크는 D06에 명시해야 한다. float64 round-trip 전달을 유지하고 표시 반올림값을 계산 입력으로 쓰지 않는다.

AT-118 공통 환산 사례: P=4일, 옛 T=100, phase=0.20~0.30 → epoch=101, duration=9.6시간. 현재 T=101이면 중심=0, 폭=0.1, phase=0.95~1.05. 현재 T=102이면 중심=0.75, phase=0.70~0.80. 절대 epoch와 duration은 변하지 않는다. 이 계산 예제는 저장 범위의 대안을 결정하지 않는다.

결정 담당: 윤성용·강재민·김동혁, 소비자 확인 백지웅. 인계: [D06 #113](https://ssafy.atlassian.net/browse/S15P21C206-113). **미결: 저장 범위·산정 입력·공동 승인 없음.**

## 4. C02-R3: duration 상한과 추천 중첩

추천 밖 주기는 전체 격자 안이면 허용한다. 이는 모든 위상·duration이 허용되거나 후보 매칭에 성공한다는 뜻이 아니다.

현재 6.2 제안은 `minWindowDays/P` 이상의 위상 폭, `phaseWidthMax` 이하를 검사하고 추천 fineTune과 연결되면 `suggestedDurationHours × maxDurationMultipleOfSuggested`도 적용한다. 추천이 여러 개 겹칠 때 선택 기준이 없다. DEC-19의 3배는 기본안이며 운영 확정값이 아니다.

비교 입력: P=4일, phase 폭=0.1 → 9.6시간. 겹치는 추천 A의 duration=2시간, B=4시간, 배수=3을 합성값으로 두면 A 선택은 상한 6시간으로 거절, B 선택은 12시간으로 허용이다. 배열 순서로 첫 추천을 고르면 결과가 뒤집힌다.

검토할 선택안: 가장 가까운 주기(동률 규칙 필요), 가장 엄격한 상한, 추천 표시와 독립적인 과학 규칙. 추천 N 변경으로 제출 판정이 변할지까지 함께 결정한다. 승인 전 특정 안을 validator의 합격 기준이나 운영 기본값으로 넣지 않는다.

`N_transits`(매칭 누적오차 통과 수), `N_peak`(표시 추천 수), 매칭 최소 창, UI 최소 선택 폭은 별도 필드·단위다. 현재 예제 수치는 실측을 대체하지 않는다.

결정 담당: 윤성용·강재민·백지웅. 인계: [D20 #128](https://ssafy.atlassian.net/browse/S15P21C206-128), C09·A04. **미결: 실측·rule_version·중첩 우선순위 승인 없음.**

## 5. 유지할 소비자 계약

- D-13: 별의 모든 공식 신호 스레드에 참여한 회원의 합집합 크기. 스레드 A={u1,u2}, B={u2,u3}이면 3명이며 4명이 아니다. 취소·숨김 뒤 다른 유효 공개가 남은 회원은 포함한다.
- D-14: 결과·작업이 없으면 status/jobId 모두 null. 조회는 작업을 만들지 않으며 null을 QUEUED로 바꾸지 않는다.
- D-15: 타인 공개 그래프는 기존 공개 권한으로 조회하며 잔차 재계산을 제공하지 않는다. 원본/당시 snapshot 대체와 제공 불가 안내를 유지한다. 타인의 개인 작업 조회 권한을 추가하지 않는다.
- EXP-11: 홀짝·2차 식·V/U형 도구는 제공 곡선을 브라우저에서 계산한다.
