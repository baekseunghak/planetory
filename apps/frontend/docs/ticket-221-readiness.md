기준: 2026-09-21 develop `c711da9`. 사용자는 219~223 전체 진행을 요청했다. 전체 진행 요청을 서버 정책 확정 증거로 해석하지 않는다. 이 문서는 **221 일부 구현**의 기록이며 티켓 완료 선언이 아니다.

## 구현·검증

- [x] 기존 `/settings` 슬롯에 실제 SettingsPage 등록. 시제품 MemberPages의 설정 제목·프로필/탐사 안내/공개 범위/계정 행 구성과 공개 전환 스위치를 참조했다.
- [x] `GET /api/v1/me`에서 본인 `starListVisibility`를 읽고 `PATCH /api/v1/me/settings`로 PUBLIC/PRIVATE만 저장한다. 공용 인증·CSRF·401 처리를 사용한다.
- [x] 설정 행 없는 기본 PUBLIC은 서버가 반환한다. 필드 누락·잘못된 값·다른 회원 응답을 PUBLIC으로 추정하지 않는다.
- [x] 저장 진행 중 중복 클릭 차단. 오류·응답 유실 때 PATCH를 반복하지 않고 GET으로 확인한다. 재조회도 실패하면 스위치를 숨기고 수동 재조회만 허용한다.
- [x] 닉네임 편집·사용법 다시 보기·로그아웃은 기존 P0 구성요소를 재사용한다. 안내 다시 보기는 onboarding API를 호출하지 않는다.
- [x] Chrome 설정 7개, 단위 341개, 타입 검사·운영 빌드·개발 fixture 배포 제외 검사 통과.

- [ ] 알림 종류별 수신 설정. 서비스 API 12장에는 후보 경로만 있으며 필드·기본값·오류 계약 미확정이다. 백승학 담당 174(S21)·175(S22) 제공 후 연결한다. 빈 객체나 임의 기본값으로 저장하지 않는다.

## 실행

`npm run dev:settings` → `http://127.0.0.1:58382/settings`. serve 전용 메모리 응답이며 실제 회원 계정·DB를 변경하지 않는다. 서버 재시작 시 초기화된다.

`npm run test:settings`는 Chrome을 쓰며 별도 포트58383에서 실행한다. 실제 서버 모드에는 개발 응답을 포함하지 않는다.
