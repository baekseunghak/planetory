## 검증

Windows, Node 24.18.0/npm 11.16.0, 기존 잠금 파일·의존성을 유지한다.

- `npm run check`: 타입·기본 운영 빌드/개발 코드 제외, 단위 41개(204 신규6), 공통 Chromium6, 인증9, 지도 데이터6, 렌더9, 기본 dist4 통과.
- 렌더9개는 overview 최소 로딩, 6단계/회전/교체, 예산 초과의 서버 단계 변경, 상세5행성/버퍼 재사용, 새 발견/살구색 완료, 부분 실패 재시도, context 복구/모션 줄이기, 1024px 미지원 안내, 빈 지도다.
- `npm run test:renderer-production`: 플래그를 켠 운영 dist에서 HTTP 메타 렌더·개발 도구 제외와 401 개인 캔버스 제거 **2개 통과**. Playwright 응답 주입은 운영 API 검증으로 계산하지 않는다.
- `npx playwright test --config=playwright.galaxy.config.ts --project=chrome --project=msedge`: 설치된 Chrome 9개·Edge 9개 통과.
- Firefox는 overview 1개를 시도했으나 `browserType.launch: spawn UNKNOWN`으로 페이지 실행 전 실패했다. 기능 합격/불합격으로 해석하지 않는다. 실제 Safari, Node22 Docker/Nginx, 실제 C05/C06, 10만 별/실장비 성능은 미검증이다.

## C1~C7과 재개 조건

실제 Chrome 창(현재 화면 크기)의 계측 예: 전체 보기 별0/성운32/본체·성운1회, LOD3 별53/궤도별23/성운0/행성65, 본체1회+궤도1회+행성1회. 두 상태 모두 GPU 버퍼5개다. 가시 수는 화면 크기와 카메라에 따라 달라지므로 고정 기대값으로 사용하지 않는다.

변경 파일의 Prettier 및 `git diff --check`는 통과했다. 전체 `npm run format:check`는 기존 52개 파일의 Windows CRLF에 대해 경고했다(`core.autocrlf=true`). `npx prettier --check --end-of-line auto src dev tests scripts docs *.ts *.json *.html *.md`는 전체 통과하여 줄바꿈 차이임을 확인했다. 해당 파일을 이번 204 변경에 섞어 일괄 수정하지 않았다.

- C1/C2: 공통 HTTP 오류/진입 상태를 사용한다. 로딩·빈 자료·부분 실패/재시도·그래픽 실패를 로컬 검사했다. 실제 C05/C06 응답·인증/접근 제한은 남는다.
- C3: TIC/candidateId는 문자열, depthZ는 단위 없는 정규화 깊이, periodDays/null/depthPpm은 DTO 그대로다. 성과·별 해금·후보 소유권은 서버 판단이다.
- C4: 204 운영 코드는 읽기·렌더 기능이다. 개발 시나리오 POST는 운영에 포함하지 않는다. 커뮤니티 쓰기·분석 제출 기능은 이번 범위에 없다.
- C5: 203 회원/버전 캐시와 늦은 응답 격리를 사용하고 401 시 개인 화면을 제거한다. 실제 계정 전환·공개 취소 등의 서비스 왕복은 미인수다.
- C6: Chromium/설치된 데스크톱 브라우저 결과를 구분한다. Safari 실제 환경·Firefox 실행 환경, 최종 지도 키보드 조작(205/207)은 별도 대기다.
- C7: 개발 UI/응답의 운영 제외는 빌드로 검사한다. 리뷰 승인·develop 병합은 미완료다.

재개 대상은 강재민 담당 C05-1/2(`S15P21C206-136/137`)의 메타·타일·군집과 C06 개인 별 상세, 실제 인증/시험 계정이다. 필요한 API와 계정이 제공되면 해당 백엔드 티켓 전체 종료 전에도 대조할 수 있다. W01/C05와 같은 좌표/카메라 fixture를 교차 검토하고 Node22 Docker/Nginx·지원 브라우저 환경도 별도로 검증해야 한다. 이 환경/협업 대기를 모두 백엔드 구현 대기로 뭉뚱그리지 않는다.
