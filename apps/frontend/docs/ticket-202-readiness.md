### 아직 확정하지 않은 연결 방식

서비스 API 문서는 OAuth 진입/콜백 URL, 세션 쿠키명·CSRF 방식, 최초 닉네임 필요 상태의 구체적인 응답을 확정하지 않았다. 이번 코드의 연결점을 서버 정본으로 간주하지 않는다.

| 설정                                            | 용도                                                  | 현재 상태                                                       |
| ----------------------------------------------- | ----------------------------------------------------- | --------------------------------------------------------------- |
| `VITE_OAUTH_SSAFY_URL`, `VITE_OAUTH_GOOGLE_URL` | 서버가 제공하는 로그인 진입 URL                       | 운영 기본값 없음. 미설정 버튼 비활성                            |
| `VITE_CSRF_HEADER`, `VITE_CSRF_COOKIE`          | 기존 공통 HTTP 클라이언트의 쿠키→헤더 어댑터          | 실제 이름·발급 방식 합의 대기. 토큰을 환경 변수에 저장하지 않음 |
| `VITE_NICKNAME_REQUIRED_CODE`                   | `/me`의 403/409에서 최초 닉네임 폼을 여는 명시적 코드 | 검증용 어댑터 제안. 일반 403/409로 추정하지 않음                |
| `VITE_INITIAL_NICKNAME_PATH`                    | `{nickname}`을 PATCH하는 초기 등록 경로               | 운영 기본값 없음. fixture만 `/v1/me/profile` 사용               |

서버가 다른 상태/메서드/응답 구조를 확정하면 설정만 바꾸는 것으로 충분하지 않을 수 있으므로 `SessionProvider`, `LoginPage`의 해당 어댑터를 함께 맞춘다. 현재 `/oauth/callback`은 **서버 인증 처리가 끝난 뒤의 프론트 도착 화면**으로 구현했다. 실제 OAuth code 교환 주소와 구분해야 한다.
