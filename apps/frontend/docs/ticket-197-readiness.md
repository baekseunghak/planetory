## 구현과 계약

인증 회원의 onboardingDone을 읽고 별지도와 실제 분석 단계 옆에 5단계 안내를 연결한다. 닫기는 PATCH /api/v1/me/onboarding에 true만 전송한다. 저장 실패 시 안내와 분석 입력을 유지하고 재시도를 제공한다. 별 선택·단계 이동은 완료 쓰기를 하지 않는다.

수락된 제출 후 GET으로 서버 완료 상태를 다시 읽는다. 클라이언트가 튜토리얼 성공·성과를 계산하지 않는다. 세션 전체를 refresh하지 않아 분석 편집기를 재마운트하지 않는다. 초기/새로고침의 정본은 GET 응답이며 서버 읽기 실패만으로 완료를 추정하지 않는다.

회원별 보호 라우트 경계와 요청 취소를 재사용한다. 안내 안에 남은 포커스는 닫기 성공 후 본문으로 옮기며 요청 중 다른 곳으로 이동한 포커스는 빼앗지 않는다. 단계와 저장 상태는 보조기술에 알린다. Jira의 오래된 /me/settings 표기를 현재 서버 전용 endpoint로 정정했다. 새 API·DB 변경은 없다.

## 검증

- 생산 빌드와 단위 검사 427건 통과. 마지막 접근성 변경 후 타입 검사 통과. 기존 Vite fixture 확장자·번들 크기 경고가 있다.
- 새 Chromium 안내 검사 5건 통과: 1024px/키보드, 최초·재방문·true 단방향 저장, 실제 단계·메모와 실패 재시도, 제출 후 서버 완료 관찰, 계정 이탈 중 늦은 응답 격리.
- 기존 제출·초안과 안내 57건 실행에서 56건 통과, 기존 제출 레이아웃 검사 1건이 구간 확정 버튼 대기 중 시간 초과됐다. 개발 파일 수정을 멈춘 뒤 해당 검사와 최종 안내 5건을 재실행하여 6건 통과했다. 최초 실패 원인은 확정하지 않았다.
- W16 기존 GIF 열람·무변경·키보드·포커스, 모션 줄이기·이미지 실패 대체 검사 두 시나리오의 통과 로그를 확인했다. 테스트 서버 종료가 지연되어 실행 프로세스는 수동 중단했다. 시나리오 통과와 명령 정상 종료를 구분한다.
- 실제 계정/API/DB, 스크린리더 실기기, 전체 브라우저 조합은 실행하지 않았다.

## 다시 보기와 남은 인수

기존 UsageGuide 화면과 에셋은 변경하지 않는다. [에셋 설명](../public/guides/README.md)에 따르면 5단계 GIF/PNG는 실제 화면 녹화가 아닌 설명용 도식이고 팀 내용 검토가 남아 있다. 별 선택 → 봉우리 → 구간 → 판단 → 제출의 단계 순서는 실제 안내와 일치한다. GIF 전체 프레임과 실제 조작의 내용 일치에 대한 W16 담당자 교차 검토는 완료로 주장하지 않는다.

실제 최초 계정으로 GET/PATCH 영속성, 재로그인, 첫 튜토리얼 제출과 닫기의 경합, 다른 설정 보존을 확인해야 한다. W09 진입과 W16 설명을 함께 확인한 뒤 Jira 완료 여부를 판단한다.

## 병행 경계와 실행

198은 개인 통계 슬롯과 main.tsx 등록을 맡는다. 197은 ServiceLayout, AnalysisJudgment, use-submission 및 onboarding 기능을 수정한다. 공유 인증·프로필 계약을 바꾸지 않는다.

개발 fixture 실행은 `npm run dev -- --mode fixture --port 58397 --strictPort`이다. 최초 방문 상태는 `tests/browser/onboarding.spec.ts`에서 명시적으로 주입한다. 기본 fixture 화면만 보고 최초 계정 API 인수로 간주하지 않는다. 기본 Playwright 설정에서도 이 검사를 실행할 수 있다.
