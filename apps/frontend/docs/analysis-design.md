# 분석 1–5단계 Figma 적용 (#236)

[S15P21C206-236](https://ssafy.atlassian.net/browse/S15P21C206-236)은 [Figma 02 분석 단계 · 1–5](https://www.figma.com/design/khh8ZkqU7ivmUftKWrxSxn?node-id=25-2)를 실제 분석 화면에 적용한다. 기준 프레임은 **은하 스타일**의 100:2, 100:97, 100:195, 100:293, 100:419다. 03 Dark Neumorphism은 적용하지 않는다. 기능 정본은 [분석 프론트 명세 §5.2](../../../docs/development/analysis-frontend-spec.md#52-figma-분석-15단계-화면-적용-236), 색·간격 토큰과 컴포넌트 규약의 정본은 [분석 화면 디자인 토큰](design.md)이다.

2026-09-17에는 기본 스타일(25:3 외)로 먼저 적용했다. 2026-09-18에 토큰 문서가 은하 스타일을 채택으로 정하고 기본 스타일 5화면을 구현 대상에서 제외하면서, 배치·단계 전환·입력 경로는 유지한 채 색·표면·간격만 교체했다. 아래 화면·조작 표는 두 스타일에 공통이다.

## 브랜치와 의존성

`feature/S15P21C206-236-web-analysis-design`을 #185의 develop 통합 커밋 `966ba50`에서 만들었다. 작업 폴더는 `.worktrees/analysis-236`이다. 공통 화면과 단계 전환이 같은 컴포넌트를 사용하므로 디자인은 이 브랜치 하나에서 관리한다. 182~185에 같은 스타일 변경을 각각 복제하지 않는다. 기존 기능 브랜치가 병합된 뒤 MR 기준과 의존 커밋을 다시 확인한다.

## 화면·조작

시간 곡선·주기도·접힌 곡선을 같은 위치에 두고 오른쪽 패널을 현재 단계에 맞게 전환한다. 실제 곡선 배열을 Canvas로 그리며 Figma 예시 곡선을 관측 데이터로 사용하지 않는다. 새 색상은 분석 화면에만 적용한다. 공통 서비스 메뉴·로그아웃 경로는 유지한다.

| 단계 | 편집 | 다음 행동 |
| --- | --- | --- |
| 주기 선택 | 그래프 위 봉우리 클릭/Enter, 배경 클릭 또는 격자 조회 후 Enter로 직접 선택. 선택 후에도 이 단계에 머물며 다시 고를 수 있다. 같은 화면의 슬라이더로 미세 조정 | 이 주기로 구간 선택 |
| 구간 선택 | 드래그·핸들, Shift+드래그 이동, 접힌 키보드 대체 경로 | 구간 확정하고 판단하기 |
| 판단 | 판단 3종, 근거 3종, 선택 메모 200자 | 제출값 확인 |
| 제출값 확인 | 원본 선택값에서 만든 요약, 판단·메모 수정 가능 | 제출 API 미연결로 비활성화 |

- 이전 단계로 이동만 하면 작성 내용은 유지한다. 구간을 수정하면 내용을 보존하되 다시 확정한다. 주기 변경 성공 시 구간·판단·메모를 초기화하는 기존 규칙은 유지한다.
- 확대·이동·값 조회는 다른 단계에서도 가능하다. 전체 보기 아이콘은 배율·중심만 초기화하고 휴지통은 구간·확정·파생값만 지운다. 확대·축소 버튼은 조작 도움말에서 사용할 수 있다.
- 32배 확대, 미세 조정 중 표시 위치 유지, Web Worker의 최신 결과 채택, 느린 계산만 안내·취소 노출, 실패/취소 복구를 유지한다. GPU는 기존 개발용 실험 경계 그대로다.
- 구간 폭 오류는 별도 키보드 안내를 열지 않아도 오른쪽에 표시한다. 메모 초과 입력은 자르지 않고 오류 위치로 포커스를 이동한다. 단계 진행 후에는 다음 제목/입력으로 포커스를 옮긴다.
- 곡선 버전·세그먼트·실제 Sector 간격은 데이터 상세에서 확인한다. 반복 위상의 표시 좌표와 제출용 정규화 위상은 같은 구간이어도 1만큼 다를 수 있다. 예: 표시 -0.01~0.01, 제출 0.99~1.01. 반올림한 표시값으로 계산 원본을 덮어쓰지 않는다.
- 1024px 이상에서 사용하며 좁은 화면은 기존 데스크톱 안내를 유지한다. 입력·요약이 길면 페이지를 스크롤한다.

## 은하 스타일 적용 (2026-09-18)

색·간격 값은 [디자인 토큰 문서](design.md)에 있고 여기서 중복하지 않는다. 구현하며 정한 것만 남긴다.

- 토큰은 `body:has(.analysis-screen)`과 `.analysis-screen` 두 곳에 함께 선언한다. 배경 오버레이를 `body`에서 써야 하기 때문이며 전역 `:root`는 건드리지 않는다. #236의 `.analysis-design` 클래스와 CSS 파일 이름은 정본 표기에 맞춰 `.analysis-screen`으로 바꿨다.
- 은하 배경은 `src/features/analysis/assets/galaxy-background.webp`다. 원본 PNG 2.0MB를 품질 0.92 WebP 206KB로 줄였고 평균 채널 오차는 1.3이다. 밝기 분포는 평균 rgb(10,13,21), 상위 0.1% rgb(170,168,185)로 토큰 문서의 허용 한계 rgb(184,189,204) 안이다.
- 분석 전용 CSS 4개(`folded-curve`·`periodogram`·`time-curve`·`analysis-judgment`)에 남아 있던 이전 전역 남색 팔레트를 토큰으로 치환했다. 특정성으로 덮지 않고 값 자체를 바꿔 누수를 없앴다.
- Canvas·WebGL은 CSS 변수를 읽지 못하므로 같은 값을 코드에 직접 적었다. 접힌 곡선의 벡터·래스터·GPU 세 경로가 서로 다른 색(회색 대 민트)을 쓰던 것을 관측점 `rgb(238,238,238)`로 통일했다. 시간 곡선의 예상 반복 위치 띠는 파랑에서 `--band` 금색으로 바뀌어 범례 문구도 「금색 띠」로 고쳤다.
- Figma 원본 SVG는 `#4B4B4B` 고정 스트로크이고 `<img>`로 넣으므로 `filter: invert(1) brightness(1.25)`로 맞춘다. 이 `filter`가 스태킹 컨텍스트를 만들어 판단 카드를 덮는 투명 라디오 위로 아이콘이 올라가 클릭을 가로챘다. 장식 이미지이므로 `pointer-events: none`으로 해결했다.
- 축·범례를 정본의 11px로 올리자 1024px에서 시간 곡선 범례가 `max-height: 30px; overflow: auto` 때문에 스크롤 영역이 되어 axe `scrollable-region-focusable` 위반이 났다. 범례는 절대 배치라 흐름을 밀지 않으므로 높이 제한을 없애고 줄바꿈시켰다.
- 오류 문구 색은 토큰 문서에 정의가 없어 `--fg-1`로 두었다. 오류는 색이 아니라 문구와 포커스 이동으로 알린다.

SVG 아이콘 5개는 해당 Figma 파일에서 내보낸 원본이며 [출처](../src/features/analysis/assets/README.md)를 남겼다. React 성능 지침에 따라 Canvas 인스턴스·계산 경로를 유지하고, Web Interface Guidelines 기준으로 레이블·키보드·포커스·오류·대비를 확인했다.

## 단계 병합과 미세 조정 정밀도 (2026-09-18)

기능 기준은 [분석 프론트 명세 §5.2](../../../docs/development/analysis-frontend-spec.md#52-figma-분석-15단계-화면-적용-236)다. 구현하며 정한 것만 남긴다.

- Figma의 1·2단계를 한 단계로 합쳐 4단계로 만들었다. 봉우리를 골라도 단계가 넘어가지 않고 주기도가 계속 조작 가능하며, ‘이 주기로 구간 선택’을 눌러야 2단계로 간다. `useAnalysisStage`의 파생 규칙만 바꾸고 각 컴포넌트는 새 번호를 참조한다. 주기도의 확대·이동과 전체 보기 버튼은 요청대로 그대로 두었다.
- 미세 조정은 서버 격자 한 칸(`fineTune.periodStepDays`)을 `FINE_TUNE_DIVISIONS = 128`로 나눈 간격을 쓴다. 이전에는 슬라이더가 `step="any"`여도 `sliderPeriod()`가 서버 격자에 스냅해 허용 범위 전체가 7단계뿐이었다.
- fixture 실측: 허용 범위 11.7037979~11.7655160일(폭 0.061718일), 미세 간격 8.040e-5일, 768단계. 슬라이더 폭 934px에서 1픽셀당 약 0.82단계라 포인터로 끝까지 끌어도 화면 주사율만큼만 다시 접는다. PageUp/PageDown은 서버 격자 한 칸 1.021e-2일을 그대로 움직인다.
- 128은 2의 거듭제곱이라 서버 격자 칸과 봉우리 원래 주기가 모두 격자 위에 남는다. 스냅 기준은 앵커(봉우리 원래 주기)이므로 미세 조정 뒤에도 원래 값으로 정확히 돌아올 수 있다.
- 서버 검증은 범위만 확인하고 격자 정렬을 요구하지 않는다(`validPeriod`, `phase-selection.ts`). 제출 계약은 바뀌지 않았다.
## 패널 범례 배치 (2026-09-18)

- 주기도 범례가 카드 밖으로 5.3px 나갔다. 원인은 두 가지다. `periodogram.css`의 `.analysis-periodogram p`(특정성 0,1,1)가 `.chart-caption`(0,1,0)을 이겨 **11px 대신 13px**로 그려졌고, 카드 높이가 258px로 고정이라 넘친 만큼 그대로 삐져나왔다. 규칙을 `.analysis-screen .chart-caption`으로 올려 11px을 적용했다.
- 시간 곡선 범례는 원래 절대 배치라 카드 높이에 영향을 주지 않았다. axe `scrollable-region-focusable`를 없애려고 높이 제한을 푼 뒤에는 1024px에서 두 줄이 되어 9.9px 넘쳤다. 흐름 안으로 되돌리고 음수 왼쪽 여백으로 y축 자리를 그대로 쓰게 했다.
- 두 카드는 `height: 258px` 고정 대신 `min-height: 258px` + `align-self: stretch`로 바꿨다. 범례 줄 수에 따라 카드가 커지고 같은 행의 두 카드가 서로 높이를 맞춘다. 결과 행 높이는 1440px에서 278px, 1024px에서 286px이다. **Figma의 258px보다 커진 것이므로 디자인 확인이 필요하다.** 그래프 높이를 줄이면 258px을 지킬 수 있으나 주 콘텐츠가 작아져 택하지 않았다.
- 단계별 배치는 그대로다. 카드가 높아지면서 포커스 이동 시 페이지가 스크롤되는데, 회귀 검사가 뷰포트 기준 좌표를 비교해 패널이 움직인 것처럼 보였다. 실제 `scrollY`가 0에서 20(1024)·16(1440)으로 바뀐 것뿐이라 검사를 문서 기준 좌표 비교로 고쳤다.
## 재계산 중 버튼 깜빡임 (2026-09-18)

슬라이더를 끄는 동안 ‘이 주기로 구간 선택’이 프레임마다 활성·비활성을 반복했다. 실측으로 드래그 40스텝에 접기 41회, 버튼 `disabled` 전환 82회였고 접기 한 번은 6~15ms(중앙값 10ms)라 비활성 구간이 한 프레임이었다.

- 잠금을 없애지 않았다. `go()`의 즉시 차단은 그대로 두고 **보이는 상태만** 늦춘다. 이미 진행 안내·취소 버튼이 쓰던 `PROGRESS_NOTICE_DELAY_MS`(1초) 규칙을 버튼에도 적용해, 계산이 길어질 때만 안내와 함께 잠긴다.
- 지연 로직을 `fold-progress.ts`의 `useSustained`로 빼서 안내와 버튼이 같은 기준을 쓰게 했다. 조건은 `!ready && (!pending || 지연된 pending)`이라 실패·취소는 `pending`이 아니므로 **즉시** 잠긴다.
- 비활성화를 빼거나 비활성 색만 지우는 대안은 택하지 않았다. 앞은 느린 계산·실패에서 진행 가능한 것처럼 보이고, 뒤는 눌리지 않는 버튼이 눌리는 것처럼 보이며 `disabled`가 탭 순서에서도 빠져 포커스를 잃는다.
- 결과: 같은 드래그에서 접기 41회는 그대로이고 버튼 전환 0회. 회귀 검사 2개를 추가했다(드래그 중 전환 0회, 2초 지연 접기에서 안내와 함께 잠김).

- `node scripts/check-contrast.mjs` 통과. 유리 위·플롯 안·패널 밖 세 표면에서 `--fg-1/2/3`·`--accent`·`--grid`가 모두 기준 이상이다. 최악값은 패널 밖 `--fg-3` 4.56:1이다.
- 남은 위험: 패널 밖에는 블러가 없어 순백 별 픽셀이 글자 뒤에 오면 `--fg-2` 4.28:1, `--fg-3` 3.52:1로 미달한다. 오버레이를 0.85로 올리면 해소되지만 정본 값은 0.75이므로 바꾸지 않았다. 스크립트가 이 경우를 참고 항목으로 출력한다.
- 1024px·1440px 화면과 1~5단계 이동, 32배 위치 유지, 주기 변경 시 구간·판단·메모 초기화, 제출 비활성화를 실제 브라우저에서 확인했다.

표준 브라우저 재현 명령은 `npx playwright test --project=chrome --grep-invert "GPU|WebGL"`이며 GPU 연결 회귀는 같은 명령에서 `--grep-invert` 대신 `folded-curve-gpu.spec.ts`를 지정한다. 이번 로컬 검사는 실행 중인 5236 서버와 무추적 `test-results/design-check.config.ts`를 사용했다. GPU 성능 실험·다른 브라우저·실제 서버·운영 배포 인수를 통과한 것으로 해석하지 않는다.
