# 202 MR !35 통합 검증 — 2026-09-17

최신 `origin/develop` `432ae3f`를 기존 202 브랜치에 통합했다. 201의 develop 병합은 완료되어 있으며, 이 MR의 대상은 develop이다. 아래 결과는 티켓 전체 완료가 아니라 현재 구현을 리뷰·병합할 준비에 대한 기록이다.

## 충돌 해소

- 환경 예시·Vite·Nginx의 최신 인증 프록시와 202의 콜백 실패 복귀 처리를 함께 유지했다.
- 201 헤더와 202 메뉴 로그아웃은 모두 `SessionProvider.logout()`을 호출한다. 요청 중 개인 화면을 숨기고, 실패 시 서버 세션을 임의로 지우지 않으며, 불명확한 결과는 GET 확인 후 사용자가 처리한다.
- 각 진입점의 성공·CSRF 지연·명시적 실패·응답 유실·새로고침을 회귀 검사한다. 과거 헤더 전용 처리와 중복 쓰기가 남지 않는다.
- 운영 로그인 검사는 확정된 `/oauth2/authorization/ssafy`, `/google`로 이동하는지 확인한다. 제공자 주소가 미정이라 버튼을 비활성화하던 과거 검사 전제를 제거했다. 개발 인증 API는 운영 빌드에 포함되지 않는다.
- README·공통 계약·인수 기록은 최신 API와 기존 실검증 자료를 보존했다. 이전 날짜의 검증 환경은 당시 기록으로 읽는다.

## 리뷰와 남은 인수

202 → 203 → 204 순서로 develop에 병합한다. 이번 정리는 기존 MR의 코드와 비교 대상을 정리하는 작업이며, MR 승인·병합이나 Jira 완료 처리는 수행하지 않는다.

최초 닉네임 입력과 서버 자동 생성의 합의, 현재 UI의 실제 두 제공자 신규/재로그인 전체 인수, 배포 HTTPS·Safari 등은 [202 인수 상태](ticket-202-readiness.md)에 남긴다. 이 항목을 삭제하거나 완료로 간주하지 않는다. 코드가 공용 기반에 합쳐지는 것과 해당 인수 종료는 별개다.
