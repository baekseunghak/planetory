# 별지도 데이터 어댑터 연결 계약

2026-09-14, `S15P21C206-203` / W05. 기준은 탐사 API 4.1, 별지도 표현 계약 v1.2, Jira 203 현행 본문이다. 서버 계약을 새로 정의한 문서가 아니라 이 프론트의 연결 방법과 검증 범위를 기록한다.

## 화면 연결

`src/main.tsx`의 `sky` 자리에 `SkyDataPage`를 등록했다. 이 페이지는 공통 회원·HTTP 클라이언트를 사용하며 로딩/실패/재시도/빈 범위/선택 미적재 상태를 제공한다. 204의 실제 은하 렌더러는 다음처럼 같은 페이지의 `renderScene`에 연결한다. 아래 `GalaxyScene`은 후속 구현 예시다.

```tsx
function GalaxyPage() {
  return <SkyDataPage renderScene={(props) => <GalaxyScene {...props} />} />;
}
```

렌더러가 받는 `{store, data}`는 다음과 같이 사용한다.

| 입력·함수                                           | 역할                                                                                                                             |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `data.meta`                                         | `version`, 전체 `starCount`, `bounds`, `tileSize`, `zoomLevels`, `overview`, `firstVisit`, 선택적 `asOf`                         |
| `data.stars`, `data.clusters`                       | 현재 범위에서 받은 서버 노드. 전체 목록이 아니므로 길이를 전체 별 수로 사용하지 않는다                                           |
| `store.setView({level, box, overview})`             | 현재 단계·역투영 경계 상자로 필요한 타일을 요청. 최대 축소 첫 화면은 `level:0, box:null, overview:true`로 메타의 overview만 사용 |
| `store.select(ticId)`                               | 선택 ID 보존. 카메라 이동으로 미적재되어도 미발견·삭제로 판정하지 않음                                                           |
| `store.refresh()` / `retry()`                       | 메타 다시 확인 / 실패한 요청 복구. 이미 성공한 같은 버전 타일은 재사용                                                           |
| `data.pending`, `failures`, `error`, `needsRefresh` | 요청 중·일부 실패·메타/계약 오류·최신성 확인 대기. 렌더러도 필요한 상태를 표시                                                   |
| `selectionStatus`                                   | `none`, `loaded`, `not-loaded`. 상세 권한과는 별도                                                                               |

카메라의 중심·회전·기울기·배율은 렌더러가 소유한다. `refresh()` 때문에 카메라나 선택을 초기화하지 않는다. 카메라 변화마다 `viewportBounds(matrix)`로 계산한 상자를 `setView`에 전달한다. 렌더러는 서버 `x/y/depthZ`를 재배치하지 않는다. `firstVisit`는 그대로 노출하며 안내 완료/튜토리얼 완료를 서로 추론하지 않는다.

## 좌표·타일 요청

- `viewportBounds`의 행렬은 WebGL 열 우선 4×4 월드→클립 행렬이다. 입력 z는 API `depthZ`의 정규화 값 -1~1이다. 연출용 깊이 확대는 행렬에 포함하고 원본 DTO는 바꾸지 않는다.
- 화면의 각 변 바깥으로 해당 축 크기의 **20%씩** 여유를 두는 해석을 사용했다. 역투영된 절두체를 전체 `depthZ ∈ [-1,1]` 구간과 교차시켜 월드 x/y 경계 상자를 얻는다. z=0 평면만 계산하지 않는다. 직교·원근, 회전·기울기·음수 좌표를 검증했다.
- 여백의 구체적 해석과 최종 204 카메라 행렬은 W01/C05 제공자와 같은 fixture로 교차 확인할 항목이다. 이 검증은 팀 승인 완료를 대신하지 않는다.
- 메타 타일 범위와 교차시켜 요청한다. 타일 경계는 `[min,max)`이고 음수도 `floor`로 처리한다. 메타 최대 좌표의 타일과 한 점만 있는 지도도 포함한다.
- HTTP 요청은 `/api/v1/me/sky/tiles?level=...&x=...&y=...&w=...&h=...&version=...`이다. `keys`, 타일 ID 목록, 16타일 제한을 사용하지 않는다. 한 요청의 w/h는 각각 `tileSize × 64` 이하이다.
- 내부 타일 캐시가 비어 있는 연속 영역을 기본 최대 8×8 타일로 묶고 동시에 최대 4개 요청한다. **8은 네트워크 묶음 선택값이며 서버의 64 상한을 바꾸지 않는다.** 65×65 영역을 64 상한에 맞게 나누는 별도 단위 검증도 있다.
- 캐시는 회원/버전/level/격자 x/y로 구분한다. 같은 TIC·nodeId가 겹친 응답에 있어도 중복 렌더링하지 않는다. 공식 군집의 `count/counts/bounds`와 구성은 서버 값이며 프론트가 다시 군집화하지 않는다.
- 기본 캐시 예산은 1,024 셀, 현재 보이는 셀은 고정하여 부분 실패 때 유지하고 화면 밖 오래된 셀부터 제거한다. 보이는 영역이 예산보다 크면 활성 셀 수까지 허용한다. 잘못된 카메라/과도한 범위로 65,536 셀을 넘으면 명시적인 확대 안내 오류로 중단한다. 이를 서버 API 제한이나 10만 별 성능 합격으로 해석하지 않는다. 최종 카메라·실제 시드 기준 예산 조정은 204/215에서 측정한다.

## 새 발견·진행 변경의 연결

분석 제출·공개 등록·재개를 구현하는 담당자는 **기존 API가 성공해서 반환한 값**으로 아래 이벤트를 호출한다. 분석 화면이나 새 쓰기 API를 이 티켓에서 구현하지 않았다.

```ts
import { publishSkyChange } from "../sky-data/events";
// result는 기존 API의 성공 응답, member는 공통 useSession()의 현재 회원
publishSkyChange(member.memberId, {
  skyVersion: result.skyVersion,
  asOf: result.asOf,
});
```

이벤트는 같은 회원의 현재 마운트된 지도에만 전달한다. 다른 페이지에서 지도에 다시 진입하면 메타부터 조회하므로 이벤트 이력을 별도 저장하지 않는다. 성공 응답에 `skyVersion`이 없으면 임의 값을 만들지 말고 해당 API 계약을 확인한다.

버전은 순서가 없는 문자열이다. 같으면 재조회하지 않고 다르면 메타를 확인한 뒤 현재 영역을 다시 받는다. 새 메타를 받는 동안 이전 한 버전의 자료는 오래된 자료라는 안내와 함께 유지한다. 새 버전 확정 시 기존 버전 캐시를 비우고 새 타일을 넣으며 버전끼리 섞지 않는다. 메타 실패는 수동 재조회할 수 있다.

요청 세대와 AbortController로 옛 카메라·배율·버전 응답을 버린다. 이미 폐기한 버전이나 현재 메타보다 이른 `asOf`도 거절한다. `asOf`는 서버 응답 생성 시각이며 제안 필드라 없을 수 있다. 제공되면 UTC 시각으로 검증·비교하고 브라우저 시간을 대신 넣지 않는다. 이것으로 서버의 트랜잭션 일관성이 검증됐다고 주장하지 않는다.

타일의 `versionChanged`나 버전 불일치는 메타+타일을 한 번 자동 갱신한다. 갱신 중 다시 바뀌면 무한 반복하지 않고 최신성 확인 대기/명시적 재시도로 전환한다. 일반 통신 실패는 자동 재시도하지 않는다.

## 오류와 개인 데이터

필수 배열 누락, 잘못된 ID/숫자/배율 단계, 깊이 범위, 행성 수와 공전 배열 불일치, 군집 집계 오류, 요청을 덮지 않는 타일 응답은 성공한 빈 지도와 구분한다. 일부 영역 실패는 성공 영역을 보존하고 실패 영역만 재조회한다.

401은 201/202 공통 인증 흐름으로 돌아가 개인 화면을 제거한다. 지도 unmount/회원 변경 시 요청·메모리 캐시·선택을 정리하고 늦은 응답은 복구하지 못한다. localStorage에 발견·진행·좌표를 저장하지 않는다. 회원 ID는 로컬 캐시 분리에 쓰며 요청 쿼리로 보내지 않는다. 서버는 세션으로 회원을 판정한다.

## 개발 화면과 운영 구분

`npm run dev:sky-data`의 `/sky`만 128개의 **가상 격자 좌표**와 6단계 서버 응답을 쓴다. 격자 그림은 좌표/캐시 오류를 보기 위한 검사 화면이고 새 은하 디자인이 아니다. 서버 역할의 개발 플러그인만 fixture 군집을 계산한다. 클라이언트의 공식 군집 재계산 허용 예시가 아니다.

개발 버튼은 버전 변경·일부 영역 실패·복구를 재현한다. 운영 빌드와 일반 실행/preview에는 고정 계정·가상 API·SVG 검사 화면·개발 버튼이 포함되지 않는다. `vite build --mode sky-data`도 fixture를 켜지 않는다. 실제 API 연결은 기존 `API_PROXY_TARGET`/`VITE_API_BASE` 설정을 사용한다.

운영 화면은 데이터 상태까지 연결했고 은하 렌더러 자리는 204에서 연결할 예정이다. 기존 보관 시제품의 은하/성운/근접 뷰 전체를 이번 티켓에 복사하지 않는다.
