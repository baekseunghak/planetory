## 공식 스레드 전용 게시판 (288)

2026-09-27 사용자 승인, [Jira 288](https://ssafy.atlassian.net/browse/S15P21C206-288). 기존 목록·검색·상세·페이지 컴포넌트를 재사용해 시네마/기존 화면 모두에 **공식 스레드** 탭과 `/community/signal-threads`를 연결한다. 별도의 게시판 테이블이나 DB 변경은 없다.

- 화면에서 검색어·범위·TIC를 입력하면 기존 피드 API에 `type=SIGNAL_THREAD`를 붙인다. 화면 URL에는 종류를 넣지 않고 경로가 종류를 고정한다. API를 직접 쓰는 소비자는 `type=POST`도 사용할 수 있다.
- 새 글 쓰기·작성자·태그 입력은 숨긴다. 다른 게시판에서 진입하면 작성자·태그·게시판·이전 커서를 제거하고 검색어·TIC를 유지한다. 자유 게시판 전환은 STAR 범위를 뜻하는 TIC도 제거한다.
- 공식 전용 주소에 author/tag/FREE 또는 알 수 없는 type 쿼리를 직접 붙이면 임의로 넓혀 조회하지 않고 오류를 표시한다. 조건 초기화는 전용 경로를 유지한다. API의 `type` 쿼리와 화면 URL의 허용 조건은 구분한다.
- N=0을 포함한 모든 조회 가능한 공식 스레드를 최신순으로 보여준다. 핫 토픽의 10명 기준·참여자순 정렬을 사용하지 않는다. 상세/댓글/공개 분석 화면은 기존 링크를 사용한다.
- 검색·커서·상세 복귀 문맥은 기존 URL과 페이지 복원 기능을 사용한다. 뒤에 `/`가 붙은 주소도 같은 전용 화면이다.

### 배포·확인 순서

1. 백엔드 종류 필터를 먼저 배포한 뒤 로그인 상태에서 `GET /api/v1/community/feed?type=SIGNAL_THREAD&size=20`이 200이고 items가 모두 SIGNAL_THREAD인지 확인한다. 빈 목록도 정상이다.
2. 프론트 빌드를 배포한다. 운영의 `VITE_CINEMA=true`에서도 같은 전용 탭이 보인다. 새 환경 변수·Redis 설정·DB 마이그레이션은 없다. 이전 백엔드는 type을 400으로 거절하므로 프론트만 먼저 배포하지 않는다.
3. 전체/공식/별/자유/핫 토픽 탭, 검색·초기화·다음 페이지·상세 복귀를 확인한다. 숨김 대상은 노출되지 않아야 한다. 오류 발생 시 프론트를 이전 버전으로 되돌려도 추가 API 파라미터를 쓰지 않아 기존 조회를 유지한다.

로컬 `npm run dev:search`의 공식 스레드는 합성 자료다. 브라우저 자동 검증은 `npm run test:search -- --project=chrome`이며 기존 화면과 시네마 화면의 전용 탭·API 조건·검색·상세 복귀를 검사한다. 실제 운영 배포·로그인 연동 인수는 별도다.

### 288 로컬 검증 결과

- 일회용 PostgreSQL의 `CommunityReadTest` 20건 통과(실패·오류·건너뜀 0). 종류별 SQL, N=0 유지, 숨김·닫힌 별, 입력 거절·커서 결속을 검증했다.
- 검색 입력 단위 9건, 공통 검색 표본 41건 및 프론트 입력 대조 40건 통과.
- 설치된 Chrome의 검색 회귀 17건 통과. 신규 2건은 기존/시네마 화면의 공식 탭, 실제 HTTP 요청 파라미터, 검색·상세 복귀·자유 게시판 전환·끝 슬래시 주소 오류/초기화를 검증한다. 공급 응답은 합성이므로 실제 운영 API 인수는 아니다.
- 타입 검사, 기본 빌드, `VITE_CINEMA=true` 운영 빌드, 개발 자료 제외 검사 통과. 기존 번들 크기 경고는 남아 있다.
- 최초 DB 테스트 실패는 테스트용 스레드 ID의 숫자 변환을 수정해 해결했다. 기존 설치 의존성 누락은 독립 워크트리 `npm ci`로 해결했다. 번들 Chromium 실행은 이 PC에서 불가해 설치된 Chrome으로 검증했다. 운영 배포·운영 데이터 변경은 수행하지 않았다.
