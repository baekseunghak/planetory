## 구현과 계약

| 항목 | 구현·독립 검증 |
| --- | --- |
| 검색 입력 | q, TITLE_BODY/TITLE/BODY, 현재 닉네임, TIC, STAR/FREE, 대표 목적 태그. 상세 조건은 접고 펼칠 수 있고 Enter로 검색한다. |
| 문자열 | q 앞뒤 공백만 정리하고 내부 공백·특수문자를 보존한다. Unicode 문자 1~100자 경계를 검사한다. URLSearchParams로 한 번 인코딩하며 SQL 와일드카드 이스케이프를 클라이언트가 덧붙이지 않는다. TIC는 문자열이다. |
| 서버 책임 | 모든 조건 AND, 부분 일치·영문 대소문자 무시, 작성자 현재 닉네임 정확 일치, 댓글 제외, 공식 스레드 제목/시스템 요약 검색·author/tag 지정 시 제외, 생성시각/ID 내림차순. 브라우저가 현재 페이지를 별도로 검색·정렬하지 않는다. |
| 주소·페이지 | 조건과 cursor를 URL에 기록한다. 조건 적용/게시판 변경/초기화 시 cursor와 이전 페이지 이력을 폐기한다. 별 게시판 경로의 TIC는 고정한다. 잘못된 enum·중복 조건·q 없는 searchIn 주소는 임의로 넓혀 조회하지 않는다. |
| 복귀 | 상세의 이전 화면 링크와 브라우저 뒤로가기에서 조건·페이지·스크롤을 복원한다. 새 GET 이후에만 목록을 표시한다. 스크롤은 기존 메모리 저장소에 최대50개의 숫자 위치로 유지하며 브라우저 재시작/문서 전체 새로고침 후 위치 보존은 보장하지 않는다. URL의 조건·페이지는 새로고침해도 유지된다. |
| 상태·권한 | 로딩·빈 결과·통신 오류·수동 재시도를 구분한다. 오래된 cursor 실패에서 조건 유지 후 첫 페이지 복구가 가능하다. 새 검색 시 이전 요청을 중단한다. 숨김/삭제/공개 취소는 서버가 제외하고 기존 상세/하위 조회의403/404 및 탭 복귀 재조회를 유지한다. 서버 응답 없이 프론트가 공개 여부를 추정하지 않는다. |

주소 예: `/community?q=빛&searchIn=BODY&board=STAR&tag=QUESTION`. 요청은 `GET /api/v1/community/feed?q=빛&searchIn=BODY&board=STAR&tag=QUESTION&size=20`의 인코딩된 URL이다. q를 비우면 searchIn도 보내지 않는다. 일반 실행은 실제 HTTP 요청을 보내고, API 미제공 시 오류를 표시한다.

서비스 API 4.1에는 과거의 “COM-03 P1, P0 상향 요청” 문장이 남아 있다. 현행 SRS COM-03의 P0 결정과 Jira217의 P0 범위를 적용했다. DTO를 새로 만들거나 백엔드 검색 규칙을 변경한 것은 아니다.

## 재현과 검증

`apps/frontend`에서 `npm ci`, `npm run dev:search` 후 `http://127.0.0.1:58364/community`를 연다. 상단에 합성 데이터임을 표시한다. `TOI`, `10%_`, 작성자 `Orbit`, TIC `259377017`, 질문 태그와 별 게시판을 조합해 확인할 수 있다. `빛` 검색은 여러 페이지가 나오므로 아래쪽 글 → 상세 → 이전 화면으로 위치 복원을 확인한다.

검증 모드는 Vite serve에서만 합성 HTTP 공급자를 연결한다. 실제 자료를 브라우저에 내장하는 방식이 아니며 운영 빌드/preview에는 fixture·초기화 주소가 포함되지 않는다. `API_PROXY_TARGET`을 지정하는 일반 `npm run dev`에서는 실제 API를 사용한다.

- `npm test`: 전체 단위218개 통과. q 경계/인코딩/문자열 ID/잘못된 URL/별 게시판 고정을 포함한다.
- `npm run build`: 타입·운영 빌드·개발 전용 코드 제외 검사 통과.
- `npm run test:search`: 14시나리오 × Chromium·Chrome·Edge·Firefox = 56개 통과. 모든 조건 조합, 본문/제목, 특수문자/내부 공백, 현재/이전 닉네임, 댓글/공식 스레드 차이, 페이지 초기화/복귀, 오류/취소/재시도, 숨김/삭제/부모 비공개, 데스크톱 배치를 포함한다.
- 기존 community14개·posts15개 Chromium 회귀 통과. 기본 포트 충돌 때문에 검증용 임시 설정에서58366·58367을 사용했고 애플리케이션 설정은 바꾸지 않았다.
- 운영 빌드의 community2개·search1개 브라우저 검사 통과. 실제 백엔드 인수가 아닌 HTTP 응답 대체 계약 검사다.

Firefox 검증은 기존 글쓰기/프로필 검사의 native key 보완을 재사용한다. Playwright1.63 BiDi `fill`만으로 React 입력 상태가 바뀌지 않는 드라이버 문제이며 제품 입력 처리에는 우회 코드를 넣지 않았다. 초기 회귀에서 로딩 status가 두 번 출력되는 문제를 수정했다. 검색 전용 Playwright 설정은 서버 하나만 기동하도록 구성했다.

## 남은 일과 216 인계

기능·확정 계약의 독립 검증과 리뷰 제출이217의 담당 범위다. 리뷰 승인·develop 병합·종료 증거 확인 전까지 Jira는 진행 중으로 둔다. 실제 서버/배포 인수 대기를 미구현 UI와 혼동하지 않는다.

- **216-217 미검증:** 이번에 fetch한 원격 브랜치 및 develop의 backend Java 코드에서 community/feed 또는 searchIn 구현을 찾지 못했다. 실제 S16 제공 후 AND·현재 닉네임·q 경계/와일드카드·공식 스레드 예외·정렬·cursor를 실데이터로 대조한다. fixture 일치가 DB 검색/인덱스 또는 서버 권한 구현의 검증은 아니다.
- **216-217 미검증:** 실제 숨김/삭제/부모 공개 취소 후 검색 결과·상세·하위 자료·탭/목록 복귀의 노출 차단을 확인한다. W11 실제 API와 함께 인수한다.
- **216-ENV 미검증:** HTTPS 배포, 실제 지원 브라우저 전체(특히 이 Windows 환경에서 실행하지 못한 Safari)의 출시 인수.
