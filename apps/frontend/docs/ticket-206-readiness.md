## 코드 연결

- `StarDetail.tsx`가 기존 204의 선택 상세 조회를 이어받아 하나의 요청 주체로 관리한다. 회원 변경 시 전체 소유 컴포넌트를 교체하고 요청을 취소한다. URL 직접 선택은 타일 적재 전에도 C06으로 권한을 확인한다.
- `detail.ts`는 기존 readOwnedSystem의 좌표·개수·버전 검사와 패널 필드 검사를 합친다. 미탐사 실제 서버의 `currentCurveStep=null`을 허용한다. 서버가 필터링한 개인 items를 받으며 정답/소유 자격을 프론트에서 재계산하지 않는다.
- `SceneControl.focusStar(position)`는 기존 카메라 방향을 유지해 저장 depthZ까지 투영한 중심으로 접근한다. 일반 전환은 650ms이며 입력/복귀/해제 시 취소한다. 탭 복귀가 새 전환을 만들지 않는다.
- 같은 GPU 행성 버퍼에서 candidateId로 확대 대상을 고른다. 선택 행성의 화면 중심·반지름을 보간하고 다른 궤도/행성은 사라진다. ID 해시에 마지막 혼합을 추가해 인접 ID가 같은 각도에 몰리지 않게 했다. 전부 서비스 연출이며 실제 표면·크기·거리·속도가 아니다.
- 분석은 `/analysis/:ticId`, 결과는 `/results/:ticId`, 스레드 진입은 `/community/stars/:ticId`다. 상세 응답에 threadId가 없으므로 임의 스레드 ID를 만들지 않고 별 게시판에서 고르게 한다. 연결 전 공통 앱의 준비 중 화면을 사용한다.
- 링크 왕복은 TIC를 보존하고 데이터를 재조회한다. 카메라 복원은 **동일 지도 화면 내** 복귀 범위다. 분석 화면에 들어갔다 돌아왔을 때는 현재 별을 다시 조회해 접근한다. 개인 진행/카메라를 브라우저 영속 저장소에 저장하지 않는다.

## 실행·검증

`npm run dev:detail`로 58335 포트의 동일 운영 컴포넌트에 개발 전용 HTTP fixture를 연결한다. 1,000별·5개 개인 행성은 합성 입력이다. 일반/운영 모드는 fixture를 포함하지 않으며 `VITE_SKY_RENDERER_ENABLED=true`와 실제 API 프록시를 사용한다. 패키지·라이브러리 버전은 변경하지 않았다.

```powershell
npm run build:renderer
npm test
npm run test:renderer-production
npm run test:interaction
npm run test:galaxy
npm run test:detail
npx playwright test --config=playwright.detail.config.ts --project=chrome --project=msedge
$env:FRONTEND_SUITE='detail'
$env:FIREFOX_EXECUTABLE='C:/Program Files/Mozilla Firefox/firefox.exe'
$env:FIREFOX_REDUCED_MOTION='1'
npx playwright test --config=playwright.local-firefox.config.ts
```

Windows 로컬 검증에서 타입·렌더러 운영 빌드·개발 데이터 미포함 검사, 단위 64개, 운영 렌더러 2개, 기존 입력 8개, 은하 16개를 통과했다. 상세 Chromium 9개와 Chrome/Edge 기본 7개씩을 통과했다. 마지막 초점·정보 스크롤 수정의 추가 검사 결과는 아래 최종 기록에 남긴다. 과거 테스트의 선택 해제/전체 보기 기대를 206의 실제 복귀 버튼과 이전 카메라 복원에 맞춰 갱신했다.

기존 검증 서버 `0b7436f`와 격리 DB·가상 OAuth에서 **실제 C06 HTTP + 프론트 파서**를 확인했다. 내 행성 5개/인정 성과 0건/continue와 미탐사 0행성/start/currentCurveStep=null을 통과했다. 미발견 별 403, 퀘스트 404도 구분했다. 새 실제 연결 프론트 서버 실행은 자동 승인 검토에서 차단되어, 이번 검증을 새 206 화면과 실제 서버의 전체 브라우저 통합으로 세지 않는다. 기존 서버나 DB를 변경하지 않았다.

최종 추가 검사: 상세 Chromium 9개 통과. Chrome/Edge는 기본 7개와 추가 세션 만료·변경 통지 2개를 각각 확인했고, 마지막 정보 스크롤·1024px·세션·변경 통지 4개씩도 재통과했다. Windows 정식 Firefox는 6개 통과 후 목록 입력 3개를 실제 키 입력/목록 갱신 대기로 바꿔 재통과했다. BiDi fill 직후의 미갱신 목록을 바로 클릭하던 검사 문제를 고쳤으며 제품의 입력 방식을 우회하지 않았다. 최종 타입·렌더러 운영 빌드·운영 검사 2개도 통과했다. 모든 검사를 한 명령으로 마지막에 재실행했다고 주장하지 않는다.

실제 분석·결과·게시판의 업무 왕복, 최신 퀘스트 API, 배포 HTTPS, Safari 실기기, 스크린리더 수동 검증, 10만 별 성능은 통과로 기록하지 않는다. 서버 권한/소유 판단은 기존 204의 검증과 이번 C06 소비 검증을 참고하되 제공자 교차 인수가 필요하다.
