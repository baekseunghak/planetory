## 진입과 검토

`/publication/:historyId`는 개별 기록, `/publication?ticId=...`는 신호별 대표 기록을 검토한다. History 상세에 공개 검토·설정 링크를 추가했다. !175가 병합된 develop을 반영해 별 결과→검토→결과 및 History→검토→History를 연결했다.

검토 진입은 GET만 실행한다. 일괄 후보는 서버의 `batch-candidates`를 사용하고 한 신호당 대표 기록 하나를 유지한다. 초기 대표는 서버가 선정한 최신 미게시 기록이다. 다른 본인 기록은 TIC·candidate 필터가 있는 History 목록에서 고르며 상세를 다시 검증한 뒤 게시 선택을 받는다. 이미 공개 기록이 있는 History는 대표 교체 목록에서 선택하지 않는다. 취소한 기록은 개별 History에서 재공개한다.

닉네임, 제출 시각, 원래 판단·근거·메모·선택 수치·버전과 제출 당시 그래프를 표시한다. 원본 내용은 편집하지 않으며 변경은 새 분석으로 이동한다. 현재 라벨로 공개 자격을 재판정하지 않는다. History 응답의 공개 상태와 최종 게시 API가 자격을 결정한다. 그래프 누락은 명시하고 현재 데이터로 원본을 꾸며 채우지 않는다.

## 쓰기와 복구

| 사용자 동작         | 요청과 처리                                                                                                                                                   |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 개별 기록 게시      | `POST /v1/public-analyses`, 본문은 `historyId`만 보낸다.                                                                                                      |
| 모두 게시           | 선택한 최대 20개를 `POST /v1/public-analyses/batch`로 보낸다. batch 화면의 항목 하나만 게시할 때도 items 1개를 보낸다.                                        |
| 부분 실패 재시도    | 성공 항목은 유지한다. `FAILED`이며 서버 `retryable:true`인 항목만 다시 보낸다.                                                                                |
| 공개 취소           | `PUT /v1/public-analyses/{analysisId}/visibility`에 `isPublic:false`를 보낸다.                                                                                |
| 재공개              | 현재 비공개 기록의 명시적 재공개 버튼으로 같은 PUT에 `isPublic:true`를 보낸다. POST를 재공개 용도로 쓰지 않는다.                                              |
| 응답 유실·형식 오류 | 실패로 확정하거나 자동 재전송하지 않는다. History를 다시 조회한다. 공개 기록이 확인되지 않으면 사용자가 같은 기록을 다시 검토한 뒤 명시적으로 게시할 수 있다. |
| 조회까지 실패       | 기존 자료는 남기되 현재 상태를 ‘다시 확인 필요’로 표시하고 쓰기 동작을 막는다.                                                                                |

쓰기 중에는 동기 잠금과 비활성화로 중복 조작을 막는다. 화면·회원이 바뀌면 진행 중 요청을 중단하고 늦은 응답을 반영하지 않는다. 클라이언트 요청 중단은 서버 트랜잭션 취소를 보장하지 않으므로 이탈 후 재진입도 조회에서 시작한다.

POST 응답은 해당 요청의 영수증이다. 현재 공개 상태의 근거로 재사용하지 않고 쓰기 후 History를 새로 읽는다. 오래된 성공 응답이 도착해도 현재 취소된 공개를 ‘공개 중’으로 복원하지 않는다. `achievementGranted`와 `newlyGranted`는 분리해서 표시한다. 실패·응답 유실에 성과 필드가 없으면 미인정으로 추측하지 않는다. 공개 취소·재공개는 성과를 다시 지급하지 않는다.

게시 응답의 `skyVersion`을 기존 `publishSkyChange` 경로에 전달한다. 지도·History·별 결과는 복귀 시 자신의 조회를 다시 수행한다. 서버 통계나 성과를 클라이언트에서 증가시키지 않는다. 운영 숨김에서는 재공개 버튼을 제공하지 않으며 부모 상태 변경에 따른 최종 거절은 서버 오류를 표시한다.

여러 페이지에서 재시도 가능한 실패가 누적되면 최대 20개씩 명시적으로 재시도한다. 성공 항목과 최신 조회에서 이미 공개 기록이 확인된 항목은 재전송에서 제외한다. `retryable:false`를 프론트가 재시도 가능으로 바꾸지 않는다. `newlyGranted:false` 응답의 발견 별은 ‘이 공개와 연결된 발견 별’로 표시하여 이번 요청의 새 발견과 구분한다.

- 브라우저 테스트는 각 테스트마다 독립된 HTTP fixture를 사용한다. 실제 DB 트랜잭션·잠금·OAuth·성과 지급 검증과 구분한다.
