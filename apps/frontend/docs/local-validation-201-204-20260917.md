## 코드 변경

- 202/203/204에 같은 공통 API·CSRF 연결을 적용했다. 쓰기 직전에 GET /api/v1/auth/csrf를 조회하고 반환된 헤더/토큰을 사용한다. 취소/시간 초과 뒤 늦은 쓰기를 보내지 않는다. 쿠키 이름을 가정하는 옛 설정은 명시적 호환 옵션만 남겼다.
- OAuth 진입은 /oauth2/authorization/ssafy 및 /google, 백엔드 콜백은 /login/oauth2/code/{provider}, 인증 완료 후 프론트 도착은 /oauth/callback이다. 백엔드 AUTH_SUCCESS_URL과 제공자 앱의 콜백 등록은 배포 origin에 맞춰야 한다. 비밀키는 프론트에 넣지 않는다.
- Vite/Nginx는 콜백의 401/403/503만 안전한 실패/취소 안내로 연결한다. 일반 /api의 401/403/404는 바꾸지 않는다. .env.example 복사 시 두 로그인 경로가 채워지도록 했다.
- 현재 서버는 최초 닉네임을 자동 생성한다. /me 200을 받으면 바로 로그인 완료로 처리하며, 존재하지 않는 NICKNAME_REQUIRED 응답이나 새 API를 꾸며내지 않는다. 기존 닉네임 폼은 계약이 명시된 경우의 선택 어댑터로 남아 있다. **202 티켓의 최초 입력 요구를 서버 담당/기획과 정리해야 한다.**
- 204 PersonalGalaxyScene은 현재 회원·선택 TIC·지도 버전에 맞는 실제 상세만 읽는다. 선택/회원/버전 변경이나 실패 시 낡은 행성을 감추고 요청을 취소한다. 운영용 좌표 생성이나 외부 카탈로그 행성 보충은 없다.
- 밝기는 1,000개 이하의 기존 기준을 유지하고, 많은 별의 전체 보기에서 낮춘 빛을 확대하면서 회복한다. 전체 별 수를 기준으로 해 페이지가 추가됐다는 이유만으로 밝기가 튀지 않게 했다. 별 수·자리·등급은 바꾸지 않는다.
- 204 플래그는 기본 false 유지. 고정 선택 /sky?star=1 검증은 데이터/렌더 연결 시험이며 클릭→카메라 근접 전환을 완성했다는 뜻이 아니다. SceneControl.setCamera/setSystem 및 store.select 연결점은 205/206에 제공한다.

## 실제 검증 범위

실제 Spring 백엔드 develop 0b7436f(Java21)와 전용 PostgreSQL DB를 사용했다. OAuth 제공자와 별·행성 시드만 합성이다. API 응답을 가로채서 만든 결과가 아니며 개인 계정/기존 DB는 사용하지 않았다.

- 실제 입력 오류: 201 병합 클라이언트와 지웅 182 공통 클라이언트 각각 15개, 총 30개. profile 닉네임 오류, onboarding false/null, 깨진 JSON/본문 누락, CSRF 없는 쓰기, 404, 로그아웃 204와 이후 401 포함. 현행 서버가 생략하는 빈 fieldErrors를 프론트가 정상 수용했다. **비어 있지 않은 fieldErrors의 실제 기능 응답을 새로 확인한 것은 아니다.** 기존 MVC/클라이언트 계약 검사는 별도 증거다.
- Chrome 18개, Edge/정식 Firefox 각 19개 실제 통합 확인점. Edge/Firefox에는 모든 서버 선언 배율의 실제 조회를 추가했다. 각 실행의 브라우저 미처리 오류 0개.
- 첫 회원 2,501개 → 로그아웃 → 두 번째 회원 1개. 이전 별·행성·선택 정보가 개인 화면에 남지 않는다. 잘못된 제공자 콜백과 취소 안내도 확인했다.
- 5행성은 본인 확정 4개 + 본인 최신 판단 LIKELY 후보 1개. FP/UNLIKELY/UNSURE/타인 기록은 서버 응답에서 제외됐다. 행성 0개 별도 확인했다.
- 실제 DB revision을 올린 뒤 구 cursor의 versionChanged, 메타·페이지 재조회, 선택 TIC와 기존 좌표 유지 확인. **DB 변화로 입력을 만든 검사이며 지웅님의 실제 분석 제출 버튼을 통한 종단 검사는 아니다.**
- 로컬 단위 202:20개, 203:50개, 204:58개. 인증 Chromium9·데이터 Chromium8·기존 렌더 Chromium15·활성화 운영 빌드2 통과. 기존 15개 중 4개는 보관 비교 페이지 회귀이며 새 렌더 검사와 구분한다.
- 새 밝기 검사: Chromium/Chrome/Edge/정식 Firefox 각각 1개. 기본 제공 Firefox 실행은 spawn UNKNOWN으로 실패해 기존 moz-firefox 경로로 설치된 Firefox를 사용했고 통과했다. Edge 최초 실행의 계측 null 대기와 Firefox URL 정리 타이밍은 검사 코드를 고쳐 재통과했다.
- 타입·빌드·운영 번들 개발 자료 제외 검사 통과. 종속 버전을 바꾸지 않았다. 이번 실행은 Windows Node24.18.0이며 과거 Node22 Docker 결과와 구분한다.
