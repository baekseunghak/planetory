## 조작

- 마우스: 드래그 회전, Shift+드래그/우클릭 드래그 이동. 이동 모드에서는 기본 드래그도 이동이다. 휠은 가리킨 위치를 유지하며 확대/축소한다.
- 키보드: 지도에 Tab으로 진입, 방향키 이동, Shift+방향키 회전, +/− 배율, Home 전체 보기, [/ ] 화면의 별·내 행성 탐색, Enter/Space 선택, Escape 해제. Tab은 지도 밖 조작으로 이동한다.
- 별의 이름은 TIC로 표시한다. 선택은 store의 문자열 TIC, 행성은 candidateId로 유지한다. 선택 후 카메라 접근·행성 확대·전체 정보 패널은 206의 범위다. 이번 선택 라벨을 206 완성 화면으로 간주하지 않는다.
- 번호 버튼은 Tab/Enter/Space로도 선택된다. 화면 밖으로 나간 포커스 마커는 지도에 포커스를 돌려주므로 숨긴 버튼에 갇히지 않는다.

## 다음 화면과 연결

`GalaxyScene`의 `onPlanetSelect(candidateId|null)`는 206의 확대·정보 입력이다. 별 선택은 기존 `store.select(ticId)`와 204의 `PersonalGalaxyScene` 상세 조회 수명주기를 재사용한다. 206에서 중복 상세 요청 주체를 만들지 않는다. 207 목록 선택도 동일 store를 사용한다.

`GalaxyInteraction`은 CPU 히트 테스트와 DOM 입력을 담당한다. `renderer.planetTargets()`가 실제 셰이더에 사용한 시간·투영·공전 반지름을 사용하므로 공전하는 행성과 hit 위치가 함께 움직인다. 회원/버전/선택 변경에 유효하지 않은 상세·행성 hit는 제거한다. 선택된 별과 가시 포커스는 구분하며, 페이지 교체 때문에 선택 ID를 임의로 없애지 않는다.

퀘스트는 별도 쓰기 없이 GET만 소비한다. 현재 메타 version으로 요청 수명을 묶고 오래된 응답은 취소한다. 같은 회원 화면에서 확인한 완료 번호는 다시 드러내지 않는다. 재접속의 정본은 서버이며 브라우저 저장소에 진행 상태를 만들지 않는다. 208 퀘스트 패널이 연결될 때 동일 응답을 공급하도록 조회를 공유할 수 있다.

## 실행과 검증 환경

`npm run dev:interaction`은 58326에 실제 GalaxyPage + 격리 HTTP fixture를 제공한다. 개발 도구 패널은 표시하지 않으며 운영 로그인/페이지가 같은 코드로 그려진다. 1,000개 합성 별과 5개 번호는 각 입력 경계를 검사하기 위한 fixture이고 실제 튜토리얼 순차 해금의 업무 완료를 뜻하지 않는다. `interaction` 모드도 serve 전용이며 운영 build/preview에는 fixture가 없다.

실제 연결 검사는 58328의 일반 Vite와 `API_PROXY_TARGET=http://127.0.0.1:58320`, `VITE_SKY_RENDERER_ENABLED=true`를 사용했다. 기존 로컬 검증 백엔드 `0b7436f`·격리 DB·가상 OAuth 제공자에 연결했으며 개인 Google/SSAFY 계정은 사용하지 않았다. 실제 API 2,501별·회전/이동/선택·5행성·전체 보기·로그아웃 6개 검사를 통과했다. JS 오류 0건이다.

실행 중인 백엔드의 GET /me/quests는 404다. 별·행성 API 검증 결과와 퀘스트 fixture 검증을 구분한다. 새 원격 `feature/S15P21C206-139-api-tutorial-challenge-quests`와 실제 완료/건너뛰기·재열림 연동 인수는 후속 협업으로 남는다. 이번 작업에서 다른 팀원 브랜치·DB·백엔드 실행 버전을 교체하지 않았다.
