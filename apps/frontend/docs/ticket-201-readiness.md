# 201번 작업 범위와 인수 상태

2026-09-14 Jira 본문과 최신 fetch 결과를 대조했다. 기준 develop은 `321f10b`다.
대상: [S15P21C206-201](https://ssafy.atlassian.net/browse/S15P21C206-201), `[개발] 공용 프론트 실행환경·라우터·API 클라이언트 구성`.

## 이 MR에 포함하는 작업

- React·TypeScript·Vite 실행환경, 공통 메뉴와 1024px 안내, 공용 라우터.
- 평면 `/api/v1/me` 회원 조회, 쿠키 포함 요청, 401 세션 정리, 403/404 및 `fieldErrors.reason` 처리.
- 요청 취소·204·파싱 오류·응답 유실 처리, 일반 POST/PATCH 자동 재전송 금지.
- 같은 앱에서 TIC·History·원 글·복귀 주소를 전달할 수 있는 페이지 연결 인터페이스.
- 개발 전용 fixture와 배포 코드의 분리, 이에 대한 검사와 연결 문서.

별지도 렌더러, 별 상세, 행성 뷰, 퀘스트, 실제 OAuth 화면은 이 변경에 포함하지 않는다.
기존 별지도 시제품을 삭제하거나 기능 완료로 간주하지 않고 별도 보관했다. 후속 기능 티켓에서 해당 부분만 현행 계약에 맞게 재사용한다.

## 외부 연동을 완료하는 방법

1. 인증 백엔드 [156번](https://ssafy.atlassian.net/browse/S15P21C206-156)의 실제 서버와 로그인된 세션을 준비한다. 확인 시점에는 Jira가 해야 할 일이고 최신 develop에는 HelloController와 공통 오류 처리만 있다. 201번에서 서버 인증 기능을 대신 구현하지 않는다.
2. `API_PROXY_TARGET`을 실제 주소로 설정하고 fixture 없는 `npm run dev`로 GET `/api/v1/me`를 확인한다. 성공, 만료 401, 권한 403, 없음 404, 필드 오류를 실제 응답으로 검증한다. 비밀 쿠키·토큰을 검증 문서에 남기지 않는다.
3. 인증 담당과 CSRF 발급 방식 및 요청 식별 헤더를 확인한다. 미확정 이름을 확정 계약으로 기록하지 않는다. 확정 후 `.env.example` 설명과 계약 시험을 갱신한다.
4. 백지웅 담당 컴포넌트 최소 하나를 PageSlots에 연결해 같은 회원 정보와 TIC·History·복귀값을 확인한다. 분석 전체 화면이나 202번의 전체 OAuth UI 완성을 기다리는 조건이 아니다.
5. 배포 환경의 직접 주소·새로고침·쿠키 전달을 확인하고, Firefox 실행 문제를 해결한 환경 및 실제 Safari에서 공통 동작을 검증한다. Docker의 Node 22 환경도 확인한다.
6. 위 증거를 이 문서와 검증 기록에 반영한 후 리뷰 승인을 받고 MR을 병합한다. Git·Jira 컨벤션에 따라 병합·인수·결과 등록까지 끝나면 완료 처리한다.

상세 인터페이스와 설정은 [공통 연결 계약](shared-frontend-contract.md), 실행 결과는 [검증 기록](verification.md)을 따른다.
