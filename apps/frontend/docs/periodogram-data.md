# #183 주기도 개발 안내

2026-09-16 기준 `S15P21C206-183`의 응답 타입·검증기·읽기 로더·개발용 샘플을 구현했다. 기준은 [탐사 API 5.3·5.4](../../backend/docs/exploration-api-spec.md), [분석 프론트 명세](../../../docs/development/analysis-frontend-spec.md)와 Jira의 동일 CurveContext·전체 격자·공개 봉우리 요구사항이다. 앞선 [#182 분석 읽기](analysis-data.md)를 사용한다.

**현재 범위:** 1단계 응답 기반·2단계 주기도 탐색에 이어 3단계 주기 선택·미세 조정과 변경 이벤트, 4단계 판 변경 자동 복구를 연결했다. 접힌 곡선은 [#184 개발 안내](phase-folding.md)의 2단계에서 연결했다. 로더는 곡선·선택 규칙·주기도·봉우리를 검증한 경우에만 `selectionEnabled: true`를 반환하며 실패한 응답을 차트에 내보내지 않는다. 실제 API·Gold 및 서버 공통 과학 계산 검증은 남아 있다. 기존 UI와 최소 스타일을 사용하고 시각 리디자인은 나중에 적용한다.

## 응답과 검사

- [analysis-data.ts](../src/features/analysis/analysis-data.ts)는 CurveContext 읽기를 재사용하도록 공개하고 `selectionRules.version`, `fineTune.halfWidthCells`만 추가로 읽는다. 규칙이 없는 기존 관측 export는 시간 곡선을 계속 표시하되 주기 선택 준비 상태로 취급하지 않는다. 공급된 규칙이 잘못됐으면 거절한다.
- [periodogram-data.ts](../src/features/analysis/periodogram-data.ts)는 `periodMinDays`, `periodMaxDays`, `nPeriods`, `gridRule: log`, `power`, `baselineHalfDays`를 읽는다. 주기는 API의 로그 격자 식을 사용해 복원하며 첫/마지막 값은 제공 범위를 그대로 사용한다. 배열을 줄이거나 보간하지 않으며 음영 경계로 주기 범위를 잘라내지 않는다. 빈 배열·길이 불일치·null/비유한 수·알 수 없는 격자는 거절한다.
- 봉우리는 `gridIndex`와 `rank`를 별도로 유지한다. 인덱스·주기·power가 같은 주기도의 점인지 확인하고, 중복 인덱스/순위와 잘못된 min/max/step·제안값을 거절한다. 부동소수점 계산 대조 허용치는 `1e-9 × max(1, |a|, |b|)`이며 원본 값은 반올림하지 않는다.
- 서버가 제공한 봉우리별 `fineTune` 값을 보존한다. 후보 ID·이름·정답 여부를 봉우리에 복사하지 않고 이미 매칭한 공개 주기선만 별도로 읽는다. 클라이언트의 필드 투영은 서버의 비공개 데이터 노출 방지를 대체하지 않는다. 실제 서버 응답 본문 검사는 연동 시 별도로 필요하다.
- [load-periodogram.ts](../src/features/analysis/load-periodogram.ts)는 검증된 현재 문맥·곡선을 받아 `periodogram → candidate-peaks` 순서로 GET한다. Bundle, 곡선 단계, 정렬한 제거 집합과 계산 버전 둘 다 일치해야 한다. 배열·문맥·규칙 검사까지 성공해야 `ready`다. 빈 봉우리 목록은 과학적 신호 없음으로 판정하지 않고 선택 불가 상태로 남긴다.
- 조회 중 새 Bundle 헤더나 409 `BUNDLE_CHANGED`를 받으면 `PeriodogramContextChanged`를 전달한다. 이전 문맥으로 봉우리를 계속 읽거나 자체 재시도하지 않는다. 4단계에서 페이지의 문맥·곡선부터 한 번 자동 재조회하도록 연결했다. 본문만의 문맥 불일치는 자동 복구 대상이 아니다. 403·404·503과 다른 409는 원래 오류를 유지한다. 취소 뒤 늦은 응답도 반환하지 않는다.
- 잔차 주기도 202는 API 5.3이 참조하는 5.2의 `CURVE_NOT_READY`, `segments: null`, `residual` 형식으로 검사한다. 결과·작업이 없으면 status/jobId를 null로 보존하며 작업 생성·가짜 폴링을 하지 않는다. 실제 서버가 다른 미완성 DTO를 제공하면 계약 대조가 필요하다.

## 합성 응답의 원리

[periodogram-fixtures.ts](../dev/periodogram-fixtures.ts)는 개발 서버에서만 쓰는 `pg-synthetic-183-v1`이다. 0.5~40일 로그 격자 5,000점을 만들고, 미리 정한 세 위치에 수학적으로 만든 봉우리 모양의 power를 채운다. 순위·gridIndex·periodDays·power는 이 배열과 맞춘다. **BLS를 실행하거나 봉우리를 추출한 결과가 아니다.** 추천 목록의 길이 3은 실제 행성 개수가 아니다.

시간 곡선도 실관측과 구분한 10분 간격 1,009점의 합성 파형이다. 표시 범위는 7일, 기준 시각은 중앙 시각 1686.85 BTJD, 관측 한계는 3.5일이다. 문맥·배열·격자를 맞춘 UI 계약 예제이며 시간 파형에서 주기도를 계산했다는 의미가 아니다. API 본문의 축약 예제(5,000점 선언 뒤 power 3개 등)를 실행용 데이터로 그대로 복사하지 않았다.

봉우리의 샘플 미세 조정 범위는 중심 주기 P와 로그 비율 r, 예제 규칙 h=3으로 `P/r^h ~ P*r^h`를 사용하고 샘플 step은 오른쪽 한 칸 폭 `P*(r-1)`로 정했다. 이 선택은 합성 공급자의 규칙이다. 로그 격자의 좌우 간격은 다르므로 **직접 선택의 step은 생산자 합의가 남아 있다. 사용자의 결정에 따라 직접 선택의 미세 조정은 보류한다.** 서버 봉우리의 간격을 바꾸거나 숫자 입력을 step 배수로 제한하는 규칙은 추가하지 않는다. 전체 격자 밖 주기 제출은 API 6.2에서 금지하므로 실제 조정 허용 범위는 전체 격자와 미세 조정 범위의 교집합이다.

성공 JSON에는 같은 `curveContext`, 주기도 전체 배열, 공개 봉우리와 이미 매칭한 합성 주기선만 들어간다. Bundle `9007199254741093`과 matched ID `9007199254741094`는 정밀도 손실 검사를 위한 큰 문자열 ID다. 응답마다 같은 값을 돌려주며 호출 횟수에 따른 전역 상태를 만들지 않는다.

## 검증 범위

단위 검사는 전체 배열·로그 격자·큰 문자열 ID·문맥의 모든 식별 항목·공개 필드 투영·min/max/step·빈/불완전 응답·미계산·오류 보존·수동 재조회·취소를 검사한다. Chromium 검사는 브라우저에서 실제 클라이언트와 두 로더를 HTTP로 호출하고, 별도 HTTP 검사로 샘플 공개 필드와 400/403/404/409/503/202를 확인한다. 기존 화면과 프로덕션 fixture 제외 검사도 유지한다.

1단계 당시 주기 선택 버튼·차트·키보드·접기 이벤트·새 문맥의 UI 초기화는 후속 범위였다. 2단계 반영은 아래에 기록한다. 미세 조정 중 계산 API 0회, FAV-03·04·09·31 전체와 실제 API 검증을 1·2단계만으로 완료 처리하지 않는다.

2026-09-16 실행 결과: 타입 검사·프로덕션 빌드·개발 fixture 제외 검사·포맷 검사가 통과했다. 단위 56개, Chromium 프로젝트 23개(브라우저 21개·HTTP 전용 2개), 프로덕션 2개, 실관측 브라우저 1개가 통과했다(전체 82개). 실관측 검사는 기존 세 항성의 시간 차트와 함께 주기도·봉우리 미연결 응답도 확인했다. 커밋·푸시·MR·Jira 변경은 하지 않았다.

## 2단계: 전체·확대 주기도 화면

[PeriodogramPanel](../src/features/analysis/PeriodogramPanel.tsx)은 시간 곡선이 준비되면 주기도·봉우리를 읽는다. 로딩·권한 오류·조회 실패·자료 없음·문맥 불일치·잔차 미계산을 구분하며 상태를 `aria-live`로 알린다. 실패 시 시간 곡선은 유지하고 주기도 차트만 표시하지 않는다. 일반 실패는 `주기도 다시 불러오기`, 문맥 불일치·선택 규칙 미연결은 `분석 자료 다시 불러오기`로 문맥부터 읽는다. 화면 이탈·재조회에서 요청을 취소하며 이전 차트를 새 문맥에 유지하지 않는다. 새 판 감지의 자동 복구·주기 입력 초기화 전체는 후속 4단계 대상이다.

[PeriodogramChart](../src/features/analysis/PeriodogramChart.tsx)는 고정된 전체 그래프와 현재 확대 구간을 함께 표시한다. [periodogram-view.ts](../src/features/analysis/periodogram-view.ts)가 로그 축과 power 좌표를 계산하고 Canvas에 전체/가시 구간의 점을 그린다. 전체 그래프의 테두리는 상세 그래프에 표시 중인 구간이다. 데이터 배열·실제 주기는 변경하지 않는다.

- 휠·+/−·확대/축소 버튼은 1~64배로 조정한다. 64는 화면 조작 상한이며 과학적 선택 제한이 아니다. 휠은 그래프가 포커스를 가질 때만 처리하고 Ctrl/Meta 조합의 브라우저 확대는 가로채지 않는다.
- 드래그·←/→·이동 버튼은 표시 구간을 이동한다. 전체 보기·0/Home·더블클릭은 전체 범위로 돌아간다. 터치 세로 스크롤과 핀치 확대는 유지하고 모든 드래그 동작에 버튼 대안을 제공한다.
- 마우스·↑/↓·격자 번호 입력으로 어떤 점의 주기와 power든 확인한다. 입력에 label·범위·정수 간격을 지정하고 키보드 조회값은 별도 live 영역으로 알린다. 표시 숫자는 `Intl.NumberFormat`으로만 형식을 바꾸고 원본 수치는 보존한다.
- 봉우리 번호와 순위를 표시하며 `위치 보기`는 해당 봉우리 근처를 8배로 확대한다. **이 동작은 주기 선택·접기·제출값을 바꾸지 않는다.** 이미 매칭한 주기는 점선과 별도 목록으로 표시한다. 매칭 주기선이 없으면 그 상태를 설명한다.
- 관측 한계 초과 구간은 음영과 텍스트로 함께 설명한다. 경계 밖의 점을 삭제하거나 신호 유무를 판정하지 않는다. power 선·관측 경계·매칭 주기선은 선 모양과 설명으로도 구분한다.
- 기존 공통 정책인 1024px 이상 지원을 유지한다. 1024px에서 도구 모음은 줄바꿈하고 목록은 한 열로 배치한다. 1024px 미만은 공통 데스크톱 이용 안내를 유지한다. 모바일 분석 UI 구현으로 해석하지 않는다.

React 구현은 `vercel-react-best-practices`를 적용했다. 5,000점의 좌표 계산은 입력이 바뀔 때만 memo로 갱신하고, Canvas를 분리해 점 조회만으로 전체 그래프를 다시 그리지 않는다. 드래그 시작값은 ref, 뷰 변경은 함수형 state 갱신을 사용한다. ResizeObserver·해상도·휠 리스너는 정리한다. 불필요한 패키지·전역 스타일·공통 API 변경은 없으며, 주기도 검증 후 봉우리를 읽는 기존 순서는 불완전 문맥을 조기에 차단하기 위해 유지한다.

## 2단계 사용성·접근성 검토

2026-09-16에 [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md)를 새로 조회하고 위 두 React 컴포넌트·분석 페이지 연결부·전용 CSS를 검토했다. Hallmark·kill-ai-slop 시각 리디자인은 적용하지 않았다.

- `src/features/analysis/periodogram.css:78` — 시각 확인에서 세로축 숫자가 글자 단위로 줄바꿈됐다. 축 폭·nowrap을 지정해 수정하고 1024px 눈금 높이 검사를 추가했다.
- `src/features/analysis/PeriodogramChart.tsx:417` — 짧은 추천 목록에도 content-visibility를 적용해 초기 접근성 트리에 항목이 빠졌다. 50개 초과 목록에만 적용하도록 수정했다.

## 3단계: 주기 선택·미세 조정

[period-selection.ts](../src/features/analysis/period-selection.ts)는 선택 출처·원본 주기·조정 기준 주기·허용 범위를 보존한다. [PeriodSelection.tsx](../src/features/analysis/PeriodSelection.tsx)는 선택 상태와 입력을 관리하고 기존 차트의 선택선을 갱신한다. 공통 인증·라우터·API와 샘플 응답은 변경하지 않았다.

- 추천 목록의 `주기 선택`은 서버의 원본 `periodDays`, `gridIndex`, `fineTune`을 사용한다. 목록 순위로 출처를 추정하지 않는다. `위치 보기`는 계속 조회만 한다.
- `그래프에서 주기 고르기`를 켠 뒤 한 번 누르면 로그 축의 해당 주기를 직접 선택한다. 드래그는 이동만 하며 Esc로 선택 모드를 취소한다. 격자 조회 뒤 `조회한 주기 선택`이나 그래프 Enter로도 선택할 수 있다. Enter는 조회값이 없으면 표시 중앙을 고른다.
- `새 주기 (일)`은 전체 격자 범위 내의 임의 유한 주기를 받는다. 봉우리와 같은 숫자를 직접 입력해도 `sourcePeakGridIndex`는 null이다. 가까운 추천 봉우리로 자동 이동하거나 출처를 역추정하지 않는다.
- 미세 조정의 범위와 기준 주기는 최초 선택에 고정한다. 조정할 때마다 범위를 옮겨서 원래 범위를 벗어날 수 없다. 추천 봉우리의 step은 응답 원본값이다. 직접 선택은 step을 null로 보존하고 미세 조정 UI를 제공하지 않으며, 상태 함수에서도 조정을 거절한다. 직접 선택값을 바꾸려면 새 주기를 다시 선택한다. 숫자 입력은 범위 내 원본 정밀도를 보존하고, 범위 밖·빈 값·비유한 수치는 적용하지 않는다.
- 슬라이더 포인터는 최초 주기를 기준으로 간격 단위에 맞추며 양 끝값도 선택할 수 있다. 키보드 방향키·PageUp/Down과 간격 버튼은 현재 값에서 한 간격 이동하고, Home/End는 최소/최대다. 경계에서 더 이동하지 않으며 숫자 입력을 몰래 경계로 바꾸지 않는다. range의 HTML step은 any로 두어 최초 주기와 숫자로 입력한 비정수 배수를 브라우저가 자동 반올림하지 않도록 하고 실제 조작 간격은 이벤트 처리에서 적용한다.
- 선택선·요약 숫자만 표시 형식을 적용한다. 숫자 입력은 JavaScript Number의 원본 문자열을 사용한다. 확대·이동·값 조회·전체 보기·봉우리 위치 보기는 선택과 revision을 변경하지 않는다.
- 오류·빈 봉우리·미계산·로딩 중에는 선택 UI를 제공하지 않는다. 현재 자료 재조회와 별 이동 시 화면의 이전 선택을 제거한다. #183 4단계의 새 Bundle 자동 복구는 아래에 기록한다. #184의 접기·실패 복원·후속 초안 초기화는 별도다.

`PeriodogramPanel.onPeriodChange`는 선택 조작 시 한 번 호출하는 선택적 연결 지점이다. 이벤트는 `kind: reselect | fine-tune`, 증가하는 `revision`, CurveContext 전체, selection/peak 규칙 버전과 `selection` 원본값을 전달한다. 같은 숫자를 새로 선택해도 reselect이며, 같은 값의 미세 조정은 변경 이벤트를 만들지 않는다. 향후 접기 소비자는 reselect에서 접힌 배율을 초기화하고 fine-tune에서는 배율만 유지해야 한다. 아직 소비자가 연결되지 않아 접기·판단·제출 상태의 초기화나 복원 완료를 주장하지 않는다. 문맥 폐기 처리는 소비자 연결 시 함께 검증한다.

직접 확인은 위 정상 샘플 주소에서 `1위 봉우리 선택 → 한 간격 늘리기 → 슬라이더 Home/End → 미세 조정 숫자 입력` 순서다. 허용 범위 밖 숫자를 적용하면 오류와 기존 선택이 함께 남는다. `새 주기`에 같은 숫자를 넣고 선택하면 출처가 직접 선택으로 바뀐다. 샘플은 여전히 합성 주기도이며 이 입력 조작으로 BLS·잔차·봉우리 API를 호출하지 않는다.

## 4단계: 새 Bundle 복구와 이전 선택 폐기

주기도·봉우리 조회가 새 `X-Current-Bundle` 또는 HTTP 409 `BUNDLE_CHANGED`를 받으면 [useAnalysisData](../src/features/analysis/useAnalysisData.ts)의 분석 조회 흐름으로 돌아간다. `PeriodogramBundleChanged`는 자동 복구 신호, `PeriodogramContextChanged`는 본문의 문맥 불일치로 구분한다. 2xx 본문을 읽을 수 없어도 새 Bundle 헤더가 확인되면 복구한다. 본문만의 Bundle·계산 버전·제거 집합 불일치와 403/404/503·다른 409는 자동 복구하지 않는다.

1. 현재 읽기를 취소하고 문맥·시간 곡선·주기도·선택 UI를 제거한다. 새 판을 읽는다는 상태를 안내한다.
2. 분석 문맥부터 다시 읽는다. 요청의 Bundle·곡선 단계·제거 집합은 새 문맥의 값으로 만들며, 이전 값으로 봉우리 조회를 이어가지 않는다.
3. 새 문맥·곡선·주기도·봉우리가 검증되면 차트를 표시하고 선택되지 않은 상태로 시작한다. 새 Bundle 안내와 서버의 복원 불가 안내를 유지한다.
4. 문맥/곡선 로더와 주기도 로더는 **자동 복구 1회 한도**를 공유한다. 곡선에서 한 번 복구한 뒤 주기도에서 또 경합하거나 반대 순서로 경합해도 추가 자동 조회하지 않는다. 이 경우 시간 차트까지 지우고 오류와 `다시 불러오기`를 제공한다. 사용자가 수동 재시도하면 한도를 새로 시작한다.

이 기능은 현재 발생한 읽기 응답을 검사한다. 화면을 가만히 둔 동안 새 판을 감시하는 폴링·타이머를 추가하지 않았다. 직접 확인은 정상 샘플에서 봉우리 선택 후 `최신 자료 확인`을 누르면 된다. 고정 샘플은 같은 판을 다시 반환하므로 선택 초기화를 확인할 수 있으며, 실제 판 변경은 아래 테스트 응답으로 검증한다.

### 샘플 응답과 검증

[periodogram-refresh.spec.ts](../tests/browser/periodogram-refresh.spec.ts)는 기존 합성 응답을 테스트의 HTTP 가로채기에서만 수정한다. 예를 들어 최초 주기도 요청에는 이전 본문과 새 헤더(또는 409)를 반환한다. 뒤이은 문맥은 새 Bundle `9007199254741193`, 곡선 1단계, 제거 집합 `["9007199254741094"]`를 반환하고 시간 곡선·주기도·봉우리도 같은 문맥으로 맞춘다. 주기도 power는 여전히 합성 값이며 새 잔차나 BLS를 계산한 결과가 아니다. 개발 서버에 호출 횟수별 전역 상태나 새 API를 추가하지 않았다.

브라우저 검사는 주기도/봉우리 각각의 헤더·409·읽을 수 없는 본문, 주기도→주기도·곡선→주기도·주기도→곡선 반복 경합, 수동 복구, 다른 오류 보존, 초기화와 늦은 이전 응답을 다룬다. 개발 StrictMode에서 취소된 첫 마운트 요청은 자동 Bundle 복구와 구분한다. 판 변경 fixture는 요청 Bundle ID로 분기해 취소된 요청의 발생 순서에 의존하지 않는다. 단위 검사에는 이미 사용한 공유 한도로 곡선 로더가 추가 재시도를 막는 조건을 추가했다.

접근성 검토는 변경한 페이지·패널의 상태 알림과 수동 복구 버튼에 한정했다. 기존 status/alert·키보드 버튼을 재사용하며 스타일·배치 변경은 없다. React 가이드의 안정된 callback·취소 정리·이전 응답 차단을 유지했다. 실제 스크린리더·실제 API·잔차 계산·#184 접기 소비자까지 검증한 것은 아니다. 임의 위치 선택의 미세 조정은 계속 보류한다.
