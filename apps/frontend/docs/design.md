# 분석 화면 디자인 토큰과 규약

기준: Figma `Planetory · 분석 화면 배치 초안` 노드 `25:2`(`02 분석 단계 · 1-5`) 은하 스타일 5화면 / 와이어프레임 v1.2 / 현재 [`src/styles.css`](../src/styles.css). 2026-09-18 작성.

아래 값은 **Figma 은하 스타일에서 추출한 검토안**이다. Figma에 변수(디자인 토큰)가 정의되어 있지 않아 레이어에 박힌 값을 읽어 정리했으므로, Figma를 고쳐도 이 문서가 자동으로 따라오지 않는다. 이 문서가 코드의 기준이고 Figma가 배치·상호작용의 기준이다. 둘이 어긋나면 구현하지 말고 어긋난 지점을 보고한다.

**적용 범위는 분석 화면(`/analysis/:ticId`)뿐이다.** 전역 `:root`를 바꾸지 않는다. 다른 화면(별지도·커뮤니티·통계)은 현재 팔레트를 유지한다.

## 글래스모피즘

패널의 유리 효과는 **Figma 원본을 그대로 쓴다.** `rgba(57,57,70,0.2)` + `backdrop-filter: blur(11px)` + `1px solid rgba(238,238,238,0.1)`.

이 결정에는 대가가 있다. 패널이 거의 투명하고 유리색(`rgb(57,57,70)`)이 바탕(`#222831`)보다 밝아서, 은하 배경의 밝은 별 영역이 패널을 통과해 올라오면 그 위 글자 대비가 무너진다. Figma 원본 그대로는 13px 라벨이 2.82:1, 격자가 1.42:1까지 떨어진다.

유리를 건드리지 않고 이를 해결한다. 손대는 것은 **유리 뒤쪽 배경**과 **글자·격자 색**이고, 유리 자체(투명도·블러·테두리)는 그대로다.

`kill-ai-slop` 검사에서 glassmorphism이 탐지 항목으로 걸린다. 의도된 선택이므로 제거하지 않는다. 다만 아래 두 조건을 붙여 범위를 한정한다.

- 유리는 **패널 껍데기에만** 쓴다. 새 요소에 유리를 확장하지 않는다.
- 유리 위에는 **`--fg-3` 이상 밝기의 글자만** 올린다. 더 흐린 단계를 새로 만들지 않는다.

## 색

바탕 4색(`#222831` · `#393E46` · `#EEEEEE` · `#FFD369`)과 그 위의 알파 단계로 이루어진다. 새 색상을 만들지 않는다.

  --accent: #ffd369;

  /* 은하 배경 — Figma 0.4에서 올림. 아래 '대비' 참고 */
  --overlay: rgba(34, 40, 49, 0.75);

  /* 유리 — Figma 원본 그대로 */
  --panel: rgba(57, 57, 70, 0.2);
  --panel-blur: 11px;
  --panel-line: rgba(238, 238, 238, 0.1);
  --panel-shadow: 0 8px 12px rgba(34, 40, 49, 0.4);
  --plot-bg: rgba(34, 40, 49, 0.4);

  /* 조작 요소 */
  --control-bg: rgba(238, 238, 238, 0.05);
  --control-bg-weak: rgba(238, 238, 238, 0.04);
  --check-line: rgba(238, 238, 238, 0.33);

  --grid: rgba(238, 238, 238, 0.42); /* 그래프 격자. 값을 읽는 선 */
  --divider: #393e46; /* 화면 구분선. 장식 */

  /* 강조 */
  --accent-fill: rgba(255, 211, 105, 0.19);
  --accent-line: rgba(255, 211, 105, 0.5);
  --accent-sel-fill: rgba(255, 211, 105, 0.15);

## 대비

은하 배경은 이미지라 픽셀마다 밝기가 다르다. **가장 밝은 영역을 최악값으로 잡고** 배경 → 오버레이 → 패널 → 플롯 → 글자 순서로 실제 합성 결과를 계산했다. 검산은 [`scripts/check-contrast.mjs`](../scripts/check-contrast.mjs)로 재현한다.

```bash
node scripts/check-contrast.mjs
```

### Figma에서 바꾼 값 세 개

| 항목                     | Figma                | 채택                      | 이유                                                                                                 |
| ------------------------ | -------------------- | ------------------------- | ---------------------------------------------------------------------------------------------------- |
| 배경 오버레이            | `rgba(34,40,49,0.4)` | `0.75`                    | 레이어 이름이 `01 배경 명도 조절 · 오버레이`다. 유리 뒤쪽만 어둡게 해 유리를 보존한 채 대비를 올린다 |
| 흐린 글자 `0.4` · `0.33` | 두 단계              | `--fg-3`(`0.67`)으로 통합 | 오버레이를 아무리 올려도 `0.4`는 3.21:1을 못 넘는다. 알파 자체가 원인이라 배경으로는 못 고친다       |
| 그래프 격자              | `#393e46`            | `rgba(238,238,238,0.42)`  | 어느 오버레이에서도 1.0~1.4:1이다. 격자는 값을 읽는 선이므로 비텍스트 3:1을 적용한다                 |

화면을 나누는 `구분선`은 장식이므로 `#393e46`을 그대로 둔다.

`--fg-3`이 4.56:1로 여유가 거의 없다. 오버레이를 `0.75` 아래로 내리면 바로 미달한다.

### 배경 이미지 제약

`00 은하 배경 · 이미지 교체 가능`이므로 이미지가 바뀔 수 있다. 오버레이 `0.75` 기준으로 **가장 밝은 픽셀이 약 `rgb(184,189,204)` 이하**여야 한다. 더 밝은 이미지를 쓰려면 오버레이를 함께 올린다. 교체할 때마다 검산 스크립트의 `BRIGHTEST` 값을 실제 이미지 최대 밝기로 바꿔 다시 돌린다.

## 글자

Figma는 **Noto Sans KR** Regular(400)·Medium(500)만 쓴다.

**글꼴은 이번 범위에서 바꾸지 않는다.** 전역 설정이라 분석 화면만 바꾸면 화면마다 글꼴이 달라진다.

별도로 확인된 문제가 있다. 현재 `styles.css`의 `font-family: Inter, "Pretendard", "Noto Sans KR", system-ui`에서 **세 글꼴 모두 실제로 로드되지 않는다.** `@font-face`도 없고 `index.html`에 링크도 없다. 지금 한글은 `system-ui`(Windows에서 맑은 고딕)로 렌더된다. 전역 과제이므로 이 문서에서 다루지 않고 따로 올린다.

| 용도                | 크기 | 굵기 | 색       |
| ------------------- | ---- | ---- | -------- |
| 별 이름             | 18px | 500  | `--fg-1` |
| 패널 제목·서비스명  | 16px | 500  | `--fg-1` |
| 수치 강조·기본 버튼 | 14px | 500  | `--fg-2` |
| 라벨·단계·선택지    | 13px | 400  | `--fg-3` |
| 보조 설명·위상      | 12px | 400  | `--fg-3` |
| 축 라벨·단위        | 11px | 400  | `--fg-3` |

줄 간격은 전부 `1.45`다. 전역 `p { line-height: 1.8 }`과 다르므로 `.analysis-screen` 안에서 재정의한다.

### 반응형

[`App.tsx`의 `DesktopGate`](../src/app/App.tsx)가 이미 **1024px 미만을 차단**한다. 따라서 다룰 범위는 **1024px~1440px**뿐이고, 모바일 레이아웃은 필요 없다.

Figma는 1440 고정폭 하나만 있다. 1024~1440 구간은 다음으로 정한다.

- 주 열(984px)이 유동으로 줄고, 보조 열(360px)과 여백(32px)·열 간격(32px)은 고정한다.
- 1024px에서 주 열은 `1024 - 64 - 32 - 360 = 568px`가 된다.
- 보조 열을 아래로 내리지 않는다. 단계 전환 중 작업 패널이 화면 밖으로 밀리면 안 된다.

주 열 568px에서 광도 곡선이 읽히는지는 구현 후 실제로 확인해야 한다. 안 되면 `DesktopGate`의 하한을 올리는 쪽을 검토한다. 이 문서에서 미리 정하지 않는다.

### 단계 표시

| 상태    | 표기            | 색         | 비고              |
| ------- | --------------- | ---------- | ----------------- |
| 완료    | `✓ 봉우리 선택` | `--fg-3`   | 클릭으로 되돌아감 |
| 현재    | `4 판단`        | `--accent` | 밑줄, 굵기 500    |
| 진행 전 | `5 제출값 확인` | `--fg-3`   | `opacity: 0.38`   |

`✓`와 색만으로 상태를 구분하면 안 된다. 현재 단계에 `aria-current="step"`, 진행 전 단계에 `aria-disabled`를 준다.

로딩·빈 데이터·오류는 [`RequestState`](../src/components/RequestState.tsx)와 [`ErrorBoundary`](../src/components/ErrorBoundary.tsx)를 쓴다. Figma 1단계의 빈 상태(`봉우리를 선택하면 / 아래에 겹친 곡선이 표시됩니다`)가 빈 데이터 문구의 기준이다.

### 접근성에서 Figma와 다르게 갈 부분

| 항목        | Figma              | 코드                        | 이유                                     |
| ----------- | ------------------ | --------------------------- | ---------------------------------------- |
| 버튼 높이   | 42px               | 44px                        | 현재 `styles.css`가 이미 44px. 터치 타겟 |
| 아이콘 버튼 | 30×30              | 44×44 히트 영역             | 시각 크기는 30 유지, 패딩으로 확보       |
| 체크박스    | 16×16              | 16 + 행 높이 28px 전체 클릭 | `<label>`로 감싼다                       |
| 비활성 표현 | `opacity: 0.25`    | `opacity` + `disabled`      | 투명도만으로 상태를 알리지 않는다        |
| 선택됨 표현 | 금색 테두리 + 글로 | + `aria-checked`            | 색만으로 알리지 않는다                   |

그래프는 캔버스/SVG라도 **수치를 읽을 수 있는 대체 경로**가 있어야 한다. `주기 11.734616일`·`선택 위상 0.92-1.08`처럼 화면에 이미 텍스트로 있는 값이 그 역할을 한다. 새로 그리는 그래프마다 같은 수준의 텍스트 요약을 붙인다.

`backdrop-filter`는 `prefers-reduced-transparency: reduce`에서 끄고 `--panel`을 불투명한 `#2b303a`로 바꾼다. 유리는 장식이므로 꺼져도 화면이 성립해야 한다.

## 전역 코드와 다른 지점

`.analysis-screen` 안에서만 다르다. 전역 `styles.css`는 바꾸지 않는다.

| 항목        | 전역 (유지)                  | 분석 화면                             |

| 본문 글자   | `#e5e9ee`                    | `#eeeeee`                             |
| 보조 글자   | `--muted: #a8b2c1`           | `--fg-3`                              |

## Figma에 반영이 필요한 것

코드가 Figma와 의도적으로 다른 지점이다. 반영 여부는 미정이며, 반영하지 않으면 이 표가 차이의 기록으로 남는다.

1. 배경 오버레이 `0.4` → `0.75`
2. 흐린 글자 `0.4`·`0.33` 두 단계 삭제, `0.67`로 통합
3. 그래프 격자 `#393e46` → `rgba(238,238,238,0.42)`
4. 버튼 높이 `42px` → `44px`
5. Figma 변수(디자인 토큰) 정의 — 현재 0개
6. 1·2단계(`100:2`·`100:97`) 통합 — 봉우리 선택과 미세 조정을 한 화면에서 끝내기로 해 구현은 4단계다. 봉우리를 골라도 단계가 넘어가지 않는다 (2026-09-18)
7. 오류 문구 색 `--danger` `#ffb5b5` 추가 — Figma 팔레트에 오류 색이 없어 새로 정했다 (2026-09-18)

## 구현 상태 (2026-09-18)

이 문서의 토큰으로 분석 화면을 구현했다. 구현·검증 기록은 [분석 디자인 적용 기록](analysis-design.md)에 있다. 배경 이미지는 `src/features/analysis/assets/galaxy-background.webp`이며 상위 0.1% 밝기 rgb(170,168,185)로 위 허용 한계 안이다. 검산 스크립트의 `BRIGHTEST`를 이 실측값으로 바꿨다.

구현하며 이 문서에 없어 정한 것:

- 오류 문구는 `--danger`(`#ffb5b5`)를 쓴다. 금색은 선택 강조에 쓰므로 오류에 겹쳐 쓰지 않는다. 색만으로 알리지 않으며 문구와 포커스 이동이 1차 신호이고 색은 보조다. 정상 상태와 같은 요소를 쓰는 곳(예상 띠 없음 안내 등)에는 적용하지 않는다.
- 기본 버튼은 `--accent` 단색 채움에 `--bg` 글자로 구현했다. 팔레트 안이며 대비가 높다.
- Figma 원본 SVG 아이콘은 `#4B4B4B` 고정 스트로크다. `<img>`로 넣어 stroke를 토큰으로 바꿀 수 없어 `filter`로 맞춘다.

## 아직 정하지 않은 것

- 패널 밖 글자의 별 픽셀 대비. 유리 뒤는 `blur(11px)`가 별을 주변과 평균내지만 단계 표시·보조 링크·헤더는 블러 없이 배경 위에 바로 놓인다. 순백 별 픽셀이 글자 뒤에 오면 오버레이 0.75에서 `--fg-2` 4.28:1, `--fg-3` 3.52:1로 미달한다. 오버레이 0.85면 전부 통과하지만 은하가 그만큼 어두워진다. 검산 스크립트가 이 경우를 참고 항목으로 출력한다.
- 상단 행 높이. Figma는 258px이지만 범례가 그 안에 들어가지 않아 구현은 `min-height: 258px`로 두고 내용에 맞춰 늘린다. 실측 1440px 278px · 1024px 286px. 그래프 높이를 줄여 258px을 지킬지, 늘어난 높이를 받아들일지 정해야 한다.
- 1024px에서 주 열 568px일 때 광도 곡선 가독성. 구현 후 실측
- 전역 글꼴 로드 누락 — 분석 화면 범위 밖, 별도 과제
