# #182 분석 데이터 읽기·시간 곡선·판 갱신 — 2~4단계

목적은 현재 분석 문맥을 읽고 그 문맥의 곡선 세그먼트를 검증해 화면에 표시하는 것이다. 적용 기준은 develop `d387bd4`의 [탐사 API 5.1·5.2절](https://lab.ssafy.com/s15-bigdata-dist-sub1/S15P21C206/-/blob/d387bd4beaa78f6c34c793be29a9b58571aa3721/apps/backend/docs/exploration-api-spec.md)과 SRS EXP-01~03, DAT-11, POL-04·05이다. 프론트 표시용 합성 응답 검증 단계이며, 실제 C08 API·D09 Gold 데이터의 연동이나 승인 증거가 아니다.

## 요청 흐름

1. 공통 `usePageContext()`에서 TIC를 읽는다. 로그인 확인은 기존 SessionProvider가 수행한다.
2. [useAnalysisData](../src/features/analysis/useAnalysisData.ts)가 분석 전용 [loadAnalysis](../src/features/analysis/load-analysis.ts)와 공통 `api()`를 통해 `GET /api/v1/stars/{ticId}/analysis-context`를 요청한다.
3. [어댑터](../src/features/analysis/analysis-data.ts)가 TIC, Bundle ID/버전, 계산 버전, 제거 후보 집합, 공통 기준 시각과 공개 가능한 필드를 검사한다.
4. 검사한 현재 문맥으로 `GET /api/v1/stars/{ticId}/curves?bundleId=...&curveStep=...&removed=...`를 요청한다. 원본은 `removed`를 생략한다.
5. 같은 문맥의 응답인지 검사한 후 Bundle, 단위, Sector, 간격, 전체·유효·결측 점 수를 표시한다. 재시도는 현재 분석 문맥부터 다시 읽는다.

4단계에서는 문맥·곡선을 한 쌍으로 확정하고, 재조회·이동·unmount 시 이전 요청을 취소하며 늦은 응답을 무시한다. 공통 `api()`의 선택 옵션 `onResponse`로 헤더를 읽고 판 비교·재조회는 분석 전용 코드에서 처리한다. `useResource()` 자체는 변경하지 않았다. 공통 파일 변경과 담당자 확인 항목은 [공통 계약](shared-frontend-contract.md)에 기록한다.

## 샘플 응답은 어디서 나오는가

아래는 `fixture` 모드의 합성 응답 설명이다. 후속으로 연결한 프로토타입의 TESS 3개 항성은 별도 `observations` 모드이며, 출처·비닝·실행법은 [관측 데이터 안내](observation-fixtures.md)를 따른다. 현재 5182 로컬 실행 도구는 관측 모드를 사용한다.

[analysis-fixtures.ts](../dev/analysis-fixtures.ts)의 `analysisContextFixture()`와 `analysisCurveFixture()`가 매 호출마다 새 객체를 만든다. 별과 상태별 라우팅은 `analysisFixtureResponse()`가 담당한다. 고정 숫자를 쓰므로 같은 요청은 같은 응답을 준다. 무작위 생성이나 실제 DB 조회는 하지 않는다.

[fixture-plugin.ts](../dev/fixture-plugin.ts)는 Vite 개발 서버의 `/api` 미들웨어다. `fixture` 모드에서 브라우저의 실제 HTTP GET을 받아 위 객체를 `JSON.stringify()`하여 응답한다. `/api/v1/me` 샘플 로그인은 기존 구현을 유지한다. 분석 조회가 계산 작업이나 저장 요청을 만들지는 않는다.

React 컴포넌트는 샘플 파일을 import하지 않는다. 일반 서버 모드에서는 같은 요청을 `API_PROXY_TARGET`으로 프록시하며, 실제 서버 연결이 실패해도 샘플로 대체하지 않는다. 운영 빌드에서는 fixture 플러그인·합성 응답·샘플 안내 문구가 제외되는지 검사한다.

## 3단계 시간 차트

[time-curve.ts](../src/features/analysis/time-curve.ts)는 검증된 세그먼트에서 `BTJD = startBtjd + index × binMinutes / 1440`으로 시각을 복원한다. 원래 배열을 변경하지 않고 유효점의 원본 인덱스·세그먼트 ID·Sector·실제 시각·밝기를 보존한다. 화면 좌표는 별도로 둔다.

- 세그먼트 내부의 null은 음영으로 표시하고 그 앞뒤의 선을 끊는다. 유효한 0은 결측으로 취급하지 않는다.
- 세그먼트를 시작 시각 순서로 배치한다. 각 세그먼트 내부는 실제 시간 간격을 유지하고, 세그먼트 사이는 총 표시 구간 길이의 8%를 나눠 경계 공간으로 사용한다. 이 값은 표시용 간격이며 과학 시각이나 계산에 사용하지 않는다.
- 경계를 `//`로 표시하고 각 Sector에 실제 BTJD 눈금을 붙인다. 실제 시간 간격은 접는 설명에서 확인한다. 겹치는 세그먼트는 관측 시간이 겹친다고 안내하며 허위 공백을 만들지 않는다.
- 정상 샘플은 유효점 11개, 연속 관측선 4개다. Sector 14의 마지막 배열 시각과 Sector 41의 시작 시각 사이 간격은 표시 반올림 기준 736.59139일이다.
- [TimeCurveChart](../src/features/analysis/TimeCurveChart.tsx)는 실험 ObservationChart의 Canvas·DPR 재설정·ResizeObserver·휠 앵커 확대·포인터 캡처 방식을 시간 세그먼트에 맞게 적용했다. 실험 파일을 import하지 않으며 위상 선택 코드나 실험의 과학 수치 기본값을 가져오지 않는다.
- 그래프는 휠·+/−·버튼으로 1~64배 확대·축소하고, 드래그·←/→·버튼으로 이동한다. 0/Home·전체 보기·더블클릭으로 표시 범위를 복원한다. 64배는 표시 조작의 상한이며 과학적 선택 제한이 아니다.
- 마우스 또는 ↑/↓로 관측점의 실제 시각·밝기를 확인한다. 관측 공백에서는 가짜 수치를 표시하지 않는다. 조작은 API·원본 데이터·진행 상태를 변경하지 않는다.

3단계의 차트 스타일은 분석 전용 CSS에 한정한다. 당시 새 패키지, 전역 스타일·라우터·API 클라이언트 수정은 없었다. 기준 시각·단위·Bundle은 2단계 요약을 그대로 사용한다. 후속 4단계는 아래에 기록한다. 위상 선택에 따른 밴드는 해당 후속 기능에서 연결한다.

추가 단위 검사는 실제 BTJD·서로 다른 케이던스, null/경계의 분리된 그리기 경로, 단일점·상수·전 결측, 시간 범위 겹침, 20,000점 보존과 확대·이동 경계를 다룬다. 20,000점은 합성 배열의 보존 검사이며 운영 성능 측정은 아니다. 브라우저 검사는 키보드·휠·드래그·초기화·1024px·Canvas 크기와 조작 중 추가 API 요청 없음을 확인한다.

2026-09-15 3단계 실행 결과: 타입 검사·프로덕션 빌드·fixture 제외 검사, 단위 테스트 25개, Chromium 브라우저 테스트 12개, 프로덕션 미리보기 테스트 2개(전체 39개), 로컬 줄바꿈을 허용한 포맷 검사가 통과했다. 5182 포트의 실행 화면에서도 두 Sector, 결측 음영과 분리된 관측선을 확인했다.

## 4단계 판 갱신과 요청 상태

적용 기준은 탐사 API 2.3절(D-5, `BUNDLE_CHANGED`)과 5.1절(C02-R1)이다. 디자인은 이후 한 번에 적용하며 현재는 기능 확인용 화면이다.

- 곡선 응답의 `X-Current-Bundle`이 읽어 둔 Bundle ID와 다르면 그 응답을 버리고 갱신 안내 후 문맥부터 다시 읽는다. HTTP 409 `BUNDLE_CHANGED`도 같은 흐름이다. ID는 숫자로 변환하지 않고 문자열로 비교한다.
- 문맥 응답 자체의 헤더와 본문이 다르면 곡선을 요청하기 전에 다시 읽는다. 헤더가 없으면 본문 검증으로 읽을 수 있지만 헤더 기반 감지는 할 수 없다. 실제 서버가 이 헤더를 제공하는지, 다른 출처 배포라면 CORS에서 노출하는지는 통합 검증 대상이다.
- 자동 재조회는 한 번이다. 두 번째에도 판이 일치하지 않으면 오류와 `다시 불러오기`를 표시한다. 403·404·503·일반 409는 원래 오류를 유지하며 판 변경으로 반복하지 않는다.
- 문맥과 곡선을 함께 검증한 뒤 화면에 반영한다. 재조회 중에는 이전 차트를 숨기고 차트의 확대·이동 상태를 초기화한다. 이전 요청은 AbortSignal과 요청 순번으로 차단하므로 이동·재진입 뒤 늦은 결과가 현재 화면을 덮지 않는다.
- 새 문맥의 `currentCurveContext`를 사용한다. 서버가 유지한 곡선 단계·제거 조합을 그대로 요청하며, `notice: STEP_NOT_RESTORABLE`이면 서버가 반환한 현재 진행 문맥을 사용하고 복원 불가를 안내한다. 프론트가 임의로 0단계나 후보 교집합을 만들지 않는다.
- 준비된 화면의 `최신 자료 확인`으로 문맥부터 수동 재조회한다. 같은 판이면 차트가 다시 표시되고 다른 판이면 갱신 안내를 추가한다. 버튼·재시도는 GET만 실행한다.

현재 원본 읽기 단계에는 주기적인 판 확인 요청을 추가하지 않았다. 요청이 없는 동안 서버의 판 변경을 실시간으로 알 수는 없으며 다음 조회에서 감지한다. 잔차 작업 폴링은 후속 잔차 기능에서 같은 헤더를 비교하도록 연결한다. 주기·위상·제출 초안은 아직 없으므로 해당 입력 초기화까지 구현했다고 보지 않는다. 미계산 잔차는 그대로 안내하며 작업을 생성하거나 가짜 폴링을 하지 않는다.

정상 샘플 259377017은 여전히 같은 판을 반환한다. 259377023은 매번 이전 본문과 새 헤더를 반환하는 고정 실패 예제라 수동 재시도해도 성공으로 바뀌지 않는다. 전환 성공 검사는 Playwright가 첫 곡선 응답만 이전 본문+새 헤더(또는 409)로 가로채고, 다음 문맥·곡선에는 새 Bundle `9007199254740997`, 버전 8, 1단계 문맥을 반환한다. 이 과정은 테스트 안에서만 수행하며 공유 fixture에 횟수별 전역 상태나 새 쓰기 API를 만들지 않는다.
